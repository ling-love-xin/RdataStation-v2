# Mock 视图 UI 统一（卡片化 / 入口合并 / 样式原语）

日期：2026-11-01
范围：`crates/mock/src/mock_view/*`（中央详情 tab、右 Dock、三个对话框）

## 1. 问题

改动前，`mock` 视图的"同一件东西"有三个版本：

| 东西 | 份数 | 各自为政的地方 |
| --- | --- | --- |
| 一张卡片 | 3 | `border_1().rounded(radius)` 手抄三遍，内距 `p_1` / `p_2` / `px_2` 混用 |
| 段标题（「属性」/「参数」/「列（N）」） | 3 | 三份 `border_b_1().pb_1()`，线与字的间距 0 / 4 / 8px |
| 标签-值行 | 6 | 其中两处漏 `min_w_0`（长值顶破容器） |
| 选生成器 | 2 个窗口 | 字段行 720px 两栏窗口 + 列编辑 840px 两栏窗口，内容重叠 |
| 按钮语义 | 71 个按钮 | primary 只有 3 个，"这一步的主行动"全靠读文字 |

后果：改卡片内距要动三四处，漏改一处就静默错位；用户要猜"开哪个窗口"、猜"点哪个是操作"。

## 2. 做法：抽一层样式原语

新增 `crates/mock/src/mock_view/style.rs`。渲染侧只描述**语义**，形态在函数内单一来源：

| 原语 | 用途 |
| --- | --- |
| `card` / `card_interactive` | 卡片容器（常态 / 可悬浮：底 + 描边同时变） |
| `section` | 段标题（小字 + 次级色 + 下方细线，线与字同属一个元素） |
| `kv` | 标签-值行（左标签可收缩，右值） |
| `data_type_tag` / `confidence_tag` | chip（色相即语义） |
| `card_title` / `card_note` | 卡片内主文字 / 说明文字（一律可截断） |
| `button(id, label, ActionKind)` | 按钮语义：`Main`（填色，每容器最多一个）/ `Soft`（描边，其余全部） |
| `icon_button` / `danger_icon_button` | 图标按钮（小号 + 无框 + 统一 500ms tooltip） |

### 颜色：按数据族分色，不按字母序

一张卡片里 13 种类型要能一眼分族，靠色不靠读字：

- 数值（Integer / BigInt / Float / Double / Decimal）= 蓝
- 文本（Varchar / Text）= 绿
- 逻辑（Boolean）= 强调色
- 时间（Date / DateTime / Timestamp）= 橙
- 二进制与 ID（Uuid / Blob）= 灰

置信度：high=绿（推断可信）/ manual=蓝（人手定的）/ low=灰（推断没把握）。

## 3. 字段卡片：三段式

```
┌──────────────────────────────────────────────────────────────┐
│ 列名              [INTEGER] [high] ↳ 引用 t.id    ↑ ↓ ⧉ 🗑  │  头部：身份 ｜ 操作
│ [随机整数 ▾]      空值 10% · 1~1000                          │  内容：生成器入口 + 摘要
└──────────────────────────────────────────────────────────────┘
```

- **身份信息与操作分栏**：左边是"这一列是什么"（跟着列名读），右边是"能对它做什么"。
  混排时"点哪个是操作"是猜谜。
- **卡片上只留一个文字入口**（生成器名）：生成器入口与编辑入口是同一个。
- 操作全是 icon-only + tooltip（↑↓ 移序 / 复制 / 删除），删除只染图标不染底
  （一排卡片摆着时，红底按钮会盖过卡片内容）。
- 结果表 tab 的列卡片同款，只读（不给操作图标——就地改会让结果与产出它的配置分叉）。

## 4. 生成器入口合并

删掉字段行那个独立的 720px「生成器库」两栏窗口及其一整套状态：

- `open_library` / `render_browse_two_column` / `render_inspector` / `render_inspect_footer`
- `select_generator` 与 `selected`（"先选中、右栏检视、点应用才落地"这条路）
- `LibraryWriteback::Panel`（直接写面板列）——枚举退化为结构体，只剩"列编辑草稿"一个目标
- 面板侧 `open_generator_library(_with)` 与 `set_column_name`

选生成器只剩一处：列编辑对话框的左栏，**一律先落在草稿、由「应用」落地**（与 V2 同口径），
不再有"点一下就把表改了，反悔只能再选回去"的差别。

自定义生成器精调层改走**独立 560px 窗口**（`open_create_dialog`）：内嵌左栏只有 280px，
表单（名字 / 类型 / 业务组 / 基础生成器 / 参数 / 样例）塞进去会挤成两段。

## 5. 「智能」归位

从字段卡片（"智能"按钮）+ 右栏底部（"恢复智能默认"）→ **选择器左栏顶部常驻「智能推荐」**：

- 它是"选哪个生成器"的一种解法（与手选并列），不是一个独立动作；
  摆在卡片操作按钮里看着像"对所有列批量智能"。
- 跟着选择器走，而不是躺在右栏底部——它作用的就是"左栏正在选的东西"。
- 按**当前列名输入框的值**（用户可能刚改过名还没应用）重推，不按打开对话框时的快照。

## 6. 按钮语义

`Main`（Primary 填色）每个容器最多一个，其余一律 `Soft`（Secondary 描边）：

- 中央表头动作行：`生成` = Main；`持久化` / `追加` / `保存到草稿箱` / `另存为` = Soft
  （这一步的主行动是"生成"，出口是生成之后的事）
- 列编辑页脚：`应用` = Main；`取消` / `应用并新增下一列` = Soft

## 8. 下一步（本轮未做）

1. **右 Dock 清单行**：仍是 24px 紧凑行，卡片化会损失一行能放的信息；
   它同时承载选中底 / 悬停底 / 左缘标识条 / 下缘进度线，改造要连进度线一起设计。
2. **卡片 hover 过渡动画**：gpui 的 `.hover()` 是即时的，`gpui_base::motion::transition`
   需要 hover 状态可读才能插值，本轮没接。目前动画统一在：进度扫光（三处同一套原语）、
   卡片 hover 变色、组件库自带的 Tab / 折叠 / 对话框入场。
3. **`kv` 只落了一处**（样例预览）：列编辑右栏其余"标签 + 值"行挂着测试用的
   `test_support` id，套 `kv` 会丢 id。要统一得先让测试改按别的口径定位。
