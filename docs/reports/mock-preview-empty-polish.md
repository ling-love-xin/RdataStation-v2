# Mock 预览空态与信息密度打磨（2026-11-02）

范围：`crates/mock/src/mock_view/`（中央详情 tab 为主）。前两轮（`mock-ui-unified.md` /
`mock-product-polish.md`）登记的欠账（hover 过渡 / 编辑中标识条 / 清单行卡片化）已在后续
提交清完；本轮是**新审计**出的四项，聚焦「空态组件化」与「信息密度」两条线。

## 一、改动

### P0 · 预览空态组件化（`detail.rs`）

预览段（三段分栏中最大的一块）没有数据时原来只有一行裸文本「（暂无预览）」——视觉重心
塌掉，且与右 Dock 模板 / 历史空态（已走 `empty::Empty`）同类不同形。

改为 `Empty` 组件（Inbox 图标 + 标题 + 描述 + 主操作），四种「为什么空」各说各的引导
（rds-design 空态文案规范：原因 + 下一步）：

| 状态 | 标题 | 引导 |
| --- | --- | --- |
| 草稿 tab、没结果 | 还没有生成结果 | **「生成」主按钮直达**（不必回表头找）；任务进行中禁用 |
| 切项目后（草稿 tab） | 结果已随项目切换作废 | 草稿还在，重新生成后再看（也给生成按钮） |
| 切项目后（结果表 tab） | 结果已随项目切换作废 | 回原项目重开，或重新生成 |
| 结果表 tab、本轮没它 | 这一轮没有它的结果 | 从右 Dock 清单重新生成，或切草稿 tab 再跑 |

生成按钮只给草稿 tab（结果表 tab 只读，不给「能只重跑这一张」的错觉）；disabled 判据
与表头「生成」同口径（不靠任务层拒绝）。

### P1a · 技术细节收纳进悬停

两处把 `temp_mock_*` 临时表名与毫秒耗时从常驻文案里拿掉（对用户是噪音，且挤占表名空间）：

- **结果表头事实行**：`{表} · {行数} 行 · 已生成（临时表 x · 123 ms）` → 常驻只留
  `{表} · {行数} 行 · 已生成`，技术细节进 info 悬停；
- **预览标题行**：`预览（前 10 行）· {表} · 临时表 x · 本次 50,000 行 · 123 ms` →
  常驻 `预览（前 10 行 · 共 50,000 行）`（总量是语义信息，保留可见），临时表 + 耗时进悬停。

### P1b · 中央 tab hint 收敛

- **排序提示行**（原排序生效时标题下多占一整行的 hint）→ 并进预览标题的 info 悬停
  （排序语义只在排序生效时才是问题，且是低频解释）；
- **场景来源行**：`来自场景模板「X」：列与预览都属于它自己；看别的表切 tab…` →
  常驻只说出处「来自场景模板「X」」，切换引导进悬停（出处是身份信息，引导是一次性的）。

**有意不动**：空列卡片的起手引导（空态本来就只在没列时出现）、场景态草稿提示（只在
场景模式出现）——两条都是低频状态自身的说明，不是常驻噪音。

### P2 · 小统一

- 空列卡片标题手写 `text_sm + MEDIUM` → `card_title` 原语（形态不变，来源唯一）；
- 新增 `style::info_hint_icon` 原语（悬停明细记号的尺寸 / 弱化色单一来源），右面板状态条
  与本轮三处新悬停同走它。
