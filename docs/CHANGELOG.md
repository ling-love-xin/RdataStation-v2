## 0.2.15 · 2026-11-28

> 相对 `RDS-beta-0.2.14` 的 183 个提交。主线：分析会话收成「一条源只出一行、一条会话一个 owner」并把 catalog 事实面落进 engine、SQL 发送前预检、分析资源补全局文件 CAS 与表快照闭环、回收站收成唯一入口、结果集网格继续按 DBeaver 真值对密度与表头。同期把 Rust 钉到 `1.100.0`（本机 / CI / 发版同轨）并清掉 cargo 1.100 新点名的 14 条 unused dependency 告警。

### 分析会话与引擎

- engine 新增 catalog 事实面（一个别名一条），数据对象面板改读 engine 的文件索引，`Shared.loaded_files` 整条删除。
- SQL 发送前预检：抽表引用、列多源候选、校验别名；「连接级临时表」看不见时不再误判「表不存在」。
- 源记录唯一：会话行并入连接行，一条源只出一行；源段按可用性分两段（参与分析 / 可加入）。
- 别名冲突改「拒绝 + 点名占用者」，不再用 `_2` 让位；有人在用的别名拒绝 `DETACH`（引用计数）。
- 主源进意图清单（`analysis_primary`），组装时 replay；headless 重启探针覆盖意图清单回放。
- 临时结果表登记 owner；底座「卸载」改会话视角遮蔽（不 `DETACH`）；mock 落地成功即收临时表。
- 加速档 owner 收敛到 `accel:{conn_id}`；删掉 `use_duckdb_fed` 字段，通道门控改看「能力 + 登记清单」。
- 外部源的执行计划认 `*_QUERY` 整句下推；`ExplainAnalyzer` 改走 `EXPLAIN (FORMAT JSON)`；`Decimal256` 直灌前在 Arrow 层降级 `DOUBLE`。
- 密钥管理器用过一次后不再因 `secret_directory` 配置失败。

### 分析资源与资产库

- 全局文件资产走 CAS：发布与取回、归档与元数据往返；全局文件版本链改稳定父链。
- 全局版本历史支持恢复旧版本；版本历史支持任意两版对比。
- 表资产改冻结快照闭环：快照元数据表 + manifest + 快照索引；全局引用按资产 id 登记。
- 回收站收成唯一入口（草稿箱栏），清单合并项目 / 全局三路来源，清空同时清两侧；还原与补登前校验显示名唯一。
- 资产删除语义收口：文件只能解锁退回草稿箱，表型分「逻辑删除 / 永久删除」。
- 表归档身份收口并补物理快照补偿；详情与取回对话框显示活跃取回。

### 结果集面板

- 网格密度与表头带高按 DBeaver 真值重排：行高 26→20，表头 26/40→28/50。
- 列头排序图标改自绘 DBeaver SVG；排序三角槽宽 28→19；排序箭头补手形光标。
- 获焦列补四边框；列头右键补「面板 ▸」子菜单。
- 多维数组逐级展开（层级键改造，vendor 未动）；数组子行行号逐级缩进；行号槽宽按实测只增不减。

### 编辑器

- 执行计划回执展平成计划表（审计 P1-5）。
- 预检看不见连接级临时表时不再误判「表不存在」。

### 草稿箱

- 剪贴板粘贴闭环；导入改应用内弹窗；书签扫描读文件旁的 sidecar（补回归用例）。
- 示例草稿真正落进草稿箱（`sample_drafts` 从死字段接成真行为）。

### 工作台与启动

- 启动默认进空态（欢迎页），「恢复上次项目」接成真开关；欢迎页补「从示例项目开始」。
- 示例项目自带双数据源（SQLite + DuckDB，由当前内核生成）。
- 启动路径上项目状态必须看得见：只读、恢复失败、名册预载。

### 数据对象面板

- 段头常驻，空段也占位（源 / 表 / 文件）；段头换共享 `tree::GroupHeader`。
- 挂载按钮判据回到「能连」，不再被登记挡住；面板挂载事实改读分析实例。
- 会话角色改按挂载事实判，不再看 label。

### 驱动

- MySQL 原生驱动改为按列声明类型出 Arrow：INT / DECIMAL 不再退化成字符串。
- `mysql_native` 兼容 sqlx 下发来的 SSL 参数（`ssl-mode`）。

### 工程与工具链

- Rust 钉到 `1.100.0`（`rust-toolchain.toml` 与 CI / 发版工作流三处对齐，clippy job 显式安装 clippy 组件）。
- 清掉 cargo 1.100 新点名的 unused dependency 告警：14 条（`shared` 9、`file-meta` 2、`connection` / `driver` / `engine` 各 1），工作区里随之失去引用的 2 条条目一并下线。
- `cargo test` 默认串行（`.cargo/config.toml` 新增 `RUST_TEST_THREADS=1`）：测试数据根按进程隔离，同一二进制里的带库用例并行会互抢 DuckDB / SQLite 文件（实测并发下 10 个 target / 48 条失败）；串行后全量 159 个 target / 5002 条用例全绿。
- 门控脚本补两处会「撒谎」的洞（包名逗号、没跑出结果时假绿）；`analysis_kernel_probe` 用例间不再抢 `rds_src`。

## 0.2.14 · 2026-11-26

> 相对 `RDS-beta-0.2.13` 的 124 个提交。主线：分析引擎升 DuckDB 2.0.1 并把执行面收成「一个分析实例 + 每编辑器一条会话」、结果集面板继续按 DBeaver 收口、数据对象面板源段收口、资产库补全局引用。
> 同期并入工作台欢迎页 / 统计看板拆分、面板与导航骨架统一、标题栏项目下拉修正。**本版与旧库不兼容**：2.0 新建的库是 `storage version 69`，1.5 内核打不开。

### 分析引擎与 DuckDB 2.0

- DuckDB `1.5.6` → `2.0.1`（`duckdb 1.20001.0` / `libduckdb-sys` 同版），`arrow 58.4.0 → 60.2.0`、`comfy-table 7.1 → 8.0.1`；动态库目录改 `third_party/duckdb/2.0.1`，抓取脚本按主版本分档资产名。
- 2.0 新建的库是 `storage version 69`，**1.5 客户端读不了**：本版不做 1.5 兼容、不做旧库探测/只读挂载，升级前请自留旧库副本。
- 真机复核出三条行为变化并落到代码与文档：源表清单不再在 `ATTACH` 时定型、`SET search_path` 单值可用、appender 不认 `search_path`。
- 执行面收成「一个分析实例 + 每编辑器一条会话」：项目分析库（读写）/ 全局分析库（只读）/ 各源别名同挂一个实例；`rds_tmp` 实例级共享、`TEMP` 表按会话隔离。
- 退役 `SessionHandle` 的 ProcessDb / Federated 与加速档多实例会话；联邦会话改为分析实例门面，`tmp_q_ JOIN 源表` 从「两份实例之间没有 JOIN」变成会话边界问题。
- 源别名按源唯一，实例记「连接 → 实际别名」；联邦挂载前先核对别名归属，被别的源占着就判失败并点名。
- 新临时表实际建进 `rds_tmp`，靠 `search_path` 让裸名照旧解析；清理只由用户手动触发。
- 临时结果建表即登记进实例登记册；切项目时刷新底座。
- 语句超时从设置读，被中断的语句给可读文案，不再抛底层错误原文。
- 全局分析库改走底座口径：`rds_global` 是底座 / 系统 catalog 的保留别名，不再当源别名挂（原路径会让洞察全局表取样与「全局分析表」列表全空）。
