# RdataStation v2

**查询跑完了，接下来呢？**

> 导出 CSV → Excel 打不开 → 换 pandas 重跑一遍 → 结论贴进群里。
> 三天后有人问「这个数准吗」，你翻不到那条 SQL，也说不清是哪个库的哪一版。

RdataStation 想补的正是这一段：**取数、分析、留证，在同一个本地工具里闭环。**
不是又一个全能数据库客户端——是把「结果拿到手之后」那半天，从三个工具收回一个窗口。

---

## 30 秒看懂

| | 通常的做法 | RdataStation |
| --- | --- | --- |
| **取数** | 连库、写 SQL、跑 | 照做，但元数据三级缓存，十万张表也能秒开、秒定位 |
| **分析** | 结果导出 → Excel / pandas / Jupyter | **结果集一键进本地 DuckDB**，不重跑源库，源库断了照样能算 |
| **留证** | 临时文件散在桌面，版本靠文件名 | **资产库**：只读、带版本、带来源与 sha256 指纹，可复现 |

一句话：**它买的是「以后说得清」，不是「功能表更长」。**

---

## 三个场景，看它怎么接住

### 一、两天前那张表，是哪来的？

被问「这个数准吗」，你只剩一个 `result(3).csv`。

- 结果集工具栏**实时写血缘**：来源连接、耗时、影响行数当场留痕。
- 归档进资产库时自动带 **来源 + sha256 指纹 + 版本号**——文件变没变、哪一版是谁导的，一眼看完。
- 查询失败也留痕，**不回填假值凑数**。

### 二、分析要换三个工具，数字还对不上

聚合一类事，导出、开 Excel、再开 pandas，来回倒腾。

- 结果集点「分析」，数据**桥接进本地 DuckDB** 做二次分析，**不重跑源库查询**。
- 上限 **20,000 行明示**，截断就写清「另有 N 行超出上限未参与」，不装成全量。
- 分析结论落**新结果集**，原结果一行不动；结论满意再归档。

### 三、造测试数据，谁都不敢碰生产

下游要一批测试数据，在生产库上生成没人敢签字。

- Mock 造数**只读表结构**（列名 / 类型 / 可空 / 主键），**代码里没有任何一条写回源库的路径**。
- **143 种生成器 · 15 个分类**，含对数正态 / 泊松 / 指数 / 帕累托 / Beta 等分布族，工作日历可落到列上。
- 产物只落本地分析引擎，出口**绝不覆盖已有表**；同 seed 同配置，逐值可复现。

## 硬指标（都是实测口径，不是形容词）

| 指标 | 实测 |
| --- | --- |
| Quick Open 定位十万对象 | **158ms → 1.5ms** |
| 元数据三级缓存 | L1 内存 **<0.1ms** · L2 每连接 SQLite **<5ms** · L3 实时内省 10~500ms |
| 二次分析上限 | **20,000 行**，截断在界面上说清 |
| Mock 生成器 | **143 种 / 15 分类** |
| 内置驱动 | **6 个**，覆盖 **4 类引擎** |
| 引擎素养 | SQLite 记事务元数据 · DuckDB 做分析计算，两套迁移器、两本账本，不混用 |
| 代码底座 | Rust edition 2024 + GPUI-kit，**27 个 crate**，333,742 行 |

## 为什么敢信

- **本地优先**：零遥测、零云同步、零登录；凭据 AES-256-GCM 落盘，网络链走 SSH / SSL / SOCKS5。
- **不造假**：格式化不丢注释、空表不给假分数、未注册的能力不写进宣传。
- **写不出去**：跨源联邦是**只读**的，写语句在 ATTACH 层直接拦下——不做语义分析，宁可多拒一句。
- **规则可 diff**：洞察规则以 TOML 文件为唯一真相源，进 git、可 diff、改目录即热加载。
- **约束进测试**：零裸尺寸、零裸色值两条硬规矩由契约测试守着，回归不靠人眼。

---

## 它不做什么（这条同样重要）

图表 / 仪表盘 / 报表（留给插件生态）· 跨源写入 · 结果网格就地编辑 · ODBC / ADBC 主干 · 用假数据填充空态。

**它不适合**：只需要一个能连库跑 SQL 的窗口的人——那种场景有更成熟的选择，RdataStation 的力气花在了「查完之后」。
