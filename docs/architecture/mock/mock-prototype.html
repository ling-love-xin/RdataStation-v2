与 v1 原型的对应关系（v1 文件：v1/prototype/mock-data-generator.html，本稿为参考重画而非搬运）：
· v1 右面板「配置区（表名输入 / 行数 / 种子 / 语言 / 重置）」→ 本稿同样以目标表名输入框为起点（造新表），保留行数 / 种子 / 语言三项；v1 的「重置」并入字段行的「智能」与列编辑的「恢复智能默认」。
· v1 的字段表（可增删列、列名与类型可改、生成器下拉、空值率、唯一、⚙ 高级抽屉）→ 本稿因右 Dock 只有 280px，整体移到中央 tab（单表态那张 tab）：字段卡片两行（名称 / 类型 / 置信度 + 生成器 ▾ / 编辑 / 智能 / 删除 + 参数摘要）。
· v1 的「生成器下拉（137 项平铺）」→ 本稿按分类子菜单收口；v1 的「⚙ 高级抽屉」→ 列编辑对话框（列名 / 类型 / 生成器只读 / 参数 / 空值率 / 唯一 / 恢复智能默认）。
· v1 的「生成 → 预览表 → 导出 CSV·XLSX·Parquet·SQL / 保存草稿 / 持久化」→ 本稿：生成仍只产内存临时表 + 预览（不写库），四个出口收在右 Dock「出口」按钮组，预览表在中央 tab。
· v1 的「导入结构弹窗」→ 本稿「导入结构」对话框（连接 / 库 / schema / 表名，读源库结构）；v1 没有的「追加到既有表」是 v2 的显式出口（选表后主键自增接续表内行数），不与「持久化」混为一路。
· v1 的「历史段」→ 本稿**已画**：右 Dock 底部「生成历史」（最近 20 条，时间倒序 + 重放 / 删除 / 刷新），生成一次自动落一条，失败行显示原因；v1 的「保存模板」→ 本稿**已画**「用户模板」段（「保存为模板…」对话框只问名字 + 每行「应用 / 删除」）。
· v1 的「场景模板」→ 本稿**已画**（两个场景：「场景模板」= 下拉选 6 套内置模板；「场景结果」= 一次产多张表，一张表一个中央 tab，右 Dock「本次生成」清单是管理入口）。与 v1 的形态差异是有意的：v1 的模板对话框是「选一个模板 → 把列定义填进草稿」，一次只服务一张表；v2 是「选一套模板 → 后台一次生成模板里的**全部表**（不写库）」，结果表是一组（`results`），每张结果表对应一个 tab、标题就是表名 + 行数。场景任务与批量落库的进度量纲是**张表**（`2 / 4 张表` / `1 / 3 张表`），不是批次 / 行——面板按任务种类切文案。
· 场景表之间的**引用关系**已从「手写约定」升级为**模型化引用**（§9-I11 已落实）：关系声明在子表的列上（`ColumnDependency::foreign_key`），取值域由父列自增参数 + 父表行数**算出**（不读已落地数据）；内置 6 套模板的 24 处引用都改成声明，blog 顺带补上原本缺失的父表 `users`。面板上就是「表间关系」段 + 「＋ 加关系」对话框，关系行尾的 `1..1,000` 就是算出来的域。
