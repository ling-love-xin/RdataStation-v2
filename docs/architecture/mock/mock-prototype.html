与 v1 原型的对应关系（v1 文件：v1/prototype/mock-data-generator.html，本稿为参考重画而非搬运）：
· v1 右面板「配置区（表名输入 / 行数 / 种子 / 语言 / 重置）」→ 本稿同样以目标表名输入框为起点（造新表），保留行数 / 种子 / 语言三项，但这四项是「这张表的设计」，故落在中央 tab 的表头；v1 的「重置」并入字段行的「智能」与列编辑的「恢复智能默认」。
· v1 的字段表（可增删列、列名与类型可改、生成器下拉、空值率、唯一、⚙ 高级抽屉）→ 本稿落在中央 tab（这张表那张 tab）：字段卡片两行（名称 / 类型 / 置信度 + 生成器 ▾ / 编辑 / 智能 / 删除 + 参数摘要），列来源（导入结构 / ＋ 加列）也在这个 tab 的「列」段。
· v1 的「生成器下拉（137 项平铺）」→ 本稿按分类子菜单收口；v1 的「⚙ 高级抽屉」→ 列编辑对话框（列名 / 类型 / 生成器只读 / 参数 / 空值率 / 唯一 / 恢复智能默认）。
· v1 的「生成 → 预览表 → 导出 CSV·XLSX·Parquet·SQL / 保存草稿 / 持久化」→ 本稿：生成仍只产内存临时表 + 预览（不写库）；生成在中央表头（这张表的动作，带进度条 / 批次 / 取消 / 失败重试），四个出口在右 Dock（作用于当前 tab 那张表，生成前禁用），预览表在中央 tab。
· v1 的「导入结构弹窗」→ 本稿「导入结构」对话框（连接 / 库 / schema / 表名，读源库结构）；v1 没有的「追加到既有表」是 v2 的显式出口（选表后主键自增接续表内行数），不与「持久化」混为一路。
· v1 的「历史段」→ 本稿**已画**：右 Dock 底部折叠的「生成历史（20）· 用户模板（1）」（默认收起，点标题展开），历史最近 20 条、时间倒序 + 重放 / 删除 / 刷新，生成一次自动落一条，失败行显示原因；v1 的「保存模板」→ 同一个折叠段里的「用户模板」（「保存为模板…」对话框只问名字 + 每行「应用 / 删除」）。默认收起是因为面板的天天用部分是上面那份表清单。
· v1 的「场景模板」→ 本稿**已画**（三个场景：「场景模板」= 中央表头下拉选 6 套内置模板；「场景工作副本」= 选完先看清单、调关系，再生成；「场景结果」= 一次产多张表，一张表一个中央 tab，右 Dock 的「结果表」清单是管理入口）。与 v1 的形态差异是有意的：v1 的模板对话框是「选一个模板 → 把列定义填进草稿」，一次只服务一张表；v2 是「选一套模板 → 拿回工作副本 → 后台一次生成模板里的**全部表**（不写库）」，结果表是一组（`results`），每张结果表对应一个 tab、标题就是表名 + 行数。场景任务与批量落库的进度量纲是**张表**（`2 / 4 张表` / `1 / 3 张表`），不是批次 / 行——面板按任务种类切文案。
· 本轮改版（分权与状态单点）：右 Dock 收回「管理表」——表清单（唯一入口：表名 · 行数 · 状态点，点一行切 / 开它的 tab）+ 出口组 + 折叠的历史 / 模板；中央 tab 拿回「这张表的设计与生成状态」——表名 / 行数 / 种子 / 语言、生成、进度条与取消、失败原因与重试、列、预览、跨表后果。状态单点：进度条 / 批次文案 / 取消 / 失败原因只画一处——单表任务在中央表头，集合任务（场景）在右 Dock 场景清单下（量纲是「张表」），两者互斥；清单行只给状态点与百分比（`◐ orders 40%`）。单表生成在中央、多表生成（「生成 N 张表 / 退出场景」）在右 Dock——同一时刻只出现一个「生成」，不会分不清生单表还是生一批。出口反馈（落库 / 导出成功或失败）就地给在出口按钮下面。
· 场景表之间的**引用关系**已从「手写约定」升级为**模型化引用**（§9-I11 已落实）：关系声明在子表的列上（`ColumnDependency::foreign_key`），取值域由父列自增参数 + 父表行数**算出**（不读已落地数据）；内置 6 套模板的 24 处引用都改成声明，blog 顺带补上原本缺失的父表 `users`。面板上就是清单行下的 `↳` 子行（挂在子表那行，行尾 `✕` 删关系）+「＋ 加关系」对话框，子行尾的 `1..1,000` 就是算出来的域；结果表清单里的 `⚠ 引用的表未落库` 也来自同一份关系数据。
