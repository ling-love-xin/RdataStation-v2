# Mock 数据生成（M7）— 原型设计

> 本文件定义**长什么样**：落位与尺寸、两处排版（右 Dock / 中央 tab）、对话框、状态矩阵、主题映射、与 v1 的逐项对照。
> 交互稿：`mock-prototype.html`（v2 原生，RDS Light/Dark + 18 场景可切）。
> 语义与数据流：`mock-architecture.md`；任务与进度：`mock-dev-plan.md`。

## 1. 落位与尺寸

| 项 | 取值 | 来源 |
| --- | --- | --- |
| 落位（管理表） | 右侧 Dock 面板（`RightPanel::Mock`），与洞察 / 历史共用 Dock 槽位 | `crates/workbench/src/view.rs` |
| 面板宽度 | `ui::RIGHT_DOCK_WIDTH` = 17.5rem（280px）**起步**，用户可**拖拽调宽**（`DockSkin` 为每个 placement 都画了 resize 抓手：`resize-handle-right` + `ResizePanel` 拖动改 Dock 尺寸） | `crates/workbench_shell/src/ui.rs`、`gpui-component/src/dock/dock.rs` |
| 落位（这张表的设计） | **中央编辑区 tab**「Mock · {目标表}」（`MockDetailView` 加入编辑区 tab 组） | `crates/workbench/src/view.rs` |
| 面板头 | Dock 的 `ComponentPanel::title/tab_name`（高度 `ui::PANEL_HEADER_HEIGHT` = 2.25rem） | 同上 |
| 视图归属 | **随 mock crate**（`crates/mock/src/mock_view.rs`，与 `project::ui` / `settings_view` 同例） | 架构 §3 / 决策 D11 |
| 视内尺寸 | 视图局部常量（`NUM_INPUT_WIDTH` 5rem / `PARAM_INPUT_WIDTH` 9rem / `FIELD_LIST_MAX_HEIGHT` 16rem / `PREVIEW_MIN_HEIGHT` 10rem / `PREVIEW_ROW_NUMBER_WIDTH` 48px） | `crates/mock/src/ui.rs` |

**为什么这么拆**：「管理表」与「设计这张表」是两件事。表清单（有哪些表 · 落了没 · 关系连到谁）是**集合视角**，
出口（落库 / 追加 / 导出）以「当前表」为单位，历史与模板是落盘记录——这些归**右 Dock**；表名 / 行数 / 种子 / 语言、
列定义、预览、生成进度是**单表视角**，归**中央那张表的 tab**。v1 把两边堆在同一个右面板（`width:380px` 的可拖拽宽栏），
v2 的右 Dock 起步 280px（可拖拽调宽，但不强求用户去拖），宽表与字段卡片本来就得在中央，于是把「设计」整块搬过去。

**状态单点**：同一时刻**只有一处**画进度与取消——单表任务（生成 / 追加 / 导出）在**中央表头**，
集合任务（场景 N 张表）在**右 Dock 场景清单下**（它属于这一批），两者互斥（场景态下中央不画生成行）；
右 Dock 的清单行只给状态点与百分比（`◐ orders 40%`）。空跑一条：要停单表任务就去它那张 tab（清单行点一下）
再点「取消」——不会两处各画一遍、也不会两个都能按。

两处状态同源：中央 tab 持有配置面板实体（`Entity<MockPanel>`），清单行、出口可用性、预览都从它读，
编辑动作写回它（**单一权威**）。

入口（全部走 `Shared::open_mock_panel`）：

1. 分析库页「生成 Mock」按钮 → 展开右 Dock（不带来源）；
2. 导航树对象右键「生成 Mock 数据」（表 / 视图）→ 展开右 Dock，并按**源库表**定向：读该表结构（列名 / 类型 / 可空 / 主键）
   导入为列定义、目标表名预填为该表名（v1 主路径：源库结构 → 造新数据）；
3. 右 Dock 面板切换（活动栏 / 状态栏开关 / Quick Open 的「打开 Mock 生成」）；
4. 右 Dock 清单点一行 → 切 / 开那张表的中央 tab（草稿行 = 草稿 tab，结果行 = 该结果表的 tab）。
   右 Dock **不再有「查看详情」按钮**：清单就是入口，少一个按钮就少一份要同步的文案。

## 2. 排版方案①：右 Dock = 管理表（清单 + 出口）

```
┌ Mock 生成 ───────────────────────────────────┐
│ 本次 Mock 表（1）                                │ ← 场景工作副本态：「本次 Mock 表（5）· 电商系统 + 自定义」
│ ┌─────────────────────────────────────────┐  │   结果态：「结果表（4）· 点一行切到它的 tab」
│ │ mock_orders        1000 行  ○ 未生成     │  │ ← 表清单：点一行 = 切 / 开它的 tab（sel = 当前 tab）
│ │   ↳ user_id → users.id · 1..1,000    ✕  │  │ ← 关系挂在**子表**那行下（行尾 ✕ 删关系）
│ └─────────────────────────────────────────┘  │
│ 状态：○ 未生成 ◐ 生成中 ● 已生成 ✓ 已落库 ⚠ 引用的表没落库        │
│ 出口（作用于当前 tab 那张表；生成后可用）           │
│ [持久化到项目分析库]                              │ ← 新建表；已存在则报错并引导「追加」
│ [追加到既有表 ▾]                                 │ ← 显式选表（候选＝分析库既有表；主键自增接续）
│ [保存到草稿箱 ▾]                                 │ ← CSV / Parquet / Xlsx / SQL INSERT → {项目}/mock/
│ [另存为 ▾]                                       │ ← 同上四格式 → 系统保存对话框选路径
│ 已在项目分析库新建表 mock_orders（1000 行）         │ ← 出口反馈就地给：成功（success）/ 失败（danger）/ 只读（info）
│ 数据只写入项目分析库与文件，不回传源库（M7）        │ ← 常驻只留这一句（未打开项目时去掉路径）
│ ▸ 生成历史（20）· 用户模板（1）                     │ ← 折叠（默认收起）：天天用的是上面那份清单
└─────────────────────────────────────────────────┘
```

同一个面板剩下两种形态（同一份「清单」组件换内容）：

```
场景工作副本（选完模板、还没生成）：            结果表（一次生成完）：
┌ 本次 Mock 表（4）· 电商系统 ┐      ┌ 结果表（4）· 点一行切到它的 tab ┐
│ users        1,000 行  ○ 待生成  编辑 ✕ │      │ users        1,000 行  ✓ 已落库        │
│ products       500 行  ○ 待生成  编辑 ✕ │      │ products       500 行  ○ 未落库        │
│ orders       5,000 行  ○ 待生成  编辑 ✕ │      │ orders       5,000 行  ○ 未落库（sel）  │
│   ↳ user_id → users.id · 1..1,000    ✕ │      │   ↳ user_id → users.id · 1..1,000      │
│ order_items 15,000 行  ○ 待生成  编辑 ✕ │      │ order_items 15,000 行 ⚠ 引用的表未落库  │
│   ↳ order_id → orders.id · 1..5,000  ✕ │      │   ↳ order_id → orders.id · 1..5,000    │
│   ↳ product_id → products.id · 1..500 ✕ │      │   ↳ product_id → products.id · 1..500  │
└───────────────────────────────────────┘      └─────────────────────────────────────┘
[＋ 加表（当前草稿）] [＋ 加关系]                 还有 3 张没落库：products、orders、order_items [落库这 3 张]
[        生成 4 张表        ] [退出场景]  ← 选模板不立即生成；进度与取消也在这里（量纲 = 张表）
```

设计要点：

| 要点 | 做法 |
| --- | --- |
| 清单是唯一入口 | 点行 = 切 / 开该表的中央 tab（草稿行 → 草稿 tab，结果行 → 该表 tab）；不再有「查看详情」按钮，也不再单设「当前表」选择器（`sel` 那一行就是当前表） |
| 状态点：唯一的状态位 | `○ 未生成` / `◐ 生成中 40%` / `● 已生成` / `✓ 已落库` / `⚠ 生成失败` / `⚠ 引用的表未落库`（后者 = 它引用的表还没落库，孩子那条路会落空）；进度条与取消**不在这里**（中央单点） |
| 关系并进清单行 | 关系是「子表 → 父表」，就挂在**子表**那一行下（`↳ user_id → users.id · 1..1,000`，行尾 ✕ 删关系）；不再单开「表间关系」段 |
| 集合级动作留在管理侧 | 「生成 N 张表 / 退出场景」在场景清单下（它是**这一批**的动作）；单表生成在中央表头——同一时刻只出现一个「生成」 |
| 批量落库 | 「还有 N 张没落库：…」+「落库这 N 张」：沿当前表双向走关系闭包算出来（`pending_relation_tables`），一次补齐悬空引用 |
| 出口**显式**且分工不重叠 | 「持久化」= 新建表；「追加」= 写入既有表（显式选表，不猜同名）；两者都**不覆盖**既有数据 |
| 生成 ≠ 写入 | 「生成」只产内存临时表与预览；一切落库 / 落盘由出口按钮触发（v1 语义） |
| 出口按钮常显、生成前给禁用态 | 不给「hover 才可见」的图标；未生成时 `Button::disabled` 并附「（生成后可用）」提示 |
| 出口反馈就地 | 成功 / 失败 / 只读都写在出口按钮组下面一行（触发点就地反馈），不再飘到别处 |
| 历史与模板折叠 | 默认收起，标题写条数（`Collapsible`）；面板的天天用部分是上面那份清单 |
| 重交互用语义对话框 | 导入结构 / 列编辑 / 加关系 / 编辑表走 `window.open_dialog`（焦点陷阱 / Escape / 遮罩关闭由组件负责） |
| 空态给出下一步 | 分析库无表 → 追加菜单只有「（分析库暂无表）」禁用项；还没有表 → 中央给起手卡片（§3） |
| 渲染期零 I/O | 清单、连接清单、既有表、导入结构、生成、出口全部在事件路径执行 |
| 自身可滚动 | Dock 内容区不产生滚动 → 面板内层 `overflow_y_scrollbar()` + `flex_1().min_h_0()` |
| 生成不阻塞 UI | 生成 / 追加提交给工作线程（`MockHost::start_job`）；进度由 120ms 定时泵拉取，取消在批次边界生效 |
| 可拖拽调宽 | 起步 280px（`ui::RIGHT_DOCK_WIDTH`）；`DockSkin` 给每个 placement 画了 resize 抓手（`resize-handle-right` + `ResizePanel`）。**文档此前写「右 Dock 不可拖拽调宽」是错的**，已订正（依据 `gpui-component-0.6.1/src/dock/dock.rs` 的 `render_resize_handle`） |

## 3. 排版方案①：中央 tab = 这张表的设计与生成状态

```
┌ 工作台 │ Mock · mock_orders ✕ ────────────────────────────────────┐
│ [mock_orders      ] [1000] [随机种子] [简体中文 ▾]                       │ ← 表头：表名 / 行数 / 种子 / 语言（可改）
│ [生成] [场景模板 ▾]              临时表 temp_mock_mock_orders · 1000 行 · 12 ms │ ← 无结果时「生成」是主按钮；有结果收成「重新生成」
│ ▓▓▓▓▓▓░░░░░░░░ 4 / 10 批（≈40000 / 100000 行）            [取消]      │ ← 生成中：进度条 + 批次 + 取消（**只画在这一处**）

│ 列（5）                                      [导入结构] [＋ 加列]     │ ← 列来源也在这张 tab 里
│ ┌───────────────────────────────────────────────────────────────┐ │

│ │ [自增序列 ▾] [编辑] [智能] [删除]   空值 0% · 起始值 1 · 步长 1 │ │ ← 生成器菜单（分类子菜单）+ 三个动作 + 摘要
│ └───────────────────────────────────────────────────────────────┘ │ ← 列区最高 16rem，超出内部滚动
│ 预览（前 3 行）· 临时表 temp_mock_mock_orders · 本次 1000 行 · 12 ms    │
│ ┌──┬──────┬──────────────────────┬──────────┬────────┬──────────┐ │
│ │# │ id   │ customer_email       │ amount   │ status │created_at│ │
│ │1 │ 1    │ zhangsan@example.com │ 1234.56  │ paid   │2024-01-… │ │ ← 组件库 `DataTable`（列宽可拖 + 横向滚动），纵向占满剩余高度
│ └──┴──────┴──────────────────────┴──────────┴────────┴──────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

一张结果表一个 tab（这张表是「这次生成」的产物 → **只读**）：

```
┌ Mock · orders（5,000 行）✕ ───────────────────────────────────────┐
│ orders · 5,000 行 · 已生成（临时表 temp_mock_orders · 18 ms）       │ ← 表头只有事实：没有输入框，也不给「生成」
│ ⚠ 引用了 users.id：只落这张表，被引用的表不会跟着落库；被 order_items.order_id 引用：只落这张表，引用它的一方会落空 │ ← 跨表后果
│ 列（6）· 来自这次生成（只读）                                       │ ← 列只读：一行一列（名称 / 类型 / 生成器或取值域）
│ 预览（前 3 行）· 临时表 temp_mock_orders · 本次 5,000 行 · 18 ms    │
└─────────────────────────────────────────────────────────────────┘
```

空态（还没有列）——中央给卡片，右 Dock 只管表与出口：

```
┌ 还没有列：先把这张表造起来 ─────────────────────────────────────────┐
│ [选场景模板（6 套）] [导入源库结构] [＋ 手工加列]                        │
│ 列定义、表名 / 行数、预览都在这张 tab 里改；右侧面板负责管理表（清单 / 出口 / 历史）│
└─────────────────────────────────────────────────────────────────┘
```

| 要点 | 做法 |
| --- | --- |
| 一表一 tab | 草稿一个 tab（`DetailTarget::Draft`）+ 每张结果表一个 tab（`DetailTarget::Table(name)`），标题 = `Mock · 表名（N 行）`；切 tab 就是切表（`focus_table`） |
| 表头分两态 | 草稿 tab：表名 / 行数 / 种子 / 语言可改 + 生成动作；结果表 tab：只读事实行 + 跨表后果（不给「生成」，免得像能只重跑这一张） |
| 生成三态同一位置 | `生成`（无结果，primary）/ `重新生成`（有结果，收成小按钮）/ `生成中…`（禁用）；场景工作副本态下这一行不画，改一行 hint「这是草稿：调好再去右『＋ 加表』」 |
| 状态单点 | 进度条 / 批次文案 / 取消 / 失败原因与重试只在这里（单表任务）；右 Dock 只给状态点与百分比；**集合任务（场景 N 张表）的进度与取消在右 Dock 场景清单下** |
| 列卡片两行制 | 第一行「名称 · 类型 · 置信度徽标」，第二行「生成器菜单 + 编辑 / 智能 / 删除 + 参数摘要（或示例值）」 |
| 生成器切换不打断编辑 | 生成器有两条路径：`Button::dropdown_menu` 的**分类子菜单**（15 类 × 均值 9 项，知道「属于哪类」时最快）；菜单首项「搜索生成器…」开搜索对话框（只记得名字时）。菜单顶部另有**「最近使用」**（本会话点过的，最多 5 条，最近在前）与**「推荐」**标记（与导入结构同源的智能映射结果，只标记不写回，B7）；当前生成器打勾。参数编辑在「编辑」对话框里，避免对话框内生成器与参数行不一致 |
| 置信度三态 | `high` success / `low` muted / `manual` info（与 v1 同语义） |
| 预览可排序、但**不筛选** | 表头**右端的箭头**点一下 = **按该列重查临时表**（`ORDER BY … LIMIT 前 N 行`，见 §8；表头正文那一拍是组件的「列选择」，本表未开）；右键菜单里有同一套（升 / 降 / 取消排序）；箭头画的是**生效中的排序**（以面板回推的快照为准，被拒时箭头会被纠回去）。筛选仍不做：它把「前 N 行取样」变成长度未知的子集；排序做的是**全局前 N 行**，与标题里的「前 N 行」同一个口径 |
| 列名也看不全时 | 表头文字截断后同样给悬停全文（`render_th` 自画：截断 + 悬停；行号槽 `#` 不给） |
| 取值看不全就悬停 | 单元格 `truncate` 后挂悬停全文（`ui::PREVIEW_TOOLTIP_MAX_WIDTH` = 24rem，超长折行）；行号槽不给悬停提示（那是序号，不是数据）；**列名同样有**（表头 `render_th` 自画）|
| 预览为只读网格 | 组件库 `DataTable` + 本项目自己的 delegate（列宽可拖 / 横向滚动 / 虚拟化都是组件的；首列 `#` 行号槽钉在左）；右键=排序三项 + 复制三项（**此值 / 此列（取样内每行一个）/ 整行 TSV**）；没有结果时显示「尚无结果——点表头『生成』」 |
| 结果表列只读 | 结果表的列是这次生成的产物：就地改列会让「结果」与「产出它的配置」分叉——要改列回草稿 tab 改，再重新生成 |
| 字段区可筛 | 「列（N）」那一行右侧一个常驻搜索框（`ui::COLUMN_FILTER_WIDTH` = 9rem）：四个靶子——**列名 / 生成器名 / 类型名 / 置信度**（子串、大小写不敏感），**多词是 AND**（`id INTEGER` 只留两条都中的列）；命中数为 0 时给一句可读空态而不是空白；搜索词存在输入框实体里（不另存），筛选只作用于**草稿 tab** 的字段区（结果表 tab 的列只读，要筛就先回草稿）；计数行变成「列（3 / 50）· 已筛选」 |

## 4. 对话框

### 4.1 导入源库结构（`open_import_dialog`）

```
┌ 导入源库结构 ──────────────────────────┐
│ 从源库读取表结构（列名 / 类型 / 可空 /   │
│ 主键）并自动推断生成器；不读取数据本身。   │
│ 连接        [生产库 ▾]                  │ ← 菜单：Shared::connections（选中即预填库 / schema）
│ 数据库 / catalog [shop          ]       │
│ schema      [public             ]       │
│ 表名        [orders             ]       │
│              [取消] [导入]              │
└────────────────────────────────────────┘
```

- 读列走 **cache-aside**：先查连接级 L2 缓存（`database::NavCache`），未命中实时内省
  （`MetadataService::list_columns`，跑在进程级桥接运行时上），命中后尽力回写 L2；
- 导入结果 = 列定义 + 生成器 + 置信度 + 示例值；目标表名同步预填为该表名；
- 不读取数据本身（只读结构），导入后旧生成结果失效（避免出口拿旧结果落库）。

### 4.2 列编辑（`open_column_dialog`）

```
┌ 列编辑 ────────────────────────────────┐
│ 列名        [customer_email      ]      │
│ 类型        [VARCHAR ▾]                 │ ← 13 种（与 ColumnDataType 一一对应）
│ 生成器      安全邮箱（在字段行的菜单里切换）│ ← 只读：生成器身份只从字段行切换
│ 最小值      [2020-01-01          ]      │ ← 参数表单（按 spec 派生，标量可编辑）
│ 最大值      [2025-12-31          ]      │
│ 空值率（%）  [10                  ]      │
│ 唯一值      [开关（Switch）]             │
│ [恢复智能默认]                           │
│                    [取消] [应用]         │ ← DialogFooter（取消 secondary / 应用 primary）
└────────────────────────────────────────┘
```

集合类参数（外键取值 / 序列取值 / 加权选项）改成**多行文本**（同样是目录派生，不手写清单）：

```
│ 加权选项                                 │ ← 标签一行
│ ┌─────────────────────────────────────┐ │
│ │ 北京, 3                              │ │ ← 一行一项；choices 是「值, 权重」
│ │ 上海, 1                              │ │   分隔符取**最后一个**（值里可带逗号）
│ └─────────────────────────────────────┘ │
│ 每行「值, 权重」，如「北京, 3」…          │ ← 格式提示（muted）
│ 第 2 行「x」：权重需为数字                 │ ← 解析失败：danger 行（**不写回生成器**）
```

- **工作副本语义**：「应用」才写回目标列，取消即丢弃（`ColumnDraft`）；
- 参数表单由 `generator_catalog::spec_of()` 派生（143 变体零手工对齐）；标量参数即时补丁回生成器配置
  （JSON 补丁，见 `patch_param`）；
- 集合类参数（`ForeignKey.values` / `Sequence.values` / `Weighted.choices`）用多行文本编辑
  （`parse_complex_param` / `complex_param_text`）：合法即写回，非法则**保留上一个有效值**并在对话框里
  给带行号的提示；**参数不能采样的清况在生成前被引擎拦住**（D33：集合留空 / 权重非正 / 区间反向或空 /
  时间区间不足一分钟）——拦主而不是兑住，因为生成期空区间会 panic，而 panic 会毒化内存库连接锁，
  把整个会话弄皮（只能重启应用）；
- 生成器身份变化（如「恢复智能默认」）后参数行**重建**（事件路径 `defer_in`，不在 render 里建实体）；
- 「恢复智能默认」= `ColumnMapper::infer(列名, 类型)` 重跑映射（生成器 / 空值率 / 唯一 / 置信度 / 示例值一起复位）。

### 4.4 场景模板（`open_scenario` → `run_scenario`）

三步：**选模板**（菜单）→ **工作副本**（调关系）→ **多结果 = 多 tab**。

```
┌ 中央表头：选模板 ───────────────────────────────┐
│ [生成] [场景模板 ▾]                              │ ← 主次同排：单表生成是主按钮
│         └─ 电商系统        4 张表 · 21,500 行  ┐  │ ← 菜单项 = 名称 + 规模（张表 · 行数）
│            人力资源系统   3 张表 · 1,020 行   │  │    行数为**千分位**（六位数一眼读量）
│            社交平台       4 张表 · 161,000 行 ┘  │
└────────────────────────────────────────────────┘
┌ 右 Dock：工作副本（C1 新增） ────────────────────┐
│ 本次 Mock 表（4）· 电商系统                       │
│ users       1,000 行  ○ 待生成    [编辑] [✕]     │ ← 表清单：行尾可编辑（表名 / 行数）与删除
│ products      500 行  ○ 待生成    [编辑] [✕]     │    （删除连带清掉指向它的入边，并报出条数）
│ orders      5,000 行  ○ 待生成    [编辑] [✕]     │
│   ↳ user_id → users.id · 1..1,000            ✕  │ ← 关系挂在**子表**行下（真身在列的 dependency）
│ order_items 15,000 行  ○ 待生成   [编辑] [✕]     │    1..1,000 = 取值域（父列自增 × 父表行数）
│   ↳ order_id → orders.id · 1..5,000         ✕  │
│   ↳ product_id → products.id · 1..500       ✕  │
│ [＋ 加表（当前草稿）] [＋ 加关系]                   │ ← 四个下拉：子表.列 → 父表.列
│ [      生成 4 张表      ] [退出场景]              │ ← **选模板不立即生成**
│ ▓▓▓░░░ 2 / 4 张表                      [取消]    │ ← 进度与取消在这批的清单下（量纲 = 张表）
└──────────────────────────────────────────────────┘
┌ 右 Dock：生成后 ────────────────────────────────┐
│ 结果表（4）· 点一行切到它的 tab                   │ ← 一张结果表一个中央 tab
│ users       1,000 行  ✓ 已落库                    │    切 tab 就是切表（出口作用于当前表）
│ products      500 行  ○ 未落库                    │
│ orders      5,000 行  ○ 未落库（sel）              │
│ order_items 15,000 行  ⚠ 引用的表未落库            │
│ 还有 3 张没落库：products、orders、order_items     │ ← 关系闭包算出来的
│ [落库这 3 张]                                     │    一次补齐悬空引用
└──────────────────────────────────────────────────┘
```

**「加关系」对话框**（`open_relation_dialog`）：四个下拉（子表 / 子列 / 父表 / 父列），
父列**只列自增列**——只有算得出取值域的才能作引用目标，把不能选的藏起来比让用户选完再报错好；
四个位置没选全时「添加」禁用；添加时自动把子列生成器对齐到父域。

**「编辑表」对话框**（`open_table_dialog`）：只有**表名 / 行数**两项——行数是最常改的一项
（10 万行的财务模板要先缩下来），表名则往往要改成本项目里的真实名字（D32）。
两个跨表后果都在这里一次做完：① 改行数后关系行的**取值域自动跟着变**（面板上直接显示，
改前改后一眼看得出）；② 改名字时**同步所有指向它的入边**并报出同步了几条——
不重定向的话，指向它的关系立刻变成「指向模板里没有的表」。
校验没过**不收起对话框**（错误就地显示，改完直接再点「应用」）；
对话框只改**本次生成**的配置，不碰已生成的预览与已落地的表。

- **先载入再生成**：关系是这次生成的一部分，生成完再补就只能去改已落地的数据了；
- **编辑表只动本次生成**：改表名 / 行数都落在工作副本上，已生成的预览与已落地的表一律不碰
  （「mock 不可读数据」同样是「不改数据」）；改行数不逐个提示引用它的表，而是把它们行尾的域
  **直接改掉**——域是算出来的，用户看得到就不需要语言解释；
- **菜单不现场重算**：模板清单只留名称与规模（`ScenarioChoice`），渲染期不构造模板本体；
- **任务带工作副本**：关系挂在列的 `dependency` 上，按 id 重取会把编辑丢掉；
- **一张结果表一个中央 tab**：单表生成 1 张、场景模板 N 张 → 就有 N 个 tab，**标题 = `{表名}（{行数} 行）`**；
  出口 / 详情 / 预览三处都跟它走（越界下标不改状态）；右 Dock 清单点一行也能切过去；
- **量纲按张表**：进度行显示 `{done} / {total} 张表`，与单表生成的 `{done} / {total} 批（≈N / M 行）`
  是同一组件的两种量纲；这一处（集合任务）的进度行在**右 Dock 场景清单下**——动作与它的状态在一起；
- **草稿与结果解耦**：中央那张草稿 tab 的列仍属于草稿，与场景表无关 → 场景态下草稿 tab 上给一行 hint
  （「这是草稿：调好再去右侧『＋ 加表』」）并收起生成按钮；结果表 tab 的表头写明来源与关系；
- **跨表后果要说清**：出口只作用于**当前 tab 那张表**，关系却是跨表的 → 该表参与关系时，**结果表 tab 的表头**
  给一行 warning（只落这张会怎么悬空）；右 Dock 清单行另给 `⚠ 引用的表未落库` 状态点，并在关系闭包里还有未落库的
  表时列出清单 + 「落库这 N 张」一键依次落（见 §6 与架构 §9-I14 / D30）。

### 4.5 尚未落地（本稿不画）

- 列间表达式（`dependency` 的旧 `DependencyType` 已删，见架构 D40）：本模块**不解释表达式**；
- **跨模板 / 跨库引用**：引用目标必须在同一模板里、且父列可算域；
- **影子数据**（读已落地数据、按其特征生成相似数据）：与当前「生成不读数据」的边界相反，单独立项（§9-I13）；
- v1 原型的「⚙ 高级抽屉 / 时序关联（可选）」：v1 后端零实现（`v1/frontend/.../MockAdvancedDrawer.vue` 只有 UI），
  v2 不搬抽屉。**已部分落地**：`time_series` 生成器（起始值 + 趋势 + 周期 + 噪声，按行序展开）＋ `sequential_date`
  按同一行序铺开，两列并排即一条带季节性的时间序列；**仍未做**的是「真去看日期列的实际取值」——那是跨列求值。
- **业务日历**：**已落地为列级参数**（架构 D42）——**七个日期生成器**都带「仅工作日 + 工作周掩码 + 跳过日期（节假日）+ 上班日期（调休）」；
  四个带时刻的（`date_time` / `date_time_before` / `date_time_after` / `date_time_between`）另有「仅工作时段」，**窗口可自定义**
  （`HH:MM`，起 > 止 按跨零点 / 夜班理解）；`date` 只到天，只有工作日那一组。
  唯一不做的：内置节假日表——**刻意不做**：法定节假日与调休每年发通知，内置表必然静默过期。

入口按钮**在实现前不渲染**（不摆空控件）。

**数值类**是数据科学家最在意的一组：均匀（`random_int` / `random_float` / `random_decimal`）、正态 / 对数正态之外，还有
**泊松**（到达数）/ **指数**（等待时间）/ **帕累托**（长尾）/ **Beta**（比例）/ **二项**（成功次数）与 **`time_series`**（起始值 + 趋势 + 周期 + 噪声，
按行序展开——与 `sequential_date` 同一行序并排就是一条带季节性的时间序列）。参数护栏在**生成前**拦非法值（λ / α 非正或非有限、`p` 越界、`n = 0`）。

**日期时间类带列级工作日历**：勾「仅工作日」后，`sequential_date` / `sequential_date_with_gaps` 按**工作日数**推进（跳过的日子不占行），
其余日期生成器只采工作日；四个带时刻的另有「仅工作时段」，窗口用两个 `HH:MM` 自定（起 > 止 = 跨零点 / 夜班）。
工作周掩码 `1111100` = 周一~周五，「跳过日期」（节假日）与「上班日期」（调休）两个列表表达年度例外，
面板把掩码翻成人话（「周一~周五」）并**只在启用 / 非默认值**时把它们写进字段摘要。

**约束类**是行为变体（指定集合 / 循环序列 / 加权选择），参数为列表，面板只读展示——它们的编辑点应是模板与导入场景。

### 5.1 智能映射的置信度呈现

`ColumnMapper` 四级优先：**精确名 → 前后缀 → 模糊子串 → 类型兜底**，产出：

| 命中层 | `confidence` | 面板呈现 |
| --- | --- | --- |
| 名称精确 / 前后缀 / 模糊 | `high` | 绿色徽标（`theme.colors.success`） |
| 类型兜底 | `low` | muted 徽标（提示「按类型猜测」） |
| 用户手工选择 / 改过参数 | `manual` | info 徽标（`theme.colors.info`） |

参数摘要优先显示生成器参数（`起始值 1 · 步长 1`），无参数时回退到映射的示例值（`zhangsan@example.com`）。

## 6. 状态与空态矩阵

| 状态 | 触发 | 呈现 |
| --- | --- | --- |
| 无列 | 首次打开 / 还没导入或加列 | 中央给**起手卡片**（选场景模板 / 导入源库结构 / ＋ 手工加列）；表头的「生成」禁用；右 Dock 清单行是 `○ 未生成` |
| 已导入结构 | 导航右键定向 / 导入结构对话框 | 目标表名预填 + `已从 {库}.{schema}.{表} 导入 N 列`（success 行）+ 字段区展开 |
| 分析库无表 | 分析库为空 / 读取失败 | 追加菜单只有「（分析库暂无表）」禁用项 |
| 生成成功 | 点「生成」且宿主生成成功 | `已生成 N 行（耗时 T ms）→ 临时表 temp_mock_*`；出口按钮转为可用；中央 tab 出结果摘要与预览；右 Dock 清单行转 `● 已生成` |
| 场景模板生成成功 | 「场景模板 ▾」选一套内置模板 | `已按「电商系统」生成 4 张表（合计 21,500 行）：出口作用于当前 tab 那张`；右 Dock 清单转**结果表清单**（状态点 + 关系子行；`结果表（4）· 点一行切到它的 tab`）；**不在生成时一次性开出所有 tab**（结果表多时不淹用户，首个进面板、其余按需打开）；出口作用于当前表；**草稿不被改写** |
| 结果表切换 | 切中央 tab（或在右 Dock 清单点一行） | `gen_info` 跟着换（结果摘要 / 预览 / 出口都作用于它）；越界下标**不改状态**；只有一张时就是一个 tab，没有多余的选择动作 |
| 清单状态点 | 每次 render 从面板状态派生（`results` / `landed_tables` / `job` / `pending_relation_tables`） | 行尾一个状态点 + 一句话：`○ 未生成` / `◐ 生成中 40%` / `● 已生成` / `✓ 已落库` / `⚠ 生成失败` / `⚠ 引用的表未落库`；**不画进度条、不给取消**（那是中央那处的事） |
| 场景工作副本 | 「场景模板 ▾」选一套（**不生成**） | 清单列出本次要生成的表（名称 · 行数 · `○ 待生成`，行尾「编辑 / ✕」）+「＋ 加表（当前草稿）」/「＋ 加关系」；**关系作为子行挂在子表那行下**（行尾 ✕ 删关系）；动作行变「生成 N 张表 / 退出场景」；中央那张草稿 tab 继续可改（那里不画生成按钮，只留一行 hint） |
| 加关系 | 「＋ 加关系」→ 四下拉 | 父列**只列自增列**（算不出域的另一张表会显示「没有自增主键列」提示）；四个位置齐了「添加」才可用；提交后该列写 `dependency` 且生成器对齐到父域 |
| 关系不可解析 | 父表不在模板 / 父列非自增 / 父表行数为 0 | 面板在**提交前**给可读原因（`resolve_reference_domains`），不等到生成中途；引擎侧同样有兜底 |
| 跨表后果 | 当前 tab 那张表参与了关系（引用了别表 / 被别表引用） | **结果表 tab 的表头**一行 warning：「引用了 `user_id → users.id`：只落这张表，被引用的表不会跟着落库」/「被 `order_items.order_id` 引用：只落这张表，引用它的一方会落空」——出口只作用于当前 tab，关系却是跨表的（架构 §9-I14）；右 Dock 的清单行另给 `⚠ 引用的表未落库` 状态点 |
| 场景与历史 | 场景态 / 结果来自场景生成 | 工作副本里写明「场景生成不记入生成历史（历史是单表配置的重放来源）」——免得用户在历史段里找痕迹 |
| 加表 / 删表 | 场景清单下的「＋ 加表（当前草稿）」/ 每张表行尾的 `✕`（表）与关系子行尾的 `✕`（关系） | 加表取草稿的目标表名 / 行数 / 列（重名拒、空列拒，加完提示「已把草稿 X（N 行 · M 列）加进本次生成」）；删表连带清掉**指向它的入边**并报出条数（出边随表一起消失） |
| 编辑表 | 场景清单里点某表的「编辑」 | 对话框只有表名 / 行数；改名字时入边自动重定向并报「同步 N 条」，改行数后关系行的域跟着变（父列非自增则那一行不显示域）；空表名 / 撞已有表名 / 非法行数**不收起对话框**，错误就地显示在对话框里 |
| 批量落库 | 结果表清单下的「落库这 N 张」（关系闭包里还有没落库的表） | 进度按「张表」（`1 / 3 张表`，不定量条不需要）；收尾文案分两段：`已落库 N 张：…` 与 `失败 M 张：表名（原因）`——**成功的保留**（不回滚别人的表），失败的那张留在待落库清单里；落库成功的表的状态点转 `✓ 已落库`，引用它的那条 `⚠` 跟着消失 |
| 生成失败 | 行数 / 种子非法、无列、引擎报错 | 中央表头 danger 行 + 「重试」，保留目标与列配置（可改再试）；旧结果作废；清单行转 `⚠ 生成失败` |
| 落库成功 | 「持久化到项目分析库」 | success 行 `已在项目分析库新建表 X（N 行）`（出口按钮组下面就地给）+ 「落库目标：X」；导航树缓存失效并刷新；清单行转 `✓ 已落库` |
| 落库同名 | 「持久化到项目分析库」而表已存在 | danger 行 `项目分析库已存在表 X：请改用「追加到既有表」`，并刷新追加候选 |
| 追加成功 | 「追加到既有表」选表 | success 行 `已追加到 X（表内共 N 行）`；生成阶段已按表内行数接续自增起点 |
| 追加缺列 | 目标表缺草稿里的列 | danger 行列出缺失列名（不让 DuckDB 原始错误冒到界面） |
| 只读项目 | `Shared.project_ui.read_only` | info 行「只读模式：不允许落库与写文件（仍可生成预览）」；三个项目级出口（落库 / 追加 / 草稿箱）**在视图层预先禁用**（`MockPanel::sinks_ready` = 有结果 + 非只读 + 已打开项目），禁用理由就是这一行；「另存为」不受只读影响（不写项目库与项目目录） |
| 未打开项目 | 三个项目级出口（落库 / 追加 / 草稿箱） | 按钮**预先禁用**（同上判据）；info 行「未打开项目：落库 / 追加 / 草稿箱不可用（纯生成、预览与另存为不受影响）」。早先的做法是按钮可点、点了由任务层报错（「未打开项目：Mock 只写项目分析库…」）——同一句话天天弹不如直接不可点；任务层那句仍保留作兵底线（面板已摆着、项目被关掉时） |
| 生成中 | 点「生成」/「追加」（后台任务） | 中央表头：生成按钮转「生成中…」并禁用 + `Progress` 进度条 + 「k / N 批（≈已生成 / 目标 行）」+ 「取消」（批次边界响应；点后转「正在取消…」）；右 Dock 清单行只给 `◐ 生成中 40%`；首批回调前显示「准备中…」；**同时**状态栏右侧给一行 `◐ Mock 生成中 40% · 取消`（`status_chip_text` + `view.rs::mock_status_chip`）——面板被切走或中央 tab 被关掉时，任务还在跑也得看得见、能取消（读数仍只属于它自己那一处，见 D38） |
| 场景生成中 | 点「生成 N 张表」（后台任务 `Scenario`） | 进度与取消在**右 Dock 场景清单下**（它属于这一批）：`Progress` + 「k / N 张表（每张表逐个生成）」+ 「取消」（含生成阶段），动作行转「生成中… / 退出场景」双禁用；结果区在回填前仍是上一次的结果（或空） |
| 写入 / 导出中 | 点三个写出口（`Persist` / `Export` / `Scratchpad`） | 中央表头的进度行转**不定量动画**、文案转「写入分析库中… / 写出文件中…（N 行）」；**不渲染取消**（DuckDB / 文件系统内不能中断）；生成与其余出口按钮保持禁用 |
| 生成器搜索 | 字段行菜单首项「搜索生成器…（143 项）」 | 输入即过滤（同步，无 loading 闪烁）；命中行显「中文标签 / 名称 / 分类」，当前生成器打勾；无命中显 `List` 自带空态；点行 / 回车写回该列并关对话框 |
| 集合类参数非法 | 按组合 / 列编辑对话框里改「取值集合 / 加权选项」 | 多行文本下方出现 danger 行（带行号），生成器**保持上一个有效值**；合法后自动消失 |
| 工作日历参数非法 | 列编辑对话框里改「工作周掩码 / 跳过日期 / 上班日期 / 工作时段窗口」（掩码伋看、日期串、时刻） | 日历参数与取值集合不同：**输入时不校验**（可先粘一半）；生成时在**生成前**拦住，中央表头 / 面板 danger 行写清哪一列、哪个字段、期望格式（`YYYY-MM-DD` / 7 位 0/1 / `HH:MM`），改完重试即可；起 > 止 的窗口是合法的（跨零点），只有起 = 止会被拦 |
| 取消中 | 已点「取消」，引擎尚未到批次边界 | 取消按钮转「正在取消…」并禁用（不重复下发）；到边界后转为「已取消」文案 |
| 生成异常 | 后台线程退出（既无进度也无结果） | danger 行「后台生成任务异常结束（工作线程已退出）」；面板归位空闲可重试 |

| **预览表** | `DataTable` + `TableState` + `TableDelegate`（`gpui_kit::component::table`），**与编辑器结果集同一套原语** | 表头 / 列宽拖拽 / 横向滚动 / 虚拟化 / 键盘选择全是组件的；本 crate 只写一个几十行的 delegate（列名 / 行 / `cell_text`）。**订正（2026-09-20）**：早先这里是手搓的固定 9rem 列宽 div 表——列宽钉死、值截断后没任何办法看全，且与结果集两套观感（当初的组件选型表漏了 `table`）；仍不开的开关：行选 / 列选 / 拖列 |
| **预览排序** | `Column::sortable` / `Column::sort` + `TableDelegate::perform_sort`（组件的表头箭头与方向循环） + 自己的重查 | 方向循环（默认 → 降序 → 升序 → 默认）与箭头渲染全是组件的；入口是表头**右端的箭头**（正文那一拍是组件的列选择，本表未开，见 0.6.1 `on_col_head_click`）；delegate 只把「列 + 方向」转给面板（重查是 I/O，临时表名与宿主端口都在面板里）。**不做本地重排**：那会把「前 N 行」变成「前 N 行里的排序」（见 §3 / 架构 §9-I26） |
| **单元格 / 表头悬停全文** | gpui 自带 `tooltip` 建造器（`StatefulInteractiveElement`）+ 组件库 `Tooltip` | 组件库的 `.tooltip()` 只挂在 Button / Checkbox / Switch / Radio / Clipboard 上（它们的 `ComponentTooltip` 是 `pub(crate)`），表格单元格与表头要用 gpui 那一层：`.id(..).tooltip(\|window, cx\| Tooltip::element(..).build(window, cx))`（流式 `tooltip` 要求元素有 id）；表头走 `TableDelegate::render_th` 自画（截断 + 悬停），并用 `debug_selector` 给用例留坐标 |
| 另存为（选路径） | `App::prompt_for_new_path` + `Window::spawn` | 异步回传：取消则不动；落盘动作在回传里执行（事件路径） |
| 滚动区 | `overflow_y_scrollbar()` / `overflow_x_scrollbar()` + `max_h` / `flex_1().min_h_0()` | Dock 内容区自身不产生滚动，面板与 tab 各自给滚动主体 |
| 宿主能力 | `MockHost`（生成 / 出口 / 来源 / 只读 / 打开详情 / 重绘 / **预览按列重排**） | 与 `project::ui::ProjectUiHost` 同范式；workbench 侧桥接见 `components/mock_host.rs`（`preview_ordered` 是全端口里唯一**非阻塞**的：拿不到内存库锁就回落 `None`，因为它是随手动作，不值得等一个不可取消的出口任务） |
