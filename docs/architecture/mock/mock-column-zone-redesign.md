# Mock 表配置 tab：列管理区重设计（方案建议）

状态：**已决策 —— 只做方案 A（2026-11-05 用户拍板）**，B/C 不进本次范围
范围：中央 `Mock · {表名}` tab 的第 2 段「列区」，不含列编辑对话框（对话框本轮已按「左库 / 右属性·参数·样例」定稿）。

## 1. 现状（代码事实）

| 事实 | 位置 |
| --- | --- |
| 三段竖向可拖分栏：基本信息 / 列区 / 预览 | `crates/mock/src/mock_view/detail.rs` 的 `Render for MockDetailView`（`v_resizable("mock-detail-split-{tab_key}")`） |
| 列区段标题 `列（N）` / `列（shown / N）· 已筛选` | 同上，`section(...)` 调用处 |
| 操作行 = 场景按钮（左，`flex_1`）+ 列筛选输入 + 列来源按钮（`＋ 加列` / `导入结构`） | 同上 |
| 列清单 = 每列一张两行卡片 | `render_fields`（`mock-field-card-{id}`） |
| 卡片头行：列名 + 类型 tag + 置信度 tag + 引用徽标；**操作按钮只有 active 才显形**（上移 / 下移 / 复制 / 删除，`CARD_OPS_WIDTH` 占位） | 同上 |
| 卡片内容行：生成器入口按钮（`mock-gen-{id}`，带 dropdown caret）+ 参数摘要 + `HoverCard`（`mock-hover-{id}`） | 同上 |
| 列区吃剩余高度、预览有 200–640px 上下限 | 同上，`.flex_basis(px(0.))` + `DETAIL_PREVIEW_*` |

## 2. 现状的六个问题

1. **密度太低**：一列两行（约 60–70px），20 列 ≈ 1300px + 卡片间距；列区虽吃剩余高度，但一屏只能看 5–8 列，且与预览争高。
2. **操作靠 hover 才出现**：上移/下移/复制/删除是结构编辑的高频动作，隐藏即不可发现；键盘与触屏也基本够不到。
3. **横向不可比**：列名、类型、生成器、参数各自在不同卡片的不同宽度上，无法竖着比较（典型问题：「哪几列都用的是手机号生成器」「哪些列还是高置信度推断」）。
4. **没有批量**：5 列都要套「手机号」时得开 5 次对话框。
5. **操作行拥挤**：场景按钮 + 搜索框 + 两个来源按钮挤一行，窗口变窄时搜索框先被压。
6. **卡片承载的是「入口 + 摘要」**，但占了全 tab 最贵的高度；真正的编辑已经在对话框里。

## 3. 三个方案

### 方案 A：紧凑单行（保留卡片模型，最小改动）

- 每列压成**一行** 32–36px：`列名 · 类型 tag · 生成器名 · 参数摘要`，右侧常驻 `↑ ↓ 复制 删除`（或收进 `⋯`）。
- 保留 `mock-field-card-{id}` / `mock-gen-{id}` / `mock-moveup-{id}` 等全部现有 id 与回调 → 测试基本不用改。
- 收益：同样高度能看 2–3 倍列数；操作可发现。
- 仍缺：表头对齐（横向比较）、排序、批量。

### 方案 B：表格化（未采用）

> 用户否决：「A 方案就很合理了，不用上升的 B，这样更加简洁」。B 的口径留在 §5 仅作未来参考，本文档不作为实施依据。

- 列清单换成表格，表头对齐：

| # | 列名 | 类型 | 生成器 | 参数 | 约束 | 操作 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | user_id | BIGINT | 自增 | start=1 step=1 | 唯一 | ⋯ |
| 2 | phone | VARCHAR | 手机号（自定义） | — | 空值 10% | ⋯ |

- 行高 28px（`ui::PREVIEW_TABLE_SIZE` 同档），斑马纹，行点击 → 现有列编辑对话框，行尾 `⋯` → 上移/下移/复制/删除。
- 点表头可按列名 / 类型排序（纯视图排序，不改实际列序）。
- 工具条独立一行：`列（N）` + 搜索 + `＋ 加列` / `导入结构`（+ 阶段 2 的批量入口）。
- 复用组件库 `DataTable`（结果集与预览已是同一套：表头、列宽拖拽、横向滚动、虚拟化、键盘选择），不手搓网格。
- 收益：密度、对齐、可扫读、可排序、操作常驻；与预览表同观感。
- 代价：新增一个 delegate（约 200–300 行），列宽按 tab 记忆，测试里几处 `mock-*` id 要同步。

### 方案 C：主从（表格 + 右侧检查器）

- 在 B 的基础上，列区改左右分栏：左表格 / 右「选中列」的属性与参数即时编辑，对话框只留给高级项。
- 收益：改一个字段不用开弹窗。
- 代价：中央 tab 已有三段竖向分栏 + 对话框已有左右分栏，再叠一层左右分栏，窄窗口下三段都会被压；且与已定稿的对话框形成两套编辑入口。**未采用**（理由同 B：简洁优先）。

### 不推荐：按生成器分组（树/分组卡片）

列顺序是表结构的一等属性（生成 SQL / 落库 / 预览表头都按它），按生成器分组会打乱顺序，且同名列跨组移动语义不清。

## 4. 决策：只做 A（已实施）

用户 2026-11-05 明确：「A 方案就很合理了，不用上升的 B，这样更加简洁」。理由是列区承载的是「入口 + 摘要」，真正的编辑已在对话框里，单行足够；表格化会引入表头、排序、列宽记忆、批量等第二套语义，与「一个 tab 只做一件事」冲突。

### 4.1 A 的落地口径（本轮已实现）

| 项 | 落点 |
| --- | --- |
| 行高 34px 单行卡片（xsmall 按钮 24px + 上下 5px）；卡片间距 `gap_1` | `ui::COLUMN_ROW_HEIGHT`、`render_fields` |
| 列名格定宽 10rem（四段对齐的起点，长名截断） | `ui::COLUMN_NAME_CELL_WIDTH` |
| 生成器按钮格最大宽 9rem（超长自定义名截断，宽度让给参数摘要） | `ui::COLUMN_GENERATOR_CELL_WIDTH` |
| 置信度只在非 `high` 才画（high 是默认档，每列都挂会淹掉低可信列） | `render_fields` |
| 引用列只留 `↳` 一个字符；完整「引用 表.列」与 `ref_note` 并入悬停全文 | 同上（`full_text`） |
| 四个操作（↑ ↓ 复制 删除）**常驻**，不再是 hover 才显形、不再留占位宽度 | 同上（`ops`） |
| 列区**不再画「列（N）」段标题**；计数并到操作行最左 | `Render for MockDetailView` 的 `columns_block` |
| 无列态 = 一行提示 + 场景按钮 + 列来源按钮（**不套卡片、不占段高**） | 同上 |
| 结果 tab 的只读列同样去段标题，改一行 `{N} 列 · 只读（来自这次生成）` | `columns_block` + `render_result_columns` |
| 列清单不再限高 / 不再自行滚动（滚动所有权归列区段，两层滚动会「滚到一半卡住」） | `render_fields` 尾部、`ui::FIELD_LIST_MAX_HEIGHT` 标记为不再使用 |

## 5. 方案 B 的实施口径（不实施，仅留未来参考）

> 本文档已按「只做 A」定稿；以下口径仅供将来若真的要上表格时参考，当前代码不遵循。

1. 新增 `ColumnTableDelegate`（建议新文件 `crates/mock/src/mock_view/detail/columns_table.rs`，或 `detail.rs` 内独立模块）：
   - 列：`#` / 列名 / 类型 / 生成器 / 参数 / 约束 / 操作
   - 数据源：面板 `config_for(config_id).columns`，经 `visible_columns(panel, id, cx)` 做筛选
2. 行点击 → `MockDetailView::open_column_dialog(id, window, cx)`；行尾 `⋯` → `DropdownMenu`（上移 / 下移 / 复制 / 删除，回调沿用现有实现并先 `panel.focus_config(config_id)`）。
3. 选中态：把现在的 `hovered_column` 升级为 `hovered_column`（悬停高亮）+ `selected_column`（点开对话框的那一列，`list_active` 底色），跨帧保留。
4. 列宽记忆：按 `{tab_key}::{列名}` 存 `HashMap<String, Pixels>`，重建表时恢复（复用预览表 `PreviewTableDelegate.widths` 的做法）。
5. 空态：A 的「一行提示 + 起手按钮」是当前口径（不是 B 口径里的空卡片）。
6. 结果表 tab 的只读列（`render_result_columns`）若上表格，两个 tab 观感一致（可选）。
7. 测试影响：
   - 需要清点 `mock-field-card-` / `mock-gen-` / `mock-hover-` / `mock-moveup-` / `mock-movedown-` / `mock-copy-` / `mock-del-` 在 `crates/mock/src/mock_view/tests.rs`、`crates/workbench/tests/*` 的引用；
   - 三行布局几何用例（列编辑对话框）不涉及列区，不受影响；
   - 新增用例：列区表格渲染（行数 = 列数）、行点击开对话框、`⋯` 删除后行数 -1。

## 6. 风险

| 风险 | 处置 |
| --- | --- |
| `DataTable` 单元格内放按钮 / 菜单的命中与滚动行为 | 先做 1 列原型实测；不可靠则退化为右键菜单（结果集已有先例），行尾只留一个 `⋯` |
| 行操作按钮的 `ElementId` 必须按业务键（列 id），不能按下标 | 沿用项目既有约束 |
| 列很多时表格虚拟化与「上移/下移」的滚动跟随 | 阶段 2 再处理（先不做滚动跟随，移动后保持选中行可见即可，用 `scroll_to_item`） |
| 表格列宽与窄窗口 | 类型 / 参数列设最小宽 + 文本省略，`#` 与操作列固定窄 |
