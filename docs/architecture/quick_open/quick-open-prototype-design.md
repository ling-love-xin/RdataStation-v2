## 1. 定位与边界

一句话：**Quick Open 是工作台的统一检索入口，核心是元数据搜索** —— 一个输入框，按前缀切换「搜什么」，结果按来源分组，全程键盘可操作（↑↓ / ↵ / Esc）。

按重要性排序的搜索域：

| 序 | 域 | 说明 | 期次 |
| --- | --- | --- | --- |
| 1 | **元数据（核心）** | 表 / 视图 / 列 / schema / 例程 —— 先「按名称」，再「按全文档」两档（见 §6） | P0 名称档 / P1 全文档 |
| 2 | 文件 | 草稿箱文件（`订单口径核对.sql` 这类）；项目文件待定（Q5） | P1 |
| 3 | 连接 | 数据源连接（切到导航并选中） | P0 |
| 4 | 命令 | 「新建查询 / 打开资产库 / 打开设置」等功能入口 | P0 |

三个近邻入口的分工（避免重复建设）：

| 入口 | 搜什么 | 结果落在哪 | 心智 |
| --- | --- | --- | --- |
| 导航面板搜索框（M4） | 跨连接元数据**名称** | 导航树顶部结果区 | 「在当前导航上下文里挑对象」 |
| **Quick Open** | 元数据（名称 + 全文档）/ 文件 / 连接 / 命令 | 浮层内，**不改变导航树的浏览状态** | 「去某个地方 / 干某件事 / 找某个对象」 |
| 设置页搜索行 | 设置项（登记表） | 设置页内 | 「找一项配置」 |

明确不做（边界）：

- 不做**数据行**检索（那是数据预览 / SQL 的活，Quick Open 不跑查询）；
- 不做 SQL 执行 —— 编辑器职责；
- 不替代导航面板 —— Quick Open 只负责「跳转 / 执行」，不承载浏览与整理。

## 3. 入口（标题栏）

**保持现状形态：入口不是真输入框**（VSCode 同款 —— 点开后在浮层里输入）。两条理由：

1. 标题栏 36 px 高内放真输入，会与 `TitleBar` 自带的窗口拖拽 hitbox 抢鼠标（拖窗口 vs 点输入）；
2. 焦点、候选列表、键盘通道都应集中在浮层里 —— **单一权威输入**，避免「两处都能打字」的分裂。

需要调整的只有文案与降级：

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 占位文案 | 「搜索或输入命令…」 | 「搜索对象、文件、命令…」（元数据是主角，排在首位） |
| 右侧提示 | `Ctrl+P` | 保留 |
| 无项目 / 无连接 | 无差别 | 文案降级（无项目时去掉「文件」），对应分组不出现（见 §10） |

```

│    analytics.v_order_daily               视图 · 营销分析（生产）              │
│                                                                              │
│   文件                                                                        │
│    订单口径核对.sql                        草稿箱 · 营销分析/分析脚本/         │
│   连接                                                                        │
│    营销分析（生产）                         postgres · 项目连接 P             │
│   命令                                                                        │
│    新建查询                                                          Ctrl+N   │
├──────────────────────────────────────────────────────────────────────────────┤
```

- 面板**水平严格居中**（左右 `flex_1()` 占位），顶部距窗口 2.625 rem（对齐 v5 示意）；
- 结果区高度按内容自适应，超过 21.25 rem 时内部滚动（面板高度不跳）；
- 输入行与结果区之间、提示行之上各一条 1px `border` 分隔线。

## 5. 模式（前缀）

VSCode 语义：**前缀只认输入的第一个字符**，切换「搜索域」。

| 模式 | 触发 | 搜索范围 | 示例 | 期次 |
| --- | --- | --- | --- | --- |
| 默认 | 无前缀 | **元数据名称** + 文件 + 连接 + 命令 | `order`、`订单`、`设置` | P0 |
| 命令 | `>` | 仅命令 | `>新建查询` | P0（语义已有） |
| 元数据全文 | `#` | 元数据**全文档**（注释 / 类型 / 定义，见 §6.2） | `#渠道`、`#优惠` | P1（写侧待接线） |
| 当前连接限定 | `@` | 把默认模式限定到当前连接 / 当前分析库 | `@orders` | P2（待拍板 Q2） |
| 行号 | `:` | 当前编辑器文档的行号跳转 | `:120` | 不放第一批（属编辑器能力） |

规则细节：

- 前缀**保留在输入框里**并以 chip 形式高亮（右侧显示 `# 元数据全文`）；退格删掉前缀 → 自动回到默认模式；
- 前缀后允许直接跟字（`>新建`、`#渠道`）或空格（`> 新建`），两种都接受；
- 只识别**半角**前缀字符（全角 `＞` / `＃` 交给普通搜索词，避免输入法误触发）—— 待确认 Q6；
- 与导航搜索框的 facet 语法（`scope:` / `type:` / `driver:` / `tag:`）**不冲突**：用「首字符符号」而非「`键:`」；
- 为什么全文要单独一个模式而不是默认混排：全文是**排序 + 片段**语义（`ORDER BY rank`，给注释 / 定义片段），与名称档的「短名字列表」不是同一种结果形态，混在一起会让默认列表变吵。

## 6. 元数据搜索：两档（核心）

### 6.1 名称档（默认模式，P0）

| 维度 | 取值 |
| --- | --- |
| 数据源 | `metadata_index`（每连接的缓存库；`crates/engine` 建表 / 重建，`crates/database/src/cache.rs` 读） |
| 写侧 | `rebuild_schema_index` —— **已接线**（冷启动内省一个 schema 后重建） |
| 匹配 | `LOWER(object_name) LIKE '%needle%'`（**中缀**，中文子串天然可用） |
| 返回 | 对象类型 + 名称 + 父对象 + catalog / schema（+ 行数估算） |
| 上限 | 单连接 50 条、总计 300 条（`nav_jobs::SEARCH_LIMIT_PER_CONN` / `SEARCH_MAX_HITS`） |
| 现状 | 已可用，但**只有导航面板在用**（`nav_jobs::enqueue_search` / `drain_search_results`） |
| 不建缓存 | 未内省过的连接直接跳过（`cache::cache_file_exists` 门）——搜索不该顺手建元数据文件 |

### 6.2 全文档（`#` 模式，P1）

| 维度 | 取值 |
| --- | --- |
| 数据源 | `metadata_fts`（FTS5 虚拟表，与 `metadata_index` 同在每连接的缓存库里） |
| 表结构 | `search_type` / `schema_name` / `object_name` / `parent_name` / `search_content`（**无连接列**，连接由「打开了哪份缓存」隐含） |
| 写侧 | `sync_fts_index(Option<&str>)` —— **已存在但从未被调用**（`metadata_index` 的重建已接线，FTS 的同步没接） |
| 现有语料 | schema 名；表 = schema + 表名 + **表注释**；列 = schema + 表名 + 列名 + **数据类型** + **列注释**；视图 = schema + 视图名 + 视图注释；例程 = schema + 例程名 + 例程类型 + 例程注释 |
| 暂无语料 | 视图定义（`view_definitions.view_definition`）与例程源码（`routines.routine_definition`）**已落在缓存里但没进 FTS**；是否纳入见 Q8 |
| 匹配 | `search_content MATCH 'needle*'`（FTS5，**前缀 / 整词**；`ORDER BY rank LIMIT 50`） |
| 返回 | 类型 + schema + 对象名 + 父对象 + **snippet**（SQLite `snippet()` 生成，带 `<mark>` / `</mark>` 标记，可直接转高亮） |
| 现状 | 引擎侧 `search_fts` 可调用，但**无任何调用方**；跨连接实现可复用名称档那条路（遍历有缓存的连接，各自查） |

### 6.3 中文与分词语义（必须写清的取舍）

FTS5 默认 `unicode61` 分词器把**连续中文当作一个 token**，只有「前缀命中」才搜得到（搜 `渠道` 能命中以「渠道」开头的注释片段，命中不了注释中间的「……下单渠道……」）。三种处置：

| 方案 | 效果 | 代价 |
| --- | --- | --- |
| **A 默认 unicode61（先上）** | 前缀 / 整词命中；中文注释的中间词搜不到 | 零成本；但中文场景体验一般 |
| B `trigram` 分词器 | 中文任意子串可命中（trigram 天然支持中缀） | 索引体积明显变大（约为文本 3 倍量级）；需重建 FTS 表（迁移） |
| C 名称档兜底 | 全文搜不到时，提示「试试名称搜索」并自动回落到 `metadata_index` 中缀匹配 | 语义分档要在 UI 上讲清楚 |

**原型与文档建议：先 A + C（可上线且可解释），把 B 作为「中文注释检索效果不达标」时的升级项**（决策记录留 `quick-open-architecture.md`）。

### 6.4 结果行（元数据两档的差别）

| 档 | 行结构 |
| --- | --- |
| 名称档 | 单行：`图标 + 对象名（schema.name / 表.列，命中高亮）+ 右侧归属（连接名 · 驱动）` |
| 全文档 | 两行：第一行同名称档；第二行 = **snippet**（`search.match.background` 高亮命中词），一眼看出「为什么命中」 |

## 7. 结果行规格

### 7.1 行解剖（高 1.5rem = 24px；两行式自动增高，左右内距 0.625rem）

| 段 | 内容 | 取色 | 备注 |
| --- | --- | --- | --- |
| 结构前导 | 左侧 2px 激活条（仅选中行） | `sidebar_accent` | 与树 / 列表统一（`ui::TREE_ACTIVE_BAR`） |
| 图标 | 1rem 图标（表 / 视图 / 列 / 文件 / 连接 / 命令） | `muted_foreground` | 图标集不在第一批扩（用现有 `IconName` 子集，缺则留空） |
| 主文本 | 名称（含命中高亮） | `foreground` | 命中区间加粗 + `search.match.background` 底色（与导航 `nav_name_highlight` 同款） |
| 片段行（仅全文档档） | snippet | `muted_foreground` | 命中词同款高亮；超长省略 |
| 面包屑行（元数据 / 文件） | `连接 › schema › 表 › 列`（文件为相对路径） | `muted_foreground` | 多连接 / 多 schema 同名对象靠它消歧（原型「同名消歧」场景） |
| 为什么命中标签 | `释`（注释）/ `型`（数据类型）/ `义`（定义）；名称命中是默认，不额外标 | `muted_foreground` + `border` 描边 | 避免「为什么会被搜出来」的困惑 |
| 次级信息 | 归属（连接名 · 驱动 / 表名 / 路径） | `muted_foreground` | 右对齐、超长从头部省略（`text_ellipsis`） |
| 行尾 | 快捷键（仅命令行） | `muted_foreground` | 如 `Ctrl+N` |

- 选中态：`list_active` 底色 + 左侧激活条；hover：`list_hover`；
- 行 id 用**业务键**（文件相对路径 / 连接 id / `conn_id + schema + 对象名 + 父名` / 命令 id），**不用下标**（下标会在结果刷新后串行 hover 与选中态）。

### 7.2 分组顺序（固定，不随分数跳动）

| 顺序 | 分组 | 何时出现 |
| --- | --- | --- |
| 1 | **元数据（表 · 视图 · 列）** | 有元数据命中时（异步；组头带「搜索中…」） |
| 2 | 元数据全文（注释 / 定义） | 仅 `#` 模式 |
| 3 | 最近使用 | P2（有记录时） |
| 4 | 文件 | 打开了项目（草稿箱文件） |
| 5 | 连接 | 有连接时 |
| 6 | 命令 | 默认模式（待拍板 Q1）与 `>` 模式 |

### 7.3 各组的「主文本 / 次级信息 / 动作」

| 分组 | 主文本 | 次级信息 | 选中后动作 |
| --- | --- | --- | --- |
| 元数据 · 表 / 视图 | `schema.name` | 连接名 · 驱动 | 打开属性面板（P1）；数据预览待定（Q4） |
| 元数据 · 列 | 列名（`表.列`） | 表名 · 连接名 | 属性面板定位到列（P1） |
| 元数据 · schema | schema 名 | 连接名 | 导航定位到该 schema |
| 文件 | 文件名 | 相对路径（草稿箱 / 存档只读标记） | 中央编辑区打开（草稿可写；存档只读） |
| 连接 | 连接名 | 驱动 · 归属域短码（`G` / `P` / `GP`） | 切到导航面板并选中该连接（**不自动连接**、不改连接状态） |
| 命令 | 命令标题 | 快捷键 | 执行命令 |

## 8. 匹配与排序

- **名称档匹配**：大小写不敏感的子串匹配（不做拼音、不做数据行检索）；
- **最小长度门槛**：元数据异步搜索**至少 2 个字符**（沿用 `nav_search_query_ready` 的口径），单字符只过滤本地源（命令 / 连接 / 文件），元数据组给「再输入 1 个字符」提示——避免单字符把每个连接都扫一遍；
- **评分分档**（同分再比长度，短者优先）：
  1. 完全相等；2. 名称前缀；3. 词首命中（`camelCase` / `snake_case` 分段首字母）；4. 子串命中（位置靠前优先）；
- **全文档档排序**：沿用 FTS5 `ORDER BY rank`（不自己重排，避免与引擎语义打架）；
- **排序**：先按分档，再按「最近使用」（P2）→ 名称序；**分组之间不混排**（稳定性优先，避免结果跳动）；
- **高亮**：命中区间加粗 + `search.match.background` 底色；未命中部分保持常规字色；
- **上限**：单组最多 8 行、总计最多 50 行（超出滚动）；元数据源沿用后台上限（单连接 50 / 总计 300，FTS 引擎侧 `LIMIT 50`），面板只取前 N 条并显示**「还有 N 条」**（可展开或继续输入缩小），不静默截断；
- **异步不抢选中**：批次回填时选中行按**业务键**跟随（而不是按行号），否则新结果插入会把用户的当前位置顶掉；
- **跨档去重**：同一对象同时被名称档与全文档命中时合并为一行（标签叠加），不占两行。

## 9. 状态机与异步

```
关闭 ──(Ctrl+P / 点入口)──► 打开：清空输入 · 清空选中 · 模式=默认 · 聚焦输入
   ▲                                   │
   │                         输入变化 ──┼──► 同步源（文件/连接/命令）立即过滤
   │                                   └──► 异步源（元数据名称 / 全文档）防抖 150ms 后发一次搜索
   │                                              │
   │                                     结果回填（query 与当前输入不一致 → 丢弃）
   │                                              │
   └──(Esc / 点面板外 / 执行一条 / 再次 Ctrl+P)────┘
```

| 规则 | 说明 |
| --- | --- |
| 打开即聚焦 | 输入框在打开的那一帧拿到焦点（参照导航面板的「待聚焦标记」写法：懒创建时先记标记，下一帧消费） |
| 单输入源 | 输入框只有浮层里这一个；标题栏入口只负责「打开」 |
| 防抖 | 元数据搜索是读盘 + 跨连接，输入每次变化都发会打爆后台；150 ms 防抖，且**只在查询词变化时**发 |
| 过期批次丢弃 | 回填结果自带 `query`，与当前输入不一致直接丢（`nav_jobs::SearchResult` 已有此语义） |
| 不建缓存 | 查询**不为**未内省过的连接创建元数据缓存文件（沿用 `cache::cache_file_exists` 门） |
| 关闭语义 | Esc 一次即关（不做两段式清空）；关闭时未回的批次照常丢弃 |
| 重绘 | 弹层挂在宿主 overlay 上：状态变化后通知宿主重渲染（`Shared::notify_host`） |

## 16. 代码归属判定（crate vs 模块）

**结论（本轮建议）：不建 crate，落在 `crates/workbench/src/quick_open/` 模块；边界按「可升级」设计。**

对照 `rds-architecture` 的建 crate 三条判定：

| 判定 | Quick Open 现状 | 结论 |
| --- | --- | --- |
| 独立状态与生命周期 | 状态（开关 / 输入 / 选中 / 结果）生命周期 = 工作台窗口，无独立持久化 | ✗ |
| 稳定公开边界（对外只暴露 Service + 命令） | 是**宿主级 UI 面**，对外只需 Action 与宿主端口 | ✗ |
| 使用方 ≥2 | 只有 workbench 一个宿主 | ✗ |

另有一条依赖方向上的硬伤：面板要搜的是**各 Feature 的数据**（草稿箱文件、连接、元数据、编辑器命令）。若做 crate：

- 「Feature 依赖 palette」→ 每个 Feature 都要依赖一个 UI 组件 crate，且视其为比自身更稳定的底座（事实相反）；
- 「palette 依赖 Feature」→ 这个 crate 就是 workbench 替身，把宿主职责搬了个家，依赖没减少。

先例：主题无独立状态 → 不建 crate；settings 有独立持久化 + 稳定 Service 边界 → 建 crate。Quick Open 属前者，与标题栏 / 活动栏 / Dock 同层（工作台外壳能力）。

**升级为 crate 的触发条件**（命中任意一条再拆，届时模块边界即 crate 边界）：

1. 出现**第二个宿主** —— 独立窗口、插件面板、编辑器内嵌面板等；
2. 插件系统（M9 beta3）需要注册命令与搜索源，palette 成为**跨 crate 对外契约**（使用方 ≥2）；
3. 「最近使用 / 固定项」需要独立持久化，且脱离窗口生命周期。

## 18. 优化建议清单

> 与 §13（与现状的差异）互补：§13 是「把设计做出来必须补的」，本节是「做出来之后还能更好的」。**★ = 交互稿已体现**。

### 18.1 正确性与安全（不做的代价是「静默搜错 / 直接报错」）

| 建议 | 为什么 / 依据 | 成本 | 期次 |
| --- | --- | --- | --- |
| **FTS5 查询词清洗** | 现状 `format!("{}*", query)` 是**裸拼**：用户输入 `"` `*` `(` `NEAR` `-` 会破坏 `MATCH` 语法（报错或语义完全不同）；需按 FTS5 语法转义 / 引号包裹，裸词统一加 `*` | 低 | P1（与 §13-6 同批） |
| **LIKE 通配符转义** | `search_index` 已带 `ESCAPE '\'`，但需覆盖 `%` / `_` / `\` 三种并补单测，否则用户输入 `_` 会被当成「任意单字」 | 低 | P1 |
| **名称归一化** | 大小写 + `_`/驼峰分词（`order_items` 能被 `order` / `items` / `orderitems` 命中）+ Unicode NFC/NFKC（全角半角 / 兼容字符），避免「看着一样搜不到」 | 中 | P1–P2 |
| **单字符门槛（≥ 2）** ★ | 沿用 `nav_search_query_ready` 口径；1 个字符触发全库扫没有收益 | 低 | P0 |
| **异步不抢选中** | 见 §8：选中按业务键跟随；否则回填那一瞬用户按下的 ↵ 会落到别的对象上 | 低 | P0 |
| **FTS `rank` 加 tie-breaker** | 同分时顺序不稳定（同一 query 两次结果不同，看起来像 bug）→ 补 `object_name ASC` | 低 | P1 |
| **跨档去重** | 同一对象被名称档与全文档同时命中时合并一行（标签叠加） | 低 | P2 |
| **IME 组合态不发异步查询** | 拼音输入时每个字母都触发过滤；组合期间应只本地过滤，组合结束再发搜索 | 中 | P0（与 §13-1 同批验证） |

### 18.2 规模与资源（库大了才痛，但改起来最贵）

| 建议 | 为什么 / 依据 | 成本 | 期次 |
| --- | --- | --- | --- |
| **前缀 / 中缀两段式** | `LOWER(object_name) LIKE '%x%'` 在缓存库里**没有索引**（engine 侧无 `CREATE INDEX`）→ 每次搜索全表扫；前缀段可走索引，命中不足再退中缀 | 中 | P1 |
| **或 FTS5 trigram 统一两档** | 名称 + 全文都走索引（中文子串天然支持），代价是索引体积（约文本 3 倍量级） | 中高 | P2（与 Q8-B 同批） |
| **并发打开缓存文件上限** | 每连接一份 SQLite 文件：30 个连接同时搜 = 30 个句柄 + 30 次冷读；设上限（如 4）顺序扫描、先回先到 | 低 | P1 |
| **FTS 同步增量 + 时机** | `sync_fts_index` 是按类型 DELETE+INSERT 的重建式 → 改 schema 级增量，与 `rebuild_schema_index` 同批，**绝不在搜索路径写库** | 中 | P1 |
| **结果短时缓存** | 同 query 秒级复用（导航与 Quick Open 共享）；内省刷新 / 项目切换时失效 | 低 | P2 |
| **冷启动预热** | 项目打开后预热**已缓存**连接的索引（守住「搜索不建缓存」的门） | 低 | P2 |
| **缓存库治理** | 定期 `PRAGMA optimize` / `VACUUM`，监控 FTS 行数与体积（trigram 会放大） | 低 | P2 |
| **行数估算可用化** | `row_count_estimate` 全链路有字段，但 6 个驱动全传 `None`（`duckdb` / `mysql` / `mysql_native` / `postgres` / `postgres_native` / `sqlite`）→ 补近似值（`information_schema` / `reltuples`）后可用于排序与展示 | 中 | P2 |

| **「为什么命中」标签** ★ | §7.1；`#` 模式下尤其必要 | 低 | P1 |
| **类型双通道（形状 + 文本）** | 只靠颜色区分类型对色弱不友好；导航已有「双通道徽标」传统 | 低 | P1 |
| **组内「还有 N 条」+ 范围常显** ★ | 不静默截断；直接回答「为什么没搜到」 | 低 | P1 |
| **焦点恢复 / 移交** | Esc 后焦点回打开前的元素；`↵` 后焦点到目标面板——否则键盘流断在最后一步 | 中 | P1 |
| **保留上次查询** | 打开即续搜（可设置项） | 低 | P2 |
| **空输入态：最近 + 常用** | 比空面板或全量列表省一次输入 | 低 | P2 |
| （可选）拼音首字母 / 多选批量 / 拖拽生成引用 | 收益明确但交互面大 | 高 | P3 |

### 18.4 工程与回归

| 建议 | 为什么 | 成本 | 期次 |
| --- | --- | --- | --- |
| **provider 端口形状 + 纯函数化** | 输入（query + mode）→ 结果批次；前缀解析 / 评分 / 转义 / 截断做成无窗口纯函数（可单测），UI 只渲染 | 中 | P0 |
| **性能基线** | 合成 10 万对象缓存库，把「搜索耗时 / 结果数」纳入回归——没有基线就谈不上优化 | 中 | P1 |
| **结构化日志** | `query_len` / `hits` / `dur_ms` / `conns_searched` / `conns_skipped` / `fts_rows`：排查「搜不到」的唯一手段 | 低 | P1 |
| **契约登记** | 新模块必须进 `ui_contract` 的尺寸 + 颜色两份清单（漏登 = 两份契约对该文件静默失效） | 低 | P0 |
| **搜索语法单一权威** | 导航 facet（`scope:` 等）与 Quick Open 前缀（`>` `#` `@`）写在同一份文档，防语法漂移 | 低 | P1 |
| **文档与验收同步** | §15 测试点 → 使用手册的 USIT 验收项；实现位置映射表随代码更新 | 低 | 持续 |
