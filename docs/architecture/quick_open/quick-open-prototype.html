#元数据全文

这份原型在说什么（本轮新增项已标 ★）

1. 核心是元数据搜索：默认模式以「表 / 视图 / 列」为主角（名称档，中缀，沿用已接线的 metadata_index）；# 进全文档（注释 / 类型 / 将来可含定义），走 metadata_fts（FTS5 trigram，2026-09-19 已接线，≥ 3 字）。
2. 为什么命中 ★：行内小标签（释 / 型 / 义；名称命中是默认，不额外标）—— 尤其 # 全文档，一眼看出是注释还是定义命中的。
3. 面包屑归属 ★：第二行给 连接 › schema › 表，多连接 / 多 schema 同名对象一眼消歧（专设「同名消歧」场景）。
4. 单字符门槛 ★：1 个字符只过滤本地源（命令 / 连接 / 文件），元数据组显示「再输入 1 个字符开始搜索」——避免单字符全库扫。
5. 截断不静默 ★：组内「还有 N 条…」，底部常显搜索范围（已搜 / 跳过几个连接）。
6. 异步不抢选中 ★：批次回填按业务键跟随选中行，列表更新不夺走用户当前位置（原型看不出，但要写进实现约束）。
7. 无结果的转移入口 ★：直接给「在数据库导航中搜索 / 在草稿箱中搜索内容」两个去向，不做死胡同。
8. 键盘三态：↵ 打开并关闭 · Ctrl+↵ 后台打开 · Shift+↵ 保留面板；Ctrl+Shift+P 直达命令模式（原型里按 ↵ 可看当前三态提示）。
9. 原型未模拟：真实防抖（150ms）、IME 组合态期间不发异步查询、FTS5 查询词清洗（用户输入 " * NEAR 会破坏 MATCH 语法）、Esc 后的焦点恢复、权限与只读差异、中文分词取舍（见文档 Q8）。
10. 范围与上限（设计值）：单组 8 条 / 总计 50 条；后台单连接 50 / 总计 300；FTS 引擎侧 LIMIT 50；搜索不建缓存。
