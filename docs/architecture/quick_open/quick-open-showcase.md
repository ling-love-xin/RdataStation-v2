# RdataStation · Quick Open（统一检索 / 命令面板）—— 一页看懂

> 标题栏那条搜索框：**一个输入框 · 三档模式 · 三类来源 · 全程键盘**。
> 核心是元数据搜索：**按名字找对象，按内容找注释**。
>
> 本页是**可贴版**（纯文本 + 流程图，适合贴进 PR / wiki）；视觉版见 [`quick-open-showcase.html`](quick-open-showcase.html)
> （自包含、明暗双主题、离线可开，首屏可在三档模式间切换）。
> 两版章节一一对应；视觉版把「三档模式」的演示放进首屏浮层线框，本页把它排在第 3 节。

## 一句话

**按住 `Ctrl+P`，敲几个字——表、视图、列、文件、连接、命令，都在这一条里。**

它不是标题栏上的装饰：打开即聚焦、↑↓ 漫游、`↵` 执行、`Shift+↵` 留在原地接着敲；
`>` 切命令、`#` 搜注释与类型；**搜索在后台、结果按来源分组、被截掉多少都写在界面上**。

### 它替你做到的事

| 你关心的 | 它给什么 |
| --- | --- |
| 库很大，还快吗 | 10 万对象缓存库里，8 万条同前缀命中的搜索 **158 ms → 1.5 ms**（2026-09-19，debug 同轮对照）；名称档与全文档各自走索引，**都不做全量排序** |
| 只记得一半名字 | 名称档是**中缀**匹配：敲 `ord` 命中 `order_items`；**不受 3 字限制**，中文子串同样可用 |
| 只记得注释里写过什么 | `#` 档走 FTS5 **trigram** 全文档（注释 / 类型），snippet 直接标出命中片段 |
| 会不会偷偷建东西 | 搜索**不为**未内省过的连接创建缓存文件（沿用导航的 `cache_file_exists` 门）；**0 个新文件** |
| 结果会不会跳 | 选中锚在**业务键**上、同分行按 `id` 兜底：异步回填与重新搜索都不抢你当前的位置 |
| 结果少是不是被吞了 | 单组 ≤ 8、总计 ≤ 50，**被截的条数写在组尾**（「还有 N 条」）；搜不动时给门槛提示而不是空列表 |
| 能不能不摸鼠标 | 打开 / 漫游 / 执行 / 保留面板 / 关闭，全部有键；`Ctrl+P` 一个入口进出 |

> 数字口径以模块文档为准；工程数字（单测数量、实测耗时）见第 14 节。

## 1. 为什么它不是一个「搜索框」

V1 的标题栏上有一个输入框，但它只是块装饰。这一版逐条换成了真东西：

| 旧样子 | 现在 |
| --- | --- |
| 输入框只是外观，没有浮层、没有键盘通道 | 独立浮层实体（`quick_open/palette.rs`）：打开即聚焦、↑↓ 跨组漫游、`↵` / `Shift+↵` / `Esc` 三态确认 |
| 只能过滤一份写死的本地清单 | **三类来源**：元数据（跨连接索引，异步）、文件（草稿箱）、连接 + 命令 |
| 没有模式概念 | `>` 命令 / `#` 元数据全文 / 默认混排；前缀只认第一个字符，删掉即回默认 |
| 结果区手搓 `div` + `on_mouse_down`，无 hover / 选中态 | 组件库 `List` + `ListDelegate`：分组头（section header）、空态、hover / 选中 / 滚动全归组件 |
| 搜不到只给一个空列表 | 状态永远可见：组头「搜索中…」、门槛「再输入 1 个字符」、截断「还有 N 条」 |
| 执行动作内联在渲染闭包里 | 动作过端口（`QuickOpenHost::execute`），宿主只负责「做」；浮层不碰工作台内部 |

## 2. 三档模式 · 一个入口

前缀只认**第一个字符**（半角 `>` / `#`；全角 `＞` `＃` 当普通搜索词，避免输入法误触发）。

| 模式 | 触发 | 搜什么 | 最小词长 | 数据源 |
| --- | --- | --- | --- | --- |
| **默认** | 无前缀 | 元数据（表 / 视图 / 列） + 文件（草稿箱） + 连接 + 命令 | 元数据 **2 字**（本地源不受限） | 每连接的元数据缓存库（后台异步） |
| **命令** | `>` | 仅命令（13 条，带稳定 id 与英文关键词，如 `settings` / `database`） | 不发异步搜索 | 进程内目录（`quick_open/commands.rs`） |
| **元数据全文** | `#` | 全文档：schema / 表 / 列 / 视图 / 例程的**注释与类型** | **3 字**（trigram 的下限） | 同库的 FTS5 表（`metadata_fts`） |

> 门槛不是随手定的：名称档 2 字是为了不让**每个连接**都被扫一遍；全文档 3 字是因为
> trigram 分词器下**不足一个 trigram 必然无命中**（实测：中文注释搜「含渠道」命中、搜「渠道」无命中）。

## 3. 三个高光

如果只记三件事：

**① 元数据搜索是核心，而它是索引直出的。**
名称档：先按类别（表 → 视图 → schema → 列）各扫一段 `(connection_id, object_type, LOWER(name))` 索引，
取够一页就停——**没有全量排序、没有近似窗口**；排序键里连 `LENGTH` 都拿掉了，就为了让它能被索引直出
（8 万同前缀命中：**158 ms → 1.5 ms**）。全文档：FTS5 trigram + `ORDER BY rank`，中文注释可搜。

**② 「在搜 / 没搜够 / 被截了」三件事，界面上都写着。**
组头右侧「搜索中…」、门槛提示「再输入 N 个字符」、组尾「还有 N 条（继续输入缩小范围）」——
**静默截断与静默空列表在这套界面里是不允许的**（`Group.hidden` 承载被截条数，测试钉住）。

**③ 浮层是可测的实体，不是渲染闭包里的一坨。**
纯逻辑（前缀解析 / 评分 / 分组 / 截断）在 `model.rs` 是纯函数；浮层是独立 `Entity`；
宿主只实现一个端口 `QuickOpenHost`（执行动作 + 打开 / 关闭）。
于是**窗口测试能真按键**：`Ctrl+P` → 打字符 → ↑↓ → `↵` → 断言副作用。

## 4. 四个剧本 · 它替你做什么

每一步都用现在就能敲的键，能照着做。

### 剧本 A · 只记得表名的一半 → 3 秒找到并打开属性

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 召唤 | `Ctrl+P`：浮层在标题栏下方展开，焦点已在输入框（不用再点一下） |
| 2 | 敲一半 | 敲 `ord`——命中按来源分组：**元数据（表 · 视图 · 列）** 在最上，前缀命中排在子串命中之前 |
| 3 | 看一眼再决定 | 每行左侧是类型短标签（表 / 视图 / 列 / 模式 / 连接 / 命令 / 文件），右侧是所属 schema / 目录 |
| 4 | 进去 | `↵` 打开属性面板并定位该对象；**`Shift+↵` 不关面板**，接着敲下一个 |

### 剧本 B · 只记得注释里写过「优惠」→ `#` 档找字段

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 切档 | 输入 `#优惠`（前缀与词之间可有空格） |
| 2 | 读片段 | 结果是两行式：第一行对象名 + `内容` 标签，第二行是 **snippet**，命中片段带底色 |
| 3 | 定位 | `↵` 到属性面板；命中来自注释而不是名字，所以**不做标题过滤**（否则只在注释里命中的行会被误杀） |

### 剧本 C · 忘了菜单在哪 → `>` 档当命令行用

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 切档 | 输入 `>设置`、`>隐藏`、`>新建查询`，或直接敲英文关键词 `settings` / `database` |
| 2 | 认准目标 | 每条命令显示快捷键；关键词参与匹配但**不被高亮**（不把你看不到的词标黄） |
| 3 | 执行 | `↵` 立即执行；命令档不触发任何元数据搜索（不发异步、不打库） |

### 剧本 D · 接着改上次的草稿 → 默认档里就是文件

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 敲路径片段 | 文件行的匹配面是**相对路径**：敲 `drafts/notes` 或只敲目录名都能命中（高亮仍按文件名算） |
| 2 | 打开 | `↵` 在中央编辑区打开该草稿（可写 / 只读由编辑器按路径判定） |
| 3 | 清单太大 | 后台清单被截时，组头右侧写明原因；搜索仍在后台继续，不挡你敲字 |

## 5. 一次搜索的全流程

```
     你敲一个字符
          │
          ▼
   parse(raw) ──► Mode{ Default | Command(>) | FullText(#) } + needle（保留大小写，供高亮）
          │
          ▼
   本地源即时算（纯函数，无 I/O）：命令 / 连接 / 元数据名称档结果 / 文件
          │                                   │
          │                                   └─► cap_groups：单组 ≤ 8、总计 ≤ 50，
          │                                       被截条数 → Group.hidden（组尾「还有 N 条」）
          ▼
   词长够吗？── 不够 ──► 只出本地结果 + 提示行「再输入 N 个字符」
          │
         够
          ▼
   schedule_search：150 ms 防抖，且**只在词变化时**才发
          │
          ▼
   后台（database::nav_jobs，按消费方分槽 SearchConsumer::QuickOpen）
     ├─ 名称档：engine::search_index（缓存库，每连接一份；无缓存的连接直接跳过）
     └─ 全文档：engine::search_fts（FTS5 trigram + snippet）
          │
          ▼
   pump_results：批次自带 query —— 与当前输入不一致**直接丢**（过期批次不上屏）
          │
          ▼
   build_groups（纯函数）→ List/ListDelegate 渲染
          │
          ▼
   ↵ → QuickOpenHost::execute(action) → 宿主打开属性面板 / 新建文档 / 切面板 / 选中连接
```

| 环节 | 落点 |
| --- | --- |
| 前缀解析 / 门槛 / 评分 / 分组 / 截断 | `crates/workbench/src/quick_open/model.rs`（纯函数 + 单测） |
| 浮层本体（输入 / 键盘 / 防抖 / 回填 / 关闭） | `crates/workbench/src/quick_open/palette.rs`（独立 `Entity`） |
| 结果区渲染 | `crates/workbench/src/quick_open/delegate.rs`（`ListDelegate`） |
| 命令目录 | `crates/workbench/src/quick_open/commands.rs`（13 条，稳定 id + keywords） |
| 动作端口与宿主装配 | `palette.rs::QuickOpenHost` + `view.rs::{toggle_quick_open, execute_quick_open_action}` |
| 后台搜索通道（双消费方分槽） | `crates/database/src/nav_jobs.rs`（`SearchConsumer::{Navigator, QuickOpen}`） |
| 名称档 / 全文档查询 | `crates/engine/src/persistence/metadata_cache.rs`（`search_index` / `search_fts`） |

## 6. 结果区怎么读

```
┌ 元数据（表 · 视图 · 列）                                     搜索中… ┐   ← 组头：说明 + 状态
│  [表]  orders                     public · main                      │   ← 主行：类型标签 + 名称 + 定位
│  [列]  order_id                   orders                              │   ← 列行：父对象在右侧
│  [视图] order_view                public                               │
│  ……                                                                   │
│  还有 12 条（继续输入缩小范围）                                        │   ← 组尾：被截条数，不静默
├ 文件（草稿箱）                                                        │
│  [文件] notes.sql                 2026-09 · drafts                    │   ← 次级信息 = 所在目录
├ 连接                                                                  │
├ 命令                                                                  │
└───────────────────────────────────────────────────────────────────────┘
```

| 元素 | 口径 |
| --- | --- |
| 类型短标签 | 文本 + 位置双通道（不只靠颜色）：表 / 视图 / 列 / 模式 / 连接 / 命令 / 文件 |
| 主行 | 名称；**命中区间**加底色（`search.match.background`） |
| 次级信息 | 元数据 = catalog · schema（列显示父表）；文件 = 所在目录；命令 = 快捷键 |
| `#` 档两行式 | 第一行名称 + `名称` / `内容` 标签（说明**为什么命中**），第二行 snippet；**整档统一两行高**（`QUICK_OPEN_ROW_HEIGHT_FULLTEXT`），满足 `List` 的同行同高约束 |
| 分组次序（默认档） | 元数据 → 文件 → 连接 → 命令（对象是主线，命令是补充；空组连组头都不出现） |
| 空态 | 随模式换文案（无匹配命令 / 无匹配全文 / 无匹配…），并区分「还在搜」与「真没有」 |

## 7. 名称档：两段式 + 分类索引序直出

名称档回答「按名字找对象」，所以**必须支持中缀**（敲 `ord` 要能找到 `order_items`）——
这一点 FTS 的 trigram 做不到（< 3 字必然无命中），于是它走缓存库的 `metadata_index` 表。

| 段 | 做什么 | 怎么做到不慢 |
| --- | --- | --- |
| **前缀段** | `>= needle AND <= needle‖U+10FFFF` 范围比较（等价于「以 needle 开头」） | 走 `(connection_id, object_type, LOWER(object_name))` 索引；**每类各扫一段**，`ORDER BY LOWER(name) LIMIT n` 就是索引序，取够即停 |
| **回落段** | 前缀没装满一页时，用 `LIKE '%needle%'` 补名额 | 同一索引：`LIKE` 只当过滤谓词，**排序仍由索引提供**（旧写法是全表扫 + 全量排序） |
| **合并** | 按「档位（完全相等 → 前缀 → 中缀）→ 类别（表 → 视图 → schema → 列）→ 名序」稳定排序 | 稳定排序保住类内索引序，所以不需要把 `id` / 长度拿进键；**全程无 SQL 排序** |

10 万对象缓存库实测（debug，单连接，8 万表 + 2 万列；同轮并排跑旧写法）：

| 查询 | 现在 | 旧写法（单条中缀 + 全排序） |
| --- | --- | --- |
| `table_`（8 万同前缀命中） | **1.5 ms** | 158 ms |
| `_0042`（中缀，命中在列档） | **12 ms** | 72 ms |
| `table_000042`（表档一条不中，须扫完整段才能确认） | 45 ms | 87 ms |
| 无命中 | 45 ms | 79 ms |

> 两次提速的来路：第一步「前缀段走索引」（快，但排序还在，8 万命中仍要 178 ms）；
> 第二步**拿掉排序键里的 `LENGTH`**，让排序退化成「相等 → 类别 → 名序」——恰好与索引序一致，
> 于是窗口与排序一起消失，**既精确又快**。剩下的成本是「稀疏词要扫完该档整段」，再要降只能靠 trigram。

## 8. 全文档：FTS5 trigram

| 维度 | 取值 |
| --- | --- |
| 表 | `metadata_fts`（与 `metadata_index` 同在每连接的缓存库） |
| 语料 | schema 名；表 = schema + 表名 + 表注释；列 = schema + 表名 + 列名 + **数据类型** + 列注释；视图 = schema + 视图名 + 视图注释；例程 = schema + 例程名 + 例程类型 + 例程注释 |
| 暂无语料 | `view_definitions.view_definition` 与 `routines.routine_definition` **已落在缓存里但没进 FTS**（是否纳入见原型设计 §17 Q8）——所以今天能搜的是**注释与类型**，不是视图 / 例程源码。分组标题里的「注释 / 定义」是既有 UI 文案 |
| 分词 | `trigram`（迁移 011）——中文子串可搜，代价是**查询 ≥ 3 字**、索引体积约为文本 3 倍量级 |
| 清洗 | 查询词先经 `fts_match_query`：拆词 → 逐词加引号 → 末词前缀；`"` `*` `(` `NEAR` `-` 全按字面处理，**不报错** |
| 返回 | 类型 + schema + 对象名 + 父对象 + **snippet**（SQLite `snippet()` 生成的 `<mark>` 片段，直接转高亮） |
| 写入时机 | 与 `rebuild_schema_index` **同批**（内省一个 schema 就刷新一次）；**绝不在搜索路径写库**，且 FTS 失败只告警、不拖垮导航赖以分页的索引 |

**两个当场抓出来的底座缺陷**（都已修，写在迁移 011 的注释里）：
① 旧表是 **contentless**（`content=''`）——`MATCH` 能命中，但 `SELECT` 回来的对象名**全是 NULL**
（`Invalid column type Null at index: 0`），snippet 也无从生成，整条读路径其实不可用；
② 旧分词器 `unicode61` 把连续中文当一个 token（「含渠道与优惠信息」是一个词），**中文注释等于搜不了**。

## 9. 键盘与选中

| 键 | 行为 |
| --- | --- |
| `Ctrl+P` | 打开 / 关闭浮层（与标题栏入口同一个）；打开即聚焦、清空上次输入、重置选中 |
| `↑` `↓` | 跨组连续漫游（结果重算后按**业务键**回到原来那一行） |
| `↵` | 执行选中行：打开属性面板 / 建文档 / 切面板 / 选中连接 / 打开草稿 |
| `Shift+↵` | 执行但**保留面板**（连续操作不用重开） |
| `Esc` | 一次即关（不做两段式清空）；未回的批次照常丢弃 |
| 鼠标 | 悬停高亮、点击执行；点击遮罩关闭 |

> 选中不是按行号锚的，而是按业务键（`qo-row-{key}`）：异步回填时新结果插进来也不会把光标顶走。
> 这条与「排序稳定」「`id` 兜底」是一组——**三者合起来才让结果不跳**。

## 10. 异步与状态

| 规则 | 说明 |
| --- | --- |
| 单输入源 | 浮层里只有一个输入框；标题栏入口只负责「打开」 |
| 防抖 | 元数据是读盘 + 跨连接：**150 ms** 防抖，且**只在查询词变化时**才发 |
| 过期批次丢弃 | 回填结果自带 `query`，与当前输入不一致直接丢（`SearchResult` 语义） |
| 不建缓存 | 查询不为未内省过的连接创建元数据文件（`cache_file_exists` 门）——搜索不该顺手建文件 |
| 双消费方分槽 | `nav_jobs` 按 `SearchConsumer::{Navigator, QuickOpen}` 分槽：导航与浮层同时搜**不互抢**结果 |
| 不抢选中 | 镜像宿主选中时用 `begin_host_sync` / `end_host_sync` 守卫，避免「更新正在被更新的实体」 |
| 重绘 | 状态变化后通知宿主重渲染（`Shared::notify_host`） |

```
        │      │ 装配 Shared（含 quick_open 槽位）                                     │
        │      ▼                                                                       │
        │  quick_open/palette.rs  ──实现──►  QuickOpenHost（execute / open / close）    │
        │      │  独立 Entity：输入 · 键盘 · 防抖 · 回填 · 关闭                          │
        │      ├─ model.rs（纯函数：parse / rank / build_groups / cap_groups）          │
        │      ├─ commands.rs（命令目录：稳定 id + keywords + 快捷键）                   │
        │      └─ delegate.rs（List + ListDelegate：分组头 / 空态 / 行 / 高亮）          │
        └───────────────┬──────────────────────────────────┬──────────────────────────┘
                        │ 只读数据 + 发起搜索                │ 动作（打开面板 / 建文档…）
                        ▼                                  ▼
        crates/database（后台通道：nav_jobs 按消费方分槽）   宿主既有能力（面板 / 编辑器 / 项目）
                        │
                        ▼
        crates/engine（存储与查询：metadata_index 名称档 / metadata_fts 全文档 / 迁移 011·013）
```

| 纪律 | 含义 |
| --- | --- |
| **依赖只向下** | workbench → database → engine；浮层不直接碰 SQLite，也不拿宿主内部实体 |
| **渲染零 I/O** | 渲染期只读内存快照；搜索 / 文件清单都在后台，回填走泵 |
| **纯函数优先** | 前缀解析、门槛、评分、分组、截断都是无窗口纯函数（`model.rs` 13 项单测钉住） |
| **端口只有一个** | `QuickOpenHost::execute(action, keep_open, window, cx)`——宿主做「怎么做」，浮层只说「做什么」 |
| **组件不许手搓** | 结果区是组件库 `List` + `ListDelegate`；尺寸取自 `workbench_shell/src/ui.rs` 常量，取色走主题 token |

## 13. 质量与证据

| 套件 | 数量 | 覆盖 |
| --- | --- | --- |
| `rds-workbench --lib` | **110 项** | 含 Quick Open 专项：`model.rs` 纯逻辑 **13 项**（前缀解析 / 门槛 / 命中区间 / 评分分档 / 分组过滤 / 命令键唯一与关键词可命中 / 截断计数 / 文件行匹配面…） |
| `rds-workbench --test ui_contract` | **7 项** | 新模块必须登记进**尺寸 + 颜色**两份清单（漏登 = 契约对该文件静默失效）；视图层零裸尺寸、零裸色值 |
| Quick Open 窗口测试 | **5 项** | 真按键走生产入口：打开即聚焦 / ↑↓ + `↵` 经端口执行并关面板 / `Esc` 关闭 / 单字符门槛 / 文件源 |
| `rds-engine --lib` | **443 项** | 含搜索专项：两段式 vs 单条查询**逐条等价**、窗口取消后的「精确 + 类别优先」、两段 `EXPLAIN QUERY PLAN` 断言（走索引且无 `TEMP B-TREE`）、FTS 写入幂等与读侧身份 + snippet + 中文门槛 |
| `rds-database --lib` | **42 项** | 含 FTS 命中映射（空串 → None、catalog 缺位）与分槽通道 |

**规模基线**（`#[ignore]`，手动跑 `--ignored --nocapture`）：10 万对象（8 万表 + 2 万列）缓存库，
同轮打印「现写法 / 旧写法」并拆出两段耗时——本节第 7 节的数字就来自它，改搜索实现时重跑即可复核。

**实证缺陷（开发期当场抓出来，都已修）**：
① FTS 旧表 contentless → 读回全 NULL、snippet 无从生成；② 中文注释因 `unicode61` 分词**整句一个 token** 搜不到；
③ 名称档排序键含 `LENGTH` → 索引只能加速「找」不能加速「排」，8 万命中要 178 ms。

## 14. 边界 · 这些事它不做

| 不做 | 为什么 |
| --- | --- |
| 不检索**数据行** | 那是查询与结果区的事；这里只找对象（表 / 列 / 视图 / 文件 / 命令 / 连接） |
| 不做拼音 / 模糊纠错 | 元数据名多是英文标识符；模糊匹配会把「搜不到」的锅变成「搜出奇怪的」 |
| 不为搜索建元数据缓存 | 未内省过的连接直接跳过——搜索是只读动作，不该产生副作用 |
| 不自动连接数据库 | `↵` 命中连接只**选中**它（切到导航），连不连由你决定 |
| 不在搜索路径写索引 | FTS / 索引的刷新只在**内省**同批发生；搜索期间库是只读的 |
| 不做「静默截断 / 静默空列表」 | 截了多少、在不在搜、门槛差几字，都写在界面上 |

**还没做的（原型设计 §17 待拍板 + §18 优化清单）**：`@` 当前连接限定 · 行内动作（复制限定名 / 生成 SELECT）·
空输入态的「最近 + 常用」· 结果短时缓存 · 并发打开缓存文件上限 · 结构化日志（`query_len` / `hits` / `dur_ms` / `conns_skipped`）·
中缀稀疏词的 trigram 兜底。

**关于「升格为 crate」**：暂不拆。触发条件是——出现第二个宿主（独立窗口 / 插件面板）、
插件系统需要注册命令与搜索源（palette 成为对外契约）、或「最近使用」需要独立持久化。
**今天它是 workbench 里的一个模块，边界（纯逻辑 / 浮层 / 端口 / 委托）已经是 crate 的形状。**
