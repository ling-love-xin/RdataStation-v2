# 界面本地化（i18n）说明

记录界面文案的两套 i18n 系统、语言码映射、同步点与现状。改动涉及文案或语言切换时先读本文件。

## 一、两套 i18n 并存

| | 项目自有 | 组件库内置 |
|---|---|---|
| 实现 | `crates/shared/src/i18n.rs` | `vendor/gpui-component` 的 rust-i18n（`i18n!("locales", fallback = "en")`，`src/lib.rs:126`） |
| 词表 | `crates/shared/locales/zh.json` + `en.json`（编译期 `include_str!` 内嵌） | `vendor/gpui-component/locales/ui.yml`（1006 行，`en` / `ja` / `pt-BR` / `ru` / `zh-CN` / `zh-HK` / `zh-TW`，20+ 组件命名空间：Dialog、Select、List、Input、Table、Dock、Command、Pagination、Carousel、Chart、Questionnaire、Speech、Diff、Calendar、DatePicker、ComboBox、DropdownButton、ColorPicker、Attachment 等） |
| 语言维度 | `Locale::{Zh, En}`（`AtomicU8` 全局） | `rust-i18n` 的 `CURRENT_LOCALE` 全局，初始 `"en"`，不做系统语言检测 |
| 入口 | `shared::i18n::tr("中文原文")`（key 即中文原文，惰性解析，未登记词回退原文） | `gpui_kit::component::set_locale(&str)` / `gpui_kit::component::locale()`（`vendor/gpui-component/src/lib.rs:155`、`:160`） |

两套状态**互不影响**：只设 `shared::i18n` 不会改变 Dialog 的确认/取消、Select 占位、Empty、Pagination、Diff 等组件自带文案。

## 二、语言码映射（关键坑）

- 项目存储码（落 `appearance.locale`）：`zh` / `en`（`Locale::code()`）。
- 组件库语言键（`ui.yml` 的块名）：`zh-CN` / `zh-HK` / `zh-TW` / `en` / `ja` / `pt-BR` / `ru`。
- 直接把 `zh` 传给 `set_locale`：rust-i18n **不报错**，静默回退 `en`。所以映射单独收口在 `Locale::component_code()`（`zh` → `zh-CN`、`en` → `en`），并有测试钉住「存储码 ≠ 组件库语言码」。

## 三、接线点与生命周期

唯一同步点：`crates/settings/src/service/appearance.rs` 的 `SettingsService::set_locale`：

```rust
shared::i18n::set_locale(locale);                    // 项目自有文案
gpui_kit::component::set_locale(locale.component_code()); // 组件库内置文案
cx.refresh_windows();
```

- 启动：`crates/app/src/main.rs` 在首帧前按 `appearance.locale` 调 `SettingsService::set_locale` → 首帧即中文（默认 `zh`）。
- 运行时切换：设置页 `appearance.locale` 经 `SettingsService::apply` → `set_locale`（`SettingEffect::Immediate`）→ `refresh_windows()` 立刻重绘。
- 其它地方**不要**再调 `gpui_kit::component::set_locale`：两处写全局 locale 会互相覆盖。

## 四、现状与已知现象

- 接线前全仓 0 处调用组件库 `set_locale`，组件文案恒为英文：已实证的瑕疵是
  `docs/architecture/analytics_resource/analytics-resource-prototype-design.md:139` 记录的“取消按钮显示英文 Cancel”（调用方 `cancel_text` 留空、组件按 `en` 回退）。接线后按当前 `appearance.locale` 显示。
- 自有中文字面量在 src 里共 13,937 条（去重，含日志/错误/SQL 上下文）；**其中真正会渲染到界面的只有 1,456 条（10.4%）**：≤12 字 1,061 条（按钮/菜单/标签/表头/空态）、13–24 字 193 条、>24 字 202 条。剩余 90% 不需要翻。
- 已完成：228 条（连接对话框）+ 161 条（settings）+ 141 条（workbench 壳层）+ 89 条（editor）+ 73 条（result_panel）+ 84 条（insight）+ 90 条（analytics_resource）+ 80 条（database）+ 61 条（scratchpad）+ 36 条（project）+ 4 条（notification）+ 26 条（枚举显示名与画像标签）= **1073 条**词条，再加 settings 长文案 120 条（16 条 13–24 字 + 104 条 >24 字）= **1193 条**。
- 推进顺序（每 crate 一批、一刀一 commit + `cargo check`）：settings（✓）→ workbench（✓）→ editor（✓）→ result_panel（✓）→ insight（✓）→ analytics_resource（✓）→ database（✓）→ scratchpad（✓）→ project（✓）→ notification（✓）。**短文案（≤12 字）批次已收口**，下一步是 §六 的三块结构性缺口。
- 包裹范围含命令面板文案：`MenuItem::new(..)` / `PopupMenuItem::{new,label}(..)` 与 `.child/.label/.tooltip/.title/.placeholder/.text`、`Text::new(..)`、`cancel_text/confirm_text`、以及**字段式 + `.to_string()`**（右键菜单 `label: "复制此值".to_string()` → `label: tr("复制此值").to_string()`，见下节）。**`Tab::new(..)` 的第一个参数是 tab 标识，不翻译**（翻译会让状态随语言漂移）。

### workbench 批的三个实测坑

1. **语言菜单落库码错**：`crates/workbench/src/view/dock.rs` 原先把 `zh-CN` / `en-US` 传进
   `SettingsService::set_locale`，而 `Locale::from_code` 只认 `en` → 点 English 实际落成中文。
   已改为传 `Locale::code()`（`zh` / `en`）。
2. **`mod shared` 遮蔽外部 crate**：`crates/workbench/src/panels/mod.rs` 声明了面板间共享状态
   `mod shared;`，同模块内 `use shared::i18n::tr;` 会解析成 `panels::shared`（E0432）→ 该文件
   必须写绝对路径 `use ::shared::i18n::tr;`。
3. **已有未覆盖的文案形态**（后续批要补）：
   - 条件表达式里的字面量：`.child(if x { "（无描述）" } else { … })`
   - `const` / `static` 里的文案：`services/mock_generator.rs` 的 `NO_PROJECT_DB`（`const` 上下文
     不能 `tr`，须在使用处翻译）
   - `format!` 插值文案（1,751 行，见 §六）

### result_panel 批的两个实测坑

1. **`label: "…".to_string()` 字段形态漏覆盖**：结果集右键菜单（`crates/result_panel/src/grid/menu.rs`）
   与 `ResultAction` 的文案不是字面量实参，而是 `label: "复制此值".to_string()` 的结构体字段。
   第一轮按调用位置正则替换时 23 条全部漏掉（只命中 66 处），须补一条「字段 + `.to_string()`」
   规则（`label|name|title|text|desc|hint : "中文".to_string()`）才补齐到 25 处。由此得**通用顺序**：
   先用清单脚本抓全部中文 unique → 再按「清单里每条是否都能被某规则命中」反向校验，否则会静默漏一半。
2. **测试断言依赖中文原文**：`crates/result_panel/src/grid/tests.rs` 用
   `items.iter().find(|i| i.label == "清除此列筛选")` 定位菜单项。中文 locale 下 `tr()` 恒等、测试仍成立；
   若将来在测试里切 En，这类「按文案找控件」的断言会失效——**测试内文案不要 `tr()`**（tests 目录/`#[cfg(test)]`
   一律保持在包裹脚本的排除集合里）。

### 渲染层翻译（settings 批的教训，硬约定）

`registry::REGISTRY` 是 `OnceLock` + `Box::leak` **一次性固化**的。登记项里若写
`label: tr("外观")`，语言会被冻结在首次访问时——之后切换 `appearance.locale`，设置页
文案不再变化（重启才恢复）。

**约定**：登记表/模型里只存中文原文，`tr()` 只在**显示名出口**调用：

- `registry::{sections, section_label, page_groups}`（节名 / 分组名）
- `fields.rs`：`SettingItem::new(tr(spec.label))`、`description(tr(spec.hint))`、`placeholder(tr(spec.hint))`、`keywords` 里的 `section_label`

凡被 `OnceLock` / `Lazy` / `static` 缓存的数据，一律不允许在构造期调 `tr()`。

### insight 批的三个发现（决定后续批的翻译点选择）

1. **语义 label 与显示 label 常常同名**：`crates/insight/src/service/persistence.rs` 用
   `source.label` 拼 DuckDB 会话名、SQL 与存档记录（`open_global_session(&source.label)`），
   `schema_view.rs:333` 还把 `self.grade.label()` 写进导出 JSON 的 `health_level`。这些**一律不翻**。
   有的枚举已经把两者拆开（`RuleScope::label()` 显示、`RuleScope::storage_value()` 落库），
   这类才允许翻 `label()`。
2. **枚举 `label(self) -> &'static str` 是天然的显示名出口**：`ColumnKind` / `ColZone` / `EdaTab` /
   `RelKind` / `PanelTab` / `InsightScope` / `Grade` 等都在渲染期被 `.label(x.label())` 调用，
   在方法体内 `tr(...)` **不会冻结**（每次调用都重新查表），比在构造期翻译更正确。
   本批未动（需先逐枚举核证「显示 / 语义」分离），列为下一小批专项。
3. **画像类结构体字段是缓存**：`model/column_profile.rs` 的 `StatRow.label`（总行数/非空值/唯一值/
   标准差/偏度/峰度/长度范围/时间跨度/True 占比…）、`quality_scorer.rs` 的维度 `name`、
   `model/profile.rs` 的 `source_label` 都在**构造画像时**写入 entity 并长期缓存（切语言不重算）→
   构造期 `tr` 会冻结成旧语言。正确解法是「存中文原文、渲染出口翻译」，而 `tr` 只接
   `&'static str`、字段是 `String`，需要给 `crates/shared/src/i18n.rs` 增一个 `tr_dyn(&str) -> &str`
   （签名可用，因为 En 分支返回的 `'static` 值满足入参生命周期；中文分支原样返回）。
   **未做**，见 §六。


### analytics_resource 批的两个机械坑（脚本级）

1. **`use` 插进了 `//!` 模块头**：脚本的 fallback 分支按「文件头注释之后」插入 import，但
   `crates/analytics_resource/src/dialogs/archive/mod.rs`、`dialogs/tag/mod.rs` 等文件的 `//!`
   文档块很长，正则只吃掉第一行注释 → `use shared::i18n::tr;` 落进 `//!` 块中间，触发
   **E0753 expected outer doc comment**（`//!` 只能出现在 items 之前）。修法：先删掉错位行，再插到
   「第一个 `use` 之前，或 `//!` 块结束之后」。本批 32 个文件全部重插一次后 `cargo check` 通过。
   **规则**：批量脚本改 import 后，必须 `cargo check`；E0753 是这类脚本的典型签名。
2. **`tests.rs` 不在 `rel.parts` 里**：`Path.parts` 是目录 + 文件名，`crates/x/src/y/tests.rs` 的
   parts 不含 `tests`，只含 `tests.rs`。脚本原判据 `"tests" in rel.parts` 漏掉这类文件，
   `resource_view/tests.rs` 的一处测试夹具被误翻（已回滚）。判据已补 `rel.name == "tests.rs"`。

### database 批的三个判断（哪类中文不能翻）

数据源导航是「静态登记表 + 通知」两类文案混在一起，实测 95 条里 76 条是界面文案、19 条不是：

1. **`static ENTRIES` 也是冻结表**：`crates/database/src/nav/actions/registry.rs` 的
   `NavActionDescriptor.label: &'static str` 放在 `static ENTRIES` 里、由 `REG.get_or_init` 暴露，
   与 settings 的 `OnceLock` 同构 → 不在登记表处 `tr`，改在渲染出口
   `PopupMenuItem::new(tr(d.label))` / `PopupMenuItem::submenu(tr(d.label), …)`（本批 9 处）。
2. **通知文案要单独一条规则**：`self.host.notice("已刷新元数据".to_string(), cx)` 既不是字段也不是
   `.label(..)` 实参，前两类脚本都抓不到（本批补 21 处）。这类「方法 + `"中文".to_string()`」在
   同一 crate 里还可能出现在 `Err(..)` / `Some(..)` / `push(..)` 上，**不可一概包裹**。
3. **明确不翻的**：`Err("DuckDB 连接属性编辑待扩展".to_string())` 等错误诊断（进日志/断言）、
   `Some("表注释")` 等属性键、`parts.push("归属域：项目")` 等拼接片段、SQL 注释
   （`sql_gen.rs` 的 `format!("-- {qualified}：未加载到列信息…")`）。
   判断口径：**这句话会不会原样显示在界面上**，会才翻。

### scratchpad 批：内联 `mod tests` 也会被脚本命中

`crates/scratchpad/src/models.rs` 末尾有 `mod tests { … }`（内联，不在 `tests.rs`/`tests/` 目录里），
脚本按路径排除不到，把测试夹具 `label: "旧书签".to_string()` 翻成了 `tr(...)`。
后果不是测试失败（`cargo check` 不编译 `#[cfg(test)]`），而是**生产路径出现 `use shared::i18n::tr;` 却无使用者** →
`cargo check` 报 `warning: unused import: shared::i18n::tr`。已回滚该文件并复检到 0 warning。

**可操作规则**：`cargo check` 出现 `unused import: shared::i18n::tr` 就是「这一处只在测试里」的指纹，
按文件回滚即可；比按 AST 切 `#[cfg(test)]` 块便宜得多。

### notification 批：crate 缺 `shared` 依赖

`crates/notification` 原来只依赖 `gpui-kit / serde / chrono / tracing / uuid / settings / paths`，
没有 `shared` → 加 `use shared::i18n::tr;` 直接报 **E0433 cannot find module or crate `shared`**。
已补 `shared.workspace = true`（`Cargo.lock` 随之变动，`cargo check` 通过、0 warning）。

**规则**：新 crate 上 i18n 时先看 `Cargo.toml` 有没有 `shared`——`tr` 属于 `rds-shared`，
不是 `gpui-kit` 的能力。

### tr_dyn 与枚举显示名（本轮实测）

`tr_dyn` 的用法是「模型存中文原文 → 渲染出口翻译」，实例：

```rust
// crates/insight/src/workspace/view/column.rs
.child(tr_dyn(&row.label).to_string())   // StatRow.label 是 String，构造期不能 tr
```

**枚举 `label()` 不能一律在方法体内 `tr`**，实测反证（insight crate）：

| 出口 | 用途 | 结论 |
|---|---|---|
| `Grade::label()` → `schema_view.rs:333` | 写进导出 JSON `health_level` | 不翻方法体 |
| `Grade::label()` → `quality_scorer.rs:214` | 领域结果 `level`，被 `assert_eq!(qs.level, Grade::of(score).label())` 钉住 | 不翻方法体 |
| `RuleScope::label()` → `service/indexer.rs:131`、`insight_engine_internal/rules.rs:61` | 索引目录 / JSON `scope` | 不翻方法体 |
| `Grade::label()` → `view/drill.rs:481`、`view/schema.rs:62` | 界面标签 | 在**调用点** `tr(report.grade.label())` |
| `ColZone` / `EdaTab` / `RelTab` / `InsightScope` / `ColumnKind` / `SetKind` 的 `label()` | 只在 Tab / tag / badge 渲染处使用 | 调用点 `tr(x.label())`（11 处） |
| `SampleSource::label()`（`model/target.rs:94`，返回字段 `&str`） | 连接名 / 表名（用户数据） | 不翻 |

**规则**：先看 `label()` 被谁调用（`grep .label()`），**只要有一处是导出 / 落库 / 结果字符串，就只在
UI 调用点包 `tr`**，方法体保持中文原文。另注意 `crates/insight/src/workspace/view/drill.rs:193` 的
`s.label()` 是多源来源名（用户数据），属易误包点。

## 五、加文案 / 验证
- 界面新文案：`tr("中文原文")` 包裹，并**同时**在 `zh.json` 与 `en.json` 各加一条（键=中文原文，两文件键集合必须一致，`translation_zh_en_keys_are_aligned` 会挡漏译）；不要把交互文案留给组件库去“自动翻译”——组件库只翻它自己的词表。
- 批量推进的机器辅助做法（已用于 settings / workbench / editor / result_panel / insight / analytics_resource / database / scratchpad / project / notification 十批）：先补词条，再用脚本只替换「已在 en.json 里有词条」的 UI 调用位置（`.child/.label/.placeholder/.tooltip/.title/.text` + `section_label/group_label/label/hint/title/description` 字段 + `MenuItem::new` / `PopupMenuItem::{new,label}` / `Text::new`），长文案不动。**同一 crate 往往需要多遍**：① 调用位置（`.child(tr(...))`）；② 字段式（`label: tr("…").to_string()`）；③ 通知式（`.notice(tr("…").to_string())`）；④ 静态登记表在渲染出口（`PopupMenuItem::new(tr(d.label))`）。脚本 `.rds/tmp/wrap_tr_crate.py`、`wrap_to_string_labels.py`、`apply_db_notice.py`、`wrap_registry_labels.py`、`fix_tr_imports.py` 只是过程产物，不入库。
- **每批收口三件套**：`cargo check -p <crate> -j 1` 到 0 error/0 新 warning → `git commit`（代码）→ `docs/architecture/ui/i18n.md` 更新（词条数、进度、本批新坑）→ 再 commit 文档。这样任何一批出问题都能单独 revert。
- 组件库词表缺词/译错：改 `vendor/gpui-component/locales/ui.yml` 属 vendor patch，须在 `docs/architecture/dependencies/` 的私有 patch 记录里登记（参考 `core-packages-*-upgrade-assessment.md` 的 patch 清单）。
- 自测：`cargo check -p rds-shared -p rds-settings --tests`（映射测试在需要 GUI 链接的 `cargo test` 之前用 `--tests` 只做类型检查即可）；肉眼验收：切到 English 后 Dialog 按钮应显示 Cancel / OK，切回中文应显示取消 / 确定，且不需要重启。
