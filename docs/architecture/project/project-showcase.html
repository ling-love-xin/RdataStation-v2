01

为什么它不是一个「打开文件夹…」按钮

四处「看着能做、其实没兜住」的做法
常见做法现在
随手打开一个目录就算项目：下次靠记忆找路径，换机器就失联 名册 + 本体两层：全局库记「有哪些项目、最近打开、是否固定、是否移除」，.RSmeta 记「这个项目自己怎么跑」
同一个项目开两个窗口，各自写各自的库，最后不知道谁对 一个实例一个项目：打开 = 取 OS 文件锁；占用时不硬拒——「只读打开 / 仍要打开 / 取消」三选一，陈旧锁会被系统自动释放
删项目 = rm -rf，用户文件一起没了，也无法后悔 软删可找回（移出列表）+ 硬删要点名（输入项目名，红色危险按钮），且只删 .RSmeta
有草稿时点「切换项目」直接丢内容 未保存拦截三态确认；「保存并继续」先把草稿另存为项目草稿（重名自动加序号），确认后直达目标动作
02

一个项目，两处记录

两处记录各回答一个问题，谁也不许越界

▤名册 · 全局库 project_info

回答：我有哪些项目、最近打开、固定 / 已移除、显示名与描述。

  • 跨项目共享，随工作台启动即用
  • 固定置顶（is_pinned）与软删（removed_at）记在这里
  • 可写者：项目管理自己（创建 / 改名 / 固定 / 软删 / 恢复）

◱本体 · {项目}/.RSmeta/

回答：这个项目自己怎么跑——配置、连接引用、分析库、版本台账、写锁。

  • 随项目目录走，拷走项目 = 拷走全部内部状态
  • 项目偏好（默认连接）写在 config/settings.json
  • 可写者：项目视图 + 各功能模块（Query / Mock / 洞察都写这里）
{项目}/                     ← 用户文件与内部元数据同处一个目录，但删数据只动后者
├── scratchpad/  *.sql      ← 用户文件：任何操作都不碰
└── .RSmeta/                ← 本体（设置里的结构树就是它）
    ├── project.json        ← 项目信息：名称 / 描述 / 路径 / 版本
    ├── project.db          ← 项目级元数据（SQLite）
    ├── analytics.duckdb    ← 项目分析库
    ├── project.lock        ← 写锁（OS 文件锁，进程退出自动释放）
    ├── config/settings.json← 项目偏好：默认连接（U3）在这里
    └── queries/  project_metadata/
两条不变量：① 名册是「找得到」的权威、本体是「用得对」的权威——改名只改显示名与两处记录，磁盘目录名永不变；② 删除只动 .RSmeta，名册记账与用户文件是两条命。
03

三个高光

每一条都能在界面上指出来
HIGHLIGHT 1

一个实例一个项目，
但不把人堵死

写锁是 OS 文件锁：进程退出 / 崩溃自动释放，不会留下「打不开的项目」。锁被占用时不是一句拒绝，而是三选一逃生口，占用者 pid 与陈旧锁的处理方式都写在对话框里。

只读打开仍要打开取消pid 可见
HIGHLIGHT 2

危险操作三道门，
每道都能单独拦住手滑

① 只读模式写命令全部置灰（点不动且看得出原因）；② 删除数据要输入项目名；③ 只删 .RSmeta——用户文件原地不动。软删与硬删分成两个命令。

置灰输入项目名只删 .RSmeta可找回
HIGHLIGHT 3

每一类命令
只有一份口径

标题栏菜单与卡片菜单各是一份纯函数规格（顺序 / 文案 / 图标 / 可用性），渲染只按 id 挂事件：⋯ 下拉 = 右键菜单，选择器 Tab 就是键盘可达的按钮。只读置灰策略也只有一处。

规格可断言下拉 = 右键Tab 可达固定 id

危险区 · 三道门

归档 / 移出 / 删除数据，三处入口同一批命令
① 可见性门

只读模式：写命令整片置灰

点不动，且一眼看得出为什么——设置面板里「只读（写操作已禁用）」常显。

拦截层 read_only_blocked 兜底任何绕过 UI 的调用
② 确认门

删除数据：输入项目名

把「我要删的是这个」从一次点击变成一次输入；不匹配就保持打开并给提示。

按钮 danger 变体；与卡片菜单同一动作函数
③ 范围门

只删 .RSmeta

用户文件（scratchpad/、*.sql）原地不动；想连文件一起删请去系统文件管理器。

软删可找回 → 硬删才不可逆，两个命令分开
命令语义能后悔吗
归档 / 取消归档状态 active ⇄ archived，仍在名册（可筛 状态:archived）随时反向操作
移出列表软删：从最近 / 全部隐藏，磁盘不动「已移除」Tab → 恢复
删除数据硬删：删 .RSmeta 并从名册移除不能（所以要点名）

搜索与筛选

自由文本 + facet，与筛选按钮取交集
写法含义
风控自由文本：匹配名称 / 描述 / 路径（大小写不敏感）

只读模式 · 两道防线

置灰是「点不动」，拦截是「点了也没用」

①可见性：写命令置灰

  • 卡片菜单 6 项按分支置灰；标题栏菜单顶部插一条置灰说明「只读模式：写操作不可用」
  • 设置面板：名称 / 描述输入框、保存、默认连接、创建版本快照、危险区三件套全部禁用
  • 头部常显「只读（写操作已禁用）」
读命令保留：打开 · 在资源管理器中显示 · 切项目 · 关闭项目

②拦截层：守卫 + 提示

  • 写入口先过 read_only_blocked：被拦下就写提示并重绘
  • 覆盖：保存项目信息 · 归档 · 创建版本 · 默认连接 · 以及任何绕过 UI 的调用路径
  • 窗口测试固定这条语义（写 notice、不改会话、不动磁盘）
只读是「不许写」，不是「不许看、不许走」——用户永远能退出去

键盘 · 右键 · 菜单

命令入口三处，规格一份
操作入口

命令入口三处、规格一份：标题栏菜单（project_menu_entries）· 卡片 ⋯ 与右键（card_menu_entries）。需要键盘焦点的元素不用会变的 id（状态筛选按钮固定为 picker-status，否则一换筛选就丢焦点）。
