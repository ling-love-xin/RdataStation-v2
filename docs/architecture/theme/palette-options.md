### 4.2 生成与校验

- 生成：`python tools/gen_theme_packs.py` —— 从本文件 `SCHEMES` 的角色值展开 140 键 + 13 个产品角色，派生的键（button 系列、scrollbar、`base.*` light 变体、语法补充名）在脚本里显式推导。
- 校验：`python tools/audit_theme_packs.py` —— 复用 `tools/theme_audit.py` 的 schema 键集合 / 52 对 / 9 对产品 / 41 个语法名口径，逐包逐模式跑；另打印「分层强度」ΔL（信息项，用来抓按钮 hover 这类「按下去没反应」的表面）。
- 当前结果：**8 包 × 明暗全部通过**（140/140 键、主题对照 0 不达标、产品对照 0 不达标、41 个语法名 0 未覆盖、语法着色 0 不达标）。
- 分层强度里仍有 27 处 ΔL < 0.004，全部是有意为之：浅色「弹层 = 内容区」（靠阴影/描边抬升）、深色「状态栏 = chrome」（VS Code 同口径）、深色「内容区 vs chrome / 斑马行」只差 0.002–0.004（近黑墨那套为 0，页面层级全靠描边，是 §2 明说的代价）。

### 4.3 与现役资产的有意差异

`audit_theme_packs.py` 会把「现役资产里同值、候选里拉开（通道差 ≥ 4）」的组逐条列出，当前 **9 组**（8 条说明：表头文字在明暗两套各出现一次），均为有意区分：

| 现役同值的组 | 候选里的区别 | 为什么 |
| --- | --- | --- |
| `table.head.foreground` 与其余次要文字（明、暗各 1 组） | 表头文字用 `head_fg`（略深/略亮一档） | 表头要在一眼扫视里压过单元格 |
| `chart.3` 与主色 | 图表第 3 系列保留原珊瑚 `#BC5340` | 换品牌主色时，数据系列色不跟着漂 |
| `slider.background` / `switch.background` 与 `border` | 取 `input_border`（描边更实） | 控件轨道需要比分割线更明确 |
| 状态栏 / 按钮 / 分组底 / `muted.background` | 分别取 `status` / `button` / `group` / `hover` | 现役资产挤在同一个 `#F3F3F3`，候选按层次拆开 |
| `table.foot.background` 与斑马行（暗） | 表尾取 `group`（比斑马行退一档） | 表尾是汇总带，不该和行底同色 |
| 按钮 hover 与 `muted.background`（暗） | 按钮 hover 由 `head` 派生，`muted.background` 取 `hover` | 按钮是控件、muted 块是容器，层级不同 |
| **`sidebar.foreground`（暗，现役取正文 `#CCCCCC`）** | 取 `muted` | 侧栏文字明暗统一走「次要文字」；若想更接近现役，把 `gen_theme_packs.py` 里该键改成 `fg` 重跑即可（对比度仍达标） |
| `switch.thumb.background` 与 `fg_active`（暗） | 滑块取近白，激活标签略灰 | 滑块要压在 `input_border` 轨道上，必须更亮 |

## 5. 内置多主题：现在能做到哪一步

> 三条都是本机源码实测（2026-11-12），不是推测。

1. **加载端本来就支持多主题**：`crates/app/src/main.rs::load_theme_assets` 扫 `assets/themes/*.json`，把每个文件里的 `themes[]` 全部注册进 `ThemeRegistry`（`product-tokens.json` / `theme-keys.json` 除外）。所以多套主题**文件本身就能被加载**，不用改加载逻辑。
2. **切换端只有一对明暗槽**：`Theme` 只有 `light_theme` / `dark_theme` 两个字段，`Theme::change(mode)` 只按模式应用这一对（`vendor/gpui-component/src/theme/mod.rs:388-406`，注释明确“调用方换过 `light_theme`/`dark_theme` 后，即便 mode 不变，change 也会重新应用”）。装配层已按「包」补上这一层：`attach_rds_theme` 先按包取（`assets/themes/packs/<id>/theme.json`，按 `mode` 取一对、**不依赖主题名**）替换两槽，取不到才按名字回落 `"RDS Light"` / `"RDS Dark"`；缺口是“选择维度”，不是切换 API。
3. **产品 token 没有主题维度**：`assets/themes/product-tokens.json` 只有 `light` / `dark` 两个映射，按模式解析成一个全局（`crates/workbench_shell/src/product_tokens.rs:17-59`）。换第二套主题后，活动栏底色、Quick Open 组头、搜索命中底、结果集四个高亮槽**仍是珊瑚那套的值** —— 表面只换了一半，且不报错。

**结论**：内置可以，但先定两条规矩 ——

- 主题以**包**为单位：一包 = 一个 Light + 一个 Dark + 一套产品 token，不做散装单套；
- 包 **id** 对外后不能再改（设置按 id 落盘、目录按 id 找，改名等于用户配置失效）；
  包内主题**名**可以随便改：装配按 `mode` 取，不查名字。

建议节奏：内置 **2 个包**（默认 RDS + 1 个中国风），其余当可选包；要上第 3 个包之前，先把 `ProductTokenSet` 升级成“按包解析”，否则每多一包就多一处“看着只换了一半”的静默不一致。

> 这一节说的「包」已经按 §4.1 生成好并接进装配层（8 个包，运行时副本在 `assets/themes/packs/<id>/`；
> 设置页只开 `rds` 与 `qinghua` 两档）。

**怎么切换（默认完全不变）**

- 常态入口：设置页「外观 → 主题方案」，落盘 `appearance.theme_pack`，默认 `rds`（= 现役主题）。
  内置两档：`rds`（RDS 经典）、`qinghua`（青花）；其余 6 包留在 `assets/themes/packs/` 不提供入口。
- 临时覆盖：环境变量 `RDS_THEME_PACK=<包 id>`，优先级高于设置值、不落盘（试色 / CI 用）。
- 代码：值域 `crates/settings/src/theme_pack.rs::BUILTIN`（登记表选项与写入校验同源）；
  装配 `crates/app/src/theme_pack.rs`（按 `mode` 取一对，不依赖主题名）+ `main.rs::apply_theme_pack_state`；
  变更出口 `settings::install_theme_pack_sink`（设置页改完即时重装「主题 + 产品 token」）。
- 为什么必须「主题 + 产品 token 一起换」：产品 token 只按明暗模式解析、没有主题维度，
  只换主题会让活动栏底色 / Quick Open 组头 / 搜索命中底 / 结果集四槽残留默认珊瑚包的值。
- 自检：`cargo test -p rds-settings theme_pack`（值域：默认 `rds`、未登记 id 被拒）+
  `cargo test -p rds-app theme_pack`（每个出厂包都能读出 Light+Dark、字号 16、140 键、13 个产品角色）。
- **还没做的**：第 3 个包之前把 `ProductTokenSet` 升级为“按包解析”；真机截图核验未做。


## 6. 选型建议

**现代中性**：
1. **默认 → 珊瑚石墨**：现役资产就是它的近似版，迁移只需微调，品牌资产零改动。
2. **要「数据库工具」专业感 → 石板深蓝**：与 DataGrip / TablePlus 的心智一致，注意 `info` 已改成青，别和主色蓝混用。
3. **以报表 / EDA / 长文阅读为主 → 暖纸赭石**：暖底对细网格更宽容，但截图、图表色需一并偏暖，否则冷暖打架。
4. **要品牌差异化且偏「洞察」气质 → 松林青绿**：主色与成功色同族，必须保持该套配色表里的明度差，否则在深底上会读成同一个绿。
5. **低光 / OLED / 无障碍 → 近黑墨**：暗色纯黑省电，亮色是高对比版；代价是 chrome 与内容区无灰度差，层级全靠描边。

**中国风**：
6. **内置首选 → 青花**：蓝白最克制，与“数据库工作台”的冷静气质不冲突；info 换青瓷绿后语义仍清楚。
7. **要辨识度 → 朱砂**：一眼记住，但朱砂与危险红同族，danger 已压到绛色；表单校验、删除确认这类场景要真机确认能分辨。
8. **要“深色为主 + 金线点睛” → 墨金**：warning 已改成赭橙；金只做强调，不要铺大面积（大面积金色会压掉数据本身的颜色区分度）。
9. **不建议一次内置 8 套**：每多一包 QA 成本 ×N（140 键 × 2 模式 + 41 个语法名 + 11 个产品角色 + 真机截图），且会稀释品牌识别；先上 2 包，其余留在可选包。

## 7. 验证与边界

- 两层校验：色卡页按**角色口径**验 58 项/模式（正文、次要文字、表头、主色三态、语义四色三态、图表 5 系列、涨跌、产品槽 6 个、选中态合成、语法 6 个代表名）；`audit_theme_packs.py` 按**包文件口径**再验 140/140 覆盖、52 对主题对比度、9 对产品对比度、41 个语法名覆盖与着色对比度。
