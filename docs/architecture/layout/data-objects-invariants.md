# 数据对象模块铁律

**本文是「数据对象」模块规则的唯一出处。** 代码行为与本文不一致时，先改本文、再改代码；
不允许代码在无记载的情况下偏离。变更走文末「变更记录」。

适用范围：`crates/workbench/src/panels/data_objects_tab.rs`、
`crates/workbench/src/components/data_objects/`、`crates/workbench/src/components/data_objects_load.rs`
（面板本体与加源），以及为它提供对象的三处数据源：分析库表（`crates/analytics_resource`）、
结果集临时表（`crates/engine` / `crates/editor`）、文件（`crates/engine::duckdb::file_view`）。

---

## A. 定位

1. **唯一职责**：挑分析对象，交给下游用（SQL 编辑器 / 洞察 / mock / 导出）。它不是资产库的第二个入口。
2. **可选中即可查**：凡出现在面板里的对象，都必须能在 SQL 编辑器里直接查到。每个**可分析对象**
   （叶子 / 表 / 文件）带「执行通道 + 实际引用名」，不靠用户猜怎么写 SQL。
   源段一级行（连接 / 挂载的库 / 底座）**不给引用名**（`sql_ref = None`）——它们的表要写
   `别名.schema.表`，到叶子才拼得出（见第 4 / 37 条）。
3. **只有三类对象**：源 / 表 / 文件。**分组与对象类别一一对应**：清单只有三段，
   业务身份（资产 / 未登记 / 结果集 / 载入 / 库表 / 底座 / 挂载三态 / 已加载）一律是行内小标，
   不再单独成段。不设第四类，也不加「其他资产（不可分析）」段。

| 对象 | 执行通道 | SQL 里的引用名 |
|---|---|---|
| 临时表 `tmp_q_*` | 进程单例（表本就在里面） | `tmp_q_xxx` |
| 项目分析库持久表 | 底座 `analytics` 常挂在分析实例上 | 裸名（底座在搜索路径上）；显式 `analytics.main.<表>` 仍可达 |
| 全局分析库表 | 底座 `rds_global` 同上 | 裸名；显式 `rds_global.main.<表>` 仍可达 |
| 源库表 | 源库直连（或加速/联邦挂载后） | 按连接口径 |
| 文件（已归档 / 加源） | 进程单例里的 `f_*` 视图，或文件源挂载 | `f_xxx` |

依据：`engine/src/analysis/channel.rs`（四条执行面）、`analysis/global.rs`（全局库方案 B：短命会话 + 只读挂载）、
`analysis/mount.rs`（别名规则）、`analysis/persistent.rs::list_persistent_tables`（列清单不需要挂载）。

## B. 源

4. 源 = **挂进分析实例的 catalog**：外部来源（连接、URL、数据库文件）**加两个底座**
   （`analytics` / `rds_global`）。底座**占源段**（2026-11-27 更正：2026-11-24 的「不占源段」口径
   废止，`objects()` 一直按源段出行）——它是常驻挂载、只能「会话级遮蔽」（`ToggleBase` 不
   `DETACH`，见第 42 条），它里面的表按第 8 条在表段呈现（「资产 vN / 未登记（· 全局）」）。
   **源段按「别名 → schema → 表 / 视图」成树**（2026-11-25 定层）：别名就是挂载后的 catalog，也是
   SQL 里的引用名；不套「表 / 视图」类别文件夹（第 37 条）。视觉与结构语言借数据库导航
   （表行形态 / 缩进 / 展开箭头），但**不共用导航的树与实体**（`NavView` / `NavHost` 不碰）。
   - **判据是两半对账**（2026-11-25 定，取代 2026-11-24 的「注册标记」口径）：
     意图 = 项目库 `analysis_sources` 的登记行（规格见 `analysis-sources-spec.md`），
     事实 = 进程实例的 `duckdb_databases()`。按 `alias` 匹配得三态：
     **已挂载 · 项目级**（登记 ∩ 实例）/ **已挂载 · 会话级**（实例有、登记无 → 行写「会话级 · 未登记」）/
     **未挂载 · 项目级**（登记有、实例无 → 行写「未挂载」）。
     另有一种不在三态里的行：**已连接、没挂、也没登记**（只是「可挂的源」）→ 行写「未挂载」，
     **不带scope**——它还没成为登记过的项目源，替用户说「项目级」等于替人做主。
   - 源组还收两类行（2026-11-25 用户口径）：**`已登记`**——驱动没有 ATTACH 能力（`use_duckdb_fed`
     为空）但已在项目分析源表登记：不给挂载（永远挂不上），**只在该连接于导航栏是活连接时可展开选表**
     （选中的表靠右键「载入临时表 / 项目归档」进 DuckDB，产物是表段行，不是 catalog）；
     以及**`reg:<id>`**——登记指向的连接已不在清单里，仍出一行「未挂载 · 项目级」备查。
   - **挂载事实只认分析实例**（2026-11-26 定）：判据是 `duckdb_databases()` 里那个 catalog 在不在，
     而会话本身只有一份真值——`AnalysisInstance` 里按 owner 存（`session_for_owner` / `ensure_session`），
     面板与执行器读的是同一个（旧 `SESSIONS` 门面缓存已退役，见 `analysis-instance-sessions.md` §7）。
     联邦与文件库各占一个 catalog、出行；**加速档（`rds_src`）是执行通道，不出行**（有且只有一个对象），
     它只让连接行写「已挂载」。
     **事实侧在面板里分三条取**（2026-11-27 记实）：联邦 / 分析会话的 `mounted_sources()`
     （`session_sources`）、加速档的 `mounted_conns()`（`accel_sources`，按 conn_id）、
     文件库的 `shared.loaded_files`（按路径）。三条各管一种挂载方式，**不合并**成一个判据函数——
     合并就会把「能连上」误当「已 ATTACH」（文档早先记过这起误报）。
   - **会话的角色看它挂着什么，不看 label**（2026-11-26）：`ensure_session` 对同一 owner 是 1:1 复用，
     label 只在**第一个**建会话的路径写一次——先开全局分析库（`ensure_session(owner, "全局分析")`）、
     之后联邦执行复用它，那条会话的 label 就停在「全局分析」。所以「算不算分析会话、进不进源段」的判据是
     `AnalysisInstance::is_analysis_session`：挂着源，且 owner 不是 `process`（进程面会话）也不是
     `accel:<连接 id>`（加速档挂 `rds_src` 但不占源段）。`label` 只当展示名。
   - 挂载入口（2026-11-26 统一到实例）：联邦 = `instance.ensure_session(owner, "联邦")` 后调
     返回的 `AnalysisSession::mount_sources`；本地加速 = `accel::ensure_on_instance`；数据库文件 =
     `file_view::load_database_as` / `load_database_global`。
     卸载 = `USE memory` → `DETACH`（默认 catalog 指向该别名时必须先 `USE memory`）。
     **workbench 侧的网络连接挂载入口 2026-11-25 补齐**（`data_objects_load::mount_network_source`
     / `unmount_network_source`，右键「挂载 / 卸载」），第 37 条记的「`ensure_session` 零调用」缺口已关；
     「登记为项目源 / 移除登记」是**意图侧**的独立菜单项（`register_connection_source` / `unregister_source`），
     不与挂载合并成一步——两件事分开，用户才看得懂「未挂载 · 项目级」这一格。
     **加速档的 ATTACH 别名是固定常量 `accel::SOURCE_ALIAS = "rds_src"`**，不按源命名——
     登记行里的 `alias` 对它只是期望名 / 展示名。
   - **没有挂载的源不可展开**：未挂载 = 没有可列的表，右键给「挂载」（源行行尾只留这一个动作位，
     见第 42 条），行首不给展开指示。连接此刻没连上也算「未挂载」，行上写清原因（「未连接」）。
   - 会话级加源**不入库**（切项目随 `f_*` / 会话一起清）；项目级登记跟着项目走。
     源清单此前全仓无处可住（第 6 条更正），`analysis_sources` 是**第一次落地**，不是第二份真相。
   - SQLite / `.duckdb` 这类**文件库也归源段**：未挂载给「挂载」，挂上后（catalog 进实例）才展开选表。
     **挂没挂的判据与网路连接同一条**（2026-11-25 统一）：别名在不在 `duckdb_databases()`。
     `loaded_files` 只当**清场凭据**（切项目要卸哪些路径），不再当判据——两处判据并存正是
     「能连上 ≠ 已 ATTACH」那类误报的来源；挂上之后该路径由别名行代表，不再单出一行「文件库」。
   - 源段排位（`Object::rank()`，2026-11-27 拍板）：会话源(0) → 底座(1) → 文件库(2) →
     连接 / 登记行(3)，同档按名字。底座原先与连接同档（`analytics` 按字符序落在中文连接名
     之前），这一刀给它单独一档，「底座紧随会话」才真正落到排序上。
5. 加源 = 对分析实例做外部追加。只接三类：库表（标记所属连接）、能直接读的文件（外部 / 草稿）、数据库文件。
6. 加源两档 scope：**项目级**（写进项目配置，重开自动重挂）、**会话级**（只活本次，切项目清）。UI 必须显式让用户选。
   - 库表：`use_duckdb_fed` 不是「选表意图」而是**能力 / 加速开关**（三态，见第 42 条）：
     有值 = 这条连接可被 DuckDB 直连；**三个写入口**（连接对话框保存 / 面板「加源」/
     右键「登记为项目源」）都保证 `analysis_sources` 有一行（**有值即登记**，
     `data_objects_load::ensure_registration` 幂等写入，2026-11-26）；`Some(true)` 再额外表示已开本地加速。
     登记行是项目级 scope 的载体（切项目还在），与运行态的「挂了没挂」是两件事。
     **「移除登记」是显式撤销**（2026-11-27 补）：`unregister_source` 只删行、不动开关，删完
     **不会**在启动时被自动补回——所以**不做进项目对账**。此时面板照列该连接（`Some(_)` 仍在
     清单里），小标「未挂载」不带 scope（第 4 条第四种行）。历史数据 / 播种绕过写入口留下的
     未登记连接，口径同上，不按「违反有值即登记」处理。
   - 文件：**会话级 = `f_*` 按需视图**（切项目清）；**项目级 = 归档成 `copy` 快照**（生成资产、跟着项目走、只读带版本）。
     **源清单不归资源模块**（2026-11-25 更正事实）：资源模块只有**文件 / 分析库表**两档
     （`analytics_resource/src/model/kind.rs:45` 的 `ArchiveKind::{File, AnalyticsTable}`，外加一个
     不写入的兼容档 `TableRef`），**没有「源」这一类**；全仓也没有第二处持有源清单（连接清单在
     `store` 的 `connections` + 导航视图，`use_duckdb_fed` 只是按项目存的三态开关
     （`Option<bool>`：`None` 不可直连 / `Some(false)` 可直连未加速 / `Some(true)` 已开加速）。
     源清单 2026-11-25 起落在项目库 `analysis_sources`（规格见 `analysis-sources-spec.md`）——
     这是**第一次落地**，不是「再造一份」。
7. 凭据只引用既有连接，源配置里不另存；缺扩展（httpfs 等）给「去插件管理」的路，禁止静默失败。

## C. 表

8. 表段 = **库里现有的表**，三种身份同段、靠小标区分：资产当前版本（表型，`资产 vN`）、
   库里有但未登记的表（`未登记`，全局那份写 `未登记 · 全局`）、临时结果集（`结果集`）、
   载入副本（`载入`，见第 12 / 35 条）。段内次序由 `Object::rank()` 定，三档：
   资产(0) → 未登记 / 落库 / 自建 / 全局(1) → 结果集 / 载入(2)；同档按名字。
   「未登记」这一格的两种来路**同小标、靠副标题分**（2026-11-27）：`res_` 落库的表写
   「结果集落库 · 可删除释放空间」，项目自建表写「项目自建 · 未登记」——不设第四类小标：
   小标列预算 44px（+ 12 间距 = `PILL_COL_PX` 56，第 39 条），再加字会先挤掉通道列。
9. 未登记的表**留在表段**，标「未登记」；右键「登记为资产」后小标变 `资产 vN`，不搬行。
   不再单列「未登记」段（2026-11-24 合并：业务身份不是形态）。
10. 「登记为资产」= 给**已存在的表**写一条资产行：不搬数据、不涨内容版本；若这张表已是某资产的当前版本，
    直接定位到那条资产，不造第二条。
11. 「升级为资产」= 写成项目分析库的持久表 + 登记成表型资产，两步不可分（只写表不登记 = 半截状态，禁止）。
    只对临时结果集（`tmp_q_`）开放。
12. 临时表只收两种：结果集 `tmp_q_`、载入 `tmp_l_`（口径见第 35 条）；洞察取样 `tmp_i_`、
    mock 产物 `tmp_m_`、插件产物 `tmp_p_` **都不进面板**（抽取的样 / 各模块的生成物，不是分析链路的输入）。
    临时表**不单独成段**：落在表段，小标分别是「结果集」「载入」、状态列写「会话级」（寿命靠状态字，不靠段）。
    工具栏「清理临时对象」的范围**就是这两种**（`tmp_q_` + `tmp_l_`）：它们都是「删了要重跑 / 重新载入才有」
    的占用；`tmp_i_` / mock 归各自模块管，从这里删会让它们的登记指向空表。载入档**只能清理、不能升级**。
    清理有**两种粒度**，不可互相替代：工具栏那颗是**全清**（清单里所有临时表一起删）；行右键「清理这张表…」
    是**单行清理**（只删这一张，范围同样限于第 12 条这两种）。用户常常只想丢掉一份载入副本，
    不该为此把别人的结果集一起清掉；反过来，单行清理也不许顺手清别的行。两者都过确认框，
    文案都要说清「删了要重跑 / 重新载入才有」。
13. 资产一律只读、带版本；分析只取当前版本。`res_` / `tmp_` 是内部标识，不是显示名；
    `f_*` 例外——文件视图行的显示名就是视图名本身（它同时是 SQL 引用名，见第 29 条）。

## D. 文件

14. 进文件分组的门槛只有一个：`structured`（= 能不能被 DuckDB 当表读；唯一来源
    `resource_host::is_structured_payload` → `engine::duckdb::file_reader_function`）。
    csv / parquet / excel / json 进；sql / py / md 等一律不进。
15. 取数模式只有两种，复用既有的 `payload_mode`，不造第三种：
    - `copy` = **快照**：读只读副本，随版本冻结，外部怎么改都不影响结果；
    - `reference` = **按需**：读源位置，源变了结果就变。
16. 外部文件默认按需（`f_*` 视图不物化）；想固定就存成 `copy` 快照。
    「由用户确定」= 加源两档时选 copy / reference，或对外部文件点「存为快照」。
17. 快照读的是**当前版本副本**；要用某一历史版本的数据，走文件行上的「用 vN 分析」二级入口，
    不把历史版本平铺进清单。
18. 数据库文件（`.db` / `.duckdb`）归**源**不归文件：以「挂载库」形态出现并展开其中的表
    （`file_view::is_database_file` / `load_database_global`）。
19. 草稿里的结构化文件**可以「加源」直接按需参与分析**（2026-11-18 口径），不强制先存快照。

## E. 与其他模块的交互（一律右键）

20. **洞察**：与数据库导航栏同一套取样口径（`SampleSource`），不另起第二套。
21. **mock**：只输出对象结构（schema），产物不进面板。
22. **草稿 / 导出**：同一条导出通道，两个目的地——草稿 = `{项目}/scratchpad/`（项目内可见目录，
    `scratchpad::MODULE_DIR_NAME`），导出 = 系统文件对话框任选路径。两者都不登记资产。
23. **资源模块的「归档」**= 资产转只读、让对象"有身份"，是资产库的唯一入口；
    它与第 35 条的「归档到分析库」（源库表 → 项目分析库持久表）**不是一件事**，
    界面文案必须带目的地或宾语（「归档到分析库…」／「归档后只读」），禁止两者都用光秃秃的「归档」。
24. 导出格式只收 DuckDB 原生：csv / parquet / json。xlsx 需插件，不做。
25. 写盘类动作（导出 / 保存草稿 / 落库）一律走 worker + 状态栏回执，不在渲染或事件路径上写库。

## F. 生命周期与清场

26. 切项目要清：会话级加源（连接 + 文件视图）、`tmp_q_` 结果集、`project_host` 清场漏掉的 `f_*` 视图。
27. 不清：项目分析库 / 全局分析库里的表、任何资产（含全局资产）、项目级加源。
28. 属于全局的不能被清——全局库里只放资产，没有临时表。

## G. 表达与渲染

29. 显示名与实际引用名**分开承担**（第 2 条要落地；2026-11-27 按实现改写）：
    - `res_` 落库表：显示名去掉 `res_` 与末尾 14 位时间戳，写成 `<源> · 2026-11-15 10:30:00`
      （`source_picker::persistent_table_label`）；引用名仍是库里的原名。
    - 结果集 / 载入：显示名去 `tmp_q_` / `tmp_l_` 前缀，引用名是 `tmp_q_*` / `tmp_l_*` 原名。
    - `f_*` 文件视图：显示名**就是**视图名（`f_<ascii 小写>`），因为它同时是引用名；
      中文会被折成下划线（已知代价，原路径写在副标题里）。
30. 同一张表可能在源段与表段各出现一次，必须用小标区分：源段**叶子**（`srctable:`）写 `库表`、
    表段写 `资产 vN`；源段**一级行**写挂载三态（`已挂载 · 项目级` / `已挂载 · 会话级` /
    `未挂载 · 项目级` / 不带 scope 的 `未挂载`）。不许靠名字猜。
31. 非结构化资产不得表述为"能力缺失 / 不可分析"，要写清原因：**这类文件不是数据**。
32. 面板多选 = 工作集，只做"勾选下发"，不改变对象本体；软上限 8 只提示不硬拦。
33. 视图纪律照旧：渲染期零 I/O、禁裸色值、禁手搓控件（走 gpui-kit）、改状态后 `window.refresh()`。

## H. 取数方式与动作名

34. **两个轴分开说，不许混成一句话。**
    - **复制轴**（数据怎么进 DuckDB）：
      `直查` = `ATTACH '<dsn>' AS 别名 (TYPE mysql|postgres|sqlite|oracle_scanner, READ_ONLY)`，
      scanner 扩展每次查询回源、零拷贝（`.duckdb` 文件走内核自带 `ATTACH`，不装扩展）；
      `复制` = 物化，把值拉进 DuckDB 落成一张表（`engine::analysis::materialize`）。
    - **寿命轴**（复制品活多久）：`归档` = 落项目分析库 `.RSmeta/analytics.duckdb`，持久；
      `载入` = 落 `memory.<表>`，随会话 / 进程消失。
    判据只有一处：`AccelKind::{extension, attach_type}`（有 scanner 扩展或原生 `.duckdb` → 可直查）。
    **禁止**用 `AccelKind::has_federable_extension` 判"能不能挂文件库"——它对 `duckdb` 返回 `false`
    （文件源本来就不要扩展，那组门控只给 Secret 注册用）。
    **这两个轴是动作语义，不落成行上的小标**（2026-11-24 定案）：凡是挂进分析实例的源，此刻都是
    `ATTACH` 的零拷贝直查；「复制」是用户按需点出来的动作（归档 / 载入各复制一份），不是连接的属性。
    给每行钉一个「直查 / 复制」只会在每行重复写「直查」，没有新信息；真要有信息量的是
    **挂没挂**——那由状态字承担（「未连接」/「未挂载 · ……可展开选表」）。

35. **两个动作名固定，菜单文案必须带目的地**（禁止只写「归档」「载入」）：
    - 右键「**归档到分析库…**」：写项目分析库持久表 + 登记表型资产，两步不可分（与第 11 条同口径，
      只是入口从结果集换成源库表）；默认表名 `<源>_<表>`，撞名在对话框里改。
    - 右键「**载入内存…**」：写 `memory.tmp_l_<源>_<表>_<时间戳>`，名字走 `generate_unique_name`
      （新来源档 `TempTableSource::Load`）——两个源都有 `orders` 也不撞名；随会话 / 进程消失，
      **不登记、不可升级为资产**（第 11 条只给 `tmp_q_`）、不进资产视野。
    - 两者都是写库动作：一律 worker + 状态栏回执（第 25 条），不在渲染 / 事件路径上做。
    - **入口只在已挂进分析实例的源上**（源段叶子：`session:` 会话行、`conn:` 连接行
      （加速档与文件库挂上后都从这条行展开）、`fileview:` 库文件行）。裸连接（还没挂）
      的表**不提供**这两个动作——路径是先在连接上开「本地加速」或联邦，挂上之后再归档 / 载入。
      这不是缺口而是口径：一个菜单动作只做一件事，挂载是用户可见的一步（源段会多一行），
      **不得**由归档 / 载入隐式替用户建会话、挂源、占内存。

36. 「**分析**」不作动作名。它是领域词（分析库 / 分析实例 / 资产分析）：归档、载入、洞察、mock
    都"为了分析"，用它当动词就分不出落点与寿命。界面动词只允许：归档到分析库 / 载入内存 /
    登记 / 升级 / 挂载 / 卸载 / 导出 / 存到草稿 / 存为快照
    （第 17 条的「用 vN 分析…」是固定入口名，不作新动词）。

37. **生产面在导航栏，消费面在源段**：
    - 导航栏（`crates/database::nav_view`）= **生产面**：浏览源库全貌（catalog → schema → 类别文件夹）、
      跑 DDL、把连接注册成分析源、**开本地加速 / 联邦把源挂进分析实例**；
    - 数据对象源段 = **消费面**：只列**分析实例此刻能查到**的对象；「归档到分析库…」「载入内存…」
      的入口都落在源段的**已挂载叶子**上（第 35 条）。
    - 两者**共用连接清单与 `NavigatorService`**（归档前选表用的就是它），
      **但不共用树**：源段是**分析实例视角的「别名 → schema → 表 / 视图」**，
      不带类别文件夹、不带 DDL（2026-11-25 更正措辞：原文「扁平」会被读成没有 schema 层，
      而挂载后的引用本就是 `别名.schema.表`，别名即 catalog；见第 4 条）。
      也**不共用导航的实体**：`NavView` / `NavHost` 一行代码都不碰。
    - 推论：源段连接行的叶子必须以分析实例视角列举（会话源走
      `federation::session::list_tables_for`；连接行走
      `AnalysisInstance::list_mounted_tables_for_conn`（加速档与文件库都按 `alias_for_conn` 取，
      别名可以是让位后的 `rds_src_2`）；没有连接身份的文件库行走
      `file_view::list_tables_global`）；
      `NavigatorService` 直连内省只用于**归档前选表**，不作叶子来源。
    - 导航栏**不给**「归档到分析库 / 载入内存」：它只到「挂载」为止。归档 / 载入 是消费面动作，
      必须先有分析实例视角的源表才知道自己在搬什么。

38. **行上状态只放短码，全文去属性窗口**（2026-11-24，按实测定的口径）：
    能用 → 寿命（外部 / 会话级 / 项目持久 / 受管）；不能用 → **原因的第一段**，超过 6 字退化成「失败」
    （`Object::availability_chip()`）。状态格钉 `max_w(96px)` + `overflow_hidden` + `text_ellipsis` 兜底；
    整句（`Object::availability_text()`）只在右键「属性…」窗口里出现。
    依据是量出来的，不是审美：整句 30 字在 12px 字号下 **209px**，而面板 380px 宽时状态格下限位只有 40px
    ——整句会把状态块顶到行外 25px（300px 宽时 105px），连带把行尾按钮挤出可视区，同时把名字压成 0。
    数由 `panels/data_objects_tab/layout_probe.rs`（headless 真窗口、真排版）产出，用例里断言
    「状态块右缘 ≤ 行右缘」。同一份测量还定了另一条事实：**名字可用宽 = 面板宽 − 290px**
    （内距 + 展开位 + 图标 + 各 gap + 小标 + 通道 + 状态 + 行尾按钮实测总和），作为后续「丢列 / 走马灯」的判据。

39. **面板一窄就按预算丢列，顺序不许反**（`components/data_objects/layout.rs`，判据全在纯函数里）：
    - 判档只用一个数：**行可用宽**（在 prepaint 量到面板真实宽度，写进 keyed state，下一帧生效；
      首帧量不到按全列画——宁可第一帧挤，也不先极简再跳回来）。
    - 三档：`Full`（宽 ≥ 410）/ `DropChannel`（≥ 318，丢**执行通道**列，名字吃回 92px = 列 80 + 它的
      一个 `gap_3` 12）/ `DropChannelAndPill`（< 318，再丢**小标**，再吃回 56px = 最宽小标 44 + gap 12）。
      阈值由「名字至少留 120px ≈ 14 字」反算，不是拍脑袋的数：`410 = 290 + 120`、`318 = 198 + 120`。
    - **丢列省下的是「列 + 它那份间距」**：只减列宽会算乐观 12px——第一版就这么错了，
      被「260 档名字实测 111 vs 预算 94」的断言抓出来。`PILL_COL_PX` 取最宽档（44）而不是 `载入`（37），
      所以 `name_space` 是**上限**：真实行可能窄十来像素，但绝不会更宽。
    - 顺序：**先通道、再小标**。小标是「不靠名字猜身份」的唯一判据（第 30 条），能留就留；
      执行通道信息在属性窗口里有整份（第 38 条那一格同理）。
    - 写死一条校准：`layout_probe` 断言「行宽 − 名字宽 = `ROW_CHROME_PX`（±2px）」。布局常量一漂，
      用例就红——预算表与真排版不许各说各话。

40. **名字放不下才走马灯，而且只在鼠标停住那一行滚**（`layout::should_marquee` / `marquee_offset`）：
    - 触发要两个**实测**数：名字格**逐行**量到的实际宽（prepaint 写 keyed state）+ 名字按同字体
      同字号 shaping 出来的自然宽；`文字宽 > 格子宽 + 0.5` 才滚。缺一个就会变成「短名也在滚」或
      「长名还在被截」。逐行量而不是拿 `name_space` 推：行尾按钮数随行的可点性变化
      （源连接行没有勾选钮，同宽面板里名字格不等宽——长状态行 300 档实测 name=200 vs 151）。
    - 只给 hover 那一行挂动画（`on_hover` 记 key，状态没变不 notify）。常驻滚动会让整张清单每帧重绘。
    - 文字按**自然宽**排（`flex_none` 不许压缩），外层照旧裁切，动画只挪裁切窗口——
      不是把字压扁。位移上限 = `自然宽 − 格子宽`，两端各停 18%，中段 smoothstep。
    - 真机依据（`layout_probe::marquee_runs_only_on_the_hovered_row_that_does_not_fit`）：
      260 档格子 111.0 / 内层 210.0 / 起点 x=36.0，时钟推 1.2s 后 x=-36.0（位移 72 ≈ 公式 72.7）；
      680 档 hover 后**不出现**走马灯。

41. **面板骨架与兄弟面板同一套：动作在面板工具栏里，计数在底部状态栏**（2026-11-25 用户口径）：
    - `toolbar_buttons()` 返回 `None`——「加源 / 存快照」长在面板自己的工具栏里，**不上 Dock 标题栏**。
      兄弟面板（资产库 `ResourcePanelTab`）原话就是「模块内部已有工具栏，Dock 标题栏只做容器管理」；
      标题栏里有的 tab 有按钮、有的没有，横向也对不齐。
    - 工具栏 = 面板第一行，高 `ui::PANEL_HEADER_HEIGHT`（2.25rem = 36px，与数据库导航 / 编辑器 /
      洞察 / 资产库头行同一档），`px_3`（12px）+ `gap_1`，底 `HAIRLINE`。32 是「面板内第二行」
      那一档（资产库的面板内工具条），夹在一排 36 的头行里横向一眼就差 4px。
    - 行内四个控件（搜索框 / 加源 / 存快照 / ⓘ）**同高 24**（Small 档）。为什么不是 26 / 28：

    - 面板最窄一档（`RowTier::DropChannelAndPill`）按钮退成纯图标（`icon_only`），tooltip 保留

42. **源段：叶子行零按钮；源行只留「挂载 / 卸载」这一个动作位**（2026-11-25 用户口径）：
    - **叶子行（表 / 视图）**：行 = 缩进位 + 展开位 + 图标 + 名字 + 来源/类型副标（+ `≈N`），
      **行尾没有任何按钮**（不摆「选用 / 已选」这类）；
      「选入工作集 / 移除」、复制引用名、归档到分析库…、载入内存…、洞察取样… 全部在右键菜单。
    - **源行（树根 = 连接 / 库文件）**：行尾只留**一个动作位**——
      - 有 ATTACH 能力：显示「挂载 / 卸载」（= 启用 / 关闭它在联邦库里的 catalog；未挂载时给「挂载」，挂上后给「卸载」）；
      - 无 ATTACH 能力（开关为空、但已在项目分析源表登记）：不给挂载动作，行尾为空；
      - 文件库：同「挂载 / 卸载」。
    - 除这一个动作位之外，源行上的属性 / 改名 / 登记 / 移除登记仍走右键菜单。
    - 理由：源行是"源的开关"，一进一出必须一眼可做；叶子行是"选数据"，动作多且低频，
      行尾按钮要么挤名字、要么变成第二套交互。源段已是三层树（第 4 条），每层 `TREE_INDENT`
      再加 14px，窄面板（`RowTier::DropChannelAndPill`，< 318px）下名字只剩 120px 上下。
    - **加速档不触发源段行，但不再是「不存在」**（2026-11-26 更正）：加速是"一条 ATTACH + 固定
      catalog `rds_src`、一次一个库"，只在执行面存在，**不产生源段行**；但 `use_duckdb_fed` 有值的连接
      **必须**在 `analysis_sources` 里有一行（有值即登记），且加速档挂上后连接行写「已挂载」
      （判据是 `instance.mounted_conns()`）。旧口径「不进 `analysis_sources`、不算已挂载」自本轮废止。
      **会话侧同一口径**（2026-11-27）：加速档挂在 `data_objects` 那条会话上，会以 `session:` 行同形
      出现在 `session_sources` 里（owner 不是 `accel:<id>`，`is_analysis_session` 拦不住它）；
      `objects()` 判源时按 `mounted_conns()` 的**实际别名**（`rds_src` / 冲突让位的 `rds_src_2`）
      把它摘掉——连接行写「已挂载」、叶子可展开（走 `alias_for_conn`），源段不多一行。
    - **文件库行同样有这颗动作位**（2026-11-27 补齐）：挂上来的 `.db` / `.duckdb` 行走
      `SourceAction::ToggleMount { path: Some(本体路径), mounted: true }`，文案「卸载」，
      卸载走 `unmount_file_database`（与右键菜单同一份判据）。
    - **已完成（2026-11-26）**：源段叶子的 `data-object-srctable-pick-<key>`（「选用 / 已选」）已删；
      `objects()` 的 `accel:` 行与 `SourceRef::Accel` 死分支已删（刀 4，`eec47963`）。
      表段行上给 `can_pick()` 对象的 `data-object-pick-<key>`（`toggle_picked`）**不在此列**，仍保留。
