# 健壮性调整单（按模块 · 可直接交给 AI 会话）

> **本文不是路线图，是工单。** 每一条（`H-x.y`）都能独立交给一个会话做完并验收。
> 目标不是「和同类项目对齐功能」，而是让已有的东西**不崩、不静默、可复现、可回归、可诊断** ——
> 并把我方差异点（mock / 分析存档 / 洞察 / 联邦 / 插件）做成别人抄不走的东西。

## 0. 怎么用

把下面这段连同要做的编号一起丢给会话：

```text
你负责 H-<x.y>。先读 docs/architecture/hardening-plan.md 的 §1 通用约定与 H-<x.y> 整节，
再读该节列出的文件，做完按 §1 的规矩交一个提交，并把验收命令的真实输出贴出来。
不许顺手做别的编号。
```

规矩：

1. **一条编号一个提交**（跨文件、跨 crate 也算一条，但别把两条编号塞进一个提交）。
2. 开工前先**实测**（跑命令 / 读文件），区分「已核实」与「未核实」；本文档给的数字都标了出处。
3. 验收命令**必须真跑过**；跑不了（缺 Docker / 缺真库 / 缺目标平台）要写明原因与复现条件。
4. **只 `git add` 自己碰过的路径**：本仓常有别的线在途改动（`docs/architecture/connection/*`、`crates/workbench/*`、`crates/app/*` 等）。
5. 不改别人的口径：要改协议 / 状态机 / 设计文档，先在提交信息里说明理由，并同步对应 `docs/architecture/*`。

## 1. 通用约定

**「健壮」在本仓的五个判据**（调整单里的每一项都至少改善其中一条）：

| 判据 | 含义 | 反例（本仓真实出现过） |
| --- | --- | --- |
| 不崩 | 边界输入、极端尺寸、断线与取消、并发 | 恰好 1000 行时「分段续取」永不终止地追加重复行（`editor_exec.rs` 旧路径） |
| 不静默 | 失败说得出为什么，降级要有可见理由 | 用户规则静默不生效（v1 的 `insight` 注册表漏调用）；`infer_type` 把日期静默落成文本 |
| 可复现 | 同输入同输出；有指纹 / 版本 / 日志 | mock 生成依赖进程内随机；存档只留文件不留「怎么来的」 |
| 可回归 | 有测试或基线守住，不靠人记 | 插件崩溃后「不静默重连」只有口径、没有 UI 侧测试 |
| 可诊断 | 出问题能定位到具体那一层 | 驱动起不来只剩一句「失败」，没有最近 stderr |

**提交规矩**：subject ≤ 50 字符、祈使语气、不加句号；body 每行 ≤ 72 字符；中文注释与文档。
**测试基线**：动手前先看一眼 `docs/architecture/module-status.md`（全仓唯一一份「刚跑过」的台账）。

## 2. 工程基线（先做，零产品依赖）

### H-1.1 测试进门禁（按 crate 分层）

- **现状**：`ci.yml` 只跑 `clippy-all`，文件头明确写着「**有意不跑测试**」；2004 项测试全在本机跑。
- **可以今天就做的**：无 UI 依赖的 crate 共 5 个 —— `rds-engine` / `rds-plugin` / `rds-shared` / `rds-paths` / `rds-connection`（实测：`grep -i gpui crates/*/Cargo.toml`，其余包都拖 gpui-kit）。
- **实测数字**：`rds-engine` lib 483、`rds-plugin` 175（114 lib + 61 集成）、`shared`+`paths`+`connection` 92 —— **合计 750 项**。
- **调整**：`ci.yml` 在 `clippy-all` 后加一步
  `cargo test --locked -p rds-engine -p rds-plugin -p rds-shared -p rds-paths -p rds-connection`。
- **验收**：该命令在**干净 target** 下绿；把输出行数写进提交信息。
- **边界**：不试图把 UI 测试塞进 CI（GPUI 要图形栈）；那件事见 H-1.7。

### H-1.2 fmt 与告警门禁（分两步，别一步到位）

- **现状**：`ci.yml` 注释写明「存量文件有 rustfmt 漂移（本仓只格式化本轮 hunk）」与「告警未清零前 `-D warnings` 会直接红」。
- **调整**：第一步（单独提交）`cargo fmt --all` + 加 `.git-blame-ignore-revs` 记下这个提交 + 同步把 `ci.yml` 的 `cargo fmt --all -- --check` 打开；第二步清存量告警（按 crate 分批），清零后加 `-- -D warnings`。
- **验收**：`cargo fmt --all -- --check` 绿；`cargo clippy-all 2>&1 | grep -c "^warning"` 从当前值降到 0。
- **边界**：**别对 `lib.rs` / `mod.rs` 顺手跑 rustfmt**（会顺 `mod` 树带出整棵模块树的存量欠账）。

### H-1.3 依赖审计（我们连 `deny.toml` 都没有）

- **现状**：全仓无 `deny.toml`；已知一处硬约束写在 `Cargo.toml` 注释里 —— `sqlx` 若开默认特性会带 `sqlx-sqlite → libsqlite3-sys`，与 `rusqlite` 的同名 native 库冲突。
- **调整**：引入 `cargo-deny`：① `bans` 拦重复版本与 yanked；② `licenses` 白名单（决定改 GPL 后要一起改，见 §16）；③ `advisories`（有网时）。
- **验收**：`cargo deny check` 可跑；把当前违规项列成清单（允许暂时豁免，但每条要有理由与去处）。
- **边界**：不为了消警告而升依赖版本（本仓对版本有强约束，见 `docs/architecture/dependencies/`）。

### H-1.4 实机测试容器化（P1/P2 卡在「没环境」的根因）

- **现状**：`sidecar_conformance.rs` 能用 `RDS_SIDECAR_BIN` 验任意 sidecar，但**没有可用的靶库**；本机无 Docker、5432 拒连。
- **调整**：加 `docker-compose.yml`（PG 映射 **55432**、MySQL **53306**，带 healthcheck；照同类项目 dbui 的做法，非默认端口避免撞车）+ 门控变量（`RDS_PG_SMOKE=host:port:user:password:db`，**未设置就 warn 并跳过**）。把「P1 的 PostgreSQL 靶子」与「P2 的导航验收」接上去。
- **验收**：有 Docker 的机器上 `docker compose up -d` 后，带门控变量跑集成测试绿；无 Docker 时自动跳过且**打印原因**。
- **边界**：不改协议、不改用例语义（只加门控与搭台）。

### H-1.5 关键路径性能基线（防回归，不是优化）

- **现状**：无 benches / criterion；只有零散实测数字（如 Quick Open 名称档 158 ms → 1.5 ms）。
- **调整**：四条路径各写一个 `#[ignore]` 基线测试，**打印数字**（不引新依赖）：① 10 万对象导航展开；② 1000×20 结果集渲染与导出；③ mock 生成 10 万行；④ insight 对一个 500 表 schema 的评分。数字落 `module-status.md` 的附录。
- **验收**：每条能一键跑出数字，并写清机器与口径（否则数字没意义）。
- **边界**：不设阈值门禁（先有基线，再谈门槛）。

### H-1.6 构建隔离（今天刚踩）

- **现状**：两个会话共用一个 `target/` 会互相踩。实测：先出现 `rds_engine` rlib 被清（`found invalid metadata files`），`cargo clean -p` 后升级成 `mysql_common` 版本不一致与 `can't find crate for extism`。
- **调整**：定一条本地约定（写进 `CONTRIBUTING`/`docs/architecture/runtime/`）：**并行会话各用 `CARGO_TARGET_DIR`**；任何 `cargo clean` 前先确认没有别的构建在跑。
- **验收**：文档里有这条约定；下一次并行会话不再出现 metadata 报错。
- **边界**：不引进新的构建系统。

### H-1.7（可选，成本高）让业务 crate 摆脱 UI 依赖

- **现状**：`mock` / `insight` / `analytics_resource` / `database` / `editor` 都直接依赖 `gpui-kit`（视图与逻辑同 crate），因此它们的测试进不了 CI。
- **调整**：按已有的「视图下沉」方向（`workbench_shell` 是防环层），把**逻辑**与**视图**分到不同 crate 或不同 feature，让 `cargo test -p <逻辑>` 能在无图形环境跑。
- **验收**：至少 `mock` 的逻辑测试能在无 UI 依赖的 target 上跑。
- **边界**：这是重构，**一次只搬一个 crate**，且搬完要有提交说明「行为不变」的证据（测试数字不变）。

## 3. 引擎与驱动（H-2）

### H-2.1 类型保真（最值钱的一条）

- **现状**：`duckdb_service.rs` 的 `infer_type` 只产 `BIGINT` / `DOUBLE` / `BOOLEAN` / `VARCHAR` 四档 —— 日期落 VARCHAR、`DECIMAL(38,10)` 落 DOUBLE 或 VARCHAR。P2.5 的底座（`create_temp_table_from_batches` + `duckdb_type_of`）已落地并有 6 条单测，但**没有生产调用方**。
- **调整**：按 `plugin-dev-plan.md` §5.1 的第 2、4、5、6、7、8、9 项接线：`QueryData` / `AnalysisRequest` 带上「带批的那一份」，分析段走 Arrow 直灌。
- **验收**：`SELECT typeof(amount), typeof(created_at), typeof(flag) FROM {临时表}` = `DECIMAL(…)/TIMESTAMP/BOOLEAN`；两条路（Arrow / 逐行）数据一致。
- **边界**：一次不做网格改造（那是 H-4.1）；旧函数保留。

### H-2.2 错误映射台账（现在只在代码里，没有对照表）

- **现状**：`sidecar/driver.rs` 的 `map_error` 有完整分流（SQL 错→`DatabaseError::Query`、断线→`ConnectionError::Network`、缺能力→`CommonError::NotSupported`…），原生驱动各自为政。
- **调整**：写一份「驱动错误 → 引擎错误域」对照表（落 `docs/architecture/driver-capability-matrix.md` 或新建小节），再加一个**契约测试**：同一组错误语义（连不上 / 语法错 / 缺权限 / 超时 / 取消 / 断线）在每个驱动上都要落到同一域。
- **验收**：契约测试对 ≥3 个驱动（duckdb / sqlite / sidecar）通过；不一致的写成已知缺口。
- **边界**：不改 UI 文案。

### H-2.3 取消矩阵（谁真能停）

- **现状**：sidecar 是**真取消**（把 `query.cancel` 递到驱动进程并等它以 `-32004` 收场）；DuckDB 走 `CancellationToken` + `spawn_blocking`；其余驱动未逐一核实。
- **调整**：做一张「取消矩阵」（每个驱动：真取消 / 只能丢弃结果 / 不支持），并让 UI 据此置灰「中断」按钮 + 说明原因（缺能力必须说出来）。
- **验收**：矩阵里每一行的判定都有测试或代码位置作依据；「不支持」的驱动点了中断会看到明确说明。
- **边界**：不给不支持的驱动假装中断。

### H-2.4 DuckDB 临时表残留清理

- **现状**：K16 已修「前缀 + 登记」（`tmp_q_` / `tmp_i_`）；若进程崩溃留下残留，重启后**没有清扫**。
- **调整**：启动时扫一遍内存库里的 `tmp_q_*` / `tmp_i_*`（内存库随进程消亡，主要针对文件库与多连接场景）+ 一条回归测试。
- **验收**：造一张残留表 → 重启 → 表被清且日志有一行说明。
- **边界**：不动 TTL 与上限策略。

### H-2.5 驱动声明与实现同步

- **现状**：`declaration.rs` / `sync_driver_declarations` 负责「清单 vs 实现」对齐；`capability.rs` 的 `CAPABILITY_DICTIONARY` 有 `Stage::NotBuilt` 与 `Acceptance::verified` 两套把关（有测试盯住）。
- **调整**：加一条契约测试：**任何驱动声明的能力键都必须能在 `CAPABILITY_DICTIONARY` 里找到且 `stage = Ready`**（防止「声明了但没做」）。
- **验收**：契约测试通过；故意加一个假键会让它红。
- **边界**：不改能力键命名。

## 4. 导航与元数据缓存（H-3）

### H-3.1 缓存事实源纪律的回归测试

- **现状**：三层缓存（L1 内存 / L2 连接级 SQLite / L3 词表）与逐行消费者状态已记在 `data-layer-wiring-matrix.md`；刷新路径靠 `fresh` 标志。
- **调整**：写「缓存与源库不一致时以谁为准」的契约测试：① 每级缓存的写侧必须登记（前缀/键唯一）；② `fresh = true` 必须跳过读缓存并重写；③ 索引缺行时**必须回源**而不是显示空（`indexed_folder_count` 已有这条口径）。
- **验收**：三条断言各有测试；故意让一处不登记会让断言红。
- **边界**：不改缓存层级与存储位置。

### H-3.2 极端 schema 不崩

- **现状**：有分页（`load_object_page`）与大 schema 不进 L1 的门禁（`CHUNK_THRESHOLD`）；实测覆盖到「10 万对象名称档」。
- **调整**：补三条边界测试：5000 列的宽表、200 层嵌套的对象路径、名字里带引号/emoji/超长（255+）的标识符。
- **验收**：三条都不崩，且树能正确显示与定位。
- **边界**：不做性能优化（那是 H-1.5）。

### H-3.3 能力门控落到文件夹（P2 的已知缺口）

- **现状**：能力信息已经在 `SidecarDatabase::descriptor()` 上，但导航对**所有**驱动摆同样的五个文件夹（空则计数 0）——「不支持的文件夹置灰并说明」做不到。
- **调整**：让 `NavNode` 支持「禁用 + 原因」（模型层改一处，视图层只读它），扫描器/导航服务据此给文件夹带原因。
- **验收**：能力为假的文件夹在树上是置灰的，悬停/详情显示「驱动没声明 sequences 能力」；能力为真的驱动行为不变。
- **边界**：这是导航模型的改动，改前先看 `crates/database/src/nav_*.rs` 是否有人在改（那条线常有人在动）。

## 5. 编辑器与结果集（H-4）

### H-4.1 大结果不卡（惰性格式化 + 可见区）

- **现状**：1000 行 × N 列**全量** `to_string()` 是已知待改项（`plugin-dev-plan.md` §3.2 与 Q6）。
- **调整**：先做**预算内**的那一步 —— 只格式化可见行 + 预取窗口，保留 `Vec<Vec<String>>` 的对外契约不变。
- **验收**：1000×20 结果集首屏渲染的耗时/内存有实测数字（对齐 H-1.5 基线）；滚动到任一位置单元格文本正确。
- **边界**：这一步**不动**筛选/排序（那是 P4 的网格改造）。

### H-4.2 结果集边界测试

- **现状**：结果集有多个导出格式（CSV / JSON / `INSERT` / **Parquet** / **Xlsx**）与分析桥，但边界用例不成套。
- **调整**：给「0 行 / 1 列 / 10 万行 / 含 NULL / 含二进制 / 含超长文本 / 含中文与 emoji」各补一条往返测试（导出后能读回、值相等）。
- **验收**：七类边界全绿；Parquet/Xlsx 在**扩展缺失**时如实报错（见 H-4.4）。
- **边界**：不新增导出格式。

### H-4.3 中断之后必须显示「已中断」

- **现状**：取消路径存在（真取消 → `-32004` → SQL 域错误），但缺一条端到端 UI 断言。
- **调整**：在编辑器窗口测试里补一条：跑一条慢查询 → 点中断 → 结果区显示「已中断」而不是「成功」或空白；与 H-2.3 的取消矩阵一致。
- **验收**：窗口测试绿；对「不支持取消」的驱动显示的是「没能停下来」。
- **边界**：不改执行管线。

### H-4.4 扩展缺失不静默降级

- **现状**：Parquet 走 DuckDB 内核自带，Xlsx 需要 `excel` 扩展（`export.rs` 注释已写明）。
- **调整**：导出前探测扩展可用性；缺失时**明确报错并指路**（而不是回退成 CSV 或产出坏文件）。
- **验收**：把 excel 扩展摘掉（或 mock 掉）跑导出，看到明确错误。
- **边界**：不自动下载扩展（离线优先）。

## 6. 插件（H-5）

### H-5.1 能力协商提前到握手（照 dbflux 的已出货协议）

- **现状**：能力由 `driver.describe` 之后才拿到；连接表单由宿主给「标准五件套」。
- **调整**（三小件，可分开做）：① `initialize` 里带上 `requested_capabilities` 与宿主要求的协议版本，对端在握手响应里回 `capabilities`；② 把 `describe` 的能力与握手那份**不一致时报一条告警**；③ 连接表单是否改由驱动下发（`form_definition`）——先只做**决策记录**，实现留给 P4。
- **验收**：握手失败/版本不符时给出两个版本号；能力不一致有日志；`sidecar_conformance` 六条仍绿。
- **边界**：协议变更要同步 `plugin-dev-plan.md` §4.2 与用户手册 §2.8。

### H-5.2 三道闸：行上限 / 帧上限 / 进程级超时

- **现状**：已有 64 MiB 单帧上限与 `EXECUTE_RPC_TIMEOUT`；**没有**「单查询返回行上限」「错误 / 日志输出上限」「进程级内存」。
- **调整**：① 驱动侧行上限（超出如实标 `truncated`，不静默截）；② 宿主侧单次响应字节上限（防对端一个 u32 骗 4 GiB）；③ sidecar 的 stderr 日志轮转上限（避免把用户盘写满）。
- **验收**：三项各有测试；超限时用户看得见原因。
- **边界**：wasm 的 fuel/epoch 属 P3，不在这条里。

### H-5.3 孤儿进程的跨平台实测

- **现状**：口径是「宿主持 stdin，sidecar 见 EOF 即退」；自动化只在「正常收摊 + `--ignore-eof` 强杀」两条路上验过。
- **调整**：写一份手工/脚本验收：**强杀宿主**（任务管理器 / `taskkill /F`），确认 sidecar 在 N 秒内自己退出；三平台各记一次结果。
- **验收**：脚本跑完打印「有无残留进程」；结果写进 `plugin-dev-plan.md` 的实机验收清单。
- **边界**：不引入平台相关杀进程组（那是本设计刻意避免的）。

### H-5.4 崩溃的用户可见性

- **现状**：崩溃 → 会话作废 + 实例标 `Error` + 需 `manual_restart`（有测试）；但**没有**「最近 stderr 尾部」随错误一起冒泡给 UI（对端日志只落文件）。
- **调整**：把 stderr 日志的**有界尾部**（比如最近 4 KiB）挂到 `SupervisorEvent` / 错误上，UI 展示「哪一步失败 + 最近输出」。
- **验收**：让靶子启动即崩，错误里能看到它的 stderr；测试断言包含关键字。
- **边界**：不改日志落盘路径。

### H-5.5 安装期完整性（P5 的底线）

- **现状**：`manifest.toml` + 权限双轨已就位；签名与逐资源校验未实现。
- **调整**：先做**不需要密钥**的那半：逐资源 SHA-256 + `checksums.json`，篡改一字节必须拒绝安装并指出是哪个文件；签名（Ed25519）留后一刀。
- **验收**：篡改测试绿；缺平台（`platforms` 不含当前）时如实置灰并说明。
- **边界**：不发布任何密钥到仓库。

## 7. mock（优势模块：做得更「可复现」）

> 定位：**可复现的测试数据工厂**。同类项目大多能造数，但**很少有人能保证「同 seed 同结果」**。

### H-6.1 确定性（这条最值钱）

- **现状**：`mock` 23.8k 行 / 181 测试；生成器由 `fake` crate 驱动（`generators.rs`）。
- **调整**：把随机源从「进程内任意」改成**可注入 seed**：同 `(seed, schema, 配置)` → 逐字节相同的数据；seed 随生成任务落库（`persistence`），历史里能复现。
- **验收**：同一 seed 生成两次，导出的 CSV 文件 sha256 相同；不同 seed 不同。
- **边界**：不改生成器的语义（只改随机源与记录）。

### H-6.2 类型对齐（与 H-2.1 联动）

- **现状**：`schema_map::parse_data_type` 是**类型串唯一入口**；但上游类型串若已失真（H-2.1），mock 造出来的类型就是错的。
- **调整**：让类型映射优先吃 `rds.canonical` / `rds.type_raw`（Arrow schema 那份），类型串解析退化成兜底；并把「未知类型」的落法写清（现在是落文本？要显式且有日志）。
- **验收**：`numeric(38,10)` / `timestamptz` / `bytea` 三类列造出来的数据保真（小数不丢精度、时间带时区、二进制是真二进制）。
- **边界**：不动生成器目录（143 变体）。

### H-6.3 规模与可取消

- **现状**：生成落 DuckDB 临时表（不回传源库，M7 约束）；大任务的进度/取消路径已有（MockEngine 管线）。
- **调整**：补「10 万行 × 50 列」的边界：必须能取消、进度可见、内存有上限（分块写，不整份驻留），并在取消后**不留半张表**（回收）。
- **验收**：生成中途取消 → 无残留表、无残留任务记录；H-1.5 的基线数字也在这条跑。
- **边界**：不做并行加速。

### H-6.4 边界数据成套

- **调整**：空表 / 全 NULL 列 / 复合主键 / 外键依赖顺序（拓扑排序）/ 自引用外键 / 超长文本 / 二进制 / 时区各一条用例。
- **验收**：八类全绿；外键顺序错误时给的是明确错误而不是死循环。
- **边界**：不做数据脱敏（那是另一件事）。

### H-6.5 与「分析存档」打通

- **现状**：mock 产物落在临时表，存档（`analytics_resource`）是另一条路。
- **调整**：让 mock 产物能一键**归档**（带 seed、配置、源 schema 指纹）——这才让「造的测试数据」变成可留存的资产。
- **验收**：归档后的产物能复现（用存档里的 seed + 配置再生成一次，指纹相同）。
- **边界**：不改存档本体层。

## 8. insight（优势模块：做得更「可解释」）

> 定位：**能说清为什么的数据质量**。同类项目的分析多数止步于「跑了几条规则」。

### H-7.1 规则生效必须看得见

- **现状**：三层作用域 `Builtin(16) → Global → Project`，注册表**按项目根缓存**（v1 的教训：手动重载漏调用 → 用户规则静默不生效）。
- **调整**：① UI 上显示「当前生效规则数 + 来源（内嵌/全局/项目）」；② 一条契约测试盯住覆盖顺序（后加载者整体覆盖）；③ 项目切换时规则集必须换（已有类型保证，补测试）。
- **验收**：放一条项目规则 → UI 数字与来源都对；切换项目后回落。
- **边界**：不改规则文件格式。

### H-7.2 评分可解释

- **现状**：`quality_scorer` 出质量分。
- **调整**：每个扣分项要能展开到「哪条规则 + 命中了哪一列/哪几行 + 权重」；报告里保留证据（同 `schema_analyzer` 已有的「结构完美、其实什么都没看」的防护口径）。
- **验收**：任一扣分点能点开看到证据；空库/无权查看时不报「完美」而是说清「没看到」。
- **边界**：不改评分权重（那是产品决策）。

### H-7.3 大库不崩 + 有基线

- **调整**：500 表 / 10 万列的 schema 上跑一遍，采样与上限写清；数字进 H-1.5 的基线。
- **验收**：不 OOM、不卡死；超时如实报「分析不完整」。
- **边界**：不做增量分析。

### H-7.4 与类型保真联动（回归）

- **现状**：类型退化/精度丢失类判定会因 `infer_type` 四档而**误报**。
- **调整**：H-2.1 落地后，回归一遍所有类型相关规则；把「因类型失真导致的误报」写成回归用例。
- **验收**：同一份数据在保真前后，误报消失且报告可解释。
- **边界**：不改规则集。

## 9. 分析存档（优势模块：做得更「可信」）

> 定位：**分析产物的正式台账**（只读 + 版本 + 来源 + 指纹）。同类项目有审计日志，但**没有把产物本身做成有版本、可复现的存档**。

### H-8.1 指纹不匹配要看得见

- **现状**：本体层有只读守卫 + 内容指纹 + 历史副本；索引修复的纪律是「扫描只报告，修复要人工确认」。
- **调整**：外部改动受管文件后，打开/引用时**必须**报「内容与指纹不一致」并给出选择（重建索引 / 恢复历史 / 接受现状），不许静默照用。
- **验收**：手动改一个受管文件 → 打开时报错并列出期望/实际指纹；恢复路径可用。
- **边界**：不自动改写本体。

### H-8.2 版本恢复闭环

- **调整**：补「从任意历史版本恢复 → 版本链不丢 → 回收站删除后仍可找回」的端到端测试（回收站走项目级 `ProjectTrash`，`origin = "resources"`）。
- **验收**：恢复、再归档、删除、找回四条路各一条测试。
- **边界**：不做版本自动清理策略。

### H-8.3 存档的「复现最小信息」

- **调整**：存档必须带够复现所需的最小信息：产生它的查询、连接标识（不含凭据）、时间、引擎/驱动版本、以及（对 mock 产物）**seed**；缺字段要显式记为「不可复现」而不是留空。
- **验收**：任一存档能答出「怎么来的」；缺信息的旧存档显示为「不可复现」。
- **边界**：不改持久化表结构前先看迁移账本。

### H-8.4 大文件

- **调整**：>100 MB 的 Parquet/Xlsx 的预览与取回要分块、可取消（`preview.rs` 现在直接读）。
- **验收**：大文件预览不卡 UI、可取消、内存有上限。
- **边界**：不做在线编辑。

## 10. 连接与凭据（H-9）

- **H-9.1 零泄露回归**：加一条自动化检查（测试 + grep 断言）：密码/口令不出现在项目文件、日志、错误信息与导出里（`engine/src/logging/redact.rs` 已有脱敏，补回归）。
- **H-9.2 连不上要能诊断**：原生驱动侧对齐 P2 已定的口径 —— 网络 / 认证 / TLS / 超时 分开呈现（sidecar 侧已有 `-32009`）。
- **H-9.3 隧道不泄漏**：`TunnelRegistry`（`engine/src/connection_manager.rs`）的端口/进程泄漏测试：连上→断开→端口释放；进程崩溃后残留要能清理。

## 11. 项目 / 草稿箱 / 存储与路径（H-10）

- **H-10.1 路径唯一解析的契约检查**：`paths` 是唯一入口（有单测）；加一条 grep 断言（类似「零裸色值」那套）：`crates/**` 里不得出现自拼的用户目录/临时目录。
- **H-10.2 崩后恢复**：强杀进程后重开 —— 项目锁、未保存拦截、草稿箱恢复各一条手工脚本 + 文档。
- **H-10.3 单实例守卫**（缺口）：同类项目（navop/fluxDB）都有；两个实例写同一项目有**数据损坏**风险。评估加互斥（Windows 命名互斥量 / Unix flock）。

## 12. 工作台 UI 与主题（H-11）

- **H-11.1 三态齐备**：每个面板必须有「加载中 / 空态 / 错误态」，且都不许出现纯空白（已有零裸尺寸/零裸色值契约测试，扩一条「空态矩阵」检查）。
- **H-11.2 键盘可达与焦点**：所有动作可键盘完成；补「焦点不丢 / 对话框关掉后焦点回原位」的窗口测试。
- **H-11.3 主题 token 覆盖契约**：新增 token 必须被明暗两套都覆盖（现有 `theme-preview.html` 是人工对照，改成契约测试）。

## 13. 发布与更新（H-12）

- **H-12.1 装包器**：现在只有 `dist/*.zip`（四平台 + 校验和）。至少补 Windows 安装器与 Linux `.deb`（含**包内容断言**：文件路径、可执行位、`ldd` 报告），或直接采用 cargo-dist 生成（同类项目 sqlab 的做法）。
- **H-12.2 更新提示**（先做轻的）：检查新版本 + 状态栏提示 + 手点下载；自替换留后。
- **H-12.3 迁移的双保险**：项目 DB 迁移前自动备份 + 失败可复位（本仓已有迁移双账本，补自动化）。

## 14. 优势模块的可信化（守住差异点）

| 模块 | 一句话定位 | 必须守住的三件 |
| --- | --- | --- |
| **mock** | 可复现的测试数据工厂 | seed 确定性 · 类型保真 · 与存档联动 |
| **分析存档** | 分析产物的正式台账 | 只读 + 指纹 · 版本链与找回 · 复现最小信息 |
| **洞察** | 能说清为什么的数据质量 | 规则生效可见 · 评分可解释 · 大库有上限 |

| **插件** | 唯一带 Arrow 数据面的扩展机制 | 版本闸 · 宿主门控（缺能力不静默）· 无孤儿进程 |
