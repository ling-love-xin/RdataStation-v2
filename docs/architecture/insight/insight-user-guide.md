## 1. 入口

洞察从几个地方进入，都落到同一个右 Dock 面板：

| 入口 | 位置 | 分析目标 |
| --- | --- | --- |
| 导航树表右键 → **查看洞察**（2026-10-30 去重：原「查看统计 / 结构洞察」并入此统一入口） | 左侧数据库导航 | 该表 |
| 分析存档行右键 → **查看洞察** | 左侧资产库（M6） | 存档本体（**CSV / Parquet / Excel / JSON**）或来源表（引用型存档） |
| 草稿箱文件右键 → **查看洞察** | 左侧草稿箱（M5） | 该文件（**CSV / Parquet / Excel / JSON**） |
| 导航树表右键 → **结构洞察** | 同上 | 该表 / 视图所在 **Schema**（schema 节点右键则是它自己；列与库节点不摆这一项） |
| 结果表列头右键 → **洞察此列** | 中央查询结果区 | 该列（✅ 已接；未绑定连接的文档按**当前活动连接**取样） |
| Quick Open（`Ctrl+P`）→ **打开洞察** | 命令面板 | 保持上次目标 |

「查看洞察」只出现在**真能分析**的行上：存档 / 草稿箱里不是数据文件的条目（`.sql` / `.md`）不会摆这一项；分析表型存档（本体是一个 DuckDB **库文件**）也还没接。导航树侧按目标类型分派：表 / 视图 → 取样画像；schema → 结构洞察；其余节点 → 纯面板（不摆入口）。

结果集列头右键「洞察此列」只在**能取样**时出现：结果成功、有列、SQL 是只读查询；连接取「产生这份结果的那条」——文档绑了连接就用它，没绑就按**当前活动连接**（与执行同一处口径）。它**不物化结果集**，而是拿那段 SQL 重跑一句带 `LIMIT 500` 的取样。

能分析的东西比入口多，但**边界是清的**：

- **数据库**：以**导航树**为准——能被导航树看见的对象（**有真正驱动 + 活连接**）就能洞察。数据与结构都是这条：数据走取样（`SampleSource`），结构走驱动元数据（与导航树同源）。
- **草稿箱 / 分析存档**：文件类**直接可以**（CSV / Parquet / Excel / JSON，含需要 DuckDB 扩展的 Excel）——它们只做**数据**画像（列画像 / 表探查），没有可报告的 schema 结构。
- 没有内置驱动、只能靠 `ATTACH` / 三方扩展到达的**远程库**不在边界内（那类源不经过导航树，也没有本文档里的结构洞察）。

面板打开但不选目标时显示空态引导，**不会**给出任何没有目标的数字。

### 2.2 下钻区按目标类型回答什么

| 目标 | 下钻区呈现 | 触发 |
| --- | --- | --- |
| **表 / 结果集** | 摘要环（检查器适用与命中）+ 总行数 / 列数 / 取样口径 + 表画像卡（前 8 列的列名 / 类型 / 缺失率，「…共 N 列（完整清单见中间报告）」） | 导航树表右键「查看洞察」、结果集、草稿箱 / 存档文件 |
| **列** | 列摘要卡：类型 / 总行数 / 空值 / 空值率 / 样本值（完整四区画像见中间页） | 结果表列头右键「洞察此列」、表画像卡点列名 |
| **Schema** | 结构摘要卡：健康分环 + 表数 / 列数 / 问题数（完整报告与导出保留待复用） | 导航树 schema 右键「查看洞察」 |
| **多列** | 聚合占位（GROUP BY / 求和 / 均值 / 计数为**后续实现**，原型同款占位） | 多列目标（完整多列规则分析保留待中间页复用） |

### 2.3 怎么读这些数字

- **类型徽标**：`DOUBLE` / `VARCHAR` / `DATETIME` / `BOOLEAN` 是**真实类型名**；颜色只区分类型族（信息 / 成功 / 警告 / 主色，`UNKNOWN` 用次级色），不单独承载信息。显示 `UNKNOWN` 表示该列全为空或类型未识别（BLOB / ARRAY）——此时**不会**出分布与类型专属统计。
- **等级色阶仅限 Schema 结构健康分**（独立域，与表 / 列画像不混用）：
  | 分数 | 等级 | 颜色 |
  | --- | --- | --- |
  | ≥ 85 | 优 | 成功色 |
  | ≥ 70 | 良 | 主色 |
  | ≥ 50 | 一般 | 警告色 |
  | < 50 | 差 | 危险色 |
  表 / 列画像**不出总分、不出等级**：只给缺失率 / 唯一率 / 类型一致 / 分布倾斜等纯事实量与检查器四态命中计数；「这份数据好不好」的审计与评级归 M6 资产库，不在本模块。
- **检查器四态**：`命中`（规则条件满足，成功色）· `未命中`（条件不满足，危险色）· `不适用`（列类型不在规则适用范围，次级色）· `排除`（被用户规则开关排除，次级色）。摘要环只统计**适用**列中的命中占比，不做加权合成。
- **采样口径**：源表 / 文件 / 结果集默认取 **500 行**落一份分析临时表，列画像 / 表探查 / 多列 / 保存快照都基于这份样本；直方图与前 5 行样本值同出此表。**全量**需在工作页工具栏手动切换，经两段确认弹窗（提示大表耗时与内存占用）后才导入不带 `LIMIT` 的全表；临时表目标（已是既定数据）恒走自身口径，不再二次取样。面板底部常驻写明当前是「取样 500 行」还是「全量」。
- **临时表口径**：分析对象是**内存库里的临时表**。三种来路，进去之后完全同路：① 结果集表（宿主建的 `tmp_q_…`）；② 「查看洞察」的**源取样**——导航树按表、存档 / 草稿箱按文件，洞察侧统一取 500 行落一个样本表（`tmp_i_` 前缀），再用同一份样本做摘要卡 / 表画像 / 检查器；③ 已有的分析临时表。洞察自己为一次分析建的样本表**用完即删**（建表即登记，分析结束就收）——所以不存在「洞察的表过期」这件事。只有**源**不在内存库里了（宿主关了结果集 / 会话结束），面板才会报「结果集已失效或已过期，请重新执行查询」。

## 3. 典型流程

### 3.1 看一列（最常用）

1. 执行查询，结果表出现。
2. 右键想看的**列头** → **洞察此列**（也可在导航树里右键表 → 查看洞察 → 表画像卡点列名）。
3. 右栏下钻区 = **列摘要卡**：类型 / 总行数 / 空值 / 空值率 / 样本值；完整四区画像（基础统计 / 分布 / 规则门控提示 / 样本 + 检查器命中事实）在中间洞察工作页呈现，不出总分与等级。
4. 想留档：快照保存能力保留（入口由中间页 / 资产库承接，见 §3.5）。

### 3.2 摸一张表的底

1. 导航树右键表（或结果集）→ **查看洞察**。
2. 右栏下钻区 = **表画像卡**：摘要环（检查器适用 / 命中）+ 总行数 / 列数 / 取样口径 + 前 8 列的列名 / 类型 / 缺失率（未统计时缺失率显示中性「—」）；行尾写「…共 N 列（完整清单见中间报告）」。
3. 工具栏点 **评估全表**（⧉，仅表 / 源列目标可点）：**逐列串行**回填事实明细（避免撞后端并发上限），集合行 r2 的检查器命中随之更新。
4. 完成后面板给出事实计数（检查器适用列数 / 命中列数）；点任一列名 → 下钻到该列的摘要卡。

两处口径需要知道（面板底部 it-note 也常驻写明）：

- **统计基于当前分析表**：默认取样 500 行落样本表，摘要卡 / 表画像 / 检查器都基于这份样本；样本值取前 5 行、直方图至少 10 行。要基于全表下钻时，在工作页工具栏手动切「全量」，经两段确认后才导入不带 `LIMIT` 的全表。
- **临时表没有主键约束**：`PK` 角标只在元数据真的带主键时才出现。从查询结果建的临时表一般没有，所以看不到 `PK` 是正常的，不是漏实现。

### 3.3 看两列的关系

右栏多列目标当前呈现**聚合占位**（GROUP BY / 求和 / 均值 / 计数为后续实现，原型同款占位）；多列**规则分析能力**（列多选 → 规则执行 → 结果渲染）完整保留，渲染入口待中间页复用。

现行六条多列规则按类型配对：

| 规则 | 类型配对 | 结果形态 |
| --- | --- | --- |
| `pearson-correlation` 相关系数 | 数值 · 数值 | 单值 |
| `spearman-correlation` Spearman 秩相关 | 数值 · 数值 | 单值 |
| `scatter-sample` 散点样本 | 数值 · 数值 | 多行样本 |
| `cramer-v` Cramér's V 关联强度 | 类别 · 类别 | 单值 |
| `cross-tab` 交叉表 | 类别 · 类别 | 多行表格 |
| `grouped-stats` 分组统计 | 数值 · 类别 | 多行表格 |

> 多列规则要求勾选**至少 2 列**（行尾写着「需 N 列：Numeric · Numeric」），列顺序要与规则参数顺序对应。
> **方向敏感性**：`grouped-stats`（数值列 / 类别列参数名本身有方向）与 `cross-tab`（行列换位表体转置）受顺序影响；`scatter-sample` 换位后 x / y 轴对调；Pearson / Spearman / Cramér's V 是对称统计量，换位数值不变。
> 类型不匹配的规则会置灰（写清需要什么类型），不让你点一个必然报错的按钮。

### 3.4 看 Schema 健康

导航树 schema 右键 → **查看洞察** → 右栏下钻区 = **结构摘要卡**：健康分环 + 表数 / 列数 / 问题数。健康分等级为 **Schema 独立域**，不与表 / 列画像混用。

- **完整报告**（健康分 + 四个折叠区：外键候选 / 类型不一致 / 孤立表 / 冗余列 + 逐行下钻 + 导出 JSON / Markdown）渲染入口保留待复用（旧结构 Tab 视角，`render_schema_report` 标 `#[allow(dead_code)]`），由中间页 / 资产库入口承接。

### 3.5 对比两次分析

**集合内对比（右栏现行入口）**：打开「多选」开关 → 勾选 ≥2 张已洞察表 → it-actions 出现**质量对比**；点它即对每张勾选表各发一次对比请求（宿主累积候选）。行卡 r2 的**对比**按钮是同一入口（单张）。行卡 r2 另有**关系**（跨表值重叠排查，结果区在集合底部）与**归档**（仅已有临时表的行可点，`temp_table` 为 None 时置灰）。

**历史快照对比（能力保留，入口承接中）**：快照保存 / 版本列表 / 版本对比 / 存储清理的能力与渲染（`render_history` / `render_version_diff`）全部保留，右栏对齐原型后暂无 UI 入口——由中间洞察工作页 / 资产库入口承接（见 `insight-dev-plan.md` §11 注记）。语义不变：

- 快照**成对写**：正文进项目 DuckDB（`insight_column_snapshots`），元数据 + 版本链进项目 SQLite（`insight_snapshots`）；元数据写失败会**回滚**刚写入的正文（不留看不见的半写记录）。
- 对比方向固定**「选中的那一版 → 最新一版」**；最新一版不可点。
- 清理按**30 天保留期**成对删，删除前有确认框写明删什么与当前存量；清理不认版本链（父版被删的条目标「更早的版本已清理」，不误标成「首版」）。

### 3.6 管理规则

面板头的 **⚙** 打开规则管理对话框（无项目时该按钮禁用：规则落在项目目录下）。

```text
┌─ 洞察规则 ────────────────────────────────────────────┐
│ [搜索规则名 / id / 分类…]   [＋ 新建项目规则] [⟳ 重新加载] │
├───────────────────────────────────────────────────────┤
│ ▼ 项目规则 · {项目}/.RSmeta/insight-rules/        (2)  │
│   我的订单空值检查   column · v1.0        [开]  ⧉     │
│   渠道分布对比       multi · v1.2         [开]  ⧉     │
│ ▼ 全局规则 · {系统目录}/insight-rules/            (0)  │
│   跨项目复用的规则放在这里，所有项目可见              │
│ ▼ 内置规则 · 应用内嵌                             (18) │
│   空值率检查         column · v1.0        [开]         │
│   ⚠ 用户的规则       project · v1.0  校验失败         │
│      第 3 行未知字段 `outputs`（期望 output）         │
├───────────────────────────────────────────────────────┤
│ 共 20 条 · 2 条禁用 · 1 条异常                         │
└───────────────────────────────────────────────────────┘
```

| 元素 | 行为 |
| --- | --- |
| 分组顺序 | 项目 → 全局 → 内置，即**覆盖优先级从高到低**（先看到「谁赢」） |
| 开关 | 改的是**生效的那一条**，不动规则文件：内置规则写一条项目级抑制记录，用户规则写自己那层的启停位 |
| ⧉ | 在**系统默认应用**里打开该规则文件（内置规则内嵌，没有这一项；文件已被删的行也不给） |
| 校验失败行 | 红色 + 错误原文（TOML 报错含行列）；文件被删是黄色一行 |
| `＋ 新建项目规则` | 在 `.RSmeta/insight-rules/` 建目录 + 写一份模板并打开。模板**能解析但不生效**（`applies_to` 留空），填上类型族才开始参与分析 |
| `⟳ 重新加载` | 丢弃缓存并按三层重建；目录监听之外的兜底与排障入口 |
| 搜索 / 底部统计 | 搜规则名 / id / 分类；统计数字取**全量**（搜索不会让「共 N 条」变小） |

两处行为值得知道：

- **开关是受控的**：点下去立即翻位（不等后台），落库失败时会把真值回填并把原因挂在状态行（如「启停未保存：…」）——不会静默丢掉失败，也不会让列表整页变错误。
- **全局层目录不存在时**，该分组给「创建目录并新建规则」：目录在**首次写入时**创建，不在启动时预设空目录（K7）。
- **信任门**（Q1 ③）：项目规则在**你做出决定前不加载**。首次打开这个对话框会弹一次确认框（列出多少条、叫什么、在哪个目录）；决定记在全局库，之后不再追问。不想加载时就选「不加载」，顶部横幅会留着改主意的入口——细节见 §4.7。

### 3.7 看一个数据文件（CSV / Excel / …）

1. 把文件放进**草稿箱**（或归档进**资产库**）。
2. 右键该文件 → **查看洞察**（只有数据文件才摆这一项）。
3. 面板取 500 行作样本，之后的摘要卡 / 表画像 / 检查器都与库表**完全一样**（分析能力只有一套）。

- 能识别的格式：**CSV / TSV / TXT / Parquet / Excel（`.xlsx` / `.xls`）/ JSON / NDJSON**——靠 DuckDB 自己的读取器，数据不绕一道应用层（Excel 需 excel 扩展）。
- 文件不必先导进数据库；`.sql` / `.md` 这类文本没有「查看洞察」（不摆一个点了报错的入口）。
- 样本出自**首次取样**：之后下钻列 / 评估全表 / 中间页分析都接着用同一份，不重新抽。

## 4. 规则编写指南

这是本模块的**对外契约**。规则是声明式分析单元，放在 `.rule.toml` 文件里。

### 4.1 放在哪：三层作用域

| 层 | 目录 | 可见范围 | 可写 | 覆盖优先级 |
| --- | --- | --- | --- | --- |
| 内置 | 应用内嵌（随二进制分发，18 条：列 9 · 多列 6 · 表 3） | 所有项目 | ❌ | 最低 |
| **全局** | `{系统目录}/insight-rules/` | 所有项目 | ✅ | 中 |
| **项目** | `{项目}/.RSmeta/insight-rules/` | 当前项目 | ✅ | 最高 |

`{系统目录}` = 应用数据目录下的 `RdataStation/system/`（与 `global.db` 同级）。子目录任意嵌套（内置规则按 `column/` `multi/` `table/` 三类分目录，用户规则不强制）。

**同名（`meta.id` 相同）整体覆盖**：上层规则完整替换下层，**不做字段级合并**。所以想改内置规则的行为，需要把整份规则抄到用户目录再改。

**在系统编辑器中打开任一内置规则**可以当作模板起点（规则管理对话框里的 ⧉）。

**禁用而非删除**：不想用某条内置规则时，用规则管理对话框的开关关掉即可（不需要写覆盖文件）。

### 4.2 字段全表

```toml
[meta]
id          = "my-rule"          # 必填，唯一标识（snake_case），用于覆盖与 API 引用
name        = "我的规则"          # 必填，展示名
category    = "column"           # 必填，column | multi | table（内置规则只用这三类；自由字符串，与目标类型对应）
applies_to  = ["Numeric"]        # 必填，适用列类型数组（见 4.3）
description = "..."              # 可选，默认空
version     = "1.0"              # 可选，默认 "1.0"
builtin     = false              # 可选，默认 false（用户规则写 false 或不写）

[query]
template    = """SELECT COUNT("{col}") FROM "{table}" """   # 必填，注意字段名是 template 不是 sql
parameters  = ["table", "col"]   # 可选（默认空数组），会被替换的参数名
result_type = "single"           # 可选，single（默认，单行对象）| list（多行数组）

[[output]]                       # 可选（默认空），一条规则可有多段
sql_name    = "cnt"              # 必填，SQL SELECT 里的列名/别名
json_name   = "count"            # 必填，输出 JSON 的键名
value_type  = "i64"              # 必填，见 4.4

[[quality]]                      # 可选，质量门控（见 4.5）
field       = "count"            # 必填，检查哪个输出字段（json_name）
min         = 1                  # 可选，下界
max         = 100000             # 可选，上界
severity    = "warning"          # 可选，默认 warning
message     = "计数偏低"          # 可选，默认 "Quality check for {field}"

[render]                         # 可选，**预留字段：解析后无人消费**（见下方说明）
component     = "NullCheckInfo"  # 可选，推荐组件名
display_order = 0                # 可选，展示排序
```

> **严格 schema**：所有表都拒绝未知字段。多写一个字段（哪怕拼错）都会导致**整条规则加载失败**。字段放错表也一样（例如把 `result_type` 写进 `[meta]`——内置规则里就有一条因此长期缺席，见 `insight-architecture.md` K 区）。
>
> **`[render]` 是预留字段**：它能被解析、能被校验，但**当前没有任何渲染方消费它**（面板按**数据形态**渲染规则结果，不看组件名）。写它不会出错，也不会改变界面；什么时候会生效要看图表可视化那条线（不在洞察模块）。**也不要靠它排序**——规则列表的顺序不取 `display_order`。

### 4.3 `applies_to` 取值

数组，元素为列类型名，**大小写不敏感**（匹配时用 `eq_ignore_ascii_case`）。内置规则实际使用的取值：

| 取值 | 含义 |
| --- | --- |
| `Any` | 任意列 |
| `Numeric` | 数值列 |
| `Text` / `VARCHAR` / `STRING` | 文本列 |
| `DateTime` / `TIMESTAMP` / `DATE` | 日期时间列 |
| `Boolean` / `BOOLEAN` / `BOOL` | 布尔列 |

多列规则用**多个元素表示多个参数位**（如 `applies_to = ["Numeric", "Numeric"]` 对应两个数值列）。

### 4.4 `value_type` 取值（**只能用这几个**）

| `value_type` | 读出的 Rust 类型 | 说明 |
| --- | --- | --- |
| `f64` | `f64` | 浮点，非空 |
| `f64?` | `Option<f64>` | 浮点，可空（SQL 返回 NULL 时输出 JSON `null`） |
| `i64` | `i64` | 整数，非空 |
| `i64?` | `Option<i64>` | 整数，可空 |
| `String` / `string` | `String` | 字符串，非空 |
| `String?` / `string?` | `Option<String>` | 字符串，可空 |
| `bool` | `bool` | 布尔，非空 |
| `bool?` | `Option<bool>` | 布尔，可空 |
| `usize` | 经 `i64` 中转的 `usize` | 计数类 |

> ✅ **写错 `value_type` 会在解析期直接报错**（列出不支持的取值与可用取值清单），不会再靠兜底分支按 `String` 读。历史遗留的 `"str"` 请改成 `String` / `String?`——内置规则里那 8 处已在 2026-09-17 全部改正（K12）。

### 4.5 规则门控怎么判

> 这里的 `[[quality]]` 是**规则自身的取值判界门控**（`QualityRule`：min / max / severity / message），与模块已撤除的表 / 列质量总分、等级不是一回事；门控未通过时只在列画像「数据质量」区挂一条事实提示。

`[[quality]]` 的每条会对指定 `field` 取值并判界：

| 情况 | 结果 |
| --- | --- |
| 只设 `min`，实际值 < min | **不通过** |
| 只设 `min`，实际值为 `null` | **不通过**（记为 `actual=null`） |
| 只设 `max`，实际值 > max | 不通过 |
| **只设 `max`，实际值为 `null`** | **通过**（当前实现不判失败） |
| 所有 `[[quality]]` 均通过 | `QualityReport.passed = true` |

> ✅ **`field` 必须是本规则 `[[output]]` 里真实存在的 `json_name`**——解析期会校验（K11 / Q6 已定：早失败优于静默错），写错时直接报错并列出该规则已有的输出字段。
>
> 以前不校验：字段不存在时取值为 `null`，而「只设 `max`」的判定对 `null` 是**通过**——门控形同虚设（内置 `null-check` 就踩了这个）。现在 `null-check` 的 `null_rate` 已由 SQL 真算出来。
>
> 仍需自己判断的一处：值合法地是 `null`（如空表算不出空值率）时，「只设 `max`」仍然通过——那是刻意的（没有数据就不该判数据有问题），要令它在 `null` 时也失败就加一个 `min`。

### 4.6 完整可照抄的示例

**示例 A：单值结果 + 参数 + 规则门控**（照抄即是一条合法规则）

```toml
[meta]
id = "my-null-rate"
name = "我的空值率检查"
description = "统计总行数与空值率"
version = "1.0"
category = "column"
applies_to = ["Any"]
builtin = false

[query]
template = """
SELECT
    COUNT(*) AS total,
    COUNT("{col}") AS non_null,
    ROUND(CAST(COUNT(*) - COUNT("{col}") AS FLOAT) / NULLIF(COUNT(*), 0), 4) AS null_rate
FROM "{table}"
"""
parameters = ["table", "col"]
result_type = "single"

[[output]]
sql_name = "total"
json_name = "total_count"
value_type = "i64"

[[output]]
sql_name = "non_null"
json_name = "non_null_count"
value_type = "i64"

[[output]]
sql_name = "null_rate"
json_name = "null_rate"      # ← 与下一条 quality 的 field 对齐，门控才会生效
value_type = "f64?"

[[quality]]
field = "null_rate"
max = 0.1
severity = "warning"
message = "空值率超过 10%"

[render]
component = "NullCheckInfo"
display_order = 0
```

**示例 B：列表结果**（`result_type = "list"`，输出为数组）

```toml
[meta]
id = "my-top-values"
name = "我的 Top 值"
category = "column"
applies_to = ["Text", "VARCHAR"]
version = "1.0"
builtin = false

[query]
template = """
SELECT
    "{col}" AS value,
    COUNT(*) AS cnt
FROM "{table}"
WHERE "{col}" IS NOT NULL
GROUP BY "{col}"
ORDER BY cnt DESC
LIMIT 10
"""
parameters = ["table", "col"]
result_type = "list"

[[output]]
sql_name = "value"
json_name = "value"
value_type = "String"

[[output]]
sql_name = "cnt"
json_name = "count"
value_type = "i64"
```

### 4.7 参数替换与安全边界

**替换语法**：`parameters` 里声明的名字，在 `template` 中用 `{名字}` 引用。执行时把 `{name}` 替换为传入值。

- 替换采用两步法（先 `{name}` → 临时标记 `@name@`，再标记 → 实际值），避免 `{col}` 与 `{col_name}` 互相误匹配。
- **表名 / 列名建议用双引号包裹**：`"{table}"`、`"{col}"`（DuckDB 标识符规范；名字含特殊字符时必须加）。

**安全边界（请如实理解）**：

| 存在的防线 | 内容 |
| --- | --- |
| 参数值字符白名单 | 传入值只允许字母数字与 `_` `-` `.`，含其他字符即报错 |
| 输出字段校验 | `[[output]].sql_name` 必须在结果集中存在，否则报错 |
| **规则 SQL 静态门**（解析期） | 只放行**单条只读查询**：必须以 `SELECT` 或 `WITH` 开头；不得出现分号（末尾一个可以）；不得出现 `ATTACH` / `COPY` / `EXPORT` / `IMPORT` / `INSTALL` / `LOAD` / `PRAGMA` / `SET` / `CALL` / `CREATE` / `INSERT` / `UPDATE` / `DELETE` / `DROP` / `ALTER` / `TRUNCATE` / `VACUUM` / `BEGIN` / `COMMIT` 等关键字；不得调用 `read_*` / `parquet_*` / `*_scan` / `*_attach` / `*_query` / `glob` / `sniff_csv` / `query_table` 这类**会读文件 / 联网 / 附加外部库**的表函数 |
| **项目规则信任门**（默认不信任） | 项目层规则在**你做出决定前不加载、不参与分析**。首次打开「洞察规则」时弹一次确认框（列出带了多少条、叫什么、在哪个目录），决定记在**全局库**（不写在项目里——项目在被信任前就是不可信输入）。已拒绝也会记住（不反复追问），列表框顶部有横幅可随时改主意 |

> 静态门**只扫语法**：字符串字面量（`WHERE name = 'copy'`）、注释与**双引号包起来的名字**（`"copy"`）里出现上述词**不算违规**。所以列名 / 表名撞上关键字时，把它用双引号包起来就能过——这也是本文一直建议的写法。报错文案会直接告诉你：哪条规则、撞上了哪个词。

| **尚未落的防线** | 说明 |
| --- | --- |
| 完整沙箱 | ✖ 不计划；已核查「禁用扩展 / 只读连接」会连带砸掉连接 DuckDB 数据源、打开 CSV/Parquet、装扩展等自身能力（同一个内存单例） |
| 内容级信任 | 信任绑定**项目路径**，不是规则内容：项目里的规则后来被改动（例如 `git pull` 带进一条新规则）**不会**重新确认——否则你自己改规则也会被反复打扰。要更严一档需加规则集指纹（见架构 §12 Q1） |

> **现状（请如实理解）**：在你信任一个项目后，它带来的规则仍**原样交给 DuckDB 执行**——静态门挡的是误写与顺手抄来的危险语句，**不是安全边界**（DuckDB 没有官方解析沙箱，黑名单天然有漏）。所以“信任”这个动作本质上是在说：“我知道这个项目带的是什么”。

> 实务建议：只运行你理解或信任来源的规则文件；把项目规则目录纳入代码评审，与对待源码同样严格；**不要随意信任来源不明的项目**（尤其是克隆下来直接打开的）。

> ⚠️ 写规则时的**破坏性变更**（2026-09-17）：以前能写多语句 / DDL 的规则，现在会在解析期变成无效规则（规则管理里一行红字 + 明确文案）。改法：把多条语句合成一条 `SELECT`（子查询 / CTE），或把外部数据先由应用侧导入临时表。

## 5. FAQ 与排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 写好的规则在列表里找不到 | 字段名/位置写错（严格 schema，整条被拒）；或 `meta.id` 与内置规则重名而自己那份解析失败 → 仍是内置规则在生效 | 打开规则管理对话框看**校验失败行**的原文，按提示改；文件不在索引里说明读取都失败 |
| 规则列表里出现「文件不见了」 | 索引记录在、磁盘文件已删 | 恢复文件或从列表移除 |
| 打开规则管理时弹「项目规则：是否加载」 | 信任门（Q1 ③）：该项目带了规则文件而你还未做过决定 | 确认来源可信 → 「信任并加载」；不确定 → 「不加载」（记住这次决定，可在列表顶部横幅改主意） |
| 项目规则都在，但分析结果里没它们的份 | 该项目**未被信任**（未决定或已拒绝） | 规则管理顶部横幅点「信任并加载」 |
| 规则报「SQL 必须以 SELECT 或 WITH 开头 / 只能是一条语句 / 不允许出现「XXX」」 | 撞上了规则 SQL 静态门（解析期，见 §4.7）：写了多语句、DDL/DML，或列名 / 表名与关键字同名 | 改成单条 `SELECT` / `WITH`（子查询 / CTE）；列名 / 表名用双引号包起来 |
| 面板提示「结果集已失效或已过期，请重新执行查询」 | 源表（结果集临时表）已不在内存库里（宿主回收 / 会话结束）。洞察自身的样本表用完即删，不会过期 | 重新执行那条查询；仍然失败则看日志 |
| 面板提示「洞察分析任务过多，请稍候重试」 | 并发操作超过 4 | 稍候重试；避免同时触发「评估全表」与多个单列分析 |
| 大表分析报内存不足（Out of Memory） | 内存库有上限（默认 2GB，可在启动前用环境变量 `RDS_DUCKDB_MEMORY_LIMIT` 调大，如 `4GB`）；到顶时溢写到数据根的 `tmp/`，溢写总量上限默认 10GB（`RDS_DUCKDB_MAX_TEMP_SIZE`） | 调大内存上限后重试；或缩小分析范围（单列分析而非评估全表） |
| 分布区是空的 | 数值列行数 < 10（不生成直方图）；或列类型为 UNKNOWN | 正常行为，非故障 |
| 统计区为空、检查器全部「不适用」或「排除」 | 表为空、样本不到数据，或列类型不在规则 / 检查器适用范围 | 检查数据源与列类型；全空列属正常空态 |
| 空表（或过滤后无行）点「查看洞察」报「取样没有拿到列」 | 0 行结果的列名曾被 native 驱动丢弃（2026-10-18 已修，见 `insight-architecture.md` K20）；升级后仍出现则可能是旧二进制 | 重新编译 / 升级后重试；空表仍会出「有列无行」的表画像卡（列名在、无数据） |
| 点「评估全表」后部分列为 `—` | 那些列评估失败（如全空/类型未识别），失败会记日志并继续 | 查看日志；单列可单独重试 |
| 改了规则文件但不生效 | 目录监听尚未落地（Phase 0 / 0.6） | 用规则管理对话框的「重新加载」 |
| 改规则后列画像数字变了 | 基础统计由规则驱动（如 `numeric-stats`） | 属预期；见 §4.8 提示 |
| 存档 / 草稿箱里某些条目**没有**「查看洞察」 | 只有**数据文件**（CSV / Parquet / Excel / JSON）才有这一项；`.sql` / `.md` 之类不是数据；分析表型存档（本体是 `analytics.duckdb` **库文件**）尚未接入 | 正常行为；把数据文件放进草稿箱 / 归档后再看 |
| 读 Excel（`.xlsx` / `.xls`）报扩展相关错误 | `read_excel_auto` 依赖 DuckDB 的 **excel 扩展**（CSV / Parquet / JSON 是内置读取器，不依赖扩展） | 装好 excel 扩展后重试（扩展安装位置与「本地加速」同一套设置） |
| 「查看洞察」报「这个格式还不能分析」 | 该文件扩展名不在读取器名单里（名单只一处：`DuckDBEngine::file_reader_function`） | 转成 CSV / Parquet 后再看（`read_csv_auto` 能吃大多数分隔文本） |

## 6. 验收清单（USIT）

**画像与检查器**
- [ ] 结果表列头右键「洞察此列」→ 下钻区显示该列的**列摘要卡**（完整四区画像在中间页；未绑定连接的文档也要能用：按当前活动连接取样）
- [ ] 数值 / 文本 / 日期 / 布尔 / 全空 五类列的画像内容正确分派
- [ ] 空值率 > 5% 时数字转警告色，规则门控提示区出现对应提示
- [ ] 检查器四态（命中 / 未命中 / 不适用 / 排除）渲染颜色与文案正确；摘要环只统计适用列的命中占比，不出总分与等级
- [ ] 导航树表右键「查看洞察」→ 下钻区表画像卡显示列清单（前 8 列）、`PK` 角标（元数据有主键时）、可空性、缺失率、行数、底部采样口径提示
- [ ] 「评估全表」串行完成（能看到中间进度），各列回填事实明细与检查器状态；点列名下钻到列摘要卡
- [ ] 草稿箱 / 分析存档里的 `.csv` / `.xlsx` / `.parquet` 文件右键「查看洞察」→ 面板显示该文件的摘要卡与表画像卡（Excel 需 excel 扩展）
- [ ] 非数据文件（`.sql`）的右键菜单里**没有**「查看洞察」（不摆点了报错的入口）

**多列与结构**
- [ ] 导航树 schema 右键「查看洞察」→ 下钻区结构摘要卡（健康分环 + 表数 / 列数 / 问题数；schema 名写错应给可读回执，而不是一张空报告）
- [ ] 多列规则分析（列多选 ≥2、类型不匹配置灰、按数据形态渲染）能力保留，渲染入口待中间页复用；右栏多列目标为聚合占位
- [ ] 结构完整报告（健康分 + 四个折叠区；类型不一致点表名下钻）渲染保留待复用
- [ ] 下钻后切到表画像卡（取样走源取样通道，**不改动数据库**；限定名按驱动加引号）
- [ ] 结构报告「导出 ▾」→ JSON / Markdown：弹系统保存对话框，落盘后**状态栏**给回执（默认名 `schema-<schema 名>`；导出内容与界面同源）

**历史**
- [ ] 快照保存 / 历史列表 / 版本对比 / 清理能力保留（入口由中间页 / 资产库承接）：写入标「当前」（首版标「首版」）
- [ ] 未打开项目时：保存入口置灰、历史视图给引导而不是一直转圈
- [ ] 保存失败（如结果集已过期）只挂一行提示，**已有的历史列表照旧可见**
- [ ] 存储用量为后端真实统计（不是前端估算）
- [ ] 点更早的一版出现对比面板（最新那版不可点）；再点一次或 ✕ 关掉
- [ ] 对比的箭头/颜色只表方向，不变的那几行是灰的；算不出差的项显示「已变」而不是乱编数字
- [ ] 列表刷新（保存 / ⟳）后对比面板收起，不留下指向旧「当前」的差值
- [ ] 「清理」要先弹确认框（框里写着删多少天前的、当前有多少）；无项目 / 无快照时入口置灰
- [ ] 没东西可清时回执写「没有 30 天前的快照」，而不是报「清理成功」

**规则**
- [ ] ⚙ 打开的规则管理对话框显示三层分组，内置规则可禁用
- [ ] 禁用一条内置规则后，该规则不再出现在适用规则列表
- [ ] 故意写坏一个 TOML：对话框出现红色行并显示**错误原文**，且其他规则照常可用
- [ ] 「新建项目规则」在 `.RSmeta/insight-rules/` 建目录与模板并打开
- [ ] 新建的规则（照抄 §4.6 示例 A）能出现在列表中并被成功执行
