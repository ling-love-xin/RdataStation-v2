RdataStation · 洞察模块（M8）

一页看懂：它是什么、能做什么、怎么运转
右 Dock 洞察面板 · 五 Tab · 规则可扩展 · 结论可带走

把数据变成结论——
这份数据长什么样，它能不能用。

点一下表、某一列、一份草稿文件——洞察面板立刻给出画像、评分与结构报告； 再把结论存成快照，下次一对比就知道数据变了什么。 整个过程不搬数据、不猜类型、不摆假数字。

01

它回答三个问题

不是再做一个「看数据」的界面，而是把「看一眼就有判断」固定成流程。
这列能不能用？空值多不多、有没有异常值？
→
列画像四区 + 四维评分卡：基础统计 / 数据分布 / 数据质量 / 样本数据
这张表值不值得信？哪几列有问题？
→
表探查：列清单（主键 / 类型 / 可空 / 质量）+「评估全表」逐列串行出分
整个库结构有没有坑？
→
结构报告：健康分 + 四区结论（外键候选 / 类型不一致 / 孤立表 / 冗余列）
上个月和现在比，变好了还是变差了？
→
快照历史：存一版、再存一版，固定方向对比（选中 → 最新）

03

五个 Tab，各自给一句结论

每个 Tab 都遵守同一条纪律：没有数据就不摆数字——不产假分数、不画假分布、不编造历史。

列列画像

  • 四区：基础统计 / 数据分布 / 数据质量 / 样本数据
  • 评分卡四维 + 五档等级
  • NULL 显式呈现，分布画不出就说原因
入口：结果表列头右键 · 导航树列节点

表表探查

  • 列清单：序号 / 列名（PK）/ 类型 / 可空 / 质量分
  • 「评估全表」逐列串行，进度一列列回填
  • 点列名即下钻到该列的画像
串行是为了不撞后端并发上限

多列多列分析

  • 选择顺序 = 参数顺序（col1 / col2 …）
  • 规则按类型族自动过滤可用性
  • 结果与失败提示同屏，表单不丢
相关系数这类规则是有方向的

结构结构报告

  • 健康分 + 四区：外键候选 / 类型不一致 / 孤立表 / 冗余列
  • 表名可点，直接下钻看表探查
  • 导出 JSON / Markdown（导出你看到的这份结论）
空区照常渲染：空 = 检查过、没问题

历史快照与对比

  • 保存当前画像，形成版本链
  • 对比方向固定「选中 → 最新」，差值标方向不评好坏
  • 30 天前的快照一键清理，正文与版本链成对删
存储用量行拿不到就不显示
04

一次洞察的旅程

五步一条线：入口只发意图，取数在接缝，面板渲染零副作用。
STEP 1
选目标
导航树 / 草稿箱 / 分析存档右键「查看统计」，或结果集列头「洞察此列」。
M4 导航 · M5 编辑器
STEP 2
取样
连源或读文件 → DuckDB 临时表（tmp_i_*），按源取样；编辑器入口连表都不建，直接重跑 LIMIT 取样。
insight/service · engine
STEP 3
算结论
列画像 / 四维评分 / 表探查 / 多列规则 / 结构分析，全部在 DuckDB 上完成。
insight_engine · quality_scorer · schema_analyzer
STEP 4
看结论
面板按 Tab 分栏渲染，四态（空 / 加载 / 错误 / 数据）各有说法；错误可重试。
insight_view · view/
STEP 5
留档 / 带走
存快照（正文进项目 DuckDB、版本链进项目 SQLite）或导出结构报告；下次对比即知变化。
insight/store · 宿主写文件
05

架构：一屏看清谁负责什么

依赖只向下：insight → engine → shared。洞察不依赖任何业务 Feature crate，工作台只做装配。
入口 · 装配
workbench：右 Dock 面板装配、订阅面板事件、把「下钻 / 导出 / 取样」翻译成宿主动作。components/{nav_host,resource_host,scratchpad_host}.rs · services/editor_insight.rs
视图 · 面板
insight_view.rs 状态宿主（目标 / 五态 / 各 Tab 载荷 / 选择与折叠）+ view/ 按 Tab 分的渲染片段（header · column · table · multi · schema · history）。渲染零 I/O、零副作用，点击只改状态并发事件。
接缝 · 服务
jobs.rs 把事件变成后台任务并回填；service/ 是同步门面（列 / 表 / 多列 / 结构 / 快照 / 清理）。面板不自己取数——这是「谁在写状态」只有一处的原因。
分析 · 规则
insight_engine / quality_scorer / schema_analyzer 出结论；rule_* 负责规则解析、校验（解析期静态门）、执行与注册表（三层作用域）。
存储
store/ 快照双写：正文进项目 DuckDB、版本链与元数据进项目 SQLite；写失败成对回滚，清理成对删。
引擎 · 数据
engine：DuckDB 连接与分析临时表（duckdb/analysis.rs，内存闸 2 GB / 溢写 10 GB）、驱动元数据接口（结构洞察不写方言 SQL）。
依赖方向：insight → engine → shared ·workbench → insight ·面板不直接碰驱动连接
06

八个值得说的特点

每一条都是实现里守住的取舍，不是口号。

⚙规则即文件

三层作用域：内置（编译期内嵌 16 条）→ 全局 → 项目，后者覆盖前者。正文以文件为唯一真相源，进 git、可 diff、目录一改即热加载。

项目规则随仓库走 ⇒ 有信任门把关

★结论可解释

四维评分（完整性 / 唯一性 / 类型一致 / 分布均匀）× 五档等级；列级与表级共用同一套阈值与文案，分数与等级是「总分算出来的」，不是各写一份。

全空列不产分——没有依据就不给分

◧类型不靠猜

类型族来自真实元数据（驱动接口），不是名字里猜出来的；结构洞察因此零方言 SQL——换成 SQLite 也照样能用。

方言差异留在驱动层消化

⇥不搬数据

取样在 DuckDB 上做，中间临时表带 tmp_i_ 前缀、用完即删；编辑器入口干脆不物化——重跑一次 LIMIT 取样。

内存闸 2 GB、溢写进 <RDS_HOME>/tmp

⧗快照可追溯

一列一条版本链，方向固定「选中 → 最新」；清理按 30 天保留期，正文与版本链成对删，两侧条数对不上就转红报警。

对比失败会放掉选中位，不留死状态

◌边界诚实

能洞察的是「能出现在数据库导航树上的对象」（真驱动 + 活连接）与草稿箱 / 分析存档两块文件；只靠 ATTACH 或三方扩展到达的远程库，不在承诺范围内。

宁可说清不做什么，也不给假入口

⛨安全两道门

规则 SQL 先过解析期静态门（只放行单条 SELECT / WITH，拒 DDL、多语句、文件与远端表函数）；项目规则再过一个信任门，未决定前不装配、不执行。

如实声明：静态门是防呆，不是沙箱

⤓结论可带走

结构报告导出 JSON / Markdown（导出的是你屏幕上这份结论）；报告里的表名可点，一键下钻回表探查。

宿主只负责选路径与写文件
07

加一条规则 = 新增一种洞察

不用改 Rust：写一个 *.rule.toml，声明 SQL 模板、输出映射与质量门控即可（下面这条就是内置的「空值率检查」，节选）。
# {项目}/.RSmeta/insight-rules/column/null-check.rule.toml
[meta]
id = "null-check"
name = "空值率检查"
category = "column"
applies_to = ["Any"]        # 任意类型都能跑

[query]
template = """
SELECT COUNT(*) AS total,
       COUNT("{col}") AS non_null,
       ROUND((COUNT(*) - COUNT("{col}")) * 1.0 / NULLIF(COUNT(*), 0), 4) AS null_rate
FROM "{table}"
"""
parameters = ["table", "col"]

[[output]]                              # SQL 列 → 界面字段 + 值类型（解析期校验）
sql_name = "null_rate"
json_name = "null_rate"
value_type = "f64?"          # 空表时 NULL：没有空值率可言

[[quality]]                             # 质量门控：读的就是上面的输出字段
field = "null_rate"
max = 0.1
severity = "warning"
message = "空值率超过 10%"

1模板

{col} / {table} 是参数占位，其余是纯 SQL——在 DuckDB 上跑。

2输出映射

声明每个输出字段的名字与值类型；解析期就校验，写错会在规则列表里当场报错并列出可用取值。

3质量门控

给字段设阈值与提示语；字段必须真实存在（否则拒绝加载），空值算「算不出来」而不是「通过」。

08

从哪儿进，能洞察什么

凡是导航树上看得见的（真驱动 + 活连接）都能进；文件类数据源按格式直接读。
入口目标取样口径状态
导航树右键「查看统计」 库 / 表 / 列 连接 → DuckDB 临时表（source 取样） 已接
导航树右键「结构洞察」 库（schema） 驱动元数据接口（零方言 SQL） 已接
草稿箱行菜单 数据文件 CSV / Parquet / Excel / JSON 直接读 已接
分析存档行菜单 已归档资源 经源取样通道（与导航树同口径） 已接
编辑器结果集列头「洞察此列」 结果集的某一列 不物化：重跑 LIMIT 取样，跟随活动连接 已接
结构报告「导出 ▾」 当前报告 JSON / Markdown，宿主选路径写文件 已接
分析表型存档（M6 本体层） 分析产出的表 DuckDB 直接读本体文件 等 M6 P4.1
