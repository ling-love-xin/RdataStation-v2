表模型（提案）

network_configs 一张表 → 资源 + 链两张表
net_resources（网络资源 · 最小单位）
CREATE TABLE net_resources ( id TEXT PRIMARY KEY, name TEXT NOT NULL UNIQUE, kind TEXT NOT NULL, -- ssh | http | socks | ssl host TEXT NOT NULL, port INTEGER NOT NULL, auth_config_id TEXT REFERENCES auth_configs(id), props TEXT, -- kind 特定 JSON：ssh.forwarding{type:-L/-D, -- targetMode:inherit/fixed,bind,portPolicy}/ -- host_key_check/keepalive/compress/ciphers； -- http.auth_scheme/CONNECT 超时； -- socks.ver/remoteDns；ssl.material created_at, updated_at ); -- 唯一性：UNIQUE(kind, host, port) 软校验（保存前 UI 查重提示）
chains（协议链 · 组合）
CREATE TABLE chains ( id TEXT PRIMARY KEY, name TEXT NOT NULL UNIQUE, hops TEXT NOT NULL, -- JSON: [resource_id…] -- 有序、可重复引用、不内嵌 timeout_s INTEGER, -- 链整体建链超时（可选） created_at, updated_at ); -- 连接侧：network_method = -- direct | { resource: id } | { chain: id }

存量迁移（network_configs → 两表）

存量形态迁移说明
单跳档案（ssh / http / socks / ssl）→ 资源 1:1内嵌加密凭据 → 拆出 / 复用 auth 档案引用（凭据字段对齐 auth_field_specs 键）
chain 档案（config 内嵌多跳）逐跳按 kind+host:port 匹配既有资源 → 命中复用、未命中建资源然后链记录 hops=资源引用；同跳板多链自动去重（正是两层模型的收益）
引用关系连接的 network_config_id → 按形态改指 resource 或 chain旧表保留只读一个过渡版本（读取期双格式识别），验证后删除
三层影响面闭包（与 密码管理 联动）：auth 档案 → 引用它的资源 → 引用资源/链的连接。改「公司代理认证」= 资源 proxy-corp（1）→ 链生产跳板链（1）→ 连接（3），密码管理页影响面即按此闭包展开。
不做与观察：远程转发（-R）不做（桌面工具无场景）；-D 动态转发已按 2026-11-10 评审纳入（见 Tab1 转发区，修订原观察项）；「引用型 ~/.ssh/config 资源」（运行时读 config、变更自动跟随）挂 观察；后台健康巡检（定期单跳探测）默认必须关、仅用户显式开启——桌面工具主动扫内网是不合适的安全姿态；「最近使用」时间戳（资源卡引用数旁补最近哪条连接使用过）提案；环境同名资源端点映射（prod/dev 不同跳板）维持观察；链不做条件分支（单一路径）。
