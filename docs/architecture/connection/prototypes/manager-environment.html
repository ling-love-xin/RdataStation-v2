🧭 模式加载 schema（过滤器）核心写法对齐 DBeaver DBSObjectFilter 与本仓 ObjectMaskRule（B5-D13）——同一 pattern 语言
显示（include）
隐藏（exclude）
不勾正则 = glob：* 任意串 · ? 单字符 · 逗号分隔多条（OR）
语义（与导航过滤器一致）：exclude 命中 → 必隐藏（优先级高于 include）；include 空 = 全量候选；include 与 exclude 均不命中 = 隐藏。
两层过滤的分工：环境策略 = 配置期（建连时解析，进内省请求与补全候选）；导航浏览过滤器（B5-D13）= 浏览期（已加载对象上叠加，不入环境）。两层同语言、可叠加。
适用层级：schema（本期）· catalog / table / column 按 DBeaver per-type 过滤能力挂 观察。过滤不进缓存指纹（指纹按物理库，过滤是呈现口径）。

策略 → 生效点映射

本矩阵为核心设计：每条策略配的规则 × 在哪层生效（消费入口）× 现状 → 目标
策略项规则生效层消费入口（代码锚点）现状目标
只读连接非 SELECT / SHOW / EXPLAIN 语句 → 拒绝 执行前拦截 sql_service::execute 入口（语句分类已有 is_read_only） 未执行拦截 + 结果报「环境策略」来源
DDL 阻断CREATE / ALTER / DROP / TRUNCATE → 拒绝 执行前拦截 同上（与只读共用分类器，粒度不同） 未执行同上；错误码区分 DDL_BLOCKED / WRITE_BLOCKED
DML 需确认UPDATE / DELETE → UI 确认后放行 编辑器 UI editor 提交前（execution.submit 之前的宿主确认） 未执行确认对话含环境名与影响语句摘要
查询超时per-环境 timeout 覆盖全局 执行层 sql_service 已有 timeout 管道（现仅全局）→ 取值加环境来源 管道有 · 环境源无环境值 > 连接 driver_properties > 全局
结果行数上限超出截断 + 明示 执行层 ResultStore 写入前（fetch 循环计数） 未执行截断行 + 「已按 prod 策略截断至 1000 行」提示
schema 白/黑名单include / exclude pattern（glob 或正则，exclude 优先）——语言对齐 ObjectMaskRule 导航与补全 database::MetadataService 内省过滤 + 补全 provider（建连时解析进快照） 未执行过滤不进缓存指纹（指纹按物理库，过滤按环境呈现）
审计写语句尝试（含被拦截）落日志 执行前拦截点 + log_store 拦截器旁路 → log_store（已有基础设施） 未执行拦截与审计同点位落，一次接线
UI 徽标 / 确认级别状态栏 PROD 徽标 · 确认弹窗级别 编辑器 / 状态栏 editor 状态栏 + 确认对话 未执行徽标 = 环境色（低实现成本，可先行）
取值优先级（提案）：连接 policy_overrides（收紧或放宽单项）> 连接绑定环境的策略 > 无环境（现状行为，全部放行）。
连接建立时快照：策略值在建连时解析一次挂 ConnectionItem（environment_id 字段已存在，补 resolved 快照），执行中改环境不影响在跑会话——避免半条语句换规则。
不做什么（边界）：不做库内权限（GRANT 之类仍在库侧）；不在驱动层改写 SQL；schema 过滤不写进元数据缓存指纹（环境是呈现口径，不是缓存身份）；未绑定环境 = 显式「无策略」而非默认 prod（防误伤）。
