现状

shared/crypto.rs · 已实现
当前实现：AES key = SHA256(安装级随机盐 {RDS_HOME}/data/encryption-salt + 机器 ID machine-id)。 优点：零输入、无明文主密码驻留内存。代价：密文与机器绑定——直接拷数据目录到新机器 = 全部凭据解不开；且本机任意进程可读盐文件，加密挡不住同机攻击者（防的是「误提交 / 误分享数据目录时的明文泄露」，不是全量威胁模型）。

密钥来源选项

提案 · 三档可选，默认 ①
① 机器绑定（现状默认）已实现
安装盐 + 机器 ID。零配置；换机需走迁移流程（Tab4）。适合个人桌面工具的默认档。
② 系统凭据管理器 提案
主密钥存 Windows Credential Manager（DPAPI 保护，按当前用户派生）。换机 = 系统账户漫游 / 手动导出；盐文件泄露不再等于密钥泄露。落点：shared::crypto 增加 KeyProvider 抽象。
③ 主密码（最高档）提案
PBKDF2/Argon2 从主密码派生 KEK，加密随机 DEK 落盘。数据目录被整份拷走也无法解密；代价：启动 / 首次解锁需输入，忘记 = 凭据不可恢复（如实提示，不做后门）。
迁移语义：三档之间切换 = 用旧 key 解密全量 → 新 key 重加密（reencrypt_all，事务内分批；失败回滚保留 AES: 旧前缀密文）。档案密文格式不变（仍是 AES:{nonce}{ct}），只换 key 派生层。

换机 / 重装迁移包

提案 · 密文机器绑定的配套出口
导出 旧机：全部 auth_configs + 网络资源 + 链 + 环境（含策略）→ 单文件 .rds-vault「连接基础设施包」——换机一次恢复，无需分头重建
包内格式
迁移用 KEK（用户一次性口令 PBKDF2 派生）加密的「连接基础设施」清单：凭据档案 + 网络资源（两层模型）+ 链 + 环境与策略 —— 导出文件本身不含明文，可安全走网盘 / 聊天传输
不含
连接定义（走项目 / 全局库常规备份）、元数据缓存（指纹重建）、known_hosts（TOFU 首连重建）
导入 新机：口令解锁 → 按当前机器密钥来源（Tab2 所选档）重加密落库
冲突
