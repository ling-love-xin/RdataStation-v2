00先说结论：域是两条，不是一条

缓存目录按连接域分流，全局侧一直有缓存，只是你手上 4 条连接都是 P_ / GP_ 前缀，所以全部落在项目侧。 第二个容易被误读的点：GP_（全局＋项目）的连接记录有两份，但它的缓存落在项目侧—— NavSource 把 GP_ 判为 Shared，而缓存域映射只把 Global 送去全局目录。因此同一个物理库被 GP_ 引用在两个项目里会各扫一份。

前缀作用域连接记录落库L2 缓存目录
G_ 仅全局 global.db / global_connections <RDS_HOME>/data/system/global_metadata/
真机：conn_G_conn_SQLite_Example.sqlite、meta_5245bb07154b9192.sqlite
P_ 仅项目 project.db / connections {project}/meta/connection_metadata/
GP_ 全局＋项目 全局库一行 + 项目库一行（共享引用） {project}/meta/connection_metadata/

01存储面：四个库 + 两个缓存目录

连接记录、驱动目录、插件登记都在 SQLite；分析明细在 DuckDB；元数据缓存是「每连接一份」的独立 SQLite 文件。

disk磁盘布局以真机为例：RDS_HOME=.rds，项目根 D:/data/A1/A1
全局库 .rds/data/system/global.db 62.76 MB。持有 global_connections、drivers、plugins、duckdb_extensions、extension_operations。连接对话框驱动下拉的唯一数据源。
全局分析库 .rds/data/system/analytics.duckdb 0.76 MB。全局侧的 DuckDB 加速 / 联邦目标库。
项目库 {project}/.RSmeta/project.db 0.58 MB。持有 connections（25 列，没有 url 列）、导航展开状态等。
项目分析库 {project}/analysis.duckdb 项目级 DuckDB；写路径独占，读路径用 READ_ONLY 打开避免单写者锁。
↓
全局域 L2 <RDS_HOME>/data/system/global_metadata/ 只放 G_ 连接：meta_{fp}.sqlite 或回退 conn_{safe}.sqlite。
项目域 L2 {project}/meta/connection_metadata/ 放 P_ 与 GP_：同一物理库在域内共享 meta_{fp}.sqlite，跨域不共享。

05指纹面：缓存文件名的唯一来源

身份 = 驱动族 + 地址 + 主体。三者任一改变都换文件；连接名、密码、SSL 参数都不参与，所以那类改动不会重扫。 本次事故的根因就在第一项：它原本写的是「驱动实现 id」，2026-11-15 已改为「驱动族」。

06缓存面：三级 + 展开链路

L1 是进程内存，L2 是每连接 SQLite，L3 是实时内省（不是缓存）。L1 曾长期无人写入，现已补齐读写。

07三处故障点（本次排查）

F1 驱动 id 断层：记录写 mysql，注册表里只有 mysql_native 已修（数据）

D4 把 sqlx 实现剥离成 sidecar 插件，内置实现改名为 mysql_native / postgres_native，mysql / postgres 这两个 id 变成「由 rds.driver.sqlx 插件贡献」。

连接记录里 driver 与 driver_id 两列仍是旧 id，DriverRegistry::get 精确匹配查不到 → CONN_DRIVER_NOT_FOUND。已把 4 行两列改为 mysql_native / postgres_native，备份 project.db.bak-20261115-1054。

设计上的欠债：提示文案里的「去装 rds.driver.sqlx 或用 MySQL (Official)」这条退路只在单测里断言过，界面上用户只看到裸 Display，没走到弹窗（data_source_service.rs:1728-1741）。

F2 指纹把「驱动实现 id」当身份，换实现即换缓存文件 已修（代码，待真机验证）

改 F1 的 driver 列会连带改指纹：canonical 从 v1|mysql|… 变成 v1|mysql_native|…，文件名从 meta_439cdbba942f1c99 变成 meta_8712861e2c2f5b96。旧缓存（500 KB / 600 KB）还在盘上，只是没人再打开，于是每次展开退回 L3。

已加 driver_family() 归一到族，且不升 format_version（升了会让 sqlite/duckdb 的完好缓存一起作废）。cargo test -p rds-store --lib -- metadata_identity 22 passed。

残留：今天新建的两个空文件（meta_8712861e2c2f5b96.sqlite 448 KB、meta_a4329bc00db1e446.sqlite 556 KB）会变成孤儿，尚未清理。

F3 插件页显示「全部 0」，但 drivers 表有 3 行 未定位

数据层是齐的：plugins 3 行（mssql-rust / oracle-rust / postgres-py，均 sidecar、is_enabled=1），drivers 7 行，日志 插件驱动行同步：写 1 → 2 → 3 行 说明 loaded_plugins 有 3 条。

但 PluginPanel::plugins_snapshot() 返回空。唯一悬空解释是 PluginPanel::new 首刷的 cx.spawn 回写竞态——weak.update 失败被 let _ = 静默吞掉，没有运行期证据。

这条分支和 F1/F2 是同一个根源的另一面：「表里有行」和「内存里有实现/有快照」不是同一个事实源，缺一道对账。
