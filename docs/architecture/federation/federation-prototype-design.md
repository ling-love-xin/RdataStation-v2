# 联邦查询 · 原型设计（只读跨源查询）

> 交互稿的目标态；实现进度见 `federation-dev-plan.md`（**第一期已收圆；T3.2 L2 挂载路径已接**）。
> 原则与编辑器一致：**不宣传未实现**、**状态如实**、**命名如实**。
> 本文里**尚未上**的局部已在 §9 列明；已落的局部在实现里都有对应单测 / 真机探针。

## 1. 入口与总览

联邦不是一个新面板，而是**执行位置的第三档**（`执行位置 ▾ → 联邦查询`，B13 已存在）。
联邦档下多出来的东西只有三样：

1. **源清单**入口（工具栏右侧「执行位置」旁）；
2. **主源**显示（状态栏 + 源清单里都能看到）；
3. 结果区的**代价与一致性**标注。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [SQL] ▾ │ ▶ 执行 ▾ │ ⇤ 格式化 │ ⋯ 更多 ▾ │   [执行位置：联邦 ▾ ⓘ] [源清单 ▾] [连接 ▾] │
├──────────────────────────────────────────────────────────────────────────┤
│  SELECT o.id, c.name                                                      │
│  FROM mysql_src.orders o                                                  │
│  JOIN oracle_prod.SALES.CUSTOMERS c ON c.id = o.customer_id               │
│  WHERE o.total > 1000;                                                    │
├──────────────────────────────────────────────────────────────────────────┤
│ 结果 1 │ 联邦 · 3 源 · 非事务一致快照                        （结果集标签条）│
```

## 2. 源清单（`源清单 ▾`）

点开是一份**清单浮层**（不是对话框：它要被反复看，而不是“确认一次”）。**已上线（T1.6）**：
形状是工具栏右侧一个下拉（`源清单：2 源 · 主源 mysql_src ▾`，**只在联邦档出现**），内容：

```
┌─ 源清单 ──────────────────────────────────────────┐
│ 联邦 · 2 个源 · 主源 mysql_src                   │  ← 汇总行（不可点）
│ 主源 oracle_prod 不可用，已改用 mysql_src         │  ← 回退说明（有才出现）
│ ✅ mysql_src · MySQL · 可用 · 42 张表 · 主源      │  ← 逐行源（不可点；失败行带原话）
│ ⚠️ oracle_prod · Oracle · 失败：ORA-12541 无监听  │
│ 重新挂载全部源（刷新表清单）                       │  ← 动作
│ 设为主源：mysql_src                               │  ← 只给可用的源
│ 重新挂载：mysql_src / 重新挂载：oracle_prod        │  ← 失败的行也要能重挂（修好再试）
└──────────────────────────────────────────────────┘
```

规矩（实现与交互稿一致）：

- **失败的行不消失**：保留别名、来源、与**原话原因**（`SourceState::Failed(原话)`，口令已脱敏）；
- 每行可**重挂**（刷新表清单；与加速档的“重新挂载源库”完全同语义）；
- 「设为主源」点击即切，状态栏报一句（未限定名的解析者）；
- 动作走**旁路线程**（`ATTACH` 是 I/O），回执在状态栏给一句“做到了什么”（如“已重新挂载 mysql_src（354 张表）”）；
- 「＋ 添加源」= 连接对话框 → 高级 → **「DuckDB 直连（本地加速 / 用作联邦源）」**开关（架构 D15）。

## 3. 主源（未限定名的解析者）

- 状态栏连接段之后显示：`通道 联邦 · 主源 mysql_src`；
- 未限定名（`SELECT * FROM orders`）**只在主源解析**；
- 两源同名表时：**报错**，错误卡片给两个限定名候选，点一下即替换光标处的表名：

```
┌─ 语义错误 ───────────────────────────────────────────────────────────────┐
│ orders 在 2 个源里都存在，未限定名无法解析：                                │
│   · mysql_src.orders_db.orders                                          │
│   · oracle_prod.SALES.ORDERS                                            │
│ [用第一个候选替换]  [用第二个候选替换]                                     │
└─────────────────────────────────────────────────────────────────────────┘
```

（这条是 D3 的落地：不猜，且给出**可执行**的修复动作。）

## 4. 用户写 SQL 的心智模型

| 写法 | 解析 |
| --- | --- |
| `orders` | 只在主源（`mysql_src`）里找 |
| `mysql_src.orders_db.orders` | 限定到 `mysql_src`（推荐写法，**跨源必须**） |
| `ora.ORDERS`（L2 源） | **两段名**：Oracle 的表挂在附加源的 `main` schema 下（真机实测：三段名会报 schema 不存在） |
| `duckdb` 本地表 / 临时表 | 不受影响（本地对象优先，与 DuckDB 一致） |

提示语只出现两处（不做常驻说教）：源清单底部一行、以及同名冲突的错误卡片里。
**按源类型给写法**（T3.2 已落）：L1 源（MySQL / PG / SQLite / DuckDB）三段名，L2 源（Oracle 这类）两段名——
有 L2 源在池里时，结果区那行小字写成
`跨源请写 别名.schema.表（oracle_src 写两段：别名.表，不写 schema）`（判据是 `kind.needs_secret()`）；
写错时的报错原话里会带 `schema "X" does not exist`，源清单里该源的重挂入口就在下一行。

### 4.1 L2 源的写保护（对用户可见的部分）

L2 源（Oracle）的扫描器**不支持 `READ_ONLY`**（真机台账），所以对它写不是由 DuckDB 拒的。
应用侧有两道闸（外加账号那道）：

1. **编辑器闸门**（先拦，加速 / 联邦两档共用）：写语句 / DDL 在提交前就拒，文案是
   `联邦通道不能写源库（外部源只读），请切回源库再试`（只说结论，不说机制）；
2. **会话层**（旁路动作也会经过它）：直接走到执行器时（如源清单上的重挂、自动化调用）由
   `FederatedSession` 拒，文案点名源：

```
┌─ 执行失败 ───────────────────────────────────────────────────────────────┐
│ 源 oracle_src 不支持只读挂载（它的扫描器没有 READ_ONLY），对它的写被拦下了：    │
│ 请在源库上执行，或改用只读账号                                              │
└─────────────────────────────────────────────────────────────────────────┘
```

会话层这一道才是 L2 的**真正保障**（编辑器那道只看语句类型，认不出就放行）；第三道是只读账号。

判据是**保守**的（不解析语义）：写语句（与驱动层同一份 `returns_rows`）只要提到该源的别名
（`oracle_src.` / `"oracle_src".` / `` `oracle_src`. ``）或它正好是主源（未限定名落在它上面）就拒。
宁可多拒一句（用户改去源库执行 / 换只读账号），也不能漏过去真写——**本地临时对象不受影响**。

> L2 也**不做本地加速**（只做联邦源）：在加速档的门控里会看到“Oracle 只能做联邦源
> （本地加速不支持）：它的凭据要走会话级 Secret”，而不是一个选了就失败的入口。

## 5. 结果区：代价与一致性

联邦结果与普通结果共用结果区，多两处标注：

| 位置 | 内容 | 依据 |
| --- | --- | --- |
| 结果集标签徽标 | `联邦`（已有） | B13 |
| 工具栏摘要尾 | `联邦 · 3 源 · 非事务一致快照`（悬停给源清单） | 架构 D8 |
| 状态行 | `共 N 行 · 耗时 x`（与普通一致） | —— |

第二期再接 DuckDB 的扫描量（架构 §8 #3）。

## 6. 错误呈现（跨源必须点名源）

```
┌─ 执行失败 ───────────────────────────────────────────────────────────────┐
│ 源 oracle_prod 报错：ORA-00942: table or view does not exist             │
│ [复制]  [在源清单里查看该源]                                              │
└─────────────────────────────────────────────────────────────────────────┘
```

- 源侧的错 → 点名源；**本地 SQL 的错**（表名拼错 / 语法）→ 正常诊断定位（B6 已有）；
- 一个源不可用但查询没用到它 → **不打扰**（不弹、不红）；
- 查询用到不可用的源 → 报错 `源 X 不可用：<原因>`，并给「重试该源」动作。

## 7. 门控与空态矩阵

| 状态 | 表现 | 恢复入口 |
| --- | --- | --- |
| 没有开启「DuckDB 本地加速」的连接 | 「执行位置 ▾」里联邦档置灰，行尾写“还没有开启「DuckDB 本地加速」的连接（连接对话框 → 高级）” | 连接对话框里开开关 |
| 只差一个源（开关开着但没连上 / 只有自己） | 置灰 + 行尾点名：“联邦查询至少需要两个已连接且开启「DuckDB 本地加速」的连接（现在只有 X 一个已连接的源；Y 还没连上（先在导航里连接它））” | 连上另一个源 |
| 扩展未装 | 该源行 `⚠️ 失败：扩展 X 未安装`（**不自动联网装**） | 行尾「安装扩展」（显式动作 + 进度 + 失败原话） |
| DuckDB 未就绪 | 联邦档置灰（复用 B13 的门控顺序） | 引擎初始化 |
| 全部源可用但查询为空 | 正常空网格（不特殊处理） | —— |
| 结果被上限截断 | 状态行 `已拉 10,000 行（上限）` | 「提高上限 / 缩小筛选」 |
| 源挂不上（认证 / 网络 / 扩展） | 其余源照常可用；结果区小字写出“源 X 未挂上：<原话>”（原话里的口令已脱敏） | 修好连接后重跑 / 重挂该源 |
| 写 L2 源 | 会话层拒绝（见 §4.1；原话点名源 + 怎么办）；L1 源仍由 DuckDB 以 `read-only mode` 拒 | 在源库执行 / 换只读账号 / 改用只读连接 |
| L2 连接串缺件（凭据 / 服务名） | 那个源不参与，结果区小字点名：“连接 X 没参与：Oracle 连接串缺少服务名（…）” | 连接对话框里补全（服务名不能猜：写 `XE` 会得到 `ORA-01017`） |
| 把 L2 源选为本地加速 | 加速档直接档下（原因：“…只能做联邦源（本地加速不支持）…”），不给“选了就失败”的入口 | 改用联邦档 |
