搜索与树的分工

  • 树：知道在哪，看同层还有什么、谁和谁同级
  • 搜索：知道叫什么，跨根扁平出结果，每行带面包屑
  • 最小单位是表 / 视图，不搜列名，也不搜分组名
  • 最近：重复使用的对象置顶，省掉再从树里找一遍

右侧为什么常驻

  • 选中即回答「这是什么、多大、能不能用」
  • 可见范围（本机 / 仅会话）在这里讲清，避免选了才报错
  • 资产类对象标「已归档 · 只读」，与草稿文件区分

资产为什么挂在「文件」下

  • 归档本体在 resources/（文件）与 analytics.duckdb（库文件）
  • 两者都是本机磁盘上的持久物，与草稿同类；DuckDB 那栏装的是临时产物
  • 与左侧「资产库」面板同一实体：面板管生命周期，这里只是选它来分析
  • 全局实例（{system}/analytics.duckdb）同组，标注「跨项目」——它是项目之间唯一法定的传递通道
