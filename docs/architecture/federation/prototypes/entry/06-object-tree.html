对象树 · 复用与规范

picker 是第 5 个树消费方 · 复用行原语，不复用树组件 看交互原型
你要「复用草稿箱、数据库导航栏那类」，可复用的**不是树控件**，而是外壳里的行原语（激活条 / 展开槽 / 缩进 / 行高预算）。这三个面板的行模型与交互各不相同，外壳已明确不抽通用树组件——picker 同样只借原语。

01三个根各自长成什么树

数据库 mysql_src 连接（展开才内省） └ analytics catalog（有独立 schema 的驱动才有） └ orders 表（叶子） DuckDB 结果集 tmp_q_ 组：本地单例 / 仅会话 └ tmp_q_result_8f2a 表（叶子） Mock 数据 tmp_m_ / 插件输出 tmp_p_ 文件 草稿箱 └ 数据 └ *.parquet 资产库 ├ 归档文件（resources/） └ 分析表（analytics.duckdb · main） 外部文件 已引用

深度上限 3。列不做树节点（否则连到 5 层，弹层宽度不够），列结构放右侧元信息里「查看列结构」。数据库叶子只到表；表下不再展开索引 / 列 / 约束。

02复用清单（可回链到源码）

符号用说明
tree::active_bar用选中行左侧 2px 条；调用行须 .relative()
tree::disclosure_slot用10px 展开槽；宽度是缩进算式的一部分，不得改
tree::disclosure_icon用12px chevron，四个面板已统一
tree::indent_spacer
tree::indent_rem		用深度缩进；picker 一行一个视口宽度，二选一即可
tree::count_badge用搜索命中的计数角标
tree::RowHeight用虚拟列表行高预算，估算与渲染成对维护
ui::TREE_INDENT用0.875rem 步长，勿手写数字
tree::Tree / 通用树组件不用外壳已裁决「这一行长什么样归各面板」，三处行模型互不相同
为什么不用 tree::Tree：它是 set_items 整棵替换、不支持增量，且行内复合控件（计数、pill、会话标记）超出它的边界。导航 / 草稿箱 / 资产库全部走 v_virtual_list + 自绘行。

03搜索规范

  • 跨三个根，不限于当前 tab——记不清它在哪一栏时最有用
  • 匹配档位（决定排序）：前缀 100 > 子串 70 > 子序列 40（ods 能命中 orders）
  • 同档内按使用频次（最近用过置顶），再按名称字典序
  • 结果行带面包屑（数据库 / mysql_src / analytics），点一下即选中，不必先展开树
  • 最小单位是表 / 视图：不搜列名、不搜分组名、不搜索引（已裁决）
  • 上限 50 条，超出显示「refine」提示，不做分页
  • 清空：Esc 只清搜索词（与草稿箱 / 资产库的 Esc 语义一致），不清选中
  • 大小写不敏感；不做拼音首字母匹配（会引入拼音表依赖，收益低）

04键盘

键行为
Ctrl+F聚焦搜索框
↑ ↓在当前可见行间移动选中（含搜索结果）
→展开当前节点 / 进入第一个子节点
←收起当前节点 / 回到父节点
Enter确认选中（等价点主按钮）
Esc有搜索词先清词，否则关闭对话框

行本身是 Button::ghost() 而不是自绘 div：直接拿到 track_focus + tab_stop，不必自己补键盘激活；ElementId 用业务键（conn+catalog+schema+table / 相对路径），不用下标，否则增删后焦点会串行。

05懒加载与预载

根策略
数据库连接行展开时才内省（NavigatorService 有 L1/L2 缓存，首次走 block_on，与现有 render_connected 同款先例）；打开对话框不预载全部连接的表
DuckDB打开即预载（本地库 + 单例，量级小）；会话表按 owner 过滤
文件 · 草稿箱打开即 list_local_entries(u32::MAX) 递归拍平（现状 collect_drafts 已这么做）
文件 · 资产库本项目登记 + 全局登记两段并列：归档文件读 M6 登记，分析表读 information_schema.tables（限定 table_schema='main'）；全局段走全局库连接
两个实现约束：① WHERE table_schema='main' 不能去掉，否则 temp schema 的临时表混进资产库；② 全局分析库是单写者（GlobalDatabaseManager::duckdb_conn() 持有），picker 不得再 Connection::open 一份去列它——现状 collect_analysis_tables 正是直接 open 文件，接全局前必须换通道。

06与三个现有面板的差异

面板展开态交互
数据源导航 M4落库，驱动后台加载拖拽 / 右键菜单 / 重命名
草稿箱 M5纯内存搜索 / 命中角标
资产库 M6落设置分组 / 版本 / 标签 / 检出
picker（本条）纯内存，随对话框关闭丢弃单选 + 搜索 + 最近使用

picker 不做：拖拽、右键菜单、重命名、多选、新建。它是「选一个目标就走」的模态，把面板的管理动作搬进来会变成第二个资产库。

07落地切片（Phase 5 的改法）

现状：PickerState 是扁平索引字段（conns / catalogs / schemas / tables / selected_table / drafts / selected_draft / analysis_tables / selected_analysis），render_* 五个函数各自拼单列列表。改成树只需三步，不动 SourceKind：

步改什么为什么
1新增 fn group_of(kind) -> Group{Database,DuckDb,File}，只用于 tab 与组标题三个根是视图分组，不是新的数据模型；5 个叶子保留
2PickerState 增 expanded: HashSet / query: String / selected: Option / recent: Vec树态与搜索态必须进状态对象——模态渲染闭包每帧重建 UI
3五处 render_* 合成一个 render_rows(&[Row])，Row 只带 depth / kind / label / meta / selectable三个根共用一套行渲染；各行数据源各自产出 Row

has_target() 改为按选中节点 kind 判断（Table / File / Temp 可确认，Group / Folder / Conn 不可）。confirm_prefix + 选中标签 的现有逻辑不动。

没做验证的部分：本页是设计，不是实现。树 + 虚拟列表 + 模态内 block_on 内省的组合有没有卡顿、v_virtual_list 在模态闭包里创建 handle 的生命周期是否可行，都需要在 Phase 5 起头用一个最小窗口用例先钉住（照 visible_databases_dialog 的先例）。

08仍未决

  • 「最近使用」存哪：内存（本会话）还是落设置（跨会话）？落设置要新增一个 key，且要能被「项目已删」清掉。
  • 全局表的读取通道：见 §09，需先实测「单写者连接 + 只读 ATTACH」是否共存。
  • 全局与本项目同名时怎么排：G_ 前缀已能区分，是否还要在排序上把全局段整体置后，待定。

已裁决（不再讨论）：① 不等 M6 二期，资产库「分析表」直接按 ArchiveKind::Analysis 完整语义（带版本 / 归档态 / 只读）；② 搜索最小单位是表 / 视图，不搜列名。

09全局实例在树里怎么放

事项做法 / 依据
位置文件根 → 资产库 → 全局 · 跨项目共享，与本项目两段并列，不混排
命名全局表带 G_ 前缀（全局分析库的连接前缀），树里直接显示，不另加符号
语义项目 → 全局 → 项目 是唯一法定路径，项目之间禁止直传（global/mod.rs:18-19）；分发后在本项目成为副本，改动只影响副本
存储拓扑全局表 {system}/analytics.duckdb（单写者）+ 全局登记 {system}/global.db（scope='global'）；项目侧是 {项目}/.RSmeta/analytics.duckdb
硬约束全局库是单写者，只能复用 GlobalDatabaseManager::duckdb_conn()；picker 不得 Connection::open 一份去列它（现状 collect_analysis_tables 正是直接 open）
缺口generate_attach_global_sql（legacy.rs:336，ATTACH '…' AS global）没有生产调用点——本地单例与联邦会话目前都没挂全局库，选中全局表会 table does not exist
待实测全局单写者连接与只读 ATTACH 能否共存；判别动作：同一用例里持有 GlobalDatabaseManager 连接并另开 ATTACH '…' (READ_ONLY)，看是否报锁
为什么两段分开而不合并：用户必须一眼看出自己改的是「本项目副本」还是「全局原表」。合并成一个列表后，改错对象是不可逆损失（全局升级路径只允许单向）。
