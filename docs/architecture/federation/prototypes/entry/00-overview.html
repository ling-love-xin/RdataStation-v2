二次分析是「同会话」：结果集表与分析 SQL 都在联邦会话里，这样用户 SQL 才能跨源 join。本地档逐字不变。

三个决策点

  • ① 分析对象：表 / 文件 / 结果集，单选（沿用 source_picker）
  • ② 数据量：行数 / 百分比 / 过滤 / 种子（沿用 ProbeConfig）
  • ③ 会话：默认本地 DuckDB，可选「用联邦查询」

为什么 ③ 默认关

  • 洞察与二次分析是默认进入，不是通道选择；多加一次必答项只会拖慢常规分析
  • 联邦有真实代价：首次要装扩展、每源一次 ATTACH、远端扫描
  • 不足 2 个可挂源时，开关不出现（而不是灰显）

共享的是什么

  • 会话（按 conn_id 缓存），不是一条全局连接
  • 同一 owner 的编辑器 / 洞察 / 结果集分析共用一个会话
  • ATTACH 与扩展 LOAD 从「每次」降到「每 owner 一次」

边界

  • 外部源只读；本地临时对象可用
  • 不做跨源写 / 跨源事务 / 快照一致
  • 挂不上的源不阻断，查询用到时才报错并点名
