数据对象 · 原型总览

先核对模型，再看三页界面
这套原型的核心只有一句：「分析中用到哪些表」和「被管理起来的成果」是两层，之间只有一条单向升级路。下面的三段模型是判断任何一页界面是否越界（把资产当工作区表、或把临时表当成果）的依据。

01b数据量口径：只有洞察能采样

同一条「取数」，三种用途对完整性的要求不一样，界面上必须说清，别让用户以为自己看的是全量。

用途能不能少行口径与代价
洞察可以采样本来就是「看一眼分布」：一次全取 LIMIT 500 落到 tmp_i_，采样是它的语义，不是妥协。
分析不许丢结果集再分析 / 编辑器 SQL：对这一份结果的全量行做统计，少几万行就不是同一份结果。早期 20,000 行上限已按此口径删除。
联邦不许丢跨源 join 一旦截断，结果直接是错的；慢就慢，靠后台挂载 + 进度承担，不靠少读行。
资产不许丢只读、只取最新版本；要旧数据先在资产模块回退，不在取数时挑版本。

实现含义：凡「有可能少行」的地方（当前只有洞察），必须在界面上写明采样行数；凡不该采样的地方，代码里不该出现行数上限。

04需要你核对的五个点

A
源库表要不要进「数据对象」列表？

它会占据大量行（14 个连接）。我按「进，但标外部引用、连接分组默认收起、展开才拉表清单」处理。

我的建议：进。否则用户找源表还得回左侧导航树。
B
资产行要不要显示版本徽标？

我按「显示最新 vN」处理，且不给版本选择，回退只在资产模块做。

我的建议：显示。否则「我读的是哪一版」无从判断。
C
工作集有没有上限？

多源洞察一次挂 N 个源，N 越大首次取样越慢（是一次全取）。

已定（2026-11-16）：软上限 8。超过只在面板底部提示代价，不硬拦——代码与外框一致。
D
哪些对象允许「清理」？

我按：临时表（tmp_q_/tmp_i_）与分析库表可删；资产不可删，只能去资产模块走回收站。

我的建议：保持这条边界，别在分析侧给资产删除入口。
E
「升级为资产」放在哪、谁能升级？

已定（2026-11-16）：只有临时表与临时结果集可以升级成资产；入口不在数据对象面板，而在数据导航栏 / 草稿箱等原有入口。资产对象只能是数据对象——连接、账号这类信息不能成为资产。

所以 07 面板的职责只是「把资产列出来、只读引用」，不给升级按钮；08 对话框也不承担升级（它是「命名 + 临时 / 留分析库」）。
