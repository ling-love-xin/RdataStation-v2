数据对象 · 原型总览

先核对模型，再看三页界面
这套原型的核心只有一句：「分析中用到哪些表」和「被管理起来的成果」是两层，之间只有一条单向升级路。下面的三段模型是判断任何一页界面是否越界（把资产当工作区表、或把临时表当成果）的依据。

01三段模型

源 外部
数据在别人那里，我们只有读的权利。
  • 源库表
    连接里的表，按连接 / 库 / 表定位
  • 文件
    本地 parquet / csv 等，按路径定位
  • 全局分析库表
    data/system/analytics.duckdb
→只读引用
不占空间
分析中的表 本机
为了算这一次而存在，可以随时丢。
  • 结果集 tmp_q_
    查询 / 二次分析物化，会话级
  • 洞察产物 tmp_i_
    按采样口径取出的子集
  • 项目分析库表
    落库的分析结果，长期可分析、可删
→升级
单向
资产 受管
有版本、只读、名字不带前缀。
  • 本体
    分析库里的持久表，或已加载的文件
  • 参与分析
    只读，且只取最新版本
  • 要用旧版本
    先在资产管理里回退
  • 不做快照
    读资产 = 直读本体，不复制副本

02对象分类：界面上每一行长什么样

对象身份（在库里是什么）通道标签生命周期可做
源库表 conn_id + 库 + 表 → 源库 不受我们控制 分析 · 加入工作集 · 作联邦源

04需要你核对的五个点

A
源库表要不要进「数据对象」列表？

它会占据大量行（14 个连接）。我按「进，但标外部引用、连接分组默认收起、展开才拉表清单」处理。

我的建议：进。否则用户找源表还得回左侧导航树。
B
资产行要不要显示版本徽标？

我按「显示最新 vN」处理，且不给版本选择，回退只在资产模块做。

我的建议：显示。否则「我读的是哪一版」无从判断。
C
工作集有没有上限？

多源洞察一次挂 N 个源，N 越大首次取样越慢（是一次全取）。原型没设上限。

我的建议：软上限 8，超过时在「分析已选」旁提示代价，不硬拦。
D
哪些对象允许「清理」？

我按：临时表（tmp_q_/tmp_i_）与分析库表可删；资产不可删，只能去资产模块走回收站。

我的建议：保持这条边界，别在分析侧给资产删除入口。
E
「升级为资产」放在哪？

候选：① 07 行内动作；② 资产管理面板的新建入口；③ 两处都有，行内是快捷方式。

我的建议：两处都有，但只保留一份实现（行内只是带着对象跳过去）。
