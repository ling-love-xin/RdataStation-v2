选中「联邦」→ 右侧数据对象自动展开，可直接加源
通道切换本身就是「我要用哪些源来算」的声明。所以选到联邦时右侧自动展开数据对象（不是弹窗），工具栏多出加源，加源复用 01 的连接树与多选。反过来，切回「源库 / 本地加速」时面板不收起——用户可能还想拿它选分析对象，只是面板顶部会说明「当前通道只用一个源」。
实现状态（2026-11-16 核对）：本页不是全部都已落地，逐条标注，避免拿原型当现状。 已实现：三档通道（源库 / 本地加速 / 联邦）可互相切换，含切回源库不被连接状态挡住； 首次切到联邦时右侧共用那份数据对象面板自动展开一次（之后归用户开合，不再抢屏）； 面板的源就落在「已挂载的源」段；结果集右键「分析这份结果集…」→ 08 命名与去向对话框。 源清单按钮上现在直接写「N 源 · M 未挂载」，浮层里有「重新挂载全部源」「设为主源」「重新挂载某个源」。 未实现：只有「加源」——往会话里新增一个源。engine 侧没有“新增源”的 API，会话是按源指纹 建的（`ensure_session` 指纹一变就整会话重建，会话内临时表随之失效），所以加源不是加一行，是重建会话： 要新开一条宿主端口（编辑器请求 → 宿主把 01 的 source_picker 调起来多选 → 回传源清单 → 编辑器重建）。 这条端口不该塞进 `SourcesPort`（它是纯内存读），要照 `editor_insight` 那套新挂一个 attach。

执行联邦前的确认（新增）

联邦不许丢数据，所以这里没有「采样 / 限制行数」的选项——只交代这次要扫多少。

将跨 2 个源全部扫描：库方预估约 120,000 行（估算，实际可能更多）。
全量参与，不截断、不采样——慢就慢在等待上，别错在结果上。
想更快：在 SQL 里加过滤或收窄源清单。
执行 回编辑器改 SQL
  • 估不出来就不编数字：行数未知时写「执行时才知道」，不塞一个假预估。
  • 零可用源：先提示「先挂上一个源」，而不是点了执行才发现空转。
  • 进度：执行后状态条给「已扫描 N / 预估 M」与已用时，不设超时自动收窄。

从 04 保留的细节（别丢）

  • 三档对照（能跨源 / 能写 / 建会话）仍放在通道下拉的说明里，不重画。
  • 门控：没有任何可用源时「联邦」置灰，悬浮给出原因，而不是选中后报错。
  • 只读拒绝：联邦档下写语句由编辑器拦截并给出「跨源无事务」的解释，不落到执行层。

展开规则（避免抢屏）

  • 首次切到联邦自动展开一次，右 Dock 若被结果占满则自动让位（面板以 tab 形式出现，不覆盖结果）。
  • 用户手动收起后，本次会话内不再自动抢；状态点仍留在工具栏上（未挂载时变黄）。
  • 切回源库 / 本地加速不收起面板，只在面板顶部说明「当前通道只用一个源」。

加源为什么复用 01

「有哪些连接、哪些表能挂」这件事只有一个出处（source_picker 的取数）。工具栏的「加源」只是把同一个树以弹层形式调起来，不另写一份清单。
