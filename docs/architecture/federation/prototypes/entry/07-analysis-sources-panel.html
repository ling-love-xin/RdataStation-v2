行上要说的三件事

  • pill：源 / 结果集落库 / 项目自建 / 资产 / 全局 / 结果集 / 草稿。它是业务身份，只贴在名字后面；段落按容器分。同一张 订单 在源库和结果集里是两行——这是防「以为是源库全量、其实分析的是结果集」的关键。
  • 通道：→ 源库 / → 进程 DuckDB / → 本地分析库 / → 联邦。文案来自内核 channel_label()，界面不自己推。
  • 状态：临时对象在面板打开时核对一次存在性，失效的置灰并说明「会话重建后不存在」，点不动就不该看起来能点。

与 02 对话框的关系

不是替换关系。01/02 的对话框保留在「从编辑器、结果面板触发的一次性多选」；面板负责常驻浏览与工作集。两者共用同一套取数、行身份与分组，不另立口径。

数据对象 ↔ 资产

  • 数据对象：分析过程中用到的表——源库表（引用）、临时表（tmp_q_/tmp_i_）、项目分析库里的表、资产。
  • 资产也可以参与分析，但只读、且一律取最新版本；要用旧版本数据，先在资产管理里回退。
  • 这里的「升级」只有一条路：临时表 → 存为表（进本项目分析库，全量搬运）。升级到全局不在这里——只有资产库详情的「升级到全局…」能进全局分析库；项目库里的表想进全局，先归档成资产。
