从 03 保留的细节（别丢）

  • 结果集工具栏的「分析」下拉仍有自定义 SQL 与 {table} 替换，本对话框只管「直接分析整份结果」这条。
  • 不截断：物化的是这份结果的全部行（早期的 20,000 行上限按新口径已去掉，代码同步改了）；对话框下方显示实际物化行数。
  • 会话失效后，数据对象里这条标「已失效 · 可重新分析」，重新分析即换新 tmp_q_。

三个去向，别混

  • 临时表（默认）：本会话的 tmp_q_，随会话重建消失——所以「数据对象」里会标失效。
  • 持久表：项目分析库里的表，长期可分析、也能删；名字带前缀只是分析库内部标识，不是资产命名。
  • 升级为资产：不在这里做。要在「数据对象」里对已有对象点升级——起名（不带前缀）、进版本、变只读；之后资产可以参与分析，但只取最新版本。

为什么先命名

名字是用户在数据对象里认路的唯一线索。自动名 tmp_q_xxx 能保证唯一，但认不出是哪一份；先给名字，临时表也带语义。

保留的入口

仍然是工具栏上的「分析」，不起新按钮：用户的心智是「分析这份结果」，而不是「新建一个对象」。命名与去向都在这一个对话框里问完。
