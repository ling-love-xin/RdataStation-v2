自定义分析 SQL基于结果集已抓取的行
分析 SQL
SELECT a.status, r.region, count(*) AS n FROM {table} a -- 结果集表 JOIN pg_src.dim.regions r -- 跨源维度 ON a.region_id = r.id GROUP BY 1, 2 ORDER BY 3 DESC
{table} 由执行层替换为当前结果集临时表；也接受 result_temp 别名。只允许只读 SELECT，DDL/DML 会被拒。
事实档
有 Arrow 事实档 → 按 schema 直灌，类型保真（decimal / timestamp 不退化）；没有（如联邦来源的结果）→ 回退显示矩阵猜型，并在结果上标注「降级档」。

形态 II 的数据流

1取当前结果集批次≤ 20,000 行，超出丢弃并记数
2Arrow 直灌到会话表在联邦会话内，命名 tmp_q_
3分析 SQL 在同一会话执行可 join 远端挂载的源
4产出新结果集标题「分析」，带血缘、单项可再分析

为什么同会话

  • 用户 SQL 要跨源 join，表不在源所在连接就看不见
  • 会话里建表与查询共用同一批挂载，不再二次 ATTACH
  • 本地档逐字不变：仍是单例 + tmp_q_

缺信息就会出错的地方

  • 会话重建 → 表消失：必须给「重新分析」入口，不能只报错
  • 降级档要不静默：结果上标「类型由显示值推断」
  • 超上限的行要能被看见：dropped_rows 显示在工具条
