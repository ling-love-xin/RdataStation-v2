05 驱动 id 重名该怎么设计 问题不在「争默认」，在清单缺一个字段

现状说明
内置侧：id 与族分开DriverDescriptor::new("mysql_native", "MySQL (Official)").with_target_database("mysql") —— 注册键 mysql_native，族 mysql。落库后 drivers.id=mysql_native、drivers.type_id=mysql。
插件侧：两者被迫合一ContributesDriver 只有 id（manifest.rs:467，无 type_id），descriptor_for 把同一个 driver.id 同时传给 id 与 target_db（factory.rs:342）。于是「oracle 的 JDBC 版」和「oracle 的 Rust 版」只能抢同一个注册键。
结果两个插件要提供同一个族时，必然撞注册键，被 check_contribution_conflicts 拒掉；想共存就只能改 id 造出 oracle_rust 这种「假族名」。
建议①：清单补 type_id
插件驱动显式声明两个值：id 是全局唯一注册键，type_id 是族，允许与他人共享。缺省时 type_id 回落为 id（向后兼容现有 3 个包）。
↓
建议②：连接存「族 + 实现」并带回退
连接记录里 driver 存族、driver_id 存实现。建连先按实现查 registry；查不到就按族回退到该族已注册的任一实现（内置优先）；仍没有才 DriverNotFound。
↓
建议③：族内排序只影响展示，不影响语义
下拉里内置在前、插件在后，用户选谁就存谁。同族多实现并存不是冲突，是设计意图 —— 默认由排序体现，不由数据决定。
建议②正是最初那个「mysql 驱动没有注册，打不开库」的根治点：插件没装时不该是错误，而该回退到族内内置实现。 目前的做法（把连接记录改成 mysql_native）是改数据绕过，不是修链路。
