为什么独立窗口是档②

  • 它是原生子窗口/独立窗口，**不与 GPUI 元素同屏竞争层级** → 没有档③的 z-order 问题
  • 代价：多一个窗口要管生命周期（本稿点右上 ✕ 看销毁行为）
  • OAuth 登录、第二屏仪表盘是它的天然场景

分帧投喂（本稿的核心）

  • 宿主先发 resultBegin（schema + 块数），再逐块 resultChunk，最后 resultEnd
  • 真实现里 chunk 里装的是 Arrow IPC 字节，不是行 —— 面板不该看见一坨 JSON 行
  • 好处：内存峰值不翻倍、可中途取消、可边到边画

阈值（dev-plan §4.2.1.2）

小结果：inline_json_max_rows = 200
        或 <= 256 KiB
  → 直接内联 JSON，省一次往返

大结果：走 IPC 分块（Arrow）
  → 控制面仍然只有方法名/错误/进度
  → 数据面是二进制，不 base64

反面做法（明确不做）：
  base64 把 Arrow 塞进 JSON
    +33% 体积 / 内存双份 / 不可流式

取消

  • 面板发 chart.cancel，宿主把取消信号交给真正的查询（DuckDB / sidecar）
  • 不是"把进度条藏起来"——查询要真的停
