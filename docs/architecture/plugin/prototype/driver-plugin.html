安装驱动插件
本稿演示了什么 （驱动这一轨和扩展那一轨的区别都在这里）

三轨来源：UI 上必须一眼可辨

  • ① 内置 Rust 驱动（PG / MySQL / SQLite / DuckDB）：编译进主程序，能力最全
  • ② 插件驱动（native sidecar）：独立子进程（本例 Oracle JDBC 桥，自带 JRE）
  • ③ 插件驱动（wasm）：已冻结（Q10 建议），UI 上如实标注，不假装可用
  • ④ 自动下载 JDBC agent（DBX 的做法）：本轮不做，也如实列出「未实现」

能力声明：哪些是真门控

  • 只看两个：supports_transaction 与 supports_federated； 其余能力位只是声明，宿主按声明隐藏功能（不假装支持）
  • arrow 位在 META_BITS_WITHOUT_UI_KEY 里被显式排除在 UI 之外 —— 它服务于插件通信

进程与凭据

  • sidecar 是独立进程：会死、会重启、会吃内存 —— 所以要有健康检查与重启计数（本稿可点「杀掉桥进程」）
  • 凭据只在驱动进程里：扩展宿主与 webview 都拿不到（§4.6.3）
  • native 权限（进程 / 网络 / 文件 / 环境）在安装时逐项明示，与扩展轨的能力不是一回事

  结果集 → Arrow IPC（二进制帧，不走 JSON）
  控制面 → JSON（方法调用 / 错误 / 进度）
