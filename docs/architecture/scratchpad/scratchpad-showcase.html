要批量改呢结果面板内嵌替换栏：先给「将替换 N 处 · M 个文件」，再原子写回；无命中不写盘，只读项目直接拒绝

1 ·为什么它不是一个「临时文件夹」

V1 与早期 v2 留下四处「看着有、其实是散装」的做法，这一版逐条换成了真东西。
旧样子现在
草稿放在隐藏目录（.scratchpad/），用户看不见、拷项目会漏 模块独立根目录 {项目}/scratchpad/（可见）；内部态（引用 + 文件元数据）分离到 .RSmeta/scratchpad/，旧的隐藏布局一次性迁移
一个面板既管草稿又管「分析资源」，语义互相纠缠 草稿箱只管草稿；提升为分析资源是移动 + 只读存档（Phase D，经命令协作，不直接依赖分析资源模块的视图）
列表全量读盘、渲染里 block_on 全异步：加载 / 导入 / 粘贴 / 清空回收站 / 搜索 / 替换 / 差异都入队到单个后台工作线程，视图 60 ms 轮询回填，请求序号丢弃过期结果
结果塞进 240 px 侧栏 重结果落中央编辑区（内容搜索命中与替换栏、冲突 Diff 面板都是），侧栏只承载输入与开关

2 ·三个高光

如果只记三件事。

① 草稿是项目的一部分，不是应用的缓存

内容在可见目录、元数据在 .RSmeta/、回收站在项目级——备份、迁移、进 Git、手工翻目录都成立。 面板只做「读这个目录 + 记一点元数据」，不需要用户理解任何内部结构。

② 「这份草稿和谁有关」被记下来了，而且只记 ID

file_meta 记「显式绑定的连接」与「最近执行用的连接」：打开时自动预选（显式绑定优先）， 在编辑器里跑一次就自动回写。凭据始终留在凭据库（AES-256-GCM），草稿里一个字节都没有。

③ 每一句「做不到 / 没做」都写着原因

只读项目拒绝写并说明；引用失效置灰标「（丢失）」并给 ⟲；冲突只有真差异才提示； 后台读盘失败进状态栏——「按了没反应」在这块界面里是不允许的。

3 ·四个剧本 · 它替你做什么

每一步都用现有按钮，能照着做。

剧本 A · 有个想法，先写下来 → 不打断手上的事

步动作怎么做
1建文件工具栏 ＋，填名字；下方模板 chip（空白 / SQL / Python / Markdown / JSON）点一下自动补后缀并填占位内容
2决定放哪先选中某个文件夹再点 ＋，内联输入行会出现在该文件夹内部（并自动展开）；没选中就建在模块根
3写与跑双击打开到中央编辑器（连接自动预选），写完 Ctrl+S 存回；树上那行的圆点（脏点）随存消失

剧本 B · 手上有份外部数据，想顺手用一下 → 复制还是引用，一眼分清

步动作怎么做
1要长期跟着项目走工具栏 ⬇ 导入（系统文件对话框，可多选）→ 复制进 scratchpad/，计入项目体积
2只是临时指个路工具栏 🔗 引用 → 选文件或目录 → 内联填别名（默认取名称）→ 只记路径，不复制
3源头挪了失效项置灰 + 标「（丢失）」→ 点 ⟲ 重新指向（只改路径，别名不变）；也可 ✎ 改名、↗ 打开位置、✕ 移除

剧本 C · 忘了东西写在哪 → 两种搜索，一个落点

步动作怎么做
1只记得文件名搜索行保持「文件名」模式，输入即实时过滤，命中的子树自动展开
2记得内容切到「内容」模式：.* 切正则、Aa 切大小写、⏎ 运行；结果进中央编辑区（命中行 + 前后各 2 行 + 行内高亮）
3找到就改点命中标题直接打开该草稿；或在结果面板的替换栏里一次改完（预览计数 → 全部替换 → 自动刷新）

剧本 D · 上面这些都不顺时 → 每一步都有出路

步情况怎么做
1删错了底部撤销栏点一下还原（5 秒内有效）；过期了就去「回收站」分组里逐条还原
2手头改着、外面被改了侧栏冲突条：先看「差异」（左=磁盘 / 右=你的，行号 + 红绿），再选「重载」（照磁盘）或「忽略」（保留你的）
3想把草稿塞进正在写的文件抓住草稿文件名拖到编辑器文本区 → 内容插到光标处（有选区则替换）；只读文档会拒绝并说明
4只想看看它在哪选中行 ↗ 打开所在位置（系统文件管理器）；引用项同样可用

5 ·与编辑器联动 · 一条闭环

环节行为为什么这样做
打开双击 / Enter / 右键「打开」→ 中央编辑器；同路径只激活不重读重读会冲掉用户没保存的修改
连接预选打开时按 file_meta 预选数据源（显式绑定优先，其次最近执行）；已删除的连接不预选预选一个下拉里没有的连接只会让执行报错
执行回写编辑器每完成一次执行留一份回执；宿主 1 秒一拍，只对草稿模块内的文件写 last_connection_id / last_executed_at编辑器不认识草稿箱；「这路径是不是我的地盘」由消费方判定
脏点编辑器里有未保存修改的文件，树上行尾出现圆点（只有文件打点），Ctrl+S 后消失脏状态归编辑器所有，草稿箱只做只读投影，1.2 秒一拍比对缓存
冲突 Diff外部改动 + 编辑器里有未保存修改 → 冲突条（差异 / 重载 / 忽略）+ 中央 Diff 面板（左=磁盘 / 右=编辑器，行号 + 红绿）判据是内容不是 mtime：diff 全 Unchanged 就不算冲突，不误报
拖放插入拖草稿文件名到编辑器文本区 → 内容插到光标处（有选区则替换）载荷只带路径，内容在落下那一刻才读；中途放弃不留负担
冲突的呈现是冲突条 + 中央 Diff 面板（不是模态对话框）：240 px 侧栅放不下差异，而模态会挡住用户正在看的编辑内容。要改成模态需挂宿主的对话框层，属待拍板项。

6 ·东西放在哪 · 内容与内部态分离

{项目}/
├─ scratchpad/                 ← 草稿本体：可见、随项目走、可进 Git
│  ├─ 订单分析.sql
│  ├─ transform.py
│  └─ data/warehouse.parquet
└─ .RSmeta/                    ← 内部态：面板永不需要过滤自己的文件
   ├─ scratchpad/
   │  └─ config.json           ← 外部引用（别名 + 绝对路径）
   │                              + 文件元数据（连接 ID）
   └─ trash/
      └─ <id>/
         ├─ payload/           ← 被删文件本体
         └─ manifest.json      ← 来源模块 + 原始相对路径
规矩原因
.RSmeta 不经 API 读写（点前缀路径一律拒绝）内部文件不该出现在列表、搜索、复制里
回收站是项目级的，条目带 origin草稿与将来的「资源删除」共用一个回收站；还原时只认自己的来源
迁移是幂等 + 非破坏 + 同名不覆盖用户在旧布局里可能有正经文件，迁移不能吃掉它

7 ·不卡：渲染期零 I/O

机制做法
全异步加载模块根、子目录、搜索、替换、差异都在单个后台工作线程（tokio 运行时）执行；视图只入队 + 60 ms 轮询回填
请求序号防过期模块根加载带自增 seq，视图只接受不早于已应用序号的结果；切项目时把在途结果作废
元数据级操作保持同步新建 / 重命名 / 删除入回收站 / 引用增删改是单次系统调用（微秒~毫秒），有意不搬后台（判定标准：会不会搬运字节或遍历全树）
外部改动去抖notify 递归监听模块根 → 变更标记 → 1.2 秒一拍合并事件风暴后重拉；监控不可用降级为手动 ↻
只画看得见的行树走虚拟列表（item_sizes 逐行给出），引用 / 回收站分组限高，保证树始终有可用高度

端口（ScratchpadHost）回答什么
project_root · read_only当前项目根（草稿箱是项目级能力）· 只读项目下拒绝写
notice · notify_host状态栏提示 · 让宿主重绘（模态层挂在宿主 render 上）
open_in_editor · show_search_results · show_diff打开草稿 · 投递命中列表 · 投递冲突 Diff（都落中央编辑区）
dirty_files · draft_content · reload_draft脏文档集合（脏点）· 读编辑器缓冲区（差异）· 用磁盘内容重载（消解冲突）
  • 渲染零 I/O：render 只读内存快照；加载 / 搬运 / 搜索 / 替换 / 差异全在后台线程 + 轮询回填。
  • 业务逻辑不进视图：复制、搜索、替换、路径防护、Diff 都是可单测的纯逻辑，放 crate；视图不出现裸 px()（尺寸进 workbench_shell/src/ui.rs）、不出现裸色值（取主题 token）——契约测试守着。
  • 为什么后台任务在 crate 内：项目态与视图状态同生命周期（窗口 / 面板），拆到 workbench 只会跨 crate 传两遍；判定标准写在架构文档 §7。
未接端口一律如实报「未接入」，不静默失败。

开发中 ·抓出来的真问题（都已修）

渲染期读盘（K1）

首次进入面板同步 block_on 读目录 → 改为只入队 + 轮询回填，并用序号丢弃过期结果。

重操作卡 UI（K1b）

外部改动后搜索结果过期（K4）

冲突误报

原计划用 mtime 判断「外部改过」→ 改为内容判据（diff 全 Unchanged 不算冲突）：草稿箱分不清磁盘上的新内容是不是自己写的。

测试真空

diff_with_content 一直没消费者也没测试 → 先补两项单测（行分类 + 两侧行号）再接到 UI。

跨 crate 拖放类型无处安放

拖起方与落点方分属两个特性 crate（互不依赖）→ 载荷下沉到最底层的 shared，只装数据。

每条都写进了架构文档的「已知问题」（§13，带现象与修法），口径以那里为准。

10 ·边界 · 这些事它不做

不做的

  • 不做进程级状态：项目态挂在窗口 / 面板实体上（多窗口不串项目）。
  • 不做 multi-root：一个窗口一个项目，否则会话 / 监控 / 元数据的复杂度抬高一个量级。
  • 不做「草稿箱内的计算」：算数据是引擎与本地的活，草稿箱只负责把文件放到位置上。
  • 不存凭据：元数据只存连接 ID；引用的外部路径只记绝对路径 + 别名，不复制本体。
还没做的卡在哪
系统文件管理器拖文件进树 = 导入仓库里目前没有 OS 拖放入口（无 FileDropEvent / ExternalPaths），要先确认 gpui-kit 是否转发平台事件；之前用工具栏 ⬇
命中跳转到具体行已能点命中打开文件；跳行要编辑器跳行端口
提升为分析资源 · 取回（检出）· 版本Phase D，依赖 analytics_resource
