01

它解决什么

V1 留下的四处「看着有、实际是假」的底座，这一版逐条换成了真东西。
旧 SQL 框只有一个 Textarea：没高亮、没补全、没多文档
→
组件库编辑内核 + 语义高亮 + 补全 + 多标签面板，性能档位（超大文件关重能力）也在
执行内联在 render 闭包里，同步直连全局分析库文件
→
后台工作线程 + 主线程轮询回填；渲染零 I/O，执行走驱动与连接
一次抓取 + 上限截断：亿行级表上没法用
→
分段抓取（1,000 行/段）+ 滚到底自动取 + 导出区分「仅已抓取 / 抓全量」
格式化是 format!("{:?}", stmt)——输出不是 SQL
→
sqlglot generator + 按语句区间原位回填：注释、空行、没写完的半句一个字节不动
02

三档模式 · 一个内核

同一份文档状态、同一个编辑内核；模式只决定「挂哪些能力、显示哪些 chrome、结果去哪」。
模式编辑语言智能执行与结果状态
文本 读写、只读、行注释、保存 无（记事本语义，不解析不上色） 不与数据库通信（按能力表拒绝并说明） 已实装
SQL + 高亮 · 补全 · 格式化 · 转译 · 模板 语义着色 · 补全 · 执行计划 · 诊断定位 执行族五项 · 分段抓取 · 事务 · 结果区 · 历史 · 导出 已实装
分析 单元（Cell）模型 · 会话 · 内联输出 逐单元（与 SQL 模式同源） 单元级执行 + 输出，可沉淀为可重跑的单元 门已就位 · 笔记本视图属 1c
诚实标注：模式矩阵（切换代价分级 + 内容变换）、能力表、单元模型与会话字段都已经在代码里； 分析模式的笔记本界面按计划搁置——不摆一个点不动的按钮。今天它的两处落地是实打实的： 结果集能「在本地 DuckDB 上分析」，以及 SQL → 分析的内容变换规则已经在测。
03

一次执行的全流程

从按键到结果落地，六步各有各的归属——这也是它能被测试、能被回放的原因。
STEP 1
解析目标
选区优先 → 光标所在语句 → 全部；批量按词法级切分（字符串/注释/$$ 块里的分号不算）
editor::execution
STEP 2
提交前两道闸
通道闸（加速/联邦拒写源库）· 项目只读闸（强只读直接拒写）——不打扰执行器
view/host.rs
STEP 3
工作线程执行
一条 job 可带多条语句，逐条独立；超时按连接的设置，中断走一次性线程
rds-editor-exec
STEP 4
结果落位
替换当前 / 追加新结果集（不抢用户在看的那份）/ 追加到选中那份（取下一段）
ResultPlacement
STEP 5
回填
网格 + 工具栏分段 + 状态行 + 血缘 + 历史一条（耗时/成败/行数/通道都是真值）
drain_exec_results
STEP 6
接着做什么
刷新 · 取下一段 · 本地筛选 / 下发重查 · 排序 · 分析 · 导出 · 洞察此列
结果区

⏹中断与超时

状态栏 ■ 中断 + 耗时累加；批量里剩余语句标「已取消」且不再发给驱动。超时按连接的 query_timeout，没配就是没有超时（不造默认值）。

⇄事务

事务是真的会话状态（驱动 API，不是拼 BEGIN 字符串）：状态栏 TX 区显示开启时长 + 提交 / 回滚 + 自动提交开关；状态随执行结论一起回来。

事务内的语句暂不可取消 / 无超时——驱动 Transaction trait 没给入口，如实记在案

⇥分段抓取

首段 1,000 行；拿满就显示 1,000+ 并允许取下一段（滚到底自动取）。每段重跑查询，所以 ORDER BY 不稳的查询会重复/跳行——这条取舍写在文档里。

04

三档执行通道

「这条 SQL 发到哪」是文档属性：互斥、可持久化、能力边界写在界面上，不靠用户猜。
通道怎么跑能力边界界面上看得见的部分
源库 直连驱动（四类库 · 六个驱动路径） 可写 · 有事务 · 数据实时 状态栏连接段 ●P·orders · 结果集徽标「源库」
本地加速 DuckDB ATTACH … READ_ONLY + USE，不写限定名也能查 只读 · 无事务 · 改写语义（本地临时对象可用）· 表清单在 ATTACH 时定型 菜单行尾写清不可用原因 · 「重新挂载源库」刷新表清单 · 写语句被双保险拒掉
联邦 一台 DuckDB 挂多个源，跨源查询写 别名.schema.表 只读 · 无事务 · 只给已挂上的源 补全按别名限定 · 历史带参与源 · 挂不上的源点名给原因
门控是真值：连接开关 → 驱动类型 → 扩展可用性 → 运行时就绪，按“谁能先改”的顺序只报第一条过不去的； 扩展没试过不拦（首次执行时在工作线程装一次），试过且失败就把原话记下来显示在菜单行尾。

◇原生就有（不手搓）

  • 虚拟滚动 · 行/列/单元格选择
  • 列宽拖拽 · 列序移动 · 冻结列
  • 点列头排序（三态循环）
  • 滚动到底自动加载（has_more / load_more）
  • 右键菜单 · 单元格自定义渲染
能力台账写在 view/results/mod.rs，避免后人再手搓一遍

＋我们补的三件

  • 本地筛选：任一单元格子串命中，300ms 防抖，只动视图层（数据一行不动）
  • 下发源库：拼 WHERE 重查 → 新结果集，去掉原 LIMIT 并提示
  • 排序下发：按点的那一列到源库排（不 CAST，让源库按自己的类型排）
筛选与排序都只改「视图行序」；换结果集时排序不继承、筛选词留着

⌘右键菜单

  • 按值筛选（写进筛选框并立即生效）
  • 复制此值
  • 按此列升序 / 降序（下发源库）
  • 冻结此列 / 取消冻结
  • 洞察此列（交给 M8 取样，不物化结果集）

⤓导出五档

  • CSV（RFC 4180）· JSON · INSERT（每 200 行一条）
  • Parquet / XLSX：经 DuckDB COPY，一次性线程 + 回执，不占执行位
  • 两档范围：仅已抓取 / 抓全量后导出（多轮取段，失败不落半截文件）
  • 筛选中导出的是筛后的行集，并在回执里明示
Parquet 离线可用（内核自带）；XLSX 首次要装 excel 扩展（联网几秒，后台跑）

◈结果集本身

  • 上限 5 份，淘汰最旧的未选中项（正在看的那份不会被挤掉）
  • 标签带通道徽标；切通道后旧结果标灰 + 顶部一行提醒
  • 失败带红点；错误卡片给「定位到第 N 行」与复制
  • 工具栏左段带来源摘要：原查询 / 下发筛选 / 排序下发 / 取下一段 / 分析 / 执行计划

↕编辑区 / 结果区

  • 可拖拽分栏（组件库 v_resizable，不手搓拖动条）
  • 下限 112px、上限 768px：不会把编辑区压成 0
  • 没有结果时结果区不占位

本地 DuckDB 分析

「查询后分析」这条主线的入口：结果集点一下，就在本地分析库上算，不重跑源库。
① 选
预置菜单
计数行数 · 按「列」分组计数（最多 8 列）
analysis::menu_items
② 或自己写
自定义分析 SQL
弹输入框，预填能跑的模板；{table} 指桥接出来的临时表；空白当场拒
dialogs::open_analysis_sql
③ 桥接
已抓到的行
上限 20,000 行，超了截断并如实说明；"NULL" 进库是真 NULL
analysis::request_for
④ 落
新结果集
原结果一行不动、也不抢选中；分析结果不摆「刷新」（重跑没有意义）
ResultPlacement::NewSet
三条口径：① 分析的对象就是眼前这份数据——源库断了、慢查询不想再跑，照样能分析； ② 值按展示文本进库，列类型由引擎按整列推断（数字列在 Parquet / XLSX 里就是数），代价是 007 这类前导零会按数字落； ③ 临时表由 TempTableManager 登记（上限 / TTL / 切项目清场），不泄漏。
07

编辑体验

能借组件库与内核的一律不手搓；自己写的部分都是纯函数 + 可逐条断言。

✎高亮与补全

  • 高亮走 sqlglot tokenizer → 字节区间 → 主题语法色；写不完的 SQL 也能着色（语法树会失败，词法不会）
  • 补全打字即触发（标识符与 .），候选来自导航侧 L2 缓存（后台预载、内存读）
  • Ctrl+Space 手动请一次：与打字那条完全同一份候选
  • 按通道给限定名：源库/加速 schema.表，联邦 别名.schema.表，未绑定连接不给候选（不猜）
  • 模板片段：6 条内置，插到光标处并选中 {table} 占位符

⇤格式化 · 转译 · 执行计划

  • 格式化：Ctrl+Shift+F，选区优先；区间原位回填——注释 / 空行 / 没写完的半句一个字节不动
  • 转译：10 个目标（PG / MySQL / SQLite / DuckDB / SQL Server / Oracle / Snowflake / BigQuery / Redshift / 标准 SQL）；先切分再逐条，脚本一条不丢
  • 执行计划：按通道取方言（加速/联邦用 DuckDB 的），落新结果集贴「执行计划」标题；SQL Server / Oracle 如实回绝（不硬拼一条跑不通的语句）

⌨九条已注册的快捷键

  • Ctrl+S 保存 · Ctrl+O 打开 · Ctrl+Shift+S 另存为
  • Ctrl+Enter 执行（选区优先）· Ctrl+Shift+Enter 执行全部
  • Ctrl+Space 补全 · Ctrl+/ 行注释 · Ctrl+Shift+F 格式化
  • Ctrl+W 关闭（脏则三态确认）
查找 / 替换、撤销 / 重做、复制粘贴一律不重绑——内核已绑并有 listener，重绑只会「看着注册了、实际被吃掉」

▤工具栏按模式分层

  • 最左：模式指示器（文本 / SQL / 分析）
  • 执行 ▾（分体按钮：主按钮 + 菜单五项）· 格式化 · ⋯ 更多 ▾（执行计划 / 转译 / 插入模板）
  • 右对齐：执行位置 ▾（三档）与 连接 ▾（P/G/GP 短码 + 运行态点）
  • 文本模式不摆执行类按钮；分析模式的执行属单元级动作（1c）
08

报错与定位

「报错只说一句话」是最费时间的体验债，这里把它拆成三件事：诊断 · 定位 · 聚焦。

⌖位置从哪来

  • PG 两条驱动路径的结构化 position（1 基字符 → 字节偏移，越界返回 None 而不是钳到末尾）
  • DuckDB 的 LINE n: + 插入符 · SQLite 的 at offset N · MySQL 的引号词
  • 共覆盖 10 类真实错误文本；认不出就不给位置——定位错比不定位更糟
  • 包装查询（分段抓取的 LIMIT/OFFSET 外壳）在报错里被还原成用户原句

▣界面三件事

  • 诊断：在出错词上打 danger 标记（内核 native 诊断）
  • 定位：选中那个词；状态栏追加「第 3 行 第 17 列」
  • 聚焦：回填发生在没有窗口的轮询里也能把焦点送回去
  • 失败不再是灰字，而是错误卡片 + 「定位到第 N 行」+ 复制驱动原文
  • 下一次成功自动清掉旧诊断
09

历史 · 会话 · 闸门

三件「跨时间」的事：跑过什么、上次看到哪儿、以及什么情况下不许写。

⟲历史面板（右 Dock）

  • 字段是真的：耗时 · 成功/失败 · 失败原因 · 返回与影响行数 · 绑定连接 · 执行通道与参与源
  • 搜索 / 重放（在编辑器打开，不替用户执行）/ 删除 / 清空
  • 刷新靠版本号：执行完摇一下，面板只在这时读盘（渲染路径零 I/O）

◷会话持久化

  • 内容 · 光标 · 选区 · 模式 · 执行通道 · 连接绑定
  • 未命名文档不存（重启认不回来）；存的是内容，不重读磁盘（上次可能没保存）
  • 通道失效 → 回退源库并说原因；连接不在列表 → 回退「跟随当前连接」并点名
真 SQLite 上跑通：关文档 → 重开 → 六项都回来

🔒写入闸门

  • 项目只读：写语句在提交前就被拒（要改数据先解锁项目）；SELECT 照跑
  • 加速 / 联邦通道：拒写源库，但允许本地临时对象（会话变量）
  • 编辑器只读与连接只读是两个独立维度，状态栏分开写
10

架构 · 依赖只向下

编辑器不认识「项目 / 连接 / 文件对话框」——这些能力一律走端口注入，所以它可测、可嵌、可换宿主。
应用层
rds-app：窗口 · 主题 · 键位注册（九条编辑快捷键都在这）· 全局快捷键表
宿主（工作台）
rds-workbench：把端口接到真实世界——执行器（editor_exec）· 连接列表与建连（editor_connections）· 通道门控（editor_channels）· 补全目录（editor_completion）· 项目锁（editor_project）· 会话存储（editor_session）· 系统文件对话框（editor_files，rfd 只在这）
编辑器 crate
rds-editor：模型与纯函数（completion · analysis · export · format · translate · edit · diagnostics · history · channel · limits · mode）+ 视图（view/host.rs 宿主面板 · view/results/ 结果区 · view/dialogs.rs 对话框 · view/completion.rs 补全适配 · widgets/status_bar.rs）
引擎 / 数据
rds-engine：驱动与会话 · 事务 · 取消与超时 · DuckDB（本地分析 / 加速 / 联邦 / 扩展目录）· 历史与模板库 · 元数据缓存 · sqlglot 原语（切分 / 格式化 / 转译 / 执行计划 / 高亮）
基础
gpui-kit（视图唯一依赖）· shared · paths（数据根 / 扩展目录）· database（导航缓存）
依赖方向 app → workbench → editor → engine → shared/paths · editor 不依赖 workbench（能力走端口）

◎端口注入

  • QueryRunner 执行 / 中断 / 分析 / DuckDB 导出
  • ConnectionsPort 连接列表与自动建连
  • ChannelsPort 通道可用性（内存快照）
  • CompletionPort 目录 + 模板
  • SessionStore 会话存储
  • ProjectPort 项目只读 · HistoryPort · 路径选择器
未接端口一律如实报“未接入”，而不是静默失败或假装可用

◑两条纪律

  • 渲染零 I/O：渲染路径只读内存快照；加载 / 执行 / 内省全在后台线程 + 轮询回填
  • 纯函数优先：候选挑排、编码、血缘、诊断解析、格式化计划……全是纯函数，逐条断言
  • 视图不出现裸 px()（尺寸进 ui.rs 常量）、不出现裸色值（取主题 token）——契约测试守着

▦为什么是独立 crate

  • 编辑器有自己的状态（文档集合 / 结果集 / 会话）与生命周期，独立才谈得上「无宿主可测」
  • 结果区不另建 crate：它的状态就是文档状态的一部分，拆出去只会跨 crate 传两遍
  • 三个 crate 的判定标准写在架构文档里（有状态 / 有视图 / 依赖方向）

⌖真机抓出来的真缺陷（都已修）

  • PG 的结构化位置是相对包装查询的 → 光标偏 16 字节（还原成原句）
  • EXPLAIN 被分段窗口包进子查询 → MySQL 1064（元信息语句不包装）
  • duckdb-rs 的 column_name 在 prepare 后调用直接 panic（改成先执行再读）
  • XLSX 不传 HEADER 就不写表头（首行数据会被当成列名）
  • PG COMMIT 永远等不到响应（sqlx runtime 被挂在只在 block_on 期间驱动的线程上）

边界 · 这些事它不做

把话说在前面，比事后解释便宜。

✕不做的

  • 结果集不内联编辑：行内改值 + 写回源库属表格能力（M4），避免「结果集」与「表数据」语义纠缠
  • 不替用户执行历史里的语句：重放只打开到编辑器
  • 不做 SQL 语义分析型补全：前缀 + 上下文判据，不猜「你想写什么」（解析留给格式化 / 转译 / 诊断）
  • 不静默联网：DuckDB 连接建起时就关掉自动安装扩展，装扩展只在明确的动作里发生

◷还没做的（都记在册）

  • 值预览弹层（超长文本放大看）· 值编辑（要行标识）
  • 只读锁 ⓘ（连接侧写策略；「提醒后放行」那一档）
  • 列类型化输出：CSV / JSON 仍是展示文本
  • 结果血缘落库（现在只在内存，重启后回看不到）
  • 候选取 60 条截断（翻页待做）
  • 分析模式笔记本视图（Phase 1c）
  • SQL Server 真机探针（等环境）
  • 事务内语句取消 / 超时——驱动 Transaction trait 没给入口
