## 1. 三种模式总览

### 1.1 定位：一个内核 + 三档能力（不是三个编辑器）

三种模式在能力上**严格递进**（文本 ⊂ SQL ⊂ 分析），共用同一个编辑器内核（文本缓冲 / 高亮 / 选区 / 诊断 / 补全挂载点 / 快捷键上下文）。模式只决定**挂哪些服务、显示哪些 chrome、结果去哪**。

| 维度 | ① 文本模式 | ② SQL 模式 | ③ 分析模式（NoteBook） |
| --- | --- | --- | --- |
| 一句话 | 带高亮的记事本 | 数据库客户端脚本窗口 | 可执行的分析笔记 |
| 对标 | 系统记事本 / VSCode 纯文本 | DBeaver · DataGrip 的 SQL 编辑器 | VSCode + Jupyter · SQL Notebook |
| 文档类型 | `Document`（任意文本） | `Document`（SQL 脚本 + 连接绑定） | `NoteBook`（单元序列 + 输出 + 会话） |
| 语法高亮 | 按扩展名（md / json / log…），无匹配则纯文本 | SQL（方言感知）+ **当前语句高亮** | 逐单元：sql / markdown / python / rust |
| 语言智能 | 无 | schema 补全 · 诊断 · 格式化 · 转译 | 逐单元同上 + 跨单元命名空间 |
| 数据库通信 | **禁止**（无连接、无执行入口） | 需绑定连接；执行 选区 / 当前语句 / 全部 / 批量 | 由**会话**驱动单元执行 |
| 执行通道 | 不适用 | 文档级：源库 / 本地加速 / 联邦（§5.7） | 会话级：通道随会话，切换即全部 stale |
| 结果去向 | 无 | 停靠结果面板 | **单元内联输出**（主）+ 可选停靠面板 |
| 工具栏 | 极简（模式指示 + 查找） | 完整（执行族 + 文档级动作 + **执行位置** + 连接） | 笔记级（会话/通道 · 全部运行 · 重启）+ 单元级动作 |
| 状态栏 | 行列 · 编码 · 换行 · 缩进 | + 连接 · 事务 · 语句数 · 耗时 · 方言 | + 会话 · 内核 · 变量数 · stale 计数 |
| 持久化 | 文件（任意路径） | 文件 + 连接绑定 + 光标 / 选区 | `.rdsnote`（单元 + 输出引用 + 会话元数据） |
| 第一期（1a/1b/1c） | 1a | 1a 编辑体验 + 1b 执行闭环 | 1c 骨架（仅 SQL 单元可执行） |

> **结果区不是"第四种模式"**：它是 SQL 模式与分析模式共用的**视图之一**，数据只有一份（见架构 §4.5「结果单权威 + 多视图」）。

### 1.2 模式判定规则（新建 / 打开时的默认模式）

优先级从高到低；判定结果**记忆到文档元数据**（下次打开同一文件沿用，含连接绑定与光标）。

| 优先级 | 来源 | 规则 | 结果 |
| --- | --- | --- | --- |
| 1 | 文档元数据 | 该文件上次的模式被显式改过 | 沿用上次模式（含连接绑定） |
| 2 | 扩展名 / 文件类型 | `.rdsnote` `.sqlnote` | 分析模式 |
| 3 | | `.sql` `.mysql` `.pgsql` `.ddl` `.tsql` | SQL 模式 |
| 4 | | 其他（`.md` `.txt` `.json` `.log` `.csv` …）与未知扩展名 | 文本模式 |
| 5 | 入口语义 | 「新建查询」/ 导航右键「在 SQL 编辑器中打开」/ 「查看数据」 | SQL 模式（并绑定该连接） |
| 6 | | 「新建笔记」 | 分析模式 |
| 7 | | 「新建文件」（草稿箱） | 文本模式 |

> V1 的 `EDITOR_MODE_RULES` 有两条已确认的实现缺陷（`ext` 只取最后一段导致 `duckdb.sql` 规则永不可达；循环内 ext/lang 顺序使规则互相遮蔽）——本表按"显式 > 扩展名 > 入口"重写，**不做 ext/lang 混合匹配**。

### 1.3 模式切换矩阵（显式动作，成本不同）

| 切换 | 内容影响 | 需要确认吗 | 规则 |
| --- | --- | --- | --- |
| 文本 → SQL | 无（同一 `Document`） | 否（无连接也可进入，执行时再要求） | 启用 SQL 语言服务；显示执行族工具栏 |
| SQL → 文本 | 丢弃结果（若有） | 是（"将隐藏结果，可切回查看"） | 断开连接；结果保留在结果面板但标灰不可交互 |
| SQL → 分析 | 内容进入单元 | 是（二选一：整篇单单元 / 按语句拆分） | 连接绑定提升为**会话默认连接** |
| 分析 → SQL | 丢弃输出与 stale 状态 | 是（"导出为脚本"语义） | 取 SQL 单元拼接为脚本；输出可选择导出为注释或丢弃 |
| 分析 → 分析（切换会话） | 输出全部标 stale | 是 | 会话切换 = 变量空间变化 |

**禁止静默切换**（V1 的 `changeFileType` 直接改字段且三处状态不同步，是本原型要规避的反面案例）。

### 1.4 只读：两个独立维度（不能合并）

| 维度 | 来源 | 表现 |
| --- | --- | --- |
| **编辑器只读** | 文档属性（查看历史快照 / 分析资源锁定 / 大文件只读预览） | 编辑区不可输入、不可补全；工具栏只留"查找 / 复制"；编辑区顶部 1 行只读条（`warning` 描边） |
| **连接只读** | 连接侧写策略 / 项目只读模式 | 编辑区**可输入可补全**；执行写语句（INSERT/UPDATE/DELETE/DDL）时：先弹确认（默认提醒）或直接拒绝（强只读），状态栏事务区显示锁形标记 |

**已落地的那一档（2026-09-18）**：**项目锁 = 强只读**——项目只读时，`INSERT` / `UPDATE` /
`DELETE` / DDL 在**提交前**就被拒（状态栏给可读原因，不打扰执行器），`SELECT` 照跑；
状态栏那一维显示「连接只读」（与「编辑器只读」互不蕴含）。判据与通道闸是**同一份**
（`channel::writes_source_object`）。“提醒后放行”那一档随连接策略（B1 余项）一起做。

两种组合都要能被表达：可编辑 + 只读连接（最常见）、不可编辑 + 任意连接（看快照）。

> **M6 已接上（2026-09-17）**：“分析资源锁定”走 `editor::persist::open_file_read_only`——**只读由发起方判定**（编辑器不认识 `resources/` 的归属），宿主把只读维度随 `OpenInEditorRequest` 传进来；同路径已打开仍旧只激活、不重读、不改只读态。

### 2.2 工具栏（②）逐控件：按语义分三层

**原则**：工具栏 = 「**执行级**（常驻）│ **文档级**（常驻 1–2 个 + 更多）│ **通道级 + 连接**（右对齐）」。同层共处，跨层用分隔线；**不允许跨层平铺**（V1 的 8 个平铺按钮 + 溢出菜单 + 2 个假按钮即反面案例）。

| 层 | 位置 | 控件 | 行为 | 依据 |
| --- | --- | --- | --- | --- |
| — | 最左 | **模式指示器** ▾ | 显示当前模式（文本 / SQL / 分析），点击切换（§1.3 矩阵） | V1 同型控件保留 |
| **执行级** | 左 | **执行 ▾**（主按钮） | 主动作 = 执行当前语句；下拉 = 执行族（§5.1） | 最高频 |
| **文档级** | 左 | 格式化 | 作用于整篇 / 选区（**有选区只排选区**；解析不了的语句原样保留并在状态栏说明；写回可撤销） | 高频 |
| **文档级** | 左 | 历史 ⟲ | 打开历史抽屉（右 Dock `History`；面板未实装前先弹层） | 复用 `history_store` |
| **文档级** | 左 | `⋯ 更多` ▾ | **已上**：执行计划 · 转译为 ▸（方言转译）；**未上**：校验语法 · 保存为片段 · 复制为 INSERT | 低频动作收拢，不占常驻宽度 |
| **通道级** | 右 | **执行位置** ▾ | 源库直连 / DuckDB 本地加速 / 联邦查询（§5.7） | 三者互斥，用指示器表达 |
| — | 右 | 连接选择器 ▾ | 当前文档的连接绑定（P/G/GP 短码 + 运行态点） | 与 M3/M4 同源 `workspace_loader::load_connections_for_scope` |
| — | 右 | 只读锁 ⓘ | 连接只读时显示（hover 给原因） | §1.4 |

**执行族下拉（▶ 展开）**：执行当前语句 / 执行选区 / 执行全部 / 批量执行（逐条独立）/ **在新结果标签中执行**。

**三条关键取舍**：

**为什么“新增标签执行”不单独占位**：它是执行族的第五种目标（执行什么的表现），不是独立动作；V1 给它一个常驻 `＋` 按钮，等于用 1/8 的工具栏宽度表达一个低频变体。
2. **“本地加速 / 联邦查询”不做成按钮**：① 三者**互斥**，并排按钮会暗示可叠加；② 它们是**会话/连接级**配置（长期有效），应随文档绑定持久化（与模式/连接持久化同一机制）；③ 通道决定能力边界（§5.7），需集中表达。V1 的 ⚡「本地加速」正是因为混入执行级、且被硬编码 `:is-duck-db="false"`，**从未显示过**。
3. **低频动作只进更多菜单**：执行计划（EXPLAIN）· 方言转译 · 校验语法 · 保存为片段 —— 都是“不是每次会话都用”的动作。

**工具栏不放的**（明确排除）：保存（走 `Ctrl+S` + 标签脏点）· 查找（走 `Ctrl+F` 内置）· 新建/打开（属工作台层）· 迷你地图 / 编辑器设置（V1 是两个只弹 toast 的假按钮——**不允许存在“只宣传不实现”的入口**）。

### 2.3 编辑区（③ ）

| 元素 | 规格 |
| --- | --- |
| 行号槽 | 右对齐、`text_xs`、`muted_foreground`；执行中出现进度点的行显示 spinner（可选） |
| 当前行 | 整行浅底（需新增产品 token `editor.active_line.background`） |
| 当前语句 | **整段**浅底（`editor.statement.background`，比当前行更弱）+ 左侧 2px 竖条（`primary`） |
| 括号匹配 | 匹配对内发光/描边（`border` 加深），失配用 `danger` |
| 选区 | `selection.background` |
| 光标 | `caret` |
| 缩进参考线 | 可选（`editor.indent_guide`），默认关 |
| 补全弹层 | 跟随光标；分组（表 / 列 / 关键字 / 函数）；每项左侧类型徽标、右侧 detail（列类型 / 所属表） |
| 诊断 | 波浪下划线（`danger` / `warning`）+ 行号槽标记；hover 显示消息 |
| 大文件 | >50MB 关闭补全与折叠；>200MB 不建编辑器，显示只读提示卡（V1 的 `rejected` 档保留语义） |

### 2.4 结果区（⑤ ⑥ ⑦）

| 区块 | 内容 |
| --- | --- |
| 结果集标签条 | 每次执行产生一个结果集；标签 = `结果 N` + **通道徽标**（`源库` / `加速` / `联邦`）+ **血缘摘要**（`原查询` / `原查询 + WHERE` / `临时表 t1 + 分析 SQL`）；**上限 5 个**，超出淘汰最旧；错误结果带 `danger` 点。⚠️ 0.6.1 的 `Tab` 没有 tooltip，所以摘要实际落在**工具栏左段**（见架构 §12 #32），标签上只留序号 / 标题 / 通道徽标 |
| 结果工具栏 | 左：`行数 N` · `耗时 1.2s` · **来源摘要**（`原查询` / `下发筛选` / `排序下发` / `取下一段` / 标题中的执行计划 / 分析）· `连接名`；右：**筛选输入** + `▢ 下发源库` 开关 · **分析 ▾**（DuckDB）· 导出 ▾（CSV / JSON / INSERT / Parquet / XLSX）· 刷新 · 复制选中 |
| 网格 | 虚拟滚动；首列固定 `#` 行号；列宽启发式（数字窄 / 长文本宽）；`NULL` 以 `muted_foreground` 斜体呈现；超长文本截断 + 值查看器；**只读**（行内编辑与写回源库属 M4 的表格能力，见架构 §3.4） |
| 结果血缘 | 重查与 DuckDB 分析**产生新结果集**（不就地替换）：原结果仍可回看；新结果集标签携带来源摘要与通道徽标 |
| 错误呈现 | 结果区显示错误卡片（`danger` 描边）：错误摘要 + `定位到第 N 行` 按钮 + `复制` |
| 结果状态行 | 分页（>1000 行自动分页；页大小可存）· 已选行数 · 截断提示（"已截断至 10000 行"） |
| 空态 | "执行后在此显示结果"；DDL 成功显示"影响 N 行"（**需补 `affected_rows`**） |

### 2.5 编辑器状态栏（⑧ ，面板内，独立于工作台状态栏）

| 区块 | 字段 | 取值来源 |
| --- | --- | --- |
| 左 | 连接点 + 连接名 | 文档连接绑定 + 运行态 |
| 左 | **执行通道**（`源库` / `加速` / `联邦`） | 执行位置指示器（§5.7）；非源库时附“快照”提示 |
| 左 | 事务区 | 未开启 / 已开启（显示时长）+ 提交 / 回滚按钮 | 已落地（B4）：状态栏 `TX 未开启` / `TX 已开启 3.4s` + **常显的「自动提交」开关**（它是模式，模式要一直看得见）+ 事务真开着时的「提交」「回滚」；只在执行器支持事务时出现。事务状态随执行结论回填，不在渲染期去问 |
| 中 | `Ln x, Col y` · 选中字数 | 编辑器内核 |
| 中 | 语句数（`N 条语句`） | **词法级切分结果**（V1/现状恒为 1，必须修） |
| 右 | 方言（`SQL` / `MySQL` / `PostgreSQL`） | 连接驱动 |
| 右 | 编码 / 换行 / 缩进（`UTF-8` `LF` `Spaces: 2`） | 文档属性（真实值，不硬编码） |
| 右 | 模式名 + 脏标记（`●`） | 内核 |

> 尺寸：高度 `1.5rem`（24px，与 `ui::ROW_HEIGHT` 同档）；工具栏高度 `2.25rem`（36px，与 `ui::PANEL_HEADER_HEIGHT` 同档）；文字一律 `text_xs`。

### 2.6 与 DBeaver 结果集的对标（差距清单）

评审问题：“本方案能否实现 DBeaver 的结果集功能？”以下是逐项对标（✅ 覆盖 / 🟡 部分 / ❌ 未覆盖）。

| DBeaver 结果集能力 | 本方案 | 说明 |
| --- | --- | --- |
| 多结果集标签 / 上限 / 错误标签 | ✅ | 上限 5 + 淘汰最旧；错误结果带 `danger` 点 |
| 本地快速筛选 | ✅ | §5.5「筛选」（300ms 防抖，不重查） |
| SQL/WHERE 重查（table filter） | ✅ | §5.5「下发源库」→ **新结果集（血缘）**——比 DBeaver 更保守（不就地替换） |
| 列排序（本地 / 服务端） | ✅ | 列头本地排序 + 右键“排序下发 SQL” |
| 列宽 / 自动列宽 / 隐藏列 / 列状态持久化 | ✅ | 列状态随结果集持久化 |
| 行选择 / 复制（单元格 / 行 / JSON / INSERT） | ✅ | 右键菜单 + `Ctrl+C` |
| 值查看器 | ✅ | 右侧/弹出面板；JSON / BLOB 专门渲染列后续（见下） |
| 分页 / 截断提示 / 行数 / 耗时 | ✅ | 状态行；`MAX_QUERY_ROWS = 10000` 截断明示 |
| 错误可定位（点错误跳行） | ✅ | §5.4 诊断回填 |
| 导出（CSV/JSON/INSERT/Parquet/XLSX） | ✅ | DBeaver 格式更多（XML/HTML/Markdown/DBF）后续按需加 |
| **结果来源与新鲜度** | ✅（**超出 DBeaver**） | 通道徽标（源库/加速/联邦）+ 血缘摘要 + ATTACH 快照提示 |
| **分段抓取（fetch size / 取下一段）** | ❌ **最大缺口** | 现设计是“一次抓取 + 上限截断”；大表（亿行级）应“先取 N 行，再取下一段”，界面显示 `N+` 未知总数 |
| 结果网格**行内编辑并写回源库** | ❌（有意划出） | 属 M4 表格能力（D23）；本模块结果集**只读** |
| 外键 / 引用导航（Referenced row） | ❌ | 需 M4 的约束元数据（`list_constraints` 已有，未接） |
| 跨结果集复制/粘贴行、拖到目标表 | ❌ | 后续；需目标表解析与写回通道（M4） |
| 数据转移（导出到另一个库/表） | ❌ | 后续；可复用 Parquet/XLSX + DuckDB 读写 |
| 列汇总行（SUM/AVG/COUNT）与网格内分组聚合 | ❌ | 后续；DuckDB 分析（§5.10）已能覆盖需求，但缺“就地汇总栏” |
| 专门查看器（JSON 树 / 图片 / 地理） | 🟡 | 值查看器先做文本 + JSON；图片/地理后续 |
| 与编辑器联动（Ctrl+点击列名/表名跳定义） | ❌ | 后续；依赖 M4 的元数据定位 |
| 结果集自动刷新（定时器） | ❌ | 便宜小项，建议 1b 顺带（V1 有过一个假开关，这次要真做） |
| 结果集“钉住”（防被后续执行覆盖） | ❌ | 本方案已有血缘与上限淘汰，钉住可后置；V1 的“未保存改动确认”思路可复用 |
| 结果集对比（diff） | 🟡 | V1 有 `ResultDiffViewer`（列/行差异 + 键列选择）；本方案列入后续（P1） |
| Mock 数据填充结果集 | 🟡 | 项目 M7 已有 mock 引擎，后续以“输出类型/单元”接入 |

**结论与建议**：

1. **读侧（展示/筛选/排序/导出/值查看/错误定位）能覆盖 DBeaver 的绝大部分**，并在“结果来源与新鲜度”上超出（通道 + 血缘）。
2. **已采纳：把「分段抓取」纳入 1b 范围**（用户 2026-09-15 认可）：`GridDataSource` 按“**已抓取窗口 + 取下一段** + 未知总数 `N+`”设计，否则大表场景会在 1b 后返工重改数据源层（见架构 D24 与 dev-plan B5b）。
3. **行内编辑写回**保持不在本期（D23）；若产品要求“像 DBeaver 一样在结果区改数据”，应作为 M4 表格能力的首个里程碑排期，而不是重新塞回编辑器。
4. **便宜且高价值的小项**（建议 1b 顺带）：结果集自动刷新定时器 · 钉住 · 列汇总栏（可选）。
5. **依赖 M4 元数据的项**（外键导航、列/表跳转、拖拽写回）统一列为 M4 后继项，编辑器侧只提供“插入限定名/生成 SQL”这类入口。

## 3. 文本模式解剖

```
┌─────────────────────────────────────────────────────────────────────┐
│ [标签条]  notes.md ✕ │ +                                            │
├─────────────────────────────────────────────────────────────────────┤
│ [文本] ▾ │ ⌕ 查找                                        [只读 ⓘ]   │  ← 仅 3 个元素
├─────────────────────────────────────────────────────────────────────┤
│  1 │ # 分析记录                                                      │
│  2 │ - 03 月渠道数据已核对                                             │
├─────────────────────────────────────────────────────────────────────┤
│ Ln 2, Col 12 │ 选中 0 字 │ Markdown │ 脏                            │  ← 无连接 / 无事务 / 无语句数
└─────────────────────────────────────────────────────────────────────┘
```

- **硬约束**：无连接选择器、无执行族、无结果区、无 schema 补全；不发起任何数据库调用（含连接状态检查）。
- 「只读 ⓘ」仅在文档只读时出现；只读时编辑区不可输入、无补全。
- 用途：打开任意文本 / 日志 / CSV 预览 / 草稿箱的 `.md` `.txt`；也是"SQL → 文本"降级后的形态（结果标灰）。

**执行通道（B13 切片一，2026-09-17）**：§5.7 的「执行位置」已按本节的形状落地——三档**互斥**、**文档属性**（随会话持久化，引擎 `editor_contexts.channel` 列）、结果集带**通道徽标**、切通道后旧结果**保留但标灰 + 顶部一行提示**、加速 / 联邦**拒写源库**且不打扰执行器。**仍不可选的是后两档本身**：执行侧还没接 `ATTACH` / 联邦路由，所以门控**如实**把它们置灰并在行尾写清是哪一条不满足（“该连接未开启本地加速” / “本地加速的执行尚未接入” / “分析引擎尚未就绪” / “尚未注册外部源”）——“选了却跑在源库上”是静默的语义错误，宁可先不给选。真接入随切片二 / 三。

**`Ctrl+F` / `Ctrl+H`（查找 / 替换）不由本模块注册**：内核已把它们绑在 `Input` context 上**并有 listener**，界面由组件库的 `SearchPanel` 渲染；应用层再绑只会重复且收不到按键（架构 §12 #24）。`Ctrl+Z`/`Ctrl+Shift+Z`、`Ctrl+A`、`Ctrl+C/V` 等同理——**内核绑定表就是这几条的权威**。

尚未实现、因此**不注册不宣传**的：`Ctrl+Space`（手动触发补全；打字补全已可用，手动那条内核有 `present_completion_items` 但本切片未接）。

执行结果落在编辑器下方的结果区（有结果或执行中才占位），状态行显示**真实值**（`N 行 × M 列 · 耗时` / `已截断` / 失败原因）；文本模式按能力表拒绝执行并在状态栏说明。

两条实现细节需按实例为准：

- **`Ctrl+F` / `Ctrl+H` 不由本 crate 注册**：内核在 `Input` context 里绑了它们并且有 listener（打开查找 / 替换会话），组件库的 `SearchPanel` 负责界面——**按键被内核消费，外层绑定收不到**（实测，见架构 §12 #24）。请勿在应用层重绑这两个键。
- **`Ctrl+W` 的处理器在宿主（workbench）而不是面板**：面板在自己的 `update` 里让 Dock 移除自己会重入（架构 §12 #23）。键位仍只在该面板内生效。
- 快捷键要能落到动作，面板根元素必须 `track_focus`（架构 §12 #25）；这类失效是**静默**的，靠 `simulate_keystrokes` 的窗口测试拦。

**关闭路径（实现口径，2026-09-16 收口）**

| 路径 | 行为 |
| --- | --- |
| `Ctrl+W` | 干净 → 直接关；脏 → **三态确认**（保存 / 不保存 / 取消；写盘失败再问一次） |
| 标签栏 `⋯` 菜单的「关闭」 | **脏文档上没有这一项**（`closable(cx) = !is_dirty()`；组件库的 TabGroup **没有每标签 ✕**，关闭入口就在这个菜单里，按当前标签的判据显隐） |
| 保存成功后 | 脏点消失，关闭项自动恢复 |

### 5.3 补全

- 触发：输入即触发（`activateOnTyping` 语义）+ `Ctrl+Space` 显式。
- 来源：表 / 列（走 `database::MetadataService` 实时内省，按连接 + catalog + schema 缓存，TTL 30s）· 关键字 · 函数（常量表）。
- 上下文：别名后（`t.` → 仅该表列）· `FROM`/`JOIN` 后（仅表）· `SELECT`/`WHERE` 后（列 + 函数 + 关键字）· 默认（全部）。
- 排序：别名列 > 表 > 列 > 函数 > 关键字（V1 的 boost 思路保留）。
- **元数据不可用时降级**：只给关键字 + 函数，并在弹层底部一行说明（不静默为空）。

### 5.4 诊断与错误回填

1. 执行失败 → 解析错误文本中的 `line/column`（多家驱动的错误格式，保留 V1 的 4 条正则思路并补测试）→ 在编辑器对应位置打 `danger` 诊断 + 选区 + 滚动居中 + 聚焦。
2. 无位置信息 → 在状态栏提示错误摘要，不强行定位到第 1 行（V1 的 `from/to` 恒 0 是缺陷）。
3. 语法校验（主动）为可选动作（工具栏"更多 → 校验语法"），不默认实时跑（避免打断输入）。

### 5.5 结果操作（筛选 / 分析 / 血缘）

> 设计要点：**从 V1 的“三模式过滤器”收敛为“两入口 + 一个开关 + 结果血缘”**——V1 把“隐藏行 / 重查源库 / 派生新数据集”三件不同层级的事做成同一输入框的三种模式（还叠了一套预设系统），输入框语义随模式变化，用户分不清“我看到的这份数据是谁给的”。

| 操作 | 入口 | 说明 |
| --- | --- | --- |
| **筛选**（本地即时） | 结果工具栏筛选框 | 只作用于当前结果集的视图层（不重查）；300ms 防抖；导出与统计跟随并明示“已筛选” |
| **下发到源库**（开关） | 筛选框旁的 `▢ 下发源库` | 打开后把条件拼为 `WHERE` **重查源库**（能看到未抓取的行与最新数据）；产生**新结果集**，原结果保留 |
| **DuckDB 分析** ▾ | 结果工具栏「分析」入口 | 在**本地内存 DuckDB** 上对**已抓到的行**跑聚合（**不重跑源库**：源库断了 / 慢查询不想再跑都能分析，且分析对象就是眼前这份数据）；预置菜单 = 计数行数 / 逐列分组计数，底部还有**自定义分析 SQL…**（对话框，预填模板，`{table}` 指桥接出来的临时表）；桥接上限 2 万行，超了截断并在结果里说明；**产生新结果集**（原结果一行不动、也不抢正在看的那份），分析结果不摆「刷新」；分析模式下可沉淀为**分析单元/会话变量**（§5.7 末） |
| 筛选预设 | 筛选框旁的预设选择器 | **绑定“筛选”而非“模式”**（存表达式 + 作用域：本地/源库）；落库而非 localStorage |
| 复制单元格 / 行 / 为 JSON / 为 INSERT | 右键菜单 + `Ctrl+C` | 沿用 V1 菜单项集合 |
| 按值筛选 | 右键“按值筛选” | 写入筛选框（默认本地）并即时生效 |
| 排序 | 列头点击（本地排序）/ 右键“排序下发 SQL”（重查） | 两者区分明确（“在哪儿排”与筛选同构：本地 / 源库） |
| 列宽 / 自动列宽 / 隐藏列 | 列头右键 | 列状态随结果集持久化 |
| 导出 | 结果工具栏 + 右键 | CSV / JSON / INSERT（编辑侧编码）与 Parquet / XLSX（经 DuckDB `COPY`，**后台跑**：XLSX 首次要装 excel 扩展）；导出的是**当前筛选后**的行集（明示） |
| 在结果面板中打开 | 内联输出的“展开” | 内联 ↔ 面板切换（同一结果集，不复制数据） |

**明确不做**：结果网格的行内编辑与写回源库。V1 把它塞进结果区（`apiSaveCellUpdate` + row identity），导致“结果集”与“表数据”语义纠缠、脏状态双轨（`dirtyRows` 与 `dirtyCells` 不一致）——“可编辑表格”属 M4 的表格能力（架构 §3.4）。

### 5.6 保存与脏状态

- 脏 = 当前内容 ≠ **最近一次保存/加载的基线**（V1 缺“输入即置脏”的写入端，本期必须做）。
- 标签脏点 `●` + 状态栏 `●`；关闭时三态确认（保存 / 丢弃 / 取消）；保存失败二次确认（沿用 V1 的三态 + 二次确认策略）。
- 自动保存草稿：SQL / 文本模式每 30s 或失焦时写工作区草稿（可关）；分析模式随 `.rdsnote` 保存。
- **标签关闭语义（已核实 Dock 能力后的两个方案，待拍板）**：
  - **方案 ①（推荐，1a）草稿兜底**：Dock 标签条的 ✕ 保持可用，**关闭即落草稿**（不阻断），配“最近关闭 → 恢复”；只有显式的“删除草稿”才确认。好处：关闭入口天然单一，彻底绕开 V1 那个“✕ 绕过未保存确认”的死结；代价：与 VSCode 的“✕ 上弹窗”习惯不同。
  - **方案 ②（产品坚持 ✕ 弹确认时）自定义标签条**：装一个自己的 `DockAreaRenderer`（`with_renderer`），用自己的 ✕（配上 `Panel::title_suffix` 脏点）→ 确认后调 `DockArea::remove_panel`。API 已确认可行（`with_renderer` / `remove_panel` 均为 `pub`），代价是重写标签条渲染（约 200–300 行）并自行保持拖拽/排序接线。
  - 两个方案下，`Ctrl+W` 类命令都走同一关闭入口（单一权威）。

### 5.7 执行通道（源库 / 本地加速 / 联邦）

**定位**：通道是**会话/连接级**属性（长期有效，随文档绑定持久化），与执行族（“执行什么”）**正交**。UI 载体 = 工具栏右侧「执行位置 ▾」（SQL 模式）/ 笔记头「会话 ▾」内的通道配置（分析模式）。

| 通道 | 数据来源 | 可用条件（门控） | 不可用时的表现 |
| --- | --- | --- | --- |
| **源库直连** | 目标库实时 | 连接已建立 | — |
| **DuckDB 本地加速** | DuckDB `ATTACH` 的源库（**只读挂载**） | `use_duckdb_fed = true` **且**驱动类型可加速（mysql / postgres / sqlite / duckdb）**且扩展可用**：网络型走带凭据的 `ATTACH … (TYPE mysql/postgres, READ_ONLY)`，文件型直接 `ATTACH … (READ_ONLY)`；扩展首次会 `INSTALL` 到 `<RDS_HOME>/extensions`（需联网一次，装过就离线可用） | 下拉项**保留形态但置灰**，行尾小字给原因（“该连接未开启本地加速” / “这个驱动暂时不能本地加速” / 扩展安装失败的原话）——遵守 `ui-constraints` 的“禁用占位 + 不可用原因”规则 |
| **联邦查询** | DuckDB + 多个外部源 | DuckDB 引擎就绪 + 已注册外部源（`register_external_database`）；无源时提供“注册新源…”入口 | 同上（并给出当前已注册源列表） |

**表名怎么解析**（切片二实测）：会话建立后 `USE rds_src` 把默认 catalog 指到附加源，所以
`SELECT * FROM orders` 这种**不写限定名**的写法直接可用；跨 schema 可以显式写
`rds_src.<schema>.<table>`。**不做 SQL 改写**（那是把同一件事换个地方做，还会引入“部分限定”
的不确定行为）。

> **方言提醒**（实测）：加速档跑的是 **DuckDB 的解析器**，所以 MySQL 的反引号（`` `t` ``）
> 会被拒（v1.5.5 也没有 `SET dialect` 可切）。这是“同一个连接、两个引擎”的固有差别，
> 界面不把它藏起来（报错原话直接给用户）。

**通道决定能力边界**（不能只在按钮上体现，必须让用户看得见）：

| 维度 | 源库直连 | 本地加速 | 联邦 |
| --- | --- | --- | --- |
| 写语句 / DDL（作用于**源库对象**） | 允许（受连接只读策略约束） | **禁止**（本地副本只读） | 视 DuckDB 侧规则 |
| 本地临时对象（`CREATE TEMP TABLE` / 临时视图 / `SELECT INTO TEMP`） | 支持 | **允许**（是分析会话的“变量”，不落源库） | 允许 |
| 事务 | 支持 | 不支持 | 不支持 |
| 取消 / 超时 | 连接级 token + `timeout_ms` | DuckDB 侧 | DuckDB 侧 |
| 数据新鲜度 | 实时 | **实时**（`ATTACH` 的是源库本身，不是复制一份）；但**表清单**在 `ATTACH` 时定型——源库后来新建的表要「重新 ATTACH」才看得见 | 同上 |
| 结果集徽标 | `源库` | `加速` | `联邦` |
| 历史记录 | 标记通道 | 标记通道 | 标记通道 |
| 执行计划语义 | 源库的 EXPLAIN | DuckDB 的 EXPLAIN | DuckDB 的 EXPLAIN |

**三条配套规则**：

1. **结果集必带通道徽标 + 血缘摘要**（hover 可查）：否则用户无法判断数据新鲜度与来源。
2. **切通道即失效**：切换通道后旧结果集保留但标灰，并在结果区顶部一行提示“通道已切换，旧结果来自 <旧通道>”。
3. **分析模式下通道属会话**：切换通道 = 会话状态变化 → **全部单元输出标 `stale`**（§4.2）；笔记头与状态栏同步显示当前通道。

**已实现 vs 计划（B13 切片二/三，2026-09-18）**：本节的表是目标态；加速档**已经真的接通**（
`engine::duckdb::accel`）：源库以 `READ_ONLY` 挂载（写源对象被 DuckDB 自己拒，本地临时对象照常允许）、
会话里 `USE` 解决表名解析、**「重新挂载源库（刷新表清单）」就在「执行位置 ▾」菜单里**
（旁路线程 + 回执，不占执行位；源库档不摆这一项——它没有“挂载”这回事）。
**两条修正**：① 状态栏与提示写的是「**源库只读**」而**不是“快照”**——实测数据是实时的，
写“快照”会让人以为看到的是旧数据（原表“数据新鲜度”一格已改）；② 门控里的“Secret 注册成功”
改为“带凭据的 `ATTACH … (READ_ONLY)`”：DuckDB v1.5.5 接受 URL 形式，而 `READ_ONLY` 已经
把写保护做到了引擎侧（不靠上层自觉）。**历史的通道标记也成了正规字段**（`db_type` 管“数据是
什么库的”、通道管“在哪儿跑的”，面板显示 `MYSQL·加速`）。**未做**：分析模式下的会话/单元
`stale`（1c）· 联邦通道的外部源注册入口 · 加速会话的临时表与
分析会话暂不共享（1c 的会话归属）。

## 6. 状态与空态矩阵

| 场景 | 表现 |
| --- | --- |
| 未绑定连接（SQL / 分析） | 编辑区可用（可写 SQL、可有高亮）；执行族禁用并附 tooltip"请先选择连接"；结果区空态 |
| 连接未运行 / 已断开 | 连接选择器显示灰色状态点；执行时先自动建连（同 M4「展开即建连」口径），失败给出可读原因 + 重试入口 |
| 连接只读 | 锁标记；写语句执行前确认或拒绝（见 §1.4） |
| 通道不可用（加速未开启 / 扩展装不上 / 无联邦源） | 「执行位置」下拉项**置灰 + 行尾给原因**；若文档已绑定该通道但已失效 → 回退源库并在结果区顶部一行提示 |
| 源库后来新建了表（加速档） | 数据本来就实时；**表清单**要「重新挂载源库（刷新表清单）」——它就在「执行位置 ▾」菜单里（本地跑的那两档才有） |
| 加速 / 联邦通道遇写语句 | 直接拒绝**源库写**（INSERT / UPDATE / DELETE / 作用源表的 DDL）并提示“本地副本不可写，请切回源库”；**允许本地临时对象**（`CREATE TEMP TABLE` / 临时视图——它们是会话变量） |
| 加速 / 联邦通道的新鲜度 | 结果集徽标 + 状态栏显式标注“ATTACH 时快照”；右上角提供“重新 ATTACH”入口 |
| 通道被切换 | 旧结果集保留但标灰 + 顶部一行提示“通道已切换，旧结果来自 <旧通道>”；分析模式下全部单元标 `stale` |
| 执行中 | 状态栏进度（spinner + 耗时累加）+ 中断按钮；结果区显示"执行中"骨架；编辑区保持可编辑 |
| 结果被截断 | 结果状态行提示"已截断至 N 行（共 M 行）"；导出提示会导出截断后的数据 |
| 无返回行（DDL/DML） | "影响 N 行"（需补 `affected_rows`）或"无返回行" |
| 结果集超出上限 | 淘汰最旧结果集；被淘汰者若有未保存改动 → 先确认 |
| 大文件（>50MB / >200MB） | 关闭补全与折叠 / 不建编辑器改只读提示卡 |
| 补全元数据不可用 | 降级为关键字 + 函数 + 一行原因说明 |
| 格式化失败 | 保留原文 + 状态栏提示（不静默吞、不改坏内容） |
| 会话 stale（分析模式） | 单元右上 `stale` + 笔记头"1 个单元已过期"；提供"重跑过期单元" |
| 无项目（工作台层） | 工作台层已由项目选择器覆盖中央区（M1 现状），编辑器不额外处理 |
