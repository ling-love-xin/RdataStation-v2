# RdataStation · SQL 编辑器 —— 一页看懂

> 中央 Dock 里那个能写、能跑、能看结果、能顺手接着分析的地方。
> **一个内核 · 三档模式 · 三档执行通道 · 五种导出。**
>
> 本页是**可贴版**（纯文本 + 流程图，适合贴进 PR / wiki）；视觉版见 [`editor-showcase.html`](editor-showcase.html)（自包含、明暗双主题、离线可开，首屏可在三档模式间切换）。
> 两版的章节一一对应；视觉版把「三档模式」的演示放在首屏窗口示意图里，本页把它排在第 2 节。

## 一句话

**写一句 SQL，按住 `Ctrl+Enter`——结果就在下面，还能接着往下算。**

它不是一个嵌在工作台里的输入框：执行、分段取数、事务、结果集、历史、导出、本地分析，是一条完整的闭环。
**错在哪儿、这句发到哪个库、这份结果怎么来的——都在界面上写着。**

### 它替你做到的事

| 你关心的 | 它给什么 |
| --- | --- |
| 跑得动吗 | **6 条驱动路径**（MySQL / PostgreSQL 各两条实现 + SQLite + DuckDB）都在真机回归里跑过 |
| 会不会被框住 | 亿行级表不做「一次抓完」：**1,000 行/段**，滚到底自动续取，未知总数写 `N+` |
| 发到哪儿去了 | 「执行位置」是**文档属性**：源库 / 本地加速 / 联邦，互斥、随文档持久化、不可用时**行尾写清差哪一条** |
| 结果还能干什么 | 筛 · 排 · 下发源库重查 · 丢给本地 DuckDB 聚合 · 右键**洞察此列** · 导出 **5 种格式**（含 Parquet / Excel）——**七条出口**，每条都产生新结果集或落到别的面板 |
| 出错了怎么办 | 定位到出错的那个词（10 类真实错误文本）+ 复制驱动原文；**认不出就不给位置** |
| 联网吗 | **0 静默联网**：DuckDB 连接建起时就关掉自动安装扩展，装扩展只发生在明确的动作里 |

> 数字口径以模块文档为准；工程数字（单测数量、探针清单）见第 14 节。

## 1. 为什么它不再是一个 Textarea

V1 留下四处「看着有、实际是假」的底座，这一版逐条换成了真东西：

| 旧样子 | 现在 |
| --- | --- |
| 只有一个 `Textarea`：无高亮、无补全、无多文档 | 组件库编辑内核 + 语义高亮（**写不完的 SQL 也能着色**）+ 补全（打字 / `Ctrl+Space` / 模板）+ 多标签面板 + 性能档位（超大文件关重能力） |
| 执行内联在 `render` 闭包里，同步直连全局分析库文件 | 后台工作线程 + 主线程轮询回填；**渲染零 I/O**，执行走驱动与连接，与「当前活动连接」不再冲突 |
| 一次抓取 + 上限截断（亿行级表没法用） | 分段抓取（1,000 行/段）+ 滚到底自动取 + 导出区分「仅已抓取 / 抓全量」 |
| 格式化是 `format!("{:?}", stmt)`——输出不是 SQL | sqlglot generator + 按语句区间**原位回填**：注释、空行、没写完的半句一个字节不动 |

## 2. 三档模式 · 一个内核

同一份文档状态、同一个编辑内核；模式只决定「挂哪些能力、显示哪些 chrome、结果去哪」。**文本 ⊂ SQL ⊂ 分析**，能力严格递进。

| 模式 | 编辑 | 语言智能 | 执行与结果 | 状态 |
| --- | --- | --- | --- | --- |
| **文本** | 读写、只读、行注释、保存 | 无（记事本语义，不解析不上色） | 不与数据库通信（按能力表拒绝并说明） | 已实装 |
| **SQL** | + 高亮 · 补全 · 格式化 · 转译 · 模板 | 语义着色 · 补全 · 执行计划 · 诊断定位 | 执行族五项 · 分段抓取 · 事务 · 结果区 · 历史 · 导出 | 已实装（默认档） |
| **分析** | 单元（Cell）模型 · 会话 · 内联输出 | 逐单元（与 SQL 模式同源） | 单元级执行 + 输出，可沉淀为可重跑的单元 | 门已就位 · **笔记本视图属 1c** |

> **诚实标注**：模式矩阵（切换代价分级 + 内容变换）、能力表、单元模型与会话字段都在代码里并逐条断言；
> **分析模式的笔记本界面按计划搁置**——不摆一个点不动的按钮。它今天的两处落地是实打实的：
> 结果集能「在本地 DuckDB 上分析」，SQL → 分析的内容变换规则已经在测。

## 3. 三个高光

如果只记三件事：

**① 「这条 SQL 发到哪」是文档属性，不是运气。**
源库 / 本地加速 / 联邦三档互斥、随文档持久化。跨重启连的是同一条连接、同一个通道；
通道失效会回退并说明原因，而不是静静换一个库接着跑。

**② 结果不是终点，是可以继续算的一张表。**
本地筛选（只动视图）、下发源库重查（拼 `WHERE` 去 `LIMIT`）、排序下发、右键按值筛选、
丢给本地 DuckDB 做聚合、右键**洞察此列**、导出成 Parquet / Excel——每一步都产生**新结果集**或落到别的面板，原结果一行不动。
（七条出口逐条拆开见第 8 节。）

**③ 每一句「做不到」都带着原因。**
报错能定位到出错的那个词、通道不可用写清差哪一条、`EXPLAIN` 支持不了的方言直接回绝、
事务内的语句取消不了也如实说明——**「按了没反应」在这套界面里是不允许的**。

## 4. 四个剧本 · 它替你做什么

每一步都用现有按钮，能照着做。

### 剧本 A · 一条查询跑太慢，先别改 SQL → 省下反复试错

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 看它到底怎么跑 | 光标停在句子里 → `⋯ 更多 ▾ → 执行计划`（按当前通道取方言）；结果落新结果集，原文不动 |
| 2 | 先只取一段回来看 | 执行后首段只取 1,000 行（状态行写 `1,000+`），不用等全表；跑久了按状态栏 `■ 中断` |
| 3 | 把语句排整齐再对比 | `Ctrl+Shift+F` 格式化——注释与半句原样保留，可 `Ctrl+Z` 撤回，排完再贴给同事 |

### 剧本 B · 把结果集做成一张可以看的表 → 不用回数据库

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 先筛出关心的行 | 结果工具栏筛选框，任一列命中即可（大小写不敏感）；只影响视图，导出会跟着筛 |
| 2 | 确实要找全部数据就下发 | 打开 `▢ 下发源库` → 条件拼成 `WHERE` 重查（自动去掉原 `LIMIT` 并提示），结果落新结果集 |
| 3 | 在本地算一版 | `⚗ 分析 ▾`：计数 / 按列分组，或自己写聚合 SQL（`{table}` 指当前这份数据，不重跑源库） |
| 4 | 带走 | CSV / JSON / INSERT 立即落盘；**Parquet / XLSX** 走 DuckDB 在后台写（首次装 `excel` 扩展会慢几秒，界面不卡） |

### 剧本 C · 两份数据要对得上 → 一条 SQL 跨源

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 切到联邦档 | `执行位置 ▾ → 联邦`：已连上、开了本地加速、驱动可挂的源才会出现在清单里；挂不上的行尾写原因 |
| 2 | 写跨源查询 | 补全只给**已挂上**的源，并按 `别名.schema.表` 给限定名——写出来的语句一定能跑 |
| 3 | 把差异固化下来 | 差异结果落新结果集，导出成 Excel 交给业务；历史里这条记录会带上**参与源** |

### 剧本 D · 写错了，我要知道错在哪 → 少一次来回

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 执行失败 | 不画空网格，给错误卡片：驱动原文 + **定位到第 N 行** + 复制；状态栏追加「第 3 行 第 17 列」 |
| 2 | 顺着诊断改 | 出错词上打 danger 标记并选中；分段抓取的 `LIMIT/OFFSET` 外壳在报错里被还原成你的原句 |
| 3 | 下次还找得到 | 失败也进历史（带原因），搜索关键词就能翻出来重放 |

## 5. 一次执行的全流程

```
  ┌────────────┐   ┌──────────────┐   ┌───────────────┐   ┌──────────────┐   ┌────────────┐   ┌──────────────┐
  │ 1 解析目标 │ → │ 2 提交前两道闸│ → │ 3 工作线程执行│ → │ 4 结果落位   │ → │ 5 回填     │ → │ 6 接着做什么 │
  │ 选区优先   │   │ 通道闸       │   │ 逐条独立      │   │ 替换/新结果集│   │ 网格+工具栏│   │ 刷新/取段    │
  │ 光标语句   │   │ 项目只读闸   │   │ 超时/中断     │   │ /追加(取段)  │   │ +血缘+历史 │   │ 筛选/分析/导出│
  │ 全部 / 批量│   │ （不打扰执行器）│  │               │   │              │   │            │   │ 洞察此列     │
  └────────────┘   └──────────────┘   └───────────────┘   └──────────────┘   └────────────┘   └──────────────┘
       editor::execution    view/host.rs       rds-editor-exec 线程    ResultPlacement   drain_exec_results   结果区
```

| 步 | 做什么 | 落点 |
| --- | --- | --- |
| ① 解析目标 | 选区 → 光标所在语句 → 全部；批量按**词法级切分**（字符串 / 注释 / `$$` 块里的分号不算） | `editor/src/execution.rs` |
| ② 提交前两道闸 | 通道闸（加速 / 联邦拒写源库）· 项目只读闸（强只读直接拒写）——被拒时**不打扰执行器** | `view/host.rs` |
| ③ 工作线程执行 | 一条 job 可带多条语句，逐条独立；超时按连接的设置；中断走一次性线程 | `rds-editor-exec` |
| ④ 结果落位 | 替换当前 / 追加新结果集（**不抢用户在看的那份**）/ 追加到选中那份（取下一段） | `ResultPlacement` |
| ⑤ 回填 | 网格 + 工具栏分段 + 状态行 + 血缘 + 历史一条（耗时 / 成败 / 行数 / 通道都是真值） | `drain_exec_results` |
| ⑥ 接着做什么 | 刷新 · 取下一段 · 本地筛选 / 下发重查 · 排序 · 分析 · 导出 · 洞察此列 | 结果区 |

**中断与超时**：状态栏 `■ 中断` + 耗时累加；批量里剩余语句标「已取消」且**不再发给驱动**。
超时按连接的 `query_timeout`，没配就是没有超时（不造默认值）。

**事务**：真的会话状态（走驱动 API，不是拼 `BEGIN` 字符串）。状态栏 TX 区 = 开启时长 + 提交 / 回滚 + 自动提交开关；
事务状态**随执行结论一起回来**（不必再问一次）。
> 事务内的语句暂不可取消 / 无超时——驱动 `Transaction` trait 没给入口，如实记在案。

**分段抓取**：首段 1,000 行；拿满就显示 `1,000+` 并允许取下一段（滚到底自动取）。
每段重跑查询，所以 `ORDER BY` 不稳的查询会重复 / 跳行——这条取舍写在文档里。

## 6. 三档执行通道

「这条 SQL 发到哪」是**文档属性**：互斥、可持久化、能力边界写在界面上，不靠用户猜。

| 通道 | 怎么跑 | 能力边界 | 界面上看得见的部分 |
| --- | --- | --- | --- |
| **源库** | 直连驱动（四类库 · 六个驱动路径） | 可写 · 有事务 · 数据实时 | 状态栏连接段 `●P·orders` · 结果集徽标「源库」 |
| **本地加速** | DuckDB `ATTACH … READ_ONLY` + `USE`，不写限定名也能查 | 只读 · 无事务 · 表清单在 ATTACH 时定型（新表要重挂） | 菜单行尾写清不可用原因 · 「重新挂载源库」刷新表清单 · 写语句双保险拒掉 |
| **联邦** | 一台 DuckDB 挂多个源，跨源查询写 `别名.schema.表` | 只读 · 无事务 · 只给已挂上的源 | 补全按别名限定 · 历史带参与源 · 挂不上的源点名给原因 |

> **门控是真值**：连接开关 → 驱动类型 → 扩展可用性 → 运行时就绪，**按“谁能先改”的顺序只报第一条过不去的**；
> 扩展没试过不拦（首次执行时在工作线程装一次），试过且失败就把原话记下来显示在菜单行尾。

## 7. 结果区 · 编辑器的下半屏

```
结果 1〔源库〕 │ 结果 2〔源库·下发筛选〕 │ 分析                      ← 结果集标签条（通道徽标 + 标题）
行数 1,204 │ 耗时 1.2s │ 下发筛选 │ ●P·orders   ⌕ 筛选 ▢下发源库 ⚗分析▾ ⤓导出▾ ⟳ 复制
┌────┬───────┬──────────┬──────────┬─────────────────────┐
│ #  │ id    │ customer │ total    │ created_at          │   ← 表头（sticky）
├────┼───────┼──────────┼──────────┼─────────────────────┤
│ 1  │ 10001 │ Ada      │ 1,280.00 │ 2026-09-01 10:20:00 │
│ 2  │ 10002 │  NULL    │    96.50 │ 2026-09-02 08:05:11 │   ← NULL 斜体（muted）
└────┴───────┴──────────┴──────────┴─────────────────────┘
共 1,204 行 · 已选第 2 行 · 已筛选 12 / 1,204 行 · 取下一段        ← 结果状态行
```

网格是组件库的原生能力，我们只补它没有的那几件——**补之前先核过源码**（台账写在 `view/results/mod.rs`）。

| 原生就有（不手搓） | 我们补的 |
| --- | --- |
| 虚拟滚动 · 行 / 列 / 单元格选择 | **本地筛选**：任一单元格子串命中，300ms 防抖，只动视图层（数据一行不动） |
| 列宽拖拽 · 列序移动 · **冻结列** | **下发源库**：拼 WHERE 重查 → 新结果集，去掉原 `LIMIT` 并提示 |
| 点列头排序（三态循环） | **排序下发**：按点的那一列到源库排（不 CAST，让源库按自己的类型排） |
| 滚动到底自动加载（`has_more` / `load_more`） | 右键菜单：按值筛选 · 复制此值 · 升 / 降序下发 · 冻结列 · 洞察此列 |
| 右键菜单 · 单元格自定义渲染 | 导出五档（见下） |

**结果集本身**：上限 5 份，淘汰最旧的未选中项（正在看的那份不会被挤掉）；标签带通道徽标；
切通道后旧结果**标灰 + 顶部一行提醒**；失败带红点，错误卡片给「定位到第 N 行」与复制。
工具栏左段带**来源摘要**：`原查询 / 下发筛选 / 排序下发 / 取下一段 / 分析 / 执行计划`。

**筛选与排序只改视图**：数据行一行不动，清掉筛选立刻恢复原状，已抓到的窗口不会被搞乱，行号列显示的是视图行号。
（换结果集时排序不继承——列都可能不是同一批；筛选词留着——你还在找同样的东西。）

**编辑区 / 结果区可拖拽分栏**（组件库原生，不手搓拖动条）：下限 112px、上限 768px，不会把编辑区压成 0；没有结果时结果区不占位。

**导出五档**：

| 格式 | 怎么落盘 | 备注 |
| --- | --- | --- |
| CSV / JSON / INSERT | 编辑器里同步编码（纯函数） | CSV 走 RFC 4180；INSERT 每 200 行一条；值为**展示文本** |
| **Parquet / XLSX** | 经 DuckDB `COPY … TO …`，**一次性线程 + 回执**（不占执行位） | Parquet 离线可用；XLSX 首次要装 `excel` 扩展（联网几秒），表头必须显式 `HEADER true` |

两档范围：**仅已抓取** / **抓全量后导出**（多轮取段；取段失败 / 切结果集 / 提交被拒一律作废，不落半截文件）。
筛选中导出的是**筛后的行集**，并在回执里明示「（已筛选）」。

## 8. 结果集是一条产线 · 七条出口

结果集不是「查询的尾巴」，而是编辑器里的**一等公民**：有标签条、有通道徽标、有来源摘要、有上限淘汰（5 份，
淘汰最旧的未选中项）。它的状态就是文档状态的一部分——所以这些衍生物全长在同一个 crate 里，不跨 crate 传两遍。

在结果网格里右键一个单元格，菜单长这样：

```
结果网格 · 右键一个单元格
├─ 按值筛选「Ada」              ← 本地 · 只动视图（300ms 防抖）
├─ 复制此值
│  （分隔线）
├─ 按「customer」升序（下发源库） ← 真的会重查
├─ 按「customer」降序（下发源库） ← 真的会重查
├─ 冻结「customer」
│  （分隔线）
└─ 洞察「customer」这一列        ← 进洞察面板（能洞察时才摆）
```

**菜单是纯函数算出来的**：`context_menu_items(值, 列名, 列序, 是否冻结, 能否洞察)` 返回该摆哪几项、每项叫什么、
点下去干什么——**界面只负责画**，所以每一项都能单独断言。

- **短预览就地折叠**：空白折叠 + 超 24 字截断，长值不把菜单撑开；
- **升 / 降序标注了「下发源库」**——它真的会重查，而不是改本地顺序；
- **能力没有就不摆入口**：「洞察此列」只在能洞察时出现，与「按值筛选」同口径。

| 出口 | 你做什么 | 落到哪 |
| --- | --- | --- |
| **① 看** | 虚拟滚动 · 列宽 / 列序 · 冻结列 · 单元格 / 行 / 列选择 · NULL 斜体 | 组件库原生，零手搓 |
| **② 筛** | 工具栏筛选框，任一列命中即可；300ms 防抖，**只动视图** | 同一份结果，行号列改显视图行号 |
| **③ 排** | 点列头（本地三态循环）· 右键升 / 降序（**下发源库**，不 CAST） | 本地排序原地；下发排序落新结果集 |
| **④ 回源库再问一遍** | `▢ 下发源库` 打开后应用筛选：拼 `WHERE` 重查（去掉原 `LIMIT` 并提示） | **新结果集**，原结果一行不动 |
| **⑤ 二次分析** | `⚗ 分析 ▾`：计数 / 按列分组（最多 8 列）/ 自定义聚合 SQL（`{table}` 指这份数据） | 本地 DuckDB → **新结果集**（见下一节） |
| **⑥ 洞察** | 右键 →「洞察「列名」这一列」：把列交给洞察面板做画像 | 洞察面板（**不物化结果集**，见下） |
| **⑦ 带走** | `⤓ 导出 ▾`：CSV · JSON · INSERT · Parquet · XLSX；两档范围 | 落盘（后台写 + 回执），**跟随筛选** |

**洞察为什么「不物化结果集」**：洞察拿到的不是这份结果的数据副本，而是「**这一列 + 产生它的 SQL + 在哪条连接上**」，
由洞察侧重跑一句带 `LIMIT 500` 的取样落到自己的临时表里。这样就不需要建 `tmp_q_*` 表，
也就没有「结果集被丢弃时回收临时表」那套生命周期。
> 代价写在案上：列类型不在这里猜（编辑器手里只有字符串化的行）——目标头在数据回来前只显示来源，不显示类型；编一个「看起来像真的」类型更糟。
> 入口的三道门：**成功 + 有列 + SQL 是只读查询**（口径走引擎的语句分类，不自写判断），连接由面板合起来判定。

**值查看 · 今天的形态**：值在菜单里**就地短预览**（折叠 + 截断）+「复制此值」；
完整的**值预览弹层**与**值编辑**还没做——台账写在 `view/results/mod.rs`：
组件库没有原生 filter / 值预览 / 值编辑，这三件（连同洞察入口）属于业务语义，各有计划步骤，
落地时加本目录下的新文件，而不是往 `grid.rs` 里堆。

## 9. 本地 DuckDB 分析

```
结果集 ⚗分析 ▾
   ├─ 预置：计数行数 / 按「列」分组计数（最多 8 列）
   └─ 自定义分析 SQL…（对话框，预填能跑的模板；{table} 指桥接出来的临时表）
        ↓ 桥接：当前已抓到的行（≤ 20,000；"NULL" 进库是真 NULL）
   本地内存 DuckDB：建临时表 → 跑分析 SQL → 用完即删（TempTableManager 登记）
        ↓
   新结果集（原结果一行不动、也不抢选中）；说明写「本地 DuckDB 分析 · 基于已抓取的 N 行」
```

**三条口径**：

1. **不重跑源库**——分析的对象**就是眼前这份数据**：源库断了、慢查询不想再跑，照样能分析；
2. 值按展示文本进库，列类型由引擎按整列推断（**数字列在 Parquet / XLSX 里就是数**），代价是 `007` 这类前导零会按数字落；
3. 临时表带前缀登记（上限 / TTL / 切项目清场），不泄漏。

分析结果**不摆「刷新」**——重跑没有意义。

## 10. 编辑体验

| 能力 | 关键点 |
| --- | --- |
| **高亮** | sqlglot tokenizer → 字节区间 → 主题语法色；**写不完的 SQL 也能着色**（语法树会失败，词法不会） |
| **补全** | 打字即触发（标识符与 `.`）；候选来自导航侧 L2 缓存（后台预载、内存读）；`Ctrl+Space` 手动请一次，**与打字那条完全同一份候选** |

| **模板片段** | 6 条内置（来自模板库），插到光标处并**选中 `{table}` 占位符**——接着敲表名就直接覆写 |
| **格式化** | `Ctrl+Shift+F`，选区优先；**区间原位回填**：注释 / 空行 / 没写完的半句一个字节不动 |
| **转译** | 10 个目标（PG / MySQL / SQLite / DuckDB / SQL Server / Oracle / Snowflake / BigQuery / Redshift / 标准 SQL）；**先切分再逐条**，脚本一条不丢 |
| **执行计划** | 按**通道**取方言（加速 / 联邦用 DuckDB 的）；落新结果集贴「执行计划」标题；SQL Server / Oracle 如实回绝（不硬拼一条跑不通的语句） |
| **查找 / 替换** | 内核已绑并有 listener，界面由组件库 `SearchPanel` 渲染——**应用层零自建、不重绑** |

| `Ctrl+Enter` / `Ctrl+Shift+Enter` | 执行（选区优先 → 光标所在语句）/ 执行全部 |

## 11. 报错与定位

「报错只说一句话」是最费时间的体验债，这里把它拆成三件事：**诊断 · 定位 · 聚焦**。

- **位置从哪来**：PG 两条驱动路径的结构化 `position`（1 基字符 → 字节偏移，越界返回 `None` 而不是钳到末尾）· DuckDB 的 `LINE n:` + 插入符 · SQLite 的 `at offset N` · MySQL 的引号词——共覆盖 **10 类真实错误文本**。
- **认不出就不给位置**——定位错比不定位更糟（用户会照着找，还以为自己的 SQL 没问题）。
- **包装查询会被还原**：分段抓取的 `LIMIT/OFFSET` 外壳在报错里换回用户原句，位置也平移回去；落在包装上的位置宁可不给。
- 界面：出错词打 danger 诊断 · 选中那个词 · 状态栏追加「第 3 行 第 17 列」· 失败给错误卡片 + 「定位到第 N 行」+ 复制驱动原文；下一次成功清掉旧诊断。

## 12. 历史 · 会话 · 闸门

| 件 | 内容 |
| --- | --- |
| **历史面板**（右 Dock） | 字段是真的：耗时 · 成功 / 失败 · 失败原因 · 返回与影响行数 · 绑定连接 · **执行通道与参与源**；搜索 / 重放（只打开到编辑器，不替用户执行）/ 删除 / 清空；刷新靠版本号，**渲染路径零 I/O** |
| **会话持久化** | 内容 · 光标 · 选区 · 模式 · **执行通道** · **连接绑定**；未命名文档不存；存的是内容，不重读磁盘（上次可能没保存）；通道失效 → 回退源库并说原因，连接不在列表 → 回退「跟随当前连接」并点名 |
| **写入闸门** | 项目只读：写语句在**提交前**就被拒（要改数据先解锁项目），SELECT 照跑；加速 / 联邦拒写源库但允许本地临时对象；**编辑器只读与连接只读是两个独立维度**，状态栏分开写 |

## 13. 架构 · 依赖只向下

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ rds-app            窗口 · 主题 · 键位注册（九条编辑快捷键都在这）             │
├──────────────────────────────────────────────────────────────────────────────┤
│ rds-workbench      宿主：把端口接到真实世界                                   │
│                    editor_exec（执行器）· editor_connections（连接列表/建连） │
│                    editor_channels（通道门控）· editor_completion（补全目录） │
│                    editor_project（项目锁）· editor_session（会话存储）       │
│                    editor_files（系统文件对话框，rfd 只在这）                  │
├──────────────────────────────────────────────────────────────────────────────┤
│ rds-editor         模型与纯函数：completion · analysis · export · format     │
│                    translate · edit · diagnostics · history · channel · mode │
│                    视图：view/host.rs（宿主面板）· view/results/（结果区）    │
│                    view/dialogs.rs · view/completion.rs · widgets/status_bar │
├──────────────────────────────────────────────────────────────────────────────┤
│ rds-engine         驱动与会话 · 事务 · 取消与超时 · DuckDB（分析/加速/联邦/  │
│                    扩展目录）· 历史与模板库 · 元数据缓存 · sqlglot 原语       │
│                    （切分/格式化/转译/执行计划/高亮）                         │
├──────────────────────────────────────────────────────────────────────────────┤
│ gpui-kit · shared · paths · database   视图唯一依赖 / 数据根 / 导航缓存       │
└──────────────────────────────────────────────────────────────────────────────┘
       依赖方向：app → workbench → editor → engine → shared / paths
       editor 不依赖 workbench（能力一律走端口注入）
```

**端口清单**（未接端口一律**如实报「未接入」**，而不是静默失败或假装可用）：

| 端口 | 回答什么 |
| --- | --- |
| `QueryRunner` | 执行 / 中断 / 取下一段 / 下发筛选 / 排序下发 / 本地分析 / DuckDB 导出 |
| `ConnectionsPort` | 有哪些连接可选 · 确保已建连 |
| `ChannelsPort` | 三档通道各自的可用性与原因（内存快照） |
| `CompletionPort` | 候选目录（按通道给限定名）+ 模板片段 |
| `SessionStore` | 会话存到哪 |
| `ProjectPort` · `HistoryPort` · 路径选择器 | 项目只读 · 历史读写 · 系统文件对话框 |

**两条纪律**：

1. **渲染零 I/O**——渲染路径只读内存快照；加载 / 执行 / 内省全在后台线程 + 轮询回填。
2. **纯函数优先**——候选挑排、导出编码、血缘摘要、诊断解析、格式化计划……全是纯函数，逐条断言。
   视图不出现裸 `px()`（尺寸进 `ui.rs` 常量）、不出现裸色值（取主题 token）——契约测试守着。

**为什么结果区不另建 crate**：它的状态就是文档状态的一部分（谁在看哪份、抓到第几段、筛了什么），
拆出去只会跨 crate 传两遍；判定标准（有状态 / 有视图 / 依赖方向）写在架构文档里。

**真机抓出来的真缺陷（都已修）**：

- PG 的结构化位置是相对**包装查询**的 → 光标偏 16 字节（改成还原成原句）；
- `EXPLAIN` 被分段窗口包进子查询 → MySQL 1064（元信息 / 会话控制语句不包装）；
- duckdb-rs 的 `column_name` 在 prepare 之后调用直接 panic（改成先执行、再经 `Rows::as_ref()` 读）；
- XLSX 不传 `HEADER` 就不写表头（首行数据会被 `read_xlsx(header = true)` 当成列名）；
- PG `COMMIT` 永远等不到响应（sqlx 的连接任务被挂在只在 `block_on` 期间驱动的 runtime 上）。

> 每条都写进了「已知问题」清单（`editor-architecture.md` §12），带着现象与修法。

## 15. 边界 · 这些事它不做

**不做的**：

- **结果集不内联编辑**：行内改值 + 写回源库属表格能力（M4）——避免「结果集」与「表数据」语义纠缠；
- **不替用户执行历史里的语句**：重放只打开到编辑器；
- **不做语义分析型补全**：前缀 + 上下文判据，不猜「你想写什么」（解析留给格式化 / 转译 / 诊断）；
- **不静默联网**：DuckDB 连接建起时就关掉自动安装扩展，装扩展只发生在明确的动作里。

**还没做的（都记在册）**：值预览弹层 · 值编辑（要行标识）· 只读锁 ⓘ（连接侧写策略；「提醒后放行」那一档）·
CSV / JSON 的列类型化输出 · 结果血缘落库 · 候选超过 60 条的翻页 · 分析模式笔记本视图（1c）·
SQL Server 真机探针 · 事务内语句取消 / 超时（驱动限制）。
