# 资产库 / 分析存档模块 · 使用手册（M6）

> 读者：产品 / 测试 / 使用者。设计理念与原理见 `analytics-resource-architecture.md`；
> 视觉与交互规格见 `analytics-resource-prototype-design.md`；任务与逐轮记录见 `analytics-resource-dev-plan.md`。
>
> **状态说明**：本手册对应**设计定稿（2026-09-15）**。至 2026-09-16，Phase 0（领域类型 / 本体层 / 归档服务 / 索引修复）与 Phase 1 的**面板本体**（面板头 / 工具栏搜索·筛选·排序 / 行渲染 / 状态行 / 两种空态）、详情面板内容层、呈现层已在 crate 内落地；**workbench 接线（面板挂载 + 归档/取回闭环）与五个对话框尚未落地**，故本手册仍按"实现后即按此验收"的规格读（已落地部分的实际范围见 §4.5 的注）。文中每条能力都标注了期次：**【一期】**= Phase 1–3 落地 · **【二期】**= Phase 4（DuckDB 分析表）· **【未定】**= Phase 5 不承诺。若 UI 与手册不一致，以手册为准并提 issue 修 UI。
>
> **一句话理解这个模块**：草稿箱是"我正在干什么"，资产库是"我留下了什么、它当时长什么样"。归档 = 存档留证据，取回 = 借出来继续改。

## 1. 这个面板能做什么

在左侧 Dock「资产库」面板里：

- **归档【一期】**：把草稿箱里的文件（或本地文件）转成**只读存档**——文件被搬进 `{项目}/resources/`，登记来源、代码与内容指纹；
- **找回来【一期】**：搜索 / 筛选 / 排序 + **单层分组** + **标签**（多值，跨类型通用）；
- **取回（检出）【一期】**：把存档**复制**一份回草稿箱继续编辑（存档本体不动），改完再归档就是**新版本**；
- **版本【一期】**：查看历史版本、按旧内容**还原**（生成新版本，不改历史）、取回某个历史版本为草稿；
- **删除与恢复【一期】**：删除进**项目级回收站**（与草稿箱共用），可还原、可永久删除；
- **索引修复【一期】**：当文件被手工改动 / 删除 / 放入时，检测并用人工确认的方式修复登记关系；
- **分析表存档【二期】**：把 DuckDB 分析表登记为存档（Mock 产物、编辑器结果落库后的表），带重建定义；
- **远端表引用【未定】**：登记"这条结论用的是某连接的某张表"，**明确标注可能失效**。

**不在本面板内**：数据源的连接与对象浏览（→ 数据库导航 M4）、文件的日常新建/编辑/重命名（→ 草稿箱 M5）、DuckDB 表的生成（→ Mock M7 / 编辑器结果区）、库表列画像与质量评分（→ 洞察 M8）、把项目级资产提升到系统级共享（→ M1，尚未上线）。

### 1.1 什么该归档、什么不该

一句话判据：**"半年后我还想原样拿回来的东西，就归档。"**

| 该归档 | 不该归档 |
| --- | --- |
| 得出结论的那段 SQL / 脚本（要连数据来源一起留证据） | 一次性的临时查询 |
| 要交给别人的报告、结论文件（`.md` / 图表定义） | 正在改、还在反复调的草稿（先用草稿箱） |
| 数据样本（`.csv` / `.parquet`），需要复核时不必再取一次数 | 产物可由上游随时重算且不重要的中间表 |
| 需要被别的模块引用的产物（洞察报告、Mock 数据） | 与项目无关的个人笔记 |

> 归档不是"另存为"：归档后本体**变为只读**，草稿箱里那份会**消失**（它被搬走了）。想继续改 → **取回**。

## 2. 入口

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 打开面板 | 左活动栏「资产库」图标 | 左 Dock 展开为资产库面板 |
| **归档草稿** | 草稿箱面板右键「归档为存档…」 | 打开归档确认对话框（预填来源连接） |
| 归档草稿（批量） | 草稿箱多选后右键 | 逐项确认或一次确认（取决于选择数量） |
| 归档草稿（快捷键） | `Ctrl+Shift+A`（草稿箱上下文） | 对当前选中草稿发起归档 |
| 归档本地文件 | 面板头 `＋▾` → 「从本地文件归档…」 | 选文件 → 归档确认对话框 |
| 从草稿箱挑选归档 | 面板头 `＋▾` → 「从草稿箱归档…」 | 打开草稿多选对话框 |
| 取回（检出） | 存档行右键 → 「取回（检出）…」 | 打开取回对话框 |
| 打开资源目录 | 面板头 `⋯` → 「打开资源目录」 | 在系统文件管理器中打开 `{项目}/resources/` |
| 回收站 | 面板头 `⋯` → 「回收站…」 | 打开回收站对话框（仅显示资产库条目） |
| 重建索引 | 面板头 `⋯` → 「重建索引…」，或状态行异常段 | 打开索引修复对话框 |
| 聚焦搜索 | `Ctrl+F`（面板聚焦时） | 聚焦搜索框 |

> **归档入口不在资产库内部**：因为存档的本体必须来自某处（草稿 / 本地文件 / 分析表），**不存在"凭空新建一个存档"**。这一点与草稿箱（可以新建空文件）不同。

```
┌ 左侧 Dock（起步 240px，可拖拽调宽）──────────────┐
│ ⛁ 资产库                          [＋ ▾] [⋯]   │  ← 面板头
├────────────────────────────────────────────────┤
│ [🔍 搜索存档 / 标签 / 来源表…]   [筛选 ▾ 1][排序 ▾] │  ← 工具栏
├ 列表主体（可滚动，>100 项虚拟化）─────────────────┤
│ ▾ 全部分组                          12 项       │  ← 分组折叠区
│   ▾ 未分组                                       │
│     ▤ dau_report.sql        v3   ●已归档  1.2 KB · 3 天前 │ ← 选中
│     ▤ 临时订单分析.sql            ●已归档  12 KB · 3 小时前│
│   ▾ 报表                                         │
│     ▤ monthly.md            v2   ●已归档  4 KB · 昨天    │
│     ▦ mock_orders                ●分析表  12,480 行 × 18 列 │
│     ⤳ ods.orders                 ●引用    无指纹 · 6 天前 │
├────────────────────────────────────────────────┤
│ 12 项 · 已归档 11 · 分析表 1 · 缺失 0 · 索引异常 0 │  ← 状态行
└────────────────────────────────────────────────┘
```

> `▤` = 文件型 · `▦` = 分析表型 · `⤳` = 引用型（三种形状固定，灰显时也认得出）；`●` = **唯一色块：复现强度徽标**。

### 3.1 一行怎么读

```
▤  dau_report.sql        v3   ●已归档   1.2 KB · 3 天前
│  │                      │    │         │        └ 相对时间（悬浮显示绝对时间）
│  │                      │    │         └ 文件型显示大小；分析表型显示行数×列数；引用型显示"无指纹"
│  │                      │    └ 复现强度徽标（见 §3.2）
│  │                      └ 版本徽标（v1 不显示，减少噪声）
│  └ 显示名（改它不动文件，见 §4.4）
└ 类型图标（形状区分，不带颜色）
```

**字段优先级（面板窄，固定顺序）**：显示名 > 强度徽标 > 版本徽标 > 相对时间 > 大小。放不下的信息**一律省略号 + 悬浮补全**，不会出现第二行。

### 3.2 复现强度徽标（最重要的一栏）

| 徽标 | 类型 | 本体在哪 | 能不能改 | 失效风险 | 期次 |
| --- | --- | --- | --- | --- | --- |
| `已归档`（`success`） | 文件 | `{项目}/resources/` | 不能（只读）；要改用**取回** | 低：文件在项目里 | 【一期】 |
| `分析表`（`info`） | DuckDB 表 / 视图 | `{项目}/.RSmeta/analytics.duckdb` | 通过重跑定义重建 | 中：表被删 / 库被重建 | 【二期】 |
| `引用`（`warning`） | 远端表 | 不在本机 | 不适用 | **高：源表可能已变** | 【未定】 |

- 徽标是**行内唯一的颜色信号**，用来回答一个问题：**"这东西半年后还打不打得开？"**
- `引用` 型打开前会校验存在性，详情面板顶部常驻黄色警告条 + 「立即校验」。

### 3.3 状态行

`N 项 · 已归档 X · 分析表 Y · 引用 Z · 缺失 W · 索引异常 V`

- `缺失` / `索引异常` 不为 0 时该段**可点击**，直接进入索引修复（§4.8）。
- 这两项是"文件系统与登记表不一致"的可视化出口——**它们出现不是 bug，而是需要你决定怎么处理**。

### 3.4 详情面板（右侧，默认 320px）

点任意一行，右侧停靠面板显示：

| 分区 | 内容 |
| --- | --- |
| 头部 | 类型图标 + 显示名（可点改）+ 别名 + 版本徽标 |
| 基本信息 | 大小 / 文件修改时间 / 归档时间 / **只读标记**（"归档后不可写，需取回编辑"） |
| 来源 | 来源草稿路径 / 来源连接（可点跳数据库导航定位）/ 来源表 / **内容指纹**（前 12 位，可复制） |
| 版本 | 最近 3 条 + 「查看全部…」 |
| 标签与分组 | 标签 chips（可加可删）+ 分组选择 |
| 内容预览 | 文本型显示前 20 行（**只读**）；二进制 / 大文件只显示元信息 |
| 危险区 | 移入回收站 |

## 4. 典型流程

### 4.1 归档一个草稿（4 步）

1. 在**草稿箱**里右键目标文件 → **「归档为存档…」**；
2. 在确认对话框里核对：显示名（可改）/ 目标位置（只读，保留草稿的目录结构）/ 分组 / 标签 / **来源连接**（若该草稿执行过 SQL，会自动带出上次使用的连接）/ 是否保留历史内容；
3. 点「归档」→ 草稿文件**移动到** `{项目}/resources/` 并**变为只读**，资产库出现该存档（v1）；
4. 底部出现撤销条（沿用草稿箱的撤销栏）——**归档后立刻反悔可一键撤回**（本体移回草稿箱、登记行删除）。撤销条自动消失的时长随草稿箱一并补齐。

**冲突时**：若 `resources/` 下已存在同名路径，对话框会询问**改名 / 取消**，**不会静默覆盖**。

**归档是原子的**：若写登记失败，本体会被移回草稿箱（不会出现"文件没了但列表里也没有"）。

### 4.2 从本地文件归档

面板头 `＋▾` → 「从本地文件归档…」→ 选文件 → 同一个确认对话框。用途：把项目外的数据样本、报告纳入项目存档（纳入后受项目生命周期与回收站保护）。

### 4.3 核心循环：归档 → 取回 → 改 → 再归档

```
草稿 a.sql  ──归档──▶  存档 a.sql (v1, 只读)
                          │
                          ├──取回（检出）──▶  草稿 a.sql（工作副本）
                          │                        │
                          │                    编辑 / 执行
                          │                        │
                          └────再归档──────────────┘
                                    ▼
                          存档 a.sql (v2, 只读，v1 内容按保留策略留档)
```

- **取回是"复制"**：存档本体不动、仍是只读；草稿箱出现一份可编辑副本，默认名带"（工作副本）"。
- 再次归档时 **`资源 id` 不变**，只是版本 +1 —— 所以引用它的地方不会断。
- **内容没变就不产生新版本**：取回后原样再归档，版本号不会涨（避免用"改过名字"冒充"改过内容"）。

### 4.4 重命名、打标签、归组

| 想做的事 | 怎么做 | 注意 |
| --- | --- | --- |
| 改**显示名** | 行上 `F2` 或右键「重命名」 | **只改显示名**，`resources/` 里的文件名与路径**不变**（避免破坏引用与 git 历史）；想改文件名 → 取回后另存，再归档为新存档 |
| 打标签 | 右键「打标签…」/ 详情面板 chips | 标签可多值、跨类型通用，是主要组织方式；支持批量 |
| 归组 | 拖行到分组头，或右键「移动到分组」 | 分组是**单层**（没有多级子文件夹、没有面包屑）；支持批量移动 |
| 新建分组 / 标签 | 分组头右键 / 标签 chips 的 `+` | 两者都支持改名与删除（删除标签会清掉它的关联） |

### 4.5 搜索、筛选、排序

- **搜索**匹配：显示名 / 别名 / **标签** / **来源表**（不只是名字）。
- **筛选**三维：类型（文件 / 分析表 / 引用）、**强度**（含"仅显示可能失效"）、标签（多选）。
- **排序**：名称 / 归档时间 / 更新时间 / 大小 / 版本；再点一次同一项**翻转方向**。
- 搜索与筛选**同时生效**；「没有匹配的存档」与「还没有任何存档」是两种不同状态——后者才会给你归档引导。

> **当前落地范围（2026-09-16）**：搜索只匹配**显示名 + 尾部字段**（别名 / 标签 / 来源表待 Phase 2——需要行模型带这些列；搜索框占位文案暂写「搜索存档」，不写"标签 / 来源表"以免"写了却搜不到"）；筛选当前为**类型 + 只看需处理**（强度与标签维待 Phase 2）；排序当前只有**名称 / 版本**（归档时间 / 更新时间 / 大小需要行上另带原始值，拿格式化后的 `1.2 KB` 比较会静默排错）；排序**换字段沿用当前方向**、同字段再点才翻转；状态行仍报**库口径**计数（不随筛选变化——`缺失`/`索引异常` 是"修复…"入口的理由，不能因为筛掉就看不见）。

### 4.6 版本历史

右键「版本历史…」：

| 列 | 含义 |
| --- | --- |
| 版本 | `v1` / `v2` …（单调递增） |
| 归档时间 / 大小 | 该版本的归档时刻与内容大小 |
| 指纹 | 内容指纹前 12 位（相同即内容相同） |
| 副本 | 该版本的历史内容是否还在（默认保留最近 5 份；超出只留元数据，显示 `缺失`） |

选中某个版本后，表格下方出现动作栏：

- **还原为当前版本** → 生成**新版本**（历史不清空，与 git `revert` 同构）；
- **取回该版本为草稿** → 把旧内容检出到草稿箱；
- **删除该版本的内容副本** → 只删内容，元数据行永久保留。

> 本模块**不做行级 diff**：要比较两个版本的内容，请取回后用编辑器的查找 / 对比能力处理。

### 4.7 删除与回收站

| 动作 | 结果 |
| --- | --- |
| 移入回收站（`Delete` / 右键 / 危险区） | 本体移入 `{项目}/.RSmeta/trash/`（**项目级**，与草稿箱共用），条目带来源标记 `resources` |
| 还原 | 回收站对话框内还原，回到原相对路径（同名自动改名，不覆盖） |
| 永久删除 / 清空回收站 | 真删内容，**不可恢复**；确认用警示对话框 |
| 跨模块条目 | 回收站里属于草稿箱的条目在本面板**只显示、不可还原**（提示"请在草稿箱还原"） |

### 4.8 索引修复（三类不一致）

面板头 `⋯` → 「重建索引…」，或点状态行的异常段：

| 现象 | 含义 | 你能做什么 |
| --- | --- | --- |
| **有文件、无记录** | `resources/` 里出现了登记表不知道的文件（手工放入 / 从别处拷入） | 「补登为存档」（选择类型，来源留空）——**列出候选，确认后才补** |
| **有记录、无文件** | 本体被手工删除 / 移动 | 「从回收站还原」或「删除记录」 |
| **指纹不匹配** | 本体内容被绕过只读改了 | 「接受当前内容（生成新版本）」或「从历史还原」 |

> **没有任何自动修复**：本面板不会静默导入文件、也不会静默删除记录——所有修复都由你确认。

## 5. 速览：一次操作落到哪

| 你做的事 | 落在哪 | 能否撤销 |
| --- | --- | --- |
| 归档 | 本体写入 `{项目}/resources/`；登记 + 版本写 `{项目}/.RSmeta/project.db` | 归档后立即（撤销条） |
| 重命名显示名 / 打标签 / 归组 | 只改 `project.db`（**不动文件**） | 可再改 |
| 取回 | 复制到 `{项目}/scratchpad/`；草稿侧记派生关系 | 删掉副本即可 |
| 再归档 | 若内容变化 → 新版本 +（按保留策略）历史内容副本进 `.RSmeta/resources/versions/` | 版本只追加，不可"取消版本" |
| 删除 | 本体进 `{项目}/.RSmeta/trash/`；登记行移除 | 撤销条 / 回收站还原 |
| 永久删除 | 真删本体与回收站条目 | **不可** |
| 只读标记 | `project.db` 的 `readonly` 列 + 文件系统属性 | 取回后编辑新副本 |

**默认保留多少历史内容**：最近 **5 份**（设置项 `keepVersions`，`0` = 只留元数据不留内容，`-1` = 全留）。超出只删内容副本，版本行永久保留——所以"版本列表还在、副本显示缺失"是正常状态。

## 7. 只读与数据安全

### 7.1 只读的三重保障

| 层 | 机制 | 强度 |
| --- | --- | --- |
| 应用守卫 | 任何写入 API 遇到 `resources/` 下的路径**直接拒绝**，并提示"这是归档本体，请先取回" | **硬约束** |
| 编辑器 | 以"分析资源锁定"的只读模式打开（工具栏只留查找 / 复制） | 硬约束 |
| 文件系统 | 只读属性 | 辅助（Windows / 网络盘可能失效，失败只提示不阻塞） |

> 结论：**只读主要靠应用层保证**。即使你在系统文件管理器里手工改掉只读属性并修改了文件，资产库也会通过**内容指纹**发现（徽标变为"内容已变"），不会悄悄放过。

### 7.2 内容指纹是什么

归档时对本体内存算一次指纹（文件型 = 文件内容摘要）。指纹相同 = 内容相同 —— 这是"版本只在内容真的变了才递增"的依据，也是"内容已变"异常判定的依据。

### 7.3 能不能手工动 `resources/` 目录

能，但会被检测到，且**推荐通过面板操作**：

| 你的手工操作 | 结果 |
| --- | --- |
| 修改文件内容 | 面板标 `内容已变`，可选"接受当前内容（生成新版本）"或"从历史还原" |
| 删除 / 移走文件 | 面板标 `缺失`（灰显，不隐藏），可选还原或删记录 |
| 放入新文件 | 不会被自动登记；重建索引时**列出来问你要不要补登** |

### 7.4 备份与版本控制

- 整个**项目目录**即自包含：`resources/`（本体）+ `.RSmeta/`（登记与回收站）。备份项目 = 备份全部存档。
- 建议把 `{项目}/resources/` **纳入 git**（本体是普通文件，可 diff、可评审）；`.RSmeta/` 属内部元数据，按项目既有约定处理。
- 归档后的本体不会再被本应用改写，因此 git 里只会在"再归档"时出现变更。

### 7.5 磁盘占用

历史内容副本是主要增长源。控制手段：调小 `keepVersions`、在版本历史里删掉个别版本的内容副本、清空回收站。详情面板会显示该存档的"历史内容占用"。

## 8. 常见问题与排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 归档后草稿箱里找不到那个文件了 | **归档是移动**，不是复制 | 在资产库找到它 → 取回（检出）拿回工作副本 |
| 存档打不开编辑（没光标） | 设计如此：**只读是常态** | 右键「取回（检出）…」→ 编辑副本 → 再归档为新版本 |
| 列表里有一行是灰的 / 打不开 | 本体缺失（被手工删或移动） | 点该行看详情横幅 → 「从回收站还原」或「删除记录」 |
| 行上出现"内容已变" | 本体被绕过只读改了 | 「接受当前内容（生成新版本）」或「从历史还原」 |
| 改了名字，但"在系统中显示"里文件还是旧名 | 重命名只改**显示名** | 想改文件名：取回后另存再归档 |
| 删掉的存档在回收站里找不到 | 该条目来源是草稿箱 | 到草稿箱的回收站里还原 |
| 永久删除后悔了 | 永久删除真删内容 | **无法恢复**；只能靠项目目录级备份 |
| 版本号一直不涨 | 内容指纹没变（内容没改） | 正常行为；只改显示名 / 标签不会产生版本 |
| 历史版本显示"副本缺失" | 超出 `keepVersions` 保留份数被裁剪 | 正常；元数据行永久保留。需要长期留档请调大 `keepVersions` |
| 搜索搜不到明明存在的存档 | 筛选仍在生效（强度 / 标签 / 类型） | 点筛选里的「清空」；或状态行核对项数 |
| 归档时提示目标已存在 | `resources/` 下已有同名路径 | 对话框选**改名**或**取消**（不会覆盖） |
| Windows 上只读属性像是没生效 | 只读主要靠应用守卫 | 属预期；内容改动仍会被指纹发现 |
| 面板点了没反应 / 卡住 | `engine` 连接池的已知缺陷（Phase 0 修复项） | 记日志提 issue；修复前避免高频并发操作 |
| 项目从 v1 迁移过来，在 Linux 上打开却看不到原有内容 | v1 的元数据目录拼写为 `.RSMETA`，v2 统一为 `.RSmeta`；大小写敏感系统上二者是不同目录 | 拼写统一已完成（连接模块 C22 ③），但 **v1 项目目录的兼容迁移**不在本模块范围；遇到时提 issue，勿手工改名或新建目录 |

- [ ] 草稿右键「归档为存档…」→ 确认对话框预填显示名与来源连接
- [ ] 归档后草稿从草稿箱消失、资产库出现该存档且标记 `已归档`、行上显示 `v1`（v1 不显示徽标 → 核对为不显示）
- [ ] `{项目}/resources/` 下出现该文件，且**文件属性为只读**
- [ ] 归档后立即出现撤销条，点击可撤回（文件回到草稿箱）
- [ ] 目标同名时**询问**，取消后草稿仍完整、无残留
- [ ] 从本地文件归档可用；批量归档可用
- [ ] （模拟写登记失败）本体被移回草稿箱，无"文件消失但列表无记录"状态

### 取回与再归档
- [ ] 取回后草稿箱出现"（工作副本）"文件，**存档本体仍在且只读**
- [ ] 编辑副本后再次归档：`资源 id` 不变、版本 +1
- [ ] 取回后原样再归档：**版本号不变**
- [ ] 重复取回时目标自动改名，不覆盖已有草稿

### 版本
- [ ] 版本历史列出全部版本，含时间 / 大小 / 指纹 / 副本状态
- [ ] 「还原为当前版本」生成新版本，历史未被清空
- [ ] 「取回该版本为草稿」内容与旧版本一致
- [ ] 裁剪到 `keepVersions` 后：内容副本删、版本行在，且显示 `缺失`
- [ ] 版本号在内容未变时不增长

### 组织与检索
- [ ] 打标签 / 去标签 / 批量打标签；标签可跨类型通用
- [ ] 分组新建 / 改名 / 删除 / 拖动归组 / 批量移动；折叠状态重启后保持
- [ ] 重命名只改显示名：`resources/` 下文件名不变
- [ ] 搜索命中显示名 / 别名 / 标签 / 来源表
- [ ] 筛选三维可用；排序方向翻转；`page_size = 0` 等边界不崩溃
- [ ] 输入 `%` 不会命中全部

### 回收站
- [ ] 删除后条目出现在项目级回收站，标记来源 `resources`
- [ ] 还原回原相对路径；同名自动改名
- [ ] 永久删除真删内容（对照：文件不再占用磁盘）
- [ ] 草稿箱条目在本面板不可还原且提示正确

### 异常与修复
- [ ] 本体缺失：行灰显 + `danger` 点 + 详情横幅 + 状态行 `缺失` 计数可点
- [ ] 内容已变：`warning` 徽标 + 两个修复动作可用
- [ ] 手工放入文件后「重建索引」列出候选，**未确认前不登记**
- [ ] 任何"自动修复"路径都不存在

### 只读与安全
- [ ] 经 API 写入 `resources/` 被拒，提示"请先取回"
- [ ] 编辑器以只读模式打开存档（工具栏仅查找 / 复制）
- [ ] 顶层目录 `.RSmeta/**` 不可经任何入口访问

### 主题与尺寸
- [ ] 明暗两套主题下徽标 / 提示条对比度可辨
- [ ] 面板 240px 下不出现异常折行；溢出项悬浮可看全
- [ ] 行高一致（紧凑行），无两行行
