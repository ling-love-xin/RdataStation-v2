前两个 384px（ui::NAME_DIALOG_WIDTH = 24rem）/ 删除确认 448px（组件 Dialog 的默认宽，vendor/dialog/dialog.rs:223）。 新建与重命名共用一个形状：单输入 + 一行提示 + 取消 / 主按钮（「创建」或「保存」），标题只有一行、没有副标题。 删除走组件 AlertDialog，不是自绘的小对话框。分组是单层的（没有子分组），「移动到分组」不进对话框。

新建分组
分组是单层的：没有子分组，也不影响存档本体

三处推翻旧稿
① 没有副标题「项目「营销分析」」——dialog.title(title) 只吃一个标题（dialogs/group.rs:107-108）。
② 没有「分组区「＋ 新建分组」」这一处入口——全仓只有三处调 request_create_group：分组头右键（group_header.rs:147-149）、行右键「移动到分组 ›」末项（list_delegate/menu.rs:241-244）、详情「移动…」末项（detail_view/body_sections.rs:237-239）。面板上并没有那个「＋」按钮。
③ 输入框占位符「分组名」是宿主建成 InputState 时设的（group_actions.rs:17-19）；对话框里算出的 placeholder 常量被 let _ = placeholder; 丢掉（group.rs:67）——当前视觉不受影响，但以后想把占位符挪进对话框会踩空。

重命名分组
只改显示名：组里的存档不动

旧稿 B 的副标题「3 个存档」同样不存在。
另外这里没有 Unchanged 那一档（与 20 页的存档重命名不同）：名字没改也能点「保存」，后端 rename_folder 对「改成当前名」是幂等返回原行（store/folder.rs:107-109），于是回执照样报「已把分组改名为「日报」」——其实什么都没发生。

C空名被挡唯一一道闸门；说明转 warning 色、主按钮置灰
新建分组
分组名不能为空

闸门就一条：value.trim().is_empty() → 「分组名不能为空」（group.rs:64-66），与后端 create_folder 的第一句拒绝同文（store/folder.rs:43-45）。
同款键盘缺口（与 20 页一样）：on_ok 恒返回 true（group.rs:137-140）→ 空名时按 Enter 仍关窗：分组没建成，也没有任何提示。按钮那条被 .disabled 挡住了，Enter 没挡。

D删除分组 · 组件 AlertDialog448px · 无 ✕ · 无图标 · 标题是问句 · 取消按钮显示英文「Cancel」
删除分组「日报」？
组里的存档不会被删，它们会回到「未分组」。

旧稿 D 整块重画。旧稿按 384px 的 .dlg-name 画了一个自绘对话框：带 #i-warn 图标、标题「删除分组」+ 副标题「「日报」· 3 个存档」、两行正文、✕、.btn-d 描边的「删除」。实际是组件 AlertDialog（group_actions.rs:189-216）：
① AlertDialog::new 自带 .close_button(false)（vendor/alert_dialog.rs:80-84）→ 没有 ✕；本处没调 .icon(…) → 没有图标。
② 宽度是 Dialog 的默认 448px（vendor/dialog/dialog.rs:223），不是 384。
③ 标题是问句「删除分组「X」？」，正文只有一句描述「组里的存档不会被删，它们会回到「未分组」。」（alert.title(…) + alert.description(…)）。
④ 确认按钮 ok_variant(Danger) → 淡红底实心（theme/schema.rs:937-947 的 button_danger = danger.mix_oklab(transparent, 0.2)），不是 .btn-d 的描边。

取消按钮是英文：只设了 ok_text("删除") 与 show_cancel(true)，没设 cancel_text（group_actions.rs:198-203）→ 组件库按 rust_i18n 的默认文案给「Cancel」（本仓从未把组件库 locale 设为中文，与 15 / 16 页同一条欠债）。

E提交之后：四条回执，各自说清做了什么
立即回执（提交那一刻）
新建「资产库：正在新建分组「X」…」
重命名「资产库：正在重命名分组为「X」…」
删除「资产库：正在删除分组…」
移动「资产库：正在移动…」
完成回执（工作线程回来）
新建「已新建分组「X」」
重命名「已把分组改名为「X」」
删除「分组已删除（里面没有存档）」/「分组已删除，N 条存档回到未分组」
移动「已移动 N 条存档到分组」/「已把 N 条存档移回未分组」
重名只在后端拦
对话框不查重名；create_folder / rename_folder 才用 folder_name_taken（同 scope 且未删）比一次（store/folder.rs:52-54、:110-112）
撞了以后回执是「资产库：新建分组：已经有同名分组「X」」

与 20 页对照着看更有意思：存档改名不查重名（两条存档可以同名），分组名查（要唯一）——两个「改显示名」的对话框长得一样，后端的口径却不同。 移动那条还有一处取舍写在注释里：逐条移、中途失败不预回滚，错误里带「（已移动 N 条）」（jobs/tag/group.rs:63-82）。

链路：request_create_group / request_rename_group（resource_host/group_actions.rs:5-81）→ enqueue_group_action → jobs/tag/group.rs 的 run_group_action → OpOutcome::GroupDone{note}；request_delete_group（:174-217）走 open_alert_dialog。 三者前置一致：无项目根 → 「无法新建分组」/「无法重命名分组」/「无法删除分组」；只读 → 「资产库：项目为只读模式，不能改分组」。

本块样式：.dlg.dlg-name（384px）/ .dlg + 内联 448px（删除确认）/ .inp / .namehint（.err = warning）。
