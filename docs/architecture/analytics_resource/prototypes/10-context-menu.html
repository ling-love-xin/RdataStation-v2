行内不摆常驻按钮，动作全走右键（顺序照 menu.rs::build）：打开（只读）/ 分发到本项目… / 查看统计 / 升级到全局… / 取回（检出）… / 版本历史… / 重命名… / 复制路径 / 在系统中显示 / 编辑标签… / 移动到分组 ▾ ─ 移入回收站。只有破坏性项前有一条分隔线，上面十一项连成一片。 多选时所有单选项置灰，可用项只剩三项：编辑标签（N 项）… / 移动到分组（整集）/ 移入回收站（N 项）。

顺序与分组照 build() 的实际拼装：只有最下面一条分隔线（隔离破坏性项），上面十一项连成一片——原型此前画了三条分隔线，是把「日常动作 / 组织动作 / 位置动作」当成视觉分组，实现没这么做。
「分发到本项目…」永远在清单里（项目行置灰）：它的判据是 !is_global || 多选 || 只读，而项目行本身就是 is_global = false。「查看统计」同理恒在（不可用时置灰，can_view_stats）。全局行反过来：除「分发到本项目…」外，取回 / 版本历史 / 重命名 / 编辑标签 / 移动到分组 逐项置灰或不摆（is_global 判据），移入回收站也置灰（本体不在项目侧）。
置灰判据：打开 · 复制路径 · 在系统中显示 都看 can_open（status != Missing 且登记了本体路径 payload_rel_path.is_some()）——所以「缺失」与「旧行没登记路径」会一起置灰这三项；取回看 can_checkout（非全局 + 常态 + 非只读）；升级到全局看 can_open + 非只读。
菜单不显示快捷键：PopupMenuItem::new(文案) 不带 action，而快捷键提示只由挂了 action 的项渲染（PopupMenuItem::action + key binding）。所以原型此前在「打开 / 重命名 / 移入回收站」后面写的 Enter / F2 / Del 在这份菜单里不会出现。

重命名不给批量（can_rename(多选, 只读) 直接否）：改哪一条都是猜。多选时置灰的是所有单选项——打开 / 分发 / 查看统计 / 升级 / 取回 / 版本历史 / 重命名 / 复制路径 / 在系统中显示（各自带 multi_count > 1 判据）；可用的只有三项：编辑标签（N 项）…（tag_entry_label）、移动到分组 子菜单（整集一起移）、移入回收站（N 项）。
批量中途失败时回执要交代「改了 / 移入了 N 处」，不能只报整体失败。移入回收站对整个选择集生效 + 二次确认（显示数量），完成后底部出撤销条。
原型此前的 .mi.cap「多选 3 项时的同一菜单（对照）」只是说明性标题，实现里菜单没有这一项。

顺序照 group_header.rs：重命名… → 设为|取消归档默认分组 → 删除分组 → 分隔线 → 新建分组…。已设为默认时第二项文案变「取消归档默认分组」，菜单里没有「已设」这类右侧提示（头上那颗「默认」小字就是它的事实提示）。
「删除分组」文案不带括号（成员去哪在确认对话框里说）；它不置灰——它是真分组菜单里唯一的破坏性项。
__all__ 与 __ungrouped__ 根本没有菜单（is_real_group 为假时压根不挂 context_menu）。原型此前写「『全部分组』右键只有『新建分组…』」是错的：要新建分组，在真分组头上或行菜单的「移动到分组 ›」子菜单里都一样有那一项。

口径（照 dnd.rs 核）：① 落点只有分组头——多选时拖一条 = 拖整个选集（载荷 ids 一批）；拖到「未分组」头 = 移出全部分组（GroupDrop::Ungroup）；②「全部分组」聚合头不接落点（NotATarget，连 drag_over 都不挂），「拖到某一行」也不接（资产库没有手工排序，拖到行上会承诺一个做不到的语义）；③ 悬停高亮用 list_active（与选中底同 token）；④ 只读项目不给拖（drag_payload 判 read_only）；⑤ 拖到当前所在分组不发请求（rows_to_move 只留真正要改归属的，与菜单里当前项置灰同一口径）。
另外两条实现细节：认不出的 id 不发（多选里刚好被筛掉 / 被删的行不会拖住整批）；拖拽幽灵 22px、形状取 kind_icon、颜色一律中性（幽灵不是状态），文案一条给名字、多条给「N 项」。
一处不对称值得记住：「未分组」头是落点但没有右键菜单——移出分组只能靠拖（真分组菜单里的「未分组」项是行菜单子菜单里的那条）。
