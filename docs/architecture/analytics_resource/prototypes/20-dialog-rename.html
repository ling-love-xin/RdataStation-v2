F2：can_rename = 单选 && !read_only（不看全局）

前置拒绝（对话框不开）
无项目根 → 通知标题「无法重命名」/「无法编辑别名」
只读项目 → 通知条「资产库：项目为只读模式，不能改显示名」
只读项目（别名）→ 通知条「资产库：项目为只读模式，不能改别名」
初值来源不同：改名取面板快照 row_name，别名取详情 row_alias；取不到就空着
提交后：先「正在…」再「已…」
改名立即回执「资产库：正在把「旧」改名为「新」…」
入队完成回执「资产库：已改名为「新」」
别名立即回执「资产库：正在更新别名…」
完成回执「资产库：已把「X」的别名设为「Y」」/「已清除「X」的别名」

两条真欠债：① 判据四套（上左卡片红字）——右键比 F2 多一条 !is_global、详情头部名字又多一条 status != Missing；同一行在同一屏上可能一处可点一处不可点，全局实例下 F2 更会走到「还没有打开项目」的错误话术； ② Enter 在闸门不过时仍会关窗：on_ok 恒返回 true（rename.rs:212-215），而 true 的语义就是关窗（vendor dialog.rs:91）——按钮那条被 .disabled 挡住了，键盘这条路没挡：空名时按 Enter，对话框关了、名字没改、也没有任何提示。

一条容易误判的事实：改名不查重名。后端只有 UPDATE analytics_resources SET name = ? WHERE id = ? AND deleted_at IS NULL（store/resource/write.rs:75-84），affected = 0 才报「资源不存在或已删除」——两条存档可以同名，界面上也不会提示。显示名不是唯一键，这条在 §3.2 里没写。

链路实现：request_rename / request_edit_alias（resource_host/group_actions.rs:83-172，前置拒绝、初值来源、入队 + refresh_resources + 立即回执都在这里）→ resource_jobs::enqueue_rename / enqueue_set_alias → jobs/rename.rs 的 run_rename / run_set_alias（失败 → OpOutcome::Failed{action:"重命名" / "编辑别名"}）→ 面板侧回执（panels/resources.rs:642-644）。

本块样式：.dlg.dlg-name / .inp / .namehint（.err = warning）。窗口用例见 tests/dialog_window.rs（改名与别名各一组闸门断言）。
