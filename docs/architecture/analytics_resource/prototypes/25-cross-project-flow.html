跨项目全流程§13.1–13.6

把23 块与24 块串成一条链：项目 A → 全局 → 项目 B。 这一页是链路视图，不是某个面板的画面——它回答「两边各自点一下之后，什么东西在哪个库里」。 唯一法定路径：跨项目只能走全局中转，项目 ↔ 项目禁止直传（代码里根本没有这条边）。

合法边 ②全局 → 任意项目分发 distribute
项目 A ↔ 项目 B 直传：没有这条边——菜单里没有、登记表里没有、job 队列里也没有。要绕过去只能先升到全局再分发，两步都留痕。

两条边都是复制不是移动：升级不动项目 A 的本体，分发不动全局那一份。「会不会在原处消失」是 M5 草稿箱归档的语义（首次 copy / 再归档 move），跟这一层不是一回事。

脚本为什么要变成表：全局库里只有 DuckDB 表，没有「全局 resources 目录」这个概念。方案 A 让它有一列可查、可对比、可复制的正文，分发时再落回文件。

走这条路要接受的代价：全局那份脚本不是文件，不能像项目里那样直接在编辑器打开改（只能分发回项目改）。
