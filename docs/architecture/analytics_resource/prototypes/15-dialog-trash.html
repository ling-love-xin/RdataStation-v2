推翻的七处：① 标题无副标题也无图标（实现是 `dialog.title("回收站")`），原型那句「只显示 origin = "resources" 的条目」不在标题行，实情靠「别人的条目不列行」体现；② 不是 `

原型没画而实现有的：名称后面跟类型（实体条目是「文件 / 目录」，reference 登记行是「受管文件 / 分析表 / 远端引用」）；目录的大小留空（不是 0）；条目来自两路——`ProjectTrash` 目录里的 copy 本体 + 库里软删的 reference 登记行，按删除时间双指针归并成一份倒序清单。
顺带一处观感问题：五列固定宽合计 472px，640 宽下再扣掉对话框内距与行内距，「原位置」只剩约 88px，长路径基本只能看到开头几个字（`resources/rep…`）。要不要把动作列收窄（两个 ghost 按钮实际约 124px）或把原位置折到名称下一行，待定。

空态就是一行「回收站是空的」（`text_xs` muted，**不用 `empty::Empty`**——一个对话框里的空清单不需要大图标那块），此时「清空回收站」置灰。 动作期：对话框自己 `set_busy(true)` + `set_note(...)`，三个写动作同时置灰（还原 / 永久删除 / 清空），提示挂在「共 N 项」那一行的右侧（warning 色）。提示文案按粒度分派：copy 还原「正在还原…」、reference 还原「正在还原登记记录…」，另外「正在永久删除…」「正在清空…」。 只读项目：对话框照常打开（不像取回那样在入口就挡回），只是 `can_write = !busy && !read_only` 让三个写动作全灰；宿主 `request_trash_action` 另有兜底——只读时给「项目为只读模式，不能改回收站」。 动作后不关窗：宿主重取一次清单 → `set_rows` / `set_foreign` / `set_busy(false)` / `set_note(None)`，行就地换掉。
