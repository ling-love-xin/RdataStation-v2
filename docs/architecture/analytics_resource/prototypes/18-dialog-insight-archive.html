这六个键是全部内容：列名 / 类型 / 可空 / 主键（来自 DESCRIBE）+ 行数 + 列数 + 时间戳。空值率、唯一值数、分布分位、检查器命中一个都没进快照——它们在洞察面板的临时表里，过期就没了。 generated_at 进指纹 → 同一张表两次归档的内容必然不同。

D第二次点「归档」会失败，而不是开 v2目标路径按相对路径查重，命中就报错
即时 洞察：已归档「warehouse.orders」到资产库（入队后无条件打印，还没等任务结果）
随后 归档失败：目标路径已被存档「洞察·warehouse.orders」（id=arp_3f9…）占用；请改名或先移除旧存档

失败来自 ArchiveService::archive_new 的 find_archive_by_rel_path：请求里 rel_path 恒为 insight/{集合条目名}.json、existing_resource_id 恒为 None → 第一次归档占住这个路径，第二次同一张表再归档就撞上「路径已占用」。 所以「每次归档都开新版本」不成立——洞察这条链路根本不产出 v2、v3，想留第二次快照只能先移除旧存档、或由人去改名。 真正的多版本只有在走归档对话框（11 页，来源是草稿 / 文件）并选「并入既有存档」时才发生。

推翻的七处：① 没有「洞察归档」对话框——旧稿 A 变体的标题、sub2、图标、srcbar、fgrid 六个字段、info note、footer「取消 / 归档」全部不存在； ② 没有可编辑的显示名（固定「洞察·{集合条目名}」）、没有目标位置回显（固定拼 insight/{名}.json）； ③ 没有「归档模式」单选——payload_mode 在代码里写死 Copy，界面上连一行说明都没有； ④ 没有标签编辑器——tags: vec!["洞察"] 写死，用户加不了第二颗； ⑤ 没有「来源表」只读输入框——它只写进 binding.source_table，在资产库详情里才看得到； ⑥ 没有保留策略下拉——keep_versions: None + 主线程读设置后随任务带入； ⑦ 没有 B 变体那个「报告视图 / 数据视图」二选一——ArchiveKind::File 写死，A2 数据视图本来就还没拍板，界面上更没有这个选项。

原型没画而实现有的：前置三条拒绝——未打开项目「洞察：归档需要先打开项目」、项目只读「洞察：项目为只读，不能归档」、集合里该条没 temp_table「洞察：该表尚未完成取样，无法归档」（同一判据也把行上的「归档 / 关系」两颗钮置灰，见 A 变体第二行）； 快照导出要抢 DuckDB 锁，所以放后台线程，入队与回执回主线程；本体先落 .RSmeta/insight-archive/ 再复制进 resources/（谁都不删 .RSmeta 那份，于是每次归档在项目目录里多留一个带时间戳的 JSON）。

欠债三处：① 回执错位——洞察侧入队后立刻说「已归档」，任务失败（路径占用 / 服务打不开）只会得到 OpOutcome::Failed{action:"归档"}，由资产库面板那侧消费；洞察面板不一定看得到。② 路径裸拼——insight/{集合条目名}.json 没有 slug 化，条目名里带 / 或反斜杠会拼出子目录 / 非法路径；.RSmeta 那份文件名同理（{名}_{时间戳}.json）。③ 「画像」名不副实——快照只有结构元数据；要让归档后的存档承载洞察结论，得先决定把哪些统计写进 JSON（这与 A2「数据视图要不要做」是同一个分界点）。
