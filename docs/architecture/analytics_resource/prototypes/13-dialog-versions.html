推翻三处：① 列序是 版本 / 时间 / 大小 / 指纹 / 变化 / 副本——原型把「相邻版本差异」放第 4、「指纹前 12 位」放第 5，正好反了；表头文案也就是「时间 / 大小 / 指纹 / 变化 / 副本」，没有「归档时间」「相邻版本差异」「内容副本」这些长名字。
② 变化列是 `较 v2 大小+0.4 KB · 指纹已变`：上界的版本号写进去，两样都能比才给（快照缺字段就不编），最旧一版空着而不是写「—（初始版本）」。
③ 「共 3 个版本 · 2 份内容副本 · 保留策略「最近 5 份」」不在 footer——footer 只有一个「关闭」；列表上方只写「共 N 个版本」，不报「几份副本」「保留策略」（副本数量要遍历目录才知道，对话框不做计算）。
另外「当前」是版本列里的一小段 success 色文字（不是带框角标），副本列是 「在位」/「副本缺失」（不是「存在」徽标）。

推翻原型的「副本缺失只留删除副本」：那一行四个动作全灰——连「删除内容副本」也灰（副本已经不在了，没有可删的东西）。能做的只有「看元数据」。
同一套判据还管两处：当前版本行（四个动作里三个写动作全灰，还原按钮文案改成「当前版本」；对比也灰——它就是本体，和谁比都不对），hint 改成「这是当前版本（本体上的内容）：取回请用详情面板的「取回（检出）…」」；只读项目下对话框照常打开，写动作灰、hint 改成「项目处于只读模式：还原 / 取回 / 删副本都是写操作」，但「与当前版本对比…」仍可点（只读查看，不写库）。这点与 12 页相反：取回在入口就被挡回，版本历史是要让人看得到的。

D「删除内容副本」的二次确认副本不进回收站，删了不可恢复
删除 v1 的内容副本？
版本记录会保留（列表里仍能看到这一版），但它的内容将无法再还原或取回。
副本不入回收站，删除后不可恢复。
原型没画这一步。删副本是真执行且不可逆（回执与二次确认是同一个口径：版本行留着、内容没了），所以要过一次 AlertDialog；确认后按钮置忙、动作栏上方出现 warning 色一句「正在删除 v1 的内容副本…」，完成后宿主重取列表并换行（不关窗，选中的版本若还在就保持选中）。

本块样式：.dlg（768px）/ .dlg-head / .dlg-body / .dlg-foot / table.dt / tr.on / .diffd / .actbar / .btn-p / .btn-d；本页已不用 .tcur（「当前」是纯文字不是角标）、.sb（副本列不摆徽标）、.note.warn（「不做原地回滚」那段说明不进对话框，只留动作栏下方一行 hint）。
「当前版本 v3」在内容末尾（动作栏之后、footer 之前），不是标题下的副标题——实现把它当 content 的最后一个子元素挂着。
表格是示意：实现是自绘的 h_flex 行（ListItem）+ 表头下一条 hairline，行间无分隔线；列宽按 ui::VERSION_COL_*（3.5 / 8 / 5 / 9 / flex / 5 rem），列表最高 20rem 内滚动，超过 50 行时末尾补一句「还有 N 个更早的版本未列出（一次最多列 50 个）」。
