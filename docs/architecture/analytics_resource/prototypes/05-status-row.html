高 24px（1.5rem）· 文案由 ArchiveCounts::line() 拼：恒有 N 项 · 已归档 X，其余四桶（分析表 / 引用 / 缺失 / 索引异常）只在非 0 时出现。 有异常（缺失或索引异常 > 0）时整行转 warning 色、右侧多一颗 ghost「修复…」按钮 → 打开「索引修复」对话框（与 ⋯ → 重建索引… 同一条 request_index_repair）——这是「文件系统 + 索引」双真相源的代价被做成可见、可处理的入口。

A常态异常桶为 0 → 它们不出现、整行 muted、没有按钮
8 项·已归档 5·分析表 2·引用 1

零桶不显示是这个计数器的口径（line() 里 if count > 0）：常态一行只有「N 项 · 已归档 X」，加上非 0 的类型桶。缺失 / 索引异常为 0 时它们根本不出现，不是写成「缺失 0」——原型此前把六个桶全列出来，等于把状态行当表格用。

B有异常missing / drifted > 0 → 整行转 warning 色 + 右侧一颗 ghost「修复…」
8 项·已归档 5·分析表 2·引用 1·缺失 1·索引异常 3 修复…

实现不是「分段高亮、点段落」：render_status_bar 判 counts.has_issues()，为真时整行文字色换成 warning，并在右侧摆一颗 Button::ghost「修复…」（px_2 内距、两端对齐）。整行一起变色不是偷懒——它表达的是「这一屏有东西要处理」，条目在哪一段由文案自己说清。
这颗按钮与 ⋯ → 重建索引… 调同一个 request_index_repair，所以不必在状态行里做两个段级热区。全局实例下这一整块替换掉：文案变「全局 N 项」，异常入口不摆（ArchiveCounts 是项目口径，全局行没有 kind 桶与异常桶）。
B 按真实面板宽 320px 画（其余几个态用 240px 只为省地方）：这条行是 px_2 + 两端对齐、字号 text_xs，四个非 0 桶加按钮已接近满宽——桶再多一条就会被裁（左段没有 min_w_0，真正的溢出点是文案而不是按钮）。

C零项空库只有「0 项 · 已归档 0」，与空态（19 页）成对出现
0 项·已归档 0
D加载中前缀「加载中… ·」+ 列表区 3–5 行骨架灰条（规格 §5；旧总集稿未画）
加载中…·0 项·已归档 0

取数期间不摆空态（否则「空库」会先闪一下）；骨架走组件 Skeleton（2s 呼吸、只改透明度，reduce_motion 下停在全亮）。列表已有行时不摆骨架，所以不会每帧重绘。加载中不抹掉计数：status_line(true) 只是给上一轮 line() 加「加载中… · 」前缀（那几项是上一次的库口径，抹成空白反而像库空了），所以显示的是「加载中… · {上次计数}」。原型此前写的「加载中… · 资产库」是假陈述。

E撤销条归档之后出现（不是回收站之后）：文案「已归档「名」」+ ghost「撤销」
7 项·已归档 4·分析表 2·引用 1
已归档「dau_report.sql」 撤销

撤销窗口 5 秒（status.rs 里 timer(Duration::from_secs(5))，与 M5 撤销栏同一时长）。撤回 = 删 resources/ 副本 + 删登记行（copy 模式）或只删登记行（reference 模式）；版本 > 1 拒绝撤回，回退走版本历史。
三处按实现改：文案是「已归档「名」」不是「已移入回收站」——这条栏只服务归档的立即反悔，回收站有自己的还原；栏高 24px（ROW_HEIGHT，py_0p5 + 20px 按钮），原型画的 28px 会让它「贴着状态行」上下跳；「撤销」是 Button::ghost（无边框，色取 primary，带 tooltip「把这条存档退回归档前的位置」），不是纯文字链接。背景是 list_hover。

本块样式：.pstatus / .pstatus .sep / .undo，以及拆块时补的骨架 .skrow / .skbar。本页已不用 .seg.warn / .seg.dang（实现不做分段高亮，整行转 warning + 一颗「修复…」按钮）。 落地代码：crates/analytics_resource/src/view_model/row.rs::ArchiveCounts::line|status_line（文案与零桶口径）+ resource_view/panel_render/banners.rs::render_status_bar（整行配色与「修复…」入口）/ render_undo_bar（撤销条）+ resource_view/status.rs（加载态与 5 秒计时）。
