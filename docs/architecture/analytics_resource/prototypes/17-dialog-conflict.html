推翻的九处：① 不是三选一的 radio 组——实际是「输入框 + 三个按钮」，处置动作全在 footer（conflict-dialog-cancel / conflict-dialog-overwrite / conflict-dialog-rename），正文里没有任何单选控件； ② 标题恒为「同名冲突」，升级与分发不换标题（旧稿那句「分发换标题『分发到本项目』」是假的），差异只在引言、覆盖提示与动词（ConflictKind::verb / holder / overwrite_note）； ③ 没有标题图标、没有副标题（旧稿 #i-warn +「冲突：全局已有同名资源」都不存在），正文里也没有「全局已有 v4 · 来自另一项目」这行——ConflictSeed 现在是三字段 kind / name / field（field 只说撞在哪一层），版本号与来源项目仍没传进来； ④ 没有 srcbar 那种「项目分析表 · 待升级」来源条、没有「冲突处置」这个字段标签； ⑤ 一句「覆盖会删什么」的 warning 行是有的，但文案是固定的两句（升级：删全局旧表 + 软删旧登记，新内容成为同名链的下一版；分发：删项目旧表 / 旧文件 + 软删旧登记，新分发成为同名链的下一版），不是旧稿那句「同名冲突不能静默覆盖，需先处置」； ⑥ 没有「跨项目唯一法定路径 = 项目 → 全局 → 项目」那条 info note（它在 §13 设计里，不在对话框里）； ⑦ footer 左边没有「升级会把表 + 版本信息复制进全局 DuckDB」这类长说明，三个按钮一律 small：取消 Secondary / 覆盖 Danger / 改名 Primary（.disabled(!can_rename)）； ⑧ 输入框是常驻的，不是「选了改名才展开」——开窗前由宿主建好并预填冲突名，所以默认状态必是「与原名相同」：提示 warning、改名灰、Enter 也提交不了（on_ok 里同样走一遍闸门，不过闸就 return true 不关窗）； ⑨ 改名与覆盖是两条并列的路，不存在「先选改名再确认」的第二次询问——覆盖按钮直接回宿主重入队 enqueue_promote(root, req, true)，改名把 req.name 换成新名后非覆盖重入队；状态栏回执「资产库：正在覆盖升级到全局…」/「正在升级到全局…」（分发侧是「正在覆盖分发到本项目…」/「正在从全局分发…」）。

原型没画而实现有的：闸门三种态（Ready / Unchanged / Blocked，各自一条提示，颜色 muted / warning / danger），B、C 两变体就是为它们补的；输入框在 Ready 态会回显要提交的新名（「将以「{新名}」升级到全局，不覆盖现有内容」）；取消直接关窗、不回调（on_close 只清 session）。

按钮外观按 vendor 实参：ButtonVariant::Danger 非 outline 时取 tokens.button_danger（danger.mix_oklab(transparent, 0.2)，即 20% 红底）+ 文字色 button_danger_foreground（danger 本身）——所以覆盖是淡红底红字、无描边，不是旧稿 .btn-d 的描边透明底。Primary 是实心品牌色 + 白字（.btn-p 那套）。禁用态 gpui 走 disabled()：Primary 底变 opacity 0.15、文字 muted_foreground 0.5。

两端版本口径已统一（2026-11-07 修掉）：升级侧 register_global 取 MAX(version) WHERE scope='global'、不带 deleted_at IS NULL，软删的旧行仍参与取最大值 → v5； 分发侧原来不接续（register_project_table 的 MAX(version) 带 deleted_at IS NULL，覆盖后旧行已软删 → 取不到 → 从 1 重开，与文案相反）；现在两处都去掉了这个过滤条件，覆盖后 = 旧 MAX + 1（v1 → v2），D 变体那句「成为同名链的下一版」由此成立。仍是数字接续、登记 id 换新。

本块样式：.dlg.proto-on 壳 + 内联（正文三段 / 输入框 / 亮起与灰掉的按钮）；不再用旧稿的 .srcbar / .locknote / .radios / .note / .fgrid。 落地代码：crates/analytics_resource/src/dialogs/conflict.rs（一个文件：ConflictKind / ConflictSeed / ConflictChoice / conflict_gate / open_conflict_dialog + 一条闸门单测），宿主在 crates/workbench/src/panels/{mod.rs,resources.rs}（开窗 ensure_conflict_dialog、重入队 request_conflict_choice）。

欠债两处：① 冲突回执现已带 ConflictField（撞在登记表 / 数据表 / 本体文件哪一层），但旧全局版本的版本号与来源项目仍没进对话框——设计上想「先摆清全局已有 v4、来自另一项目」（本页标题那句），现在还摆不出来，要再加就得扩 ConflictSeed 与 InstanceOpError::Conflict； ② 15 / 16 页的危险按钮仍按 .btn-d 描边画（与本页「淡红底实心」不一致），要不要统一到 vendor 实参后补。
