归档对话框§4.1

宽 34rem（544px）· 标题「归档为存档」· 只有草稿箱（面板头 ＋▾ → 从草稿箱归档… / 草稿行右键点名）与本地文件（＋▾ → 从本地文件归档…）两处会展开它。 结构是「只读三行（来源 / 目标位置·源位置 / 来源连接，标签在左）」+「六个字段（显示名 / 别名 / 分组 / 归档方式 / 标签 / 保留历史内容，标签在上）」。冲突不报错，改摆一行 warning 并把主按钮换成「改名归档」；提交成功 → 关窗 + 回执 + 首次归档给 5 秒撤销条。

只读块与表单刻意不同形：只读块标签在左（“告诉你”），表单标签在上（“要你填”）——扫一眼就知道哪几行动不了。只读第二行随归档方式切换：复制 = 目标位置（resources/ 下的最终相对路径，已做重名避让），引用 = 源位置（源绝对路径）。第三行「来源连接」在来源没带连接时照写「未记录」——不猜当前活动连接。
目标路径不给输入框：它由来源决定，手打就是绕过 PayloadStore::resolve 的越界与只读守卫。重名避让是主名加 -2 / -3…（保留目录与扩展名，试到 -999），开窗前就算好，所以对话框里摆出来的已经是最终名字。
显示名默认值是去扩展名的文件名（file_stem），不是带扩展名的文件名。footer 只有「取消 / 归档」两个按钮，左侧不写项目名与守卫说明——原型此前那句「应用守卫会拒写 resources/」是自造术语；真实守卫是只读项目在入口就被挡回：「项目为只读模式，不能归档」。

这里推翻原型原先的「外部文件只剩引用」：档位由扩展名决定（archive_kind_for 走 engine::duckdb::file_reader_function），认得出的数据文件（csv / parquet / xlsx / json）登记为分析表，而「引用」只对受管文件开放（allow_reference = kind == File）——所以这类文件没有单选，只有一句「分析快照固定为复制存档」，连「源位置」行都不摆（第二行仍是目标位置）。
落地口径（jobs/archive/run.rs）：探测失败降级而不是拒归档——文件先安全落进 resources/，按文件型登记指纹，日志里记一声。
另外「内容指纹」这一行不存在：指纹在归档动作里算并落库，不在对话框展示；目标位置也不改格式（复制是原样搬，resources/sales_daily.csv 仍是 csv）。

两种模式在落库形态上不同（service/archive.rs）：复制把本体搬进 resources/<rel_path> 并写相对路径；引用不动文件，file_rel_path 存的是源绝对路径——同一源二次归档会被唯一索引挡下（一个源一份引用）。
「引用型没有内容可复现」不能只靠这句说明：详情面板与行上都有对应状态（strength_badge 的「引用」档），源变更后打开会被指纹拦下、由用户决定「接受当前内容」。

D批量草稿 · 不展开这张对话框多条草稿走挑选对话框后按默认名逐个入队
只有一条草稿时（面板头全量里只勾一条、或草稿行点名一条）才展开完整的归档确认；多条走「挑选对话框 → 逐条用默认名入队」，回执是一句「已提交 N 个归档…（M 个目标被占，已自动改名）」——列表里没有位置让用户逐个改名，所以那一批没有显示名 / 别名 / 标签 / 分组 / 保留策略的可改机会（标签按草稿条目标签继承，保留策略按设置批带入）。

本块样式：.dlg.dlg-archive（544px）/ .dlg-head / .fgrid（只读块那三行）/ .fhint / .rdot / .inp / .dlg-foot；本页已不用 .srcbar（只读区改成标签/值三行）、.tags / .tagc（标签是一个逗号分隔的输入框）、.selw（分组是 ghost 按钮 + 下拉菜单）、.radios（两条竖向单选各带说明）、.inp.ro（本对话框没有只读输入框）。 落地代码：crates/analytics_resource/src/dialogs/archive/（mod.rs 的 seed / 校验 / 解析、open.rs 的表单装配与两条提交路径、fields.rs 的只读块与分组 / 模式选择器）+ resource_host/{mod,archive_actions}.rs（seed 备料、重名避让、入队）+ service/archive.rs（两种模式落库）+ jobs/archive/run.rs（撤销凭据只在首次归档给）。
