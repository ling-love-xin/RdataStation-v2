分发到本项目§13.6

全局行唯一能做的事：复制一份进当前项目。入口两处——全局行右键「分发到本项目…」／08 块详情面板那颗单动作按钮。 跟升级一样没有确认框：点一下直接入队，撞名才开冲突三选一（这张框在分发时标题变「从全局分发」，冲突持有方写「当前项目」）。

索引← 上一块：升级到全局下一块：跨项目全流程 →
A入口与两份形态分析表 → 建项目表；脚本内容表 → 重建为文件
全局分析表 → 项目分析表
全局连接 COPY … TO parquet 中转 → 项目连接 CREATE TABLE AS read_parquet(…)。落成 项目 行的 kind = 分析表。
为什么不用 ATTACH：Windows 单句柄上限，项目连接去 ATTACH 全局库文件会撞「文件被占用」。
脚本内容表 → 项目文件
读回 content 整段，写进当前项目的 resources/<原相对路径>，登记成 项目 的 File 档。
重建的路径沿用全局侧记的原始相对路径，不重新猜目录。

形态判定只有一条：全局登记的 file_rel_path 非空 = 脚本内容表 → 重建文件；为空 = 表 → 建表。用户侧看不到这个判定，也无法强制选另一种。
