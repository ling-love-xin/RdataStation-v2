取回（检出）对话框§4.2

宽 30rem（480px）· 标题「取回（检出）」，没有副标题 · 只有两个可改项：文件名（默认 <显示名>（工作副本）<扩展名>）与「取回后打开」（默认勾上）。 落点固定是草稿箱模块目录，对话框只读摆出这个目录；重名避让不在对话框里——它在动文件时做，回执才说真实路径。

推翻原型的「三种取回方式」：实现里没有「拷回草稿箱 / 在编辑器中打开只读副本 / 另存为…」三选一，也没有「目标位置」输入框。真实可改的只有文件名与一个「取回后打开」勾选——取回的本意就是「拿一份可写副本接着改」，所以去处只有一个（草稿箱），「只读打开」是详情面板「打开（只读）」那一入口的事，不是取回的变体。
默认文件名是 <显示名>（工作副本）<扩展名>：扩展名在括号外面，否则编辑器会按未知类型打开。显示名本身已经去掉了扩展名，所以扩展名由宿主持有，不从名字里猜。
只读块是「标签在左」的两行（存档「名（v3）」/ 目标目录），目录是宿主机绝对路径——M6 不认识草稿箱的目录结构（依赖方向是 analytics_resource → scratchpad），只把 root/scratchpad 交给对话框展示。

校验只拦注定失败的那几条：空、. / ..、路径分隔符与 Windows 非法字符（\ / : * ? " < > |）、保留设备名（CON / PRN / AUX / NUL / COM1-9 / LPT1-9，按去扩展名的主干比较，console.sql 不误伤）。提示是 danger 色一行小字，提交按钮按下但校验不过时对话框保持打开（不关窗、不弹 toast）。
重名不在这里判：草稿箱里已有同名是正常情况，由动文件时的 free_dest 自动避让成 -2，回执里说真实路径。原型此前把避让结果画进对话框（dau_report-2.sql 的只读输入框），那一步在开窗时并不知道——目录快照到提交之间文件系统还会变。

C只读项目 · 对话框根本不展开门禁在入口，不是「打开后三动作全灰」
资产库：项目为只读模式，不能取回
只读项目的判断在入口（request_checkout）就做完：给一句面板回执就返回，对话框不打开。所以原型 B 那套「顶部 warning 条 + 三个动作灰掉两个」并不存在——那个形态等于先把用户放进一个注定失败的窗口。
同一口径的还有归档（「项目为只读模式，不能归档」）与升级到全局（「…不能升级到全局」）；菜单项的置灰（can_checkout = !is_global && 正常 && 非只读）是第二道，防的是「用户从菜单点进来」。

本块样式：.dlg.dlg-checkout（480px）/ .dlg-head / .fgrid（只读两行）/ .inp / #i-check（勾选框）/ .dlg-foot / .note.warn；本页已不用 .radios（不是三选一）、.srcbar（没有顶部来源卡片）、.rdot（勾选不是单选）、.dlg-head .sub2（无副标题）、.warnstrip（只读项目不进对话框）。 落地代码：crates/analytics_resource/src/dialogs/checkout.rs（seed / 文件名校验 / 默认名拼法 / 两条提交路径）+ resource_host/detail_actions.rs::request_checkout（只读门禁与目录备料）+ jobs/archive/run.rs::run_checkout（free_dest 重名避让、回执给真实落点）。
