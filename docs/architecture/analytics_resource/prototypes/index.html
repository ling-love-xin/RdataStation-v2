怎么用这一套
① 要改视觉（间距 / 颜色 / 行高 / 徽标形状）→ 改 _shared/proto.css 一处，26 页同时生效；
② 要改某一块的布局或文案 → 只改那一页的 HTML，不会牵动别块；
③ 要加新状态 → 在那页里新加一个 .variant 小节，页内并排即可，不用造状态位；
④ 页脚「本块样式 + 落地代码」告诉你这块在 crates/analytics_resource/ 落到哪，评审结论可直接指到文件。
三种状态显影手法：proto.css 里本来就有 .open / .on 的（弹层、菜单、横幅、撤销条、重叠表）直接加；没有独立开关的（对话框、右键菜单、状态行、编辑区 tab、详情态）用 page.css 的 .proto-on，它只做 display 与定位还原，不改任何视觉。

这四页是本轮补的，补的是索引过去自己承认的那条缺口（旧第⑤条：分发 / 实例化 / 跨项目引用没有页）。补之前先核了代码： 双实例的数据层早已落地（全局登记表 crates/store/migrations/global/026_analytics_resource_global.sql、global/promote.rs、global/distribute.rs、dialogs/conflict.rs 的两个 ConflictKind）， 落后的只有「评审页里看不到这些画面」，以及设计稿 §13 开头那句「实现不动」的口径。 所以这四页照代码现状画：真正的落差（分析表型不能升级、升级后项目行不带标记）逐条写明；「确认框」不是规格要求，是本轮提的加法，单独摆成方案页供拍板，两件事不混为一谈。

没有拆进来的东西（如实说明）
① 四个动作的时序图（归档 / 取回 / 版本 / 回收站）仍只在设计稿 §4 里，属流程不是 UI 块；
② 应用级状态栏、标题栏 36px、活动栏 48px 是外壳，不属本模块，故不做页；
③ 主题映射（§6）与尺寸校验表在总集稿末尾与设计稿 §7，属对照表，仍在总集稿看；
④ 总集稿六张说明卡片（三种 kind / 只读三重 / 右键条件 / 异常修复 / 洞察联动 / 双实例）尚未拆成独立「说明页」——它们的结论已折进各页 .p-spec 与页脚注，需要原文时看总集稿；
⑤ §13 里两处口径没定（纯文件档（png / zip / docx）进不进全局、分发时能不能直接改名）——它们不是「没画」，是规格自己没写，故只在 26 块 E 节标【待确认】，两路的代价摆在那儿，不造画面。其中「二进制升级」的现状已收口：入口改成两张正向白名单，png / zip / docx 在入队前拿到中文回执，不再撞 UTF-8 抛英文错误；「要不要真支持」仍待拍板。
