分流的判据只有两条：view_rows.is_empty()（有没有行）与 filter.is_empty()（条件空不空，= 搜索词 + 种类 + 标签 + 只看异常四维全空）。 有行就画行；没行且条件空 → 加载中骨架（取数期）或 空库（真没有）；没行但条件非空 → 无匹配。三种空态都走组件 empty::Empty，骨架走 skeleton::Skeleton。

E3 详情面板横幅（前三档纯文本，第四档带两枚钮）

旧稿最要紧的一条过期结论：它写着「未做：索引异常首次进入的顶部一次性提示条（§5「未做」第二条）」——现在做了：render_index_issue_banner（resource_view/panel_render/banners.rs:121-174），仅项目实例、counts.has_issues()、且本会话没被关过时出现（announced_index_issue 纯内存标记）；文案「发现本体缺失 N 项、内容已变 M 项，可在状态行「修复…」处理。」，× 关掉后本会话不再出现。全局实例直接返回 None（没有本地索引口径）。

其余五处也与旧稿不同：① 顶部那条整块不可点，没有「点横幅进索引修复」——要处理走底部状态行的「修复…」（banners.rs:112-119）；② 详情横幅的缺失文案指的是索引修复，不是旧稿写的「从回收站还原」（回收站里没有本体，见 detail_view/actions.rs:89 的拒绝话术）；③ 详情横幅共五档，多出「分析表结构已变」（文案来自 analysis::STRUCTURE_CHANGED_NOTE）、「这是引用：源表可能已变更或被删除」（TableRef 常态提示）、「引用型：本体在源位置，源变更后快照失效」（detail_view/rows.rs:96-120）；④ 引用失效条是独立一条，带「接受当前内容」「从历史还原」两枚按钮，槽位由宿主按 resource_id 维护、不进索引统计（detail_view/banners.rs:28-87）；⑤ 还有一条容易漏的 render_notice 文本条：同一字段按 read_only 决定颜色（只读 = warning，其余 = info）——banners.rs:12-17。

欠债两条：① 详情横幅纯文本、没有「去修复」按钮，用户得自己回面板状态行找入口（两处文案还不同：面板条说「可在状态行「修复…」处理」，详情条说「可用索引修复还原或删除记录」）；② 加载中被筛选挡住：filter.is_empty() 才给骨架，条件非空时取数期间直接摆「没有匹配的存档」——队列还没回来就宣布「没有匹配」，快速输入时会闪。

分流与位置（resource_view/panel_render/mod.rs:47-62）： view_rows.is_empty() 为真时，filter.is_empty() 为真 → loading ? 骨架 : 空库，否则 → 无匹配；有行 → List。 三种空态都是 empty::Empty（EmptyHeader + EmptyTitle + EmptyDescription，按钮进 EmptyContent），骨架是 skeleton::Skeleton——没有一个手搓的居中 div，也没有一个手写灰条。

本块样式：.empty-state（.big / .t / .d / .btns，不再用 .sug）、.row、.sb；旧稿的 .skrow / .skbar / .sk-hint / .warnstrip / .row.miss 在本页不再引用（实现里横幅与骨架都由组件出，不是 CSS 画的）。
