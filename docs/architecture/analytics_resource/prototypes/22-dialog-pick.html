三处推翻旧稿
① 头部没有副标题「项目「营销分析」」——dialog.title("从草稿箱归档") 只吃一个标题（dialogs/pick.rs:193）。
② 行右侧那一列不是连接名，是连接 id：DraftCandidate.connection_id 来自 file_meta.preferred_connection()（显式绑定优先、其次上次执行用过的那条），而 FileMeta 注释写明「仅存 ID，凭据在 auth_store」（scratchpad/src/models.rs:94、:107-115）；pick.rs:168-175 直接把它当文本 child(connection) 打出来。
③ 旧稿写的「营销分析库」是连接显示名，实现没有这一层解析——用户实际看到的是 conn_mkt_01 这样的 id（宽度不够时还会被省略号吃掉一半）。

文案与实现逐字一致：format!("还有 {} 个未列出（一次最多选 {MAX_DRAFT_ROWS} 个）", candidates.len() - shown)（pick.rs:179-190）。
「全选」的语义是一个开关：已全选时再点 = 全清（state.set_all(!all_selected)，:132-138）——省一个按钮，也意味着「全选」不区分「只勾列出的 50 条」与「勾全部 68 条」：它只作用于候选全集，但可见的只有前 50 行。

D两条入口 × 两条收尾：挑完之后会发生什么
入口一：面板头 ＋▾ 第一项
候选 = 草稿箱里全部可归档文件（目录不算），一条都不预勾
文件树压平时把内部/隐藏路径挡在门外（relative_path_of 同一守卫）
候选为空 → 对话框不开，直接提示「资产库：草稿箱里还没有可归档的文件」
入口二：草稿行右键「归档为存档…」
候选由调用方点名，且只认快照里还在的（刚被移走/删除的路径不硬归档）
一条 → 跳过挑选对话框，直进归档确认
多条 → 预勾上再摆挑选框（留个剔除的机会）
收尾一：只勾一条
关窗后再开归档确认对话框（先 close_dialog 再回调，否则新框被旧框顶掉）
可改显示名 / 别名 / 分组 / 归档方式 / 标签；草稿标签预填进对话框，可改可删
收尾二：勾多条
默认名（文件名去扩展名）+ PayloadMode::Copy + 分组恒 None + 保留策略按设置批 + 标签继承
逐个入队；目标被占就 free_rel_path 自动改名
回执「资产库：已提交 N 个归档…（M 个目标被占，已自动改名）」

多选那条的代价写在注释里：列表里没有位置让用户逐个改名，「与其摆一个假的批量编辑，不如说清批量用的是默认名」（pick.rs:8-11）。 所以只勾一条以上（即勾 2 条及以上）就没有分组可选——分组只能进「只勾一条」那条路，或先用单选逐条归档。

键盘：本对话框没有绑 Enter。它自画 footer 两枚按钮、只调了 .on_cancel(...)、没调 .on_ok(...)（pick.rs:235-271），所以 Esc 能取消、「归档」只能用鼠标点。 这与 20 / 21 页刚好相反：那边 on_ok 恒返回 true，Enter 会关窗（哪怕该拦的没拦住）。

链路：request_archive_from_drafts / request_archive_drafts（resource_host/archive_actions.rs:7-106）→ open_draft_pick_dialog → 提交回调 pick_handler（:119-144）→ 单选 open_archive_for_draft / 多选 archive_many（:221-282）。 前置：无项目根 → 「资产库：无法归档：还没有打开项目」；只读 → 「资产库：项目为只读模式，不能归档」。

本块样式：.dlg.dlg-pick（544px）/ .picklist（max 288px）/ .pickrow / .ckbox（proto.css 原件）/ .more。 落地代码：crates/analytics_resource/src/dialogs/pick.rs（MAX_DRAFT_ROWS = 50、PickDialogState 由外部持有——builder 每帧重建，状态放进闭包里会被漏掉）。
