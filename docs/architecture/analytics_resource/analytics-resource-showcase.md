## 一句话

**把文件归档进去——从此刻起它只读、有版本、带来源；要改，就取回一份工作副本。**

它不是一个文件浏览器：归档 → 取回 → 再归档是一条完整的闭环，凭证、版本、组织、检索、回收站、索引修复都在里面。
**这份结论从哪来、改过几版、能不能回来——都在界面上写着。**

### 它替你做到的事

| 你关心的 | 它给什么 |
| --- | --- |
| 当时发出去的到底是哪一版 | **内容指纹版本**：内容变了才 `v+1`（改显示名、打标签、归组都不涨版本）；历史版本可「还原」（生成新版本、不覆盖历史）或「取回为草稿」 |
| 这个结论是用什么数据算的 | **归档凭证三件套**：来源连接 / 来源草稿路径 / 来源表 + 定义 SQL + sha256 指纹，随存档一起留 |
| 会不会被人误改 | **只读三重守卫**：应用层写入直接拒 + 编辑器以只读打开 + 文件系统只读属性（辅助） |
| 归档完反悔了怎么办 | **5 秒撤销条**（本体移回 + 删登记行）；更久之后走回收站还原 |
| 东西多了找不到 | 搜索 + 三维筛选（类型 / 只看需处理 / 标签）+ **五个排序键**（记住上次选择）+ 标签（多值、跨类型）+ 单层分组（折叠状态记住） |
| 索引坏了 / 本体被人动过 | **索引修复**：三类差异逐条列出，人工确认后补登 / 删记录 / 接受当前内容 / 从回收站还原 |
| 会不会偷偷动我的文件 | 归档是 **move + 置只读**，取回是 **复制**；永久删除要二次确认；跨模块还原被拒 |

> 数字口径以模块文档为准；工程数字（测试套件、迁移、场景清单与实证缺陷）见第 14 节。

## 1. 为什么它不再是一个「资源列表」

v1 有 2237 行后端存储，前端却**只有占位卡片**。这一版把「看着有、实际是假」的底座逐条换成了真东西：

| 旧样子 | 现在 |
| --- | --- |
| 登记表只是一行元数据指向某处 | **归档凭证三件套**（来源 + 定义 SQL + 内容指纹）；`kind` / 指纹 / 本体路径 / 只读是归档行的**语义必填**，走通用入口建不出「看起来像存档、实际没凭证」的行 |
| 版本是「写前快照」：任何一次 `update` 都 +1（改个别名也消耗一个版本号） | **指纹是版本的唯一触发条件**：内容没变就不产生版本；`parent_version_id` 指向写前快照行（v1 传的是资源自身 id，等于没有信息量） |
| 回收站是模块私有的软删表（`recycle.rs` 419 行） | **项目级 `ProjectTrash`**（上提中性化：来源是字符串 `origin`，不返回上游类型）：与草稿箱共用一处仓库，**跨模块还原被拒** |
| 文件夹树是残的（自引用 `parent_folder_id`，无改名 / 删除 / 移动 / 排序） | **标签扶正 + 单层分组**（裁决 D8）：标签多值、跨类型通用；分组单层，**删分组不删存档** |
| 搜索 `LIKE` 不转义（输入 `%` 命中全表）· 分页除零 / 负数 panic · 更新无事务 · 行映射散在四份 | 逐条修掉：`LIKE` 转义 · 分页夹紧 · **事务化更新** · **行映射收敛为 1 份** · 影响 0 行不再静默 |
| 前端：300px 卡片网格（240px 面板放不下）· 页码分页器 · LRU + TTL 缓存（本身有缺陷）· 8 条只在设置页展示的假快捷键 | **紧凑行列表（虚拟化）** · 滚动代替翻页 · 不迁缓存（本地 SQLite 没有 IPC 成本）· 快捷键**真的绑上**并有窗口测试守着 |

## 2. 三种存档类型 · 一个本体规则

| 类型 | 本体在哪 | 复现强度 | 状态 |
| --- | --- | --- | --- |
| **文件** `File` | `{项目}/resources/` 里的文件（只读） | **强**：有字节 + 指纹，能逐字节校验 | ✅ 已落地 |
| **分析表** `Analysis` | `{项目}/.RSmeta/analytics.duckdb` 里的表 | **中**：有结构与指纹，没有"导出字节"这一说 | 设计已定 · Phase 4 |
| **引用** `TableRef` | 远端表（本地只留指针 + 指纹） | **弱**：只能回答"它还在不在、变没变" | 设计已定 · Phase 5（不承诺） |

三档共用一条规则：**本体在哪由类型决定，登记表只是索引**——文件系统是权威，索引可以从本体重建，反过来不行。

> **诚实标注**：一期只落地了**文件档**（从草稿箱或本地文件归档）。分析表 / 引用两档的类型、强度与降级口径已经在代码与文档里定死，但本体层与入口还没接。

## 3. 三个高光

如果只记三件事：

**① 指纹是版本的唯一触发条件。**
`content_hash` 未变即幂等返回，不产生「假版本」；历史内容副本按策略裁剪（默认 5 份，可设「只留元数据」`0` 或「全部保留」`-1`），而**版本行永久保留**——界面上以「副本缺失」呈现，不假装能还原。

**② 只读是常态，「取回」才是修改路径。**
归档即 `move` 进 `resources/` 并置只读；修改走「取回（检出）」——复制一份可写工作副本到草稿箱，**本体一个字节不动**。与 git「签出 → 改 → 提交」同构，用户已有心智模型。

**③ 每一句「做不到」都带着原因。**
写 `resources/` 直接拒并指向"先取回"；副本被裁剪的版本显示「副本缺失」；标签 / 分组没落上会写进同一句回执；索引修复只列差异，**不静默导入、不静默删除**。

## 4. 四个剧本 · 它替你做什么

每一步都用现有按钮，能照着做。

### 剧本 A · 报告发出去两周，被问「当时是哪一版」→ 版本历史

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 找到那份存档 | 搜索显示名 / 按类型筛 / 排序切到「更新时间 ↓」（选择会被记住） |
| 2 | 看它改过几版 | 详情面板「版本」区 → 「查看全部…」打开版本历史 |
| 3 | 判断哪版是当时那份 | 每行给出：版本 / 归档时刻 / 大小 / 内容指纹前 12 位 / 内容副本是否还在 |
| 4 | 把旧内容拿出来用 | 「取回该版本为草稿」——不覆盖本体，落一份可写工作副本 |
| 5 | 或者把本体退回去 | 「还原」= 用旧内容**生成新版本**（v+1）；历史一版不丢，随时能再退 |

### 剧本 B · 接手别人的分析，想知道数据从哪来 → 凭证与指纹

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 看来源 | 详情面板「来源」区：**来源连接**（跑过 SQL 的草稿会自动带出）/ **来源草稿路径** / **来源表** |
| 2 | 看怎么算的 | 同一区给出**定义 SQL**（分析表型）与**指纹前 12 位**（可复制，用来对账） |
| 3 | 看它现在什么样 | 行尾字段与状态行：已归档 / 分析表 / 引用；缺失与「内容已变」单独计数并给「修复…」入口 |

### 剧本 C · 要改归档文件，但不想毁掉原件 → 取回 → 改 → 再归档

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 取回（检出）… | 行右键或详情面板动作区；落点自动避让重名，不会覆盖工作区已有文件 |
| 2 | 编辑工作副本 | 在工作区随便改：本体保持只读，改的是副本 |
| 3 | 再归档 | 内容变了才 `v+1`；**旧内容先留成历史副本**，再覆盖本体 |
| 4 | 内容其实没变？ | 幂等返回：不覆盖本体、不增版本，工作副本留给你（不用重跑一遍） |

### 剧本 D · 手滑归档错了 / 手滑删了 → 撤销条与回收站

| 步 | 动作 | 怎么做 |
| --- | --- | --- |
| 1 | 立刻反悔 | 状态行上方的撤销条（5 秒）：**本体移回原位 + 删登记行**；原位置被占则拒绝并说明原因 |
| 2 | 已经过点了 | `Delete` 移入回收站 → 回收站对话框「还原」（`origin` 校验 + 同名避让并同步登记路径） |
| 3 | 确定不要了 | 「永久删除」走二次确认；「清空」只清本模块名下的条目（别人的只给一句说明） |
| 4 | 想撤销更多？ | 不承诺：**撤销条只保刚归档那一次**，再归档的反悔走版本回退（见剧本 A） |

## 5. 一次归档的全流程

```
  ┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌────────────────┐   ┌────────────┐
  │ 1 解析来源   │ → │ 2 算指纹     │ → │ 3 搬本体     │ → │ 4 写登记       │ → │ 5 附属项   │
  │ 草稿 / 本地  │   │ sha256 + 体积│   │ move + 置只读│   │ 归档行 v1      │   │ 标签 / 分组│
  │ 目标占用探测 │   │ （搬运前算） │   │ 失败即中止   │   │ + 写前快照语义 │   │ 失败只记说明│
  └──────────────┘   └──────────────┘   └──────────────┘   └────────────────┘   └────────────┘
     host 事件路径        payload            payload             store              service
                                        ↑ 索引写失败 → 本体移回原处（不留半成品）
```

| 步 | 做什么 | 落点 |
| --- | --- | --- |
| ① 解析来源 | 草稿候选（相对路径 / 显示名 / 连接从 `file_meta` 带出）或系统文件选择；目标被占则先算好"改名到哪" | `resource_host.rs` |
| ② 算指纹 | sha256 + 体积，**在搬运前**算：失败即中止，不动任何状态 | `payload.rs` |
| ③ 搬本体 | `move` 进 `resources/`（跨设备退回复制 + 删除）并置只读；只读属性失败只警告 | `payload.rs` |
| ④ 写登记 | 归档行（`kind` / 指纹 / 本体路径 / 只读 + 凭证三件套）；**先本体后索引**，索引失败回滚本体 | `resource.rs` |
| ⑤ 附属项 | 标签（按名找、找不到就建；同名复用）与分组（移动语义）；失败**不回滚归档**，写进回执 | `service.rs` |
| ⑥ 广播与回执 | 变更事件（`Archived`）→ 面板刷新；状态栏回执 + 5 秒撤销条 | `service.rs` / `panels/` |

**三条口径**：顺序固定（先本体、后索引）· 附属项不牵连主操作（文件已归档好，标签/分组能在面板补做）· 事件发 / 收两端同批落地（不学 v1 那个"发了没人听"的事件）。

## 6. 版本语义：什么才算新版本

| 事件 | 结果 |
| --- | --- |
| 内容变了（指纹不同） | `v+1`：先把当前内容留一份历史副本 + 写前快照行，再覆盖本体 |
| 只改显示名 / 别名 / 标签 / 分组 | **不产生版本**（登记行更新，版本号不动） |
| 取回后原样再归档（指纹相同） | **幂等**：不覆盖本体、不增版本，工作副本留给用户 |
| 历史内容副本超出保留策略 | **只删副本**：版本行永久保留，界面标「副本缺失」 |
| 还原到旧版本 | **生成新版本**（v+1，内容 = 那一版）；历史不被覆盖，随时能再退 |
| 在某版本上操作 | 版本历史一行最多三个动作：还原 / 取回该版本为草稿 / 删除该版本的内容副本 |

> 保留策略（设置页「资产库 › 历史内容保留」）：`5` 份（默认）· `0` 只留元数据 · `-1` 全部保留；归档对话框里可为**这一次**覆盖。

## 7. 面板解剖（左侧 Dock，起步 240px）

```
┌ 资产库 ─────────────────────────── ＋ ▾   ⋯ ┐   ← 面板头：＋ 双入口 / ⋯（重建索引 / 打开资源目录 / 回收站 / 刷新）
│ ⌕ 搜索存档            [筛选 ▾]   [更新 ↓ ▾] │   ← 工具栏：搜索 · 三维筛选 · 五键排序（记住上次）
├─────────────────────────────────────────────┤
│ ▾ 全部分组                          12 项   │   ← 分组折叠区：全部分组 → 未分组 → 各分组（计数随可见行）
│   ▾ 未分组                                  │
│     ▤ dau_report.sql      v3   1.2 KB · 3 天前│  ← 行：图标 显示名 版本 强度 尾部字段
│     ▤ 临时订单分析.sql    v1   12 KB · 3 小时前│
│   ▸ 报表                            3 项    │   ← 折叠状态会被记住（按项目分开记）
│ 12 项 · 已归档 10 · 分析表 1 · 缺失 1   修复… │   ← 状态行：库口径计数 + 异常时的修复入口
└─────────────────────────────────────────────┘
  （>100 项虚拟化；空库与「无匹配」是两种空态；加载时给骨架 + 状态行前缀）
```

**行怎么读**（240px 内的字段优先级）：显示名 > 复现强度徽标（唯一色块）> 版本徽标（`v1` 不显示）> 相对时间 > 大小。
文件型给体积、分析表型给「行数 × 列数」、引用型写「无指纹」——**宁可写"没有"，也不留空让人以为"还没算"**。

**鼠标与键盘**：单击选中 · `Ctrl` 加选 · `Shift` 区间 · 双击 / `Enter` 打开（只读）· `Ctrl+A` 全选可见行 · `↑↓` 漫游（跨分组头）· `Delete` 移入回收站 · `Ctrl+F` 聚焦搜索 · `Esc` 清搜索 / 关菜单。
多选时单行动作一律置灰，删除项变成「移入回收站（N 项）」。

## 9. 组织与检索

| 件 | 口径 |
| --- | --- |
| **标签** | 多值、跨类型通用；新建 / 重命名 / 删除（**删标签不动存档**，确认框里写清"从 N 条存档上摘掉"）；详情面板与标签对话框两处入口 |
| **分组** | 单层（没有多级子文件夹）；建 / 改名 / 删 / 移动到分组；**拖行到分组头 = 归组**（多选拖一条 = 拖整选集）；**删分组不删存档**（成员回「未分组」）；分组头右键给管理项 |
| **折叠** | 点分组头折叠；**状态按项目记住**（设置项 `resources.collapsed_groups`，按项目根分桶） |
| **筛选** | 三维：类型（文件 / 分析表 / 引用）· 只看需处理 · 标签（多选并集，菜单里带用量）；按钮上标条件个数 |
| **排序** | 五个键：名称 / 归档时间 / 更新时间 / 大小 / 版本号；同键再点翻转方向、换字段沿用方向；**缺值（无体积 / 无归档时间）两个方向都排最后**；选择被记住（`resources.default_sort`） |
| **搜索** | 匹配**显示名 / 别名 / 标签 / 来源表 / 尾部字段**（大小写不敏感）——别名 / 标签 / 来源表**行上不显示**但都搜得到（可搜不高亮）；`Ctrl+F` 聚焦，`Esc` 清空；搜不到时空态里会列出可搜字段 |
| **改显示名** | 行上 `F2` 或右键「重命名…」；只改 `project.db` 里的名字，**不涨版本、不进版本历史**；`resources/` 下的文件名与路径不动 |
| **内容预览** | 详情面板里给文本型存档摆前 20 行（只读、等宽、不折行）；二进制 / 大文件 / 本体不在只给一句「仅元信息」 |

> 排序比的是**原始值**（时间戳 / 字节数），不是格式化后的尾巴——拿 `1.2 KB` 与 `900 B` 按字符串比会静默排错。

## 10. 八个对话框

| 对话框 | 什么时候出现 | 一条口径 |
| --- | --- | --- |
| **归档确认** | 从草稿箱（单选）或本地文件 | 五个字段都真的落库：显示名 · 别名 · 分组（下拉）· 标签 · 保留历史内容；目标被占时按钮改成「改名归档」 |
| **草稿多选** | 面板头 `＋ ▾ → 从草稿箱归档…` | 选多个 = 默认名批量入队；选一个展开完整确认 |
| **取回（检出）** | 行右键 / 详情动作区 | 目标名可改、重名自动避让；「完成后打开」可选 |
| **版本历史** | 详情版本区 / 行右键 | 当前版本与历史同列；行选中后动作栏才对它生效；动作后不关窗、换行 |
| **索引修复** | 状态行「修复…」/ 面板头 `⋯ → 重建索引…` | 三分组（有文件无记录 / 有记录无本体 / 指纹不匹配）；修完自动重扫并换行 |
| **回收站** | 面板头 `⋯ → 回收站…` | 只列本模块条目；行内还原 / 永久删除；页脚「清空」只清自己名下的 |
| **标签** | 详情「＋ 标签」/ 行右键 | 勾选差集 + 新建并打上；每行 ⋯ 可重命名 / 删除 |
| **分组名** | 新建 / 重命名分组 | 一个文件两个形态；空名与同名当场拒（同层唯一） |

## 11. 回收站与索引修复

**回收站**（项目级，与草稿箱共用一处仓库）：

```
移入回收站 = 本体进 {项目}/.RSmeta/trash/ + 登记行软删（deleted_at）
还原       = origin 校验 → 同名避让 → 本体回 resources/ → 登记行复活（别名 / 标签 / 指纹一起回来）
永久删除   = 真删本体 + 删行（连标签与分组关联一起清，外键没有级联）
清空       = 只清 origin = "resources" 的条目（别人的条目只给一句说明）
```

| 索引修复的三类差异 | 只报告，等人工确认 |
| --- | --- |
| 有文件、无记录 | **补登为存档**（指纹现算；来源无从得知就留空） |
| 有记录、无本体 | **从回收站还原**（按原相对路径找条目）· 或**删除记录**（二次确认） |
| 指纹不匹配（内容被绕过只读改过） | **接受当前内容**（生成新版本，旧内容不可得就如实说明）· 或**打开版本历史**去还原 |

## 12. 只读三重守卫

| 层 | 挡什么 | 失效时 |
| --- | --- | --- |
| ① **应用守卫**（硬约束） | 任何写入 `resources/` 的 API 调用：直接拒绝，文案指向"先取回" | 不失效——这是模块硬约束 |
| ② **编辑器只读打开** | 本体在编辑器里没有光标（只读档）；顶部给只读条 | 用户仍可"另存为"到别处（期望行为） |
| ③ **文件系统只读属性**（辅助） | 顺手挡一下外部工具 | Windows / 网络盘上不可靠——**只警告，不影响归档成立** |

> 指纹是最后一道：即便有人绕过前面三层改了本体，下一次刷新的索引扫描会发现「内容已变」，并在界面上摆出来。

## 13. 架构 · 依赖只向下

```
┌─────────────────────────────────────────────────────────────────────────┐
│ rds-app            窗口 · 主题 · 键位注册（Ctrl+F / Esc / Delete / Ctrl+A）│
├─────────────────────────────────────────────────────────────────────────┤
│ rds-workbench      宿主：把端口接到真实世界                                │
│                    panels/resources（面板装配 · 轮询回填）                 │
│                    services/resource_jobs（单工作线程 + 结果槽）           │
│                    components/resource_host（22 个端口的实现）              │
├─────────────────────────────────────────────────────────────────────────┤
│ rds-analytics-resource   模型与纯函数 + 视图（视图随 crate）                │
│                    纯逻辑：filter（筛选 / 五键排序 / 折叠分区）· present    │
│                    服务：service（编排 + 事件）· payload（本体层）          │
│                          store（登记 / 版本 / 标签 / 分组）· indexer（修复）│
│                    视图：resource_view · detail_view · dialogs/（八个对话框）│
├─────────────────────────────────────────────────────────────────────────┤
│ rds-engine         持久化（项目库 · DuckDB 连接）· 项目级回收站 ProjectTrash│
├─────────────────────────────────────────────────────────────────────────┤
│ gpui-kit · shared · workbench_shell   视图唯一依赖 / 错误类型 / 壳层尺寸常量│
└─────────────────────────────────────────────────────────────────────────┘
       依赖方向：app → workbench → analytics_resource → engine → shared
       M6 不依赖 M5（归档入参只有「路径 + 元数据」）；上游 scratchpad → M6 单向
```

**端口清单**（面板只发意图，宿主才有副作用；`Rc<dyn ResourcesHost>` 共 22 个方法）：

| 端口组 | 回答什么 |
| --- | --- |
| 归档（`request_archive_from_drafts` / `_from_file`） | 从哪来 · 目标被占怎么改 |
| 打开与路径（`request_open` / `_reveal` / `_copy_path` / `_open_payload_dir`） | 只读打开本体 · 在系统中显示 · 复制路径 |
| 取回与版本（`request_checkout` / `_version_history` / `_undo_archive`） | 工作副本落哪 · 版本历史 · 撤销归档 |
| 组织（`request_edit_tags` / `_remove_tag` / `_move_to_group` / `_create_group` / `_rename_group` / `_delete_group`） | 标签与分组的全部动作 |
| 删除与回收站（`request_delete` / `_open_trash`） | 移入回收站（批量）· 打开回收站对话框 |
| 健康（`request_index_repair` / `_refresh`） | 重建索引 · 重新取数 |
| 记忆（`remember_sort` / `remember_collapsed`） | 把用户的排序 / 折叠选择写回设置 |

**两条纪律**：

1. **渲染零 I/O**——面板只读自己持有的快照；取数、扫描（逐个本体算 sha256）、搬文件全在**单工作线程**上，结果经结果槽回填。
2. **纯函数优先**——筛选 / 排序 / 折叠分区、尾巴字段、相对时间、版本行合成、修复行合成、回收站行合成全是纯函数，逐条断言；视图不出现裸 `px()` 与裸色值（尺寸常量在 `ui.rs`，颜色走主题 token），契约测试守着。

## 15. 边界 · 这些事它不做

**不做的**（开发方案 §8，逐条有理由）：

- **多级文件夹树 / 面包屑 / 手动排序号**：v1 那棵树是残的，投入产出比差；标签 + 单层分组已够；
- **页码分页**（10/20/50/100）：桌面应用语义是滚动 + 虚拟列表；
- **归档本体的原地编辑**：一旦允许，指纹与版本就失去意义；
- **自动索引修复**：静默导入 / 删除会让"存档"变成用户没同意过的东西；
- **版本行级 diff**：文本 diff 归编辑器；
- **`config` JSON 手工编辑**：字段进表单，扩展进详情面板；
- **拖拽到 SQL 编辑器**：有「取回 → 打开」路径，跨面板拖拽的价值不抵复杂度；
- **v1 设计文档里从未实现的 17 条命令**（`extract_table` / `check_delete_safe` / `cleanup_expired` …）：无消费方、无真实需求。

**还没做的（都记在册）**：分析表 / 引用两档（Phase 4 / 5）· 默认分组 · 详情头部可编辑 · 回收站的自动清理策略（按时间 / 容量）· `kind` 过滤的存储层入口。
