# analytics_resource 最小完成开发计划（2026-11-27）

> 基线：`main@3d55b4cf`，R2 审计后的 6 个修复提交已合流。
> 目标：只补齐“实现完成”所需的最小闭环，不把运营能力塞进这一刀。
> 纪律：先实现完，再统一跑测试；仓库 CRLF，不改用户 WIP。

## 1. 目标与判断

R2 的 P0 身份混链、P0 还原绕过、P1 物理孤儿、P1 全局老版本入口已关闭。
当前剩余与“实现完成”直接相关的只有一处模型债：

- **全局文件版本链仍按 `name` 聚合**。当前因为全局行禁止改名而不炸，但链键不是稳定身份，一旦开放改名就会断链或混链。

本刀把这条链改成**稳定父链**，并清理已知死代码与文档漂移。完成后，本模块的“已知写入口 + 已知版本链键”都可由稳定标识闭合。

## 2. 范围

### 做

1. **全局文件版本链改稳定父链**
   - 复用 `analytics_resources.parent_resource_id`（文件每升一版已经写入父行 id），不新增迁移。
   - `global_file_versions(name)`：先按当前 head 找到链根，再按父链取全部版本；不再 `WHERE ar.name = ?`。
   - `restore_file_version(name, version)`：同样在父链内按版本号定位目标，避免改名后按 name 查不到旧版。
   - 旧数据兼容：父链在历史行已存在；若父链为空则只退到当前 head，不静默把同名但不同根的资产合并。

2. **回归用例**
   - 改名祖先行（模拟未来开放全局改名）后，版本历史仍返回完整链。
   - 同名但不同根的文件资产不会被合并进同一条链。
   - 改名后仍能按历史版本恢复。

3. **死代码与文档**
   - 删除无调用方的 `purge_name_chain`。
   - 两个仅测试使用的 `global/sql.rs` helper 收进 `#[cfg(test)]`，消掉生产构建的 `dead_code` 警告。
   - README 把“全局文件按 name 聚合”改成父链口径；面板头“四项/三项”按实际代码复核后回写。

### 不做（明确留给后续刀）

- 数据库部分唯一索引 / 存量同名数据迁移：需要单独的数据清理刀，不能和版本链混在一起。
- 回收站 TTL、批量改名 / 撤销、标签颜色、回收站分组、增量刷新、大列表性能。
- 全局版本恢复确认框：当前与项目还原同口径，属产品决策。
- `GlobalCheckout` 后的刷新责任：现有草稿箱 watcher 可能已覆盖，本轮先不做无证据改动。

## 3. 实现顺序

1. 先写计划与分支提交。
2. 在 `global/file.rs` 抽父链查询，改 `global_file_versions` 与 `restore_file_version`。
3. 补 `global/tests.rs` 三个回归。
4. 清 `purge_name_chain`、收 test-only helper、回写 README。
5. 统一跑 `rds-analytics-resource --lib`、`panel_window`、`dialog_window`、`rds-workbench --lib`。
6. 按“一刀一 commit”合回 `main`，删除功能分支。

## 4. 验收标准

- 全局文件版本历史在“祖先行改名”后仍完整；同名不同根不混链。
- 全局文件历史恢复在改名后仍能按版本号命中目标。
- 生产构建不再报 `drop_global_archive_table` / `table_stats` 的 `dead_code`。
- 上述四套测试全绿；工作树 WIP 未被修改或提交。

## 5. 风险与回退

- **旧数据父链断裂**：只影响历史显示，不回退到按 name 合并；如发现存量断链，另开数据修复刀。
- **恢复路径改动**：失败时保持旧行为回执；不改变 `restore_file_version` 的“生成新 head、旧版保留”语义。
- **回退**：本刀独立分支，代码集中在 `global/file.rs` 与测试；可直接 revert 单提交，不影响已合流的 R2 修复。
