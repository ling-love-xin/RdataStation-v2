01

为什么它不再是一个「资源列表」

v1 有 2237 行后端存储，前端却只有占位卡片
旧样子现在
登记表只是一行元数据指向某处 归档凭证三件套（来源 + 定义 SQL + 内容指纹）；kind / 指纹 / 本体路径 / 只读是归档行的语义必填——走通用入口建不出「看起来像存档、实际没凭证」的行
版本是「写前快照」：任何一次 update 都 +1（改个别名也消耗一个版本号） 指纹是版本的唯一触发条件：内容没变就不产生版本；parent_version_id 指向写前快照行（v1 传的是资源自身 id，等于没有信息量）
回收站是模块私有的软删表（recycle.rs 419 行） 项目级 ProjectTrash（上提中性化：来源是字符串 origin）：与草稿箱共用一处仓库，跨模块还原被拒
文件夹树是残的（自引用 parent_folder_id，无改名 / 删除 / 移动 / 排序） 标签扶正 + 单层分组（裁决 D8）：标签多值、跨类型通用；分组单层，删分组不删存档
搜索 LIKE 不转义（输入 % 命中全表）· 分页除零 / 负数 panic · 更新无事务 · 行映射散在四份 逐条修掉：LIKE 转义 · 分页夹紧 · 事务化更新 · 行映射收敛为 1 份 · 影响 0 行不再静默
前端：300px 卡片网格（240px 面板放不下）· 页码分页器 · LRU + TTL 缓存（本身有缺陷）· 8 条只在设置页展示的假快捷键 紧凑行列表（虚拟化） · 滚动代替翻页 · 不迁缓存（本地 SQLite 没有 IPC 成本）· 快捷键真的绑上并有窗口测试守着

三种存档类型 · 一个本体规则

本体在哪由类型决定；登记表只是索引
类型本体在哪复现强度状态
文件 File {项目}/resources/ 里的文件（只读） 强：有字节 + 指纹，能逐字节校验 ✅ 已落地
分析表 Analysis {项目}/.RSmeta/analytics.duckdb 里的表 中：有结构与指纹，没有「导出字节」这一说 设计已定 · Phase 4
引用 TableRef 远端表（本地只留指针 + 指纹） 弱：只能回答「它还在不在、变没变」 设计已定 · Phase 5（不承诺）
诚实标注：一期只落地了文件档（从草稿箱或本地文件归档）。分析表 / 引用两档的类型、强度与降级口径已经在代码与文档里定死，但本体层与入口还没接。
03

三个高光

如果只记三件事

① 指纹是版本的唯一触发条件

content_hash 未变即幂等返回，不产生「假版本」；历史内容副本按策略裁剪（默认 5 份，可设「只留元数据」0 / 「全部保留」-1），而版本行永久保留。

界面上：副本被裁掉的版本写「副本缺失」——不假装能还原。

② 只读是常态，「取回」才是修改路径

归档即 move 进 resources/ 并置只读；修改走「取回（检出）」——复制一份可写工作副本到草稿箱，本体一个字节不动。

心智模型：与 git「签出 → 改 → 提交」同构。

③ 每一句「做不到」都带着原因

写 resources/ 直接拒并指向「先取回」；副本缺失如实标注；标签 / 分组没落上写进回执；索引修复只列差异，不静默导入、不静默删除。

反例：「按了没反应」在这套界面里是不允许的。
04

四个剧本 · 它替你做什么

每步都用现有按钮，能照着做

剧本 A · 报告发出去两周，被问「当时是哪一版」

→ 版本历史把「哪一版」变成可核对的事实
  1. 找到那份存档：搜索显示名 / 按类型筛 / 排序切到「更新时间 ↓」（选择会被记住）
  2. 看它改过几版：详情面板「版本」区 → 「查看全部…」
  3. 判断哪版是当时那份：每行给出 版本 / 归档时刻 / 大小 / 指纹前 12 位 / 副本是否还在
  4. 把旧内容拿出来用：「取回该版本为草稿」——不覆盖本体
  5. 或者把本体退回去：「还原」= 用旧内容生成新版本（v+1），历史一版不丢

剧本 B · 接手别人的分析，想知道数据从哪来

→ 凭证三件套 + 指纹，对账有依据
  1. 看来源：来源连接（跑过 SQL 的草稿自动带出）/ 来源草稿路径 / 来源表
  2. 看怎么算的：定义 SQL + 指纹前 12 位（可复制去对账）
  3. 看它现在什么样：行尾字段与状态行——已归档 / 分析表 / 引用；缺失与「内容已变」单独计数并给「修复…」入口

剧本 C · 要改归档文件，但不想毁掉原件

→ 取回 → 改 → 再归档
  1. 取回（检出）…：行右键或详情动作区；落点自动避让重名，不覆盖工作区已有文件
  2. 编辑工作副本：本体保持只读，改的是副本
  3. 再归档：内容变了才 v+1；旧内容先留成历史副本，再覆盖本体
  4. 内容其实没变？ 幂等返回：不覆盖本体、不增版本，工作副本留给你

剧本 D · 手滑归档错了 / 手滑删了

→ 撤销条与回收站，两头都能回来
  1. 立刻反悔：状态行上方撤销条（5 秒）——本体移回原位 + 删登记行；原位置被占则拒绝并说明
  2. 已经过点了：Delete 移入回收站 → 回收站「还原」（origin 校验 + 同名避让并同步登记路径）
  3. 确定不要了：「永久删除」二次确认；「清空」只清本模块名下的条目（别人的只给一句说明）
  4. 想撤销更多？ 不承诺：撤销条只保刚归档那一次，再归档的反悔走版本回退（剧本 A）

一次归档的全流程

先本体、后索引；索引失败把本体移回原处
  ┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌────────────────┐   ┌────────────┐
  │ 1 解析来源   │ → │ 2 算指纹     │ → │ 3 搬本体     │ → │ 4 写登记       │ → │ 5 附属项   │
  │ 草稿 / 本地  │   │ sha256 + 体积│   │ move + 置只读│   │ 归档行 v1      │   │ 标签 / 分组│
  │ 目标占用探测 │   │ （搬运前算） │   │ 失败即中止   │   │ 凭证三件套      │   │ 失败记回执 │
  └──────────────┘   └──────────────┘   └──────────────┘   └────────────────┘   └────────────┘
     host 事件路径        payload            payload             store              service
                                        ↑ 索引写失败 → 本体移回原处（不留「文件没了、列表也没有」）
步做什么落点
① 解析来源草稿候选（相对路径 / 显示名 / 连接从 file_meta 带出）或系统文件选择；目标被占则先算好「改名到哪」resource_host.rs
② 算指纹sha256 + 体积，在搬运前算：失败即中止，不动任何状态payload.rs
③ 搬本体move 进 resources/（跨设备退回复制 + 删除）并置只读；只读属性失败只警告payload.rs
④ 写登记归档行（kind / 指纹 / 本体路径 / 只读 + 凭证三件套）；索引失败回滚本体resource.rs
⑤ 附属项标签（按名找、找不到就建；同名复用）与分组（移动语义）；失败不回滚归档，写进回执service.rs
⑥ 广播与回执变更事件（Archived）→ 面板刷新；状态栏回执 + 5 秒撤销条service.rs / panels/
顺序固定：先本体、后索引 附属项不牵连主操作 事件发 / 收两端同批落地
06

版本语义：什么才算新版本

版本化的是「内容」，不是「改过名字」
事件结果
内容变了（指纹不同）v+1：先把当前内容留一份历史副本 + 写前快照行，再覆盖本体
只改显示名 / 别名 / 标签 / 分组不产生版本（登记行更新，版本号不动）
取回后原样再归档（指纹相同）幂等：不覆盖本体、不增版本，工作副本留给用户
历史内容副本超出保留策略只删副本：版本行永久保留，界面标「副本缺失」
还原到旧版本生成新版本（v+1，内容 = 那一版）；历史不被覆盖，随时能再退
在某版本上能做什么版本历史一行最多三个动作：还原 / 取回该版本为草稿 / 删除该版本的内容副本
保留策略在设置页「资产库 › 历史内容保留」：5 份（默认）· 0 只留元数据 · -1 全部保留；归档对话框里可为这一次覆盖。

字段优先级

显示名 > 复现强度徽标（唯一色块）> 版本徽标（v1 不显示）> 相对时间 > 大小。

>100 项：虚拟化列表，滚动不卡。

组织与检索

标签多值跨类型 · 分组单层 · 排序记住上次
件口径
标签多值、跨类型通用；新建 / 重命名 / 删除（删标签不动存档，确认框里写清「从 N 条存档上摘掉」）；详情面板与标签对话框两处入口
分组单层（没有多级子文件夹）；建 / 改名 / 删 / 移动到分组；拖行到分组头 = 归组（多选拖一条 = 拖整选集）；删分组不删存档（成员回「未分组」）；分组头右键给管理项
折叠点分组头折叠；状态按项目记住（设置项 resources.collapsed_groups，按项目根分桶）
筛选三维：类型（文件 / 分析表 / 引用）· 只看需处理 · 标签（多选并集，菜单里带用量）；按钮上标条件个数
排序五个键：名称 / 归档时间 / 更新时间 / 大小 / 版本号；同键再点翻转方向、换字段沿用方向；缺值两个方向都排最后；选择被记住
搜索匹配显示名 / 别名 / 标签 / 来源表 / 尾部字段（大小写不敏感）——别名 / 标签 / 来源表行上不显示但都搜得到（可搜不高亮）；Ctrl+F 聚焦，Esc 清空；搜不到时空态里会列出可搜字段
改显示名行上 F2 / 行右键「重命名…」/ 详情头部点名字；只改 project.db 里的名字，不涨版本、不进版本历史；resources/ 下的文件名与路径不动
改别名详情头部点别名（空时显示「＋ 别名」）；留空 = 清除；别名进搜索匹配面，同样不涨版本
内容预览详情面板里给文本型存档摆前 20 行（只读、等宽、不折行）；二进制 / 大文件 / 本体不在只给一句「仅元信息」
排序比的是原始值（时间戳 / 字节数），不是格式化后的尾巴——拿 1.2 KB 与 900 B 按字符串比会静默排错。

八个对话框

每个都开得出、校验拦得住、没提交就不发事件
对话框什么时候出现一条口径
归档确认从草稿箱（单选）或本地文件五个字段都真的落库：显示名 · 别名 · 分组（下拉）· 标签 · 保留历史内容；目标被占时按钮改成「改名归档」
草稿多选面板头 ＋ ▾ → 从草稿箱归档…选多个 = 默认名批量入队；选一个展开完整确认
取回（检出）行右键 / 详情动作区目标名可改、重名自动避让；「完成后打开」可选
版本历史详情版本区 / 行右键当前版本与历史同列；行选中后动作栏才对它生效；动作后不关窗、换行
索引修复状态行「修复…」/ 面板头 ⋯ → 重建索引…三分组（有文件无记录 / 有记录无本体 / 指纹不匹配）；修完自动重扫并换行
回收站面板头 ⋯ → 回收站…只列本模块条目；行内还原 / 永久删除；页脚「清空」只清自己名下的
标签详情「＋ 标签」/ 行右键勾选差集 + 新建并打上；每行 ⋯ 可重命名 / 删除
分组名新建 / 重命名分组一个文件两个形态；空名与同名当场拒（同层唯一）

回收站与索引修复

一个仓库按来源隔离 · 三类差异只报告
移入回收站 = 本体进 {项目}/.RSmeta/trash/ + 登记行软删（deleted_at）
还原       = origin 校验 → 同名避让 → 本体回 resources/ → 登记行复活（别名 / 标签 / 指纹一起回来）
永久删除   = 真删本体 + 删行（连标签与分组关联一起清，外键没有级联）
清空       = 只清 origin = "resources" 的条目（别人的条目只给一句说明）
索引修复的三类差异只报告，等人工确认
有文件、无记录补登为存档（指纹现算；来源无从得知就留空）
有记录、无本体从回收站还原（按原相对路径找条目）· 或 删除记录（二次确认）
指纹不匹配（内容被绕过只读改过）接受当前内容（生成新版本，旧内容不可得就如实说明）· 或 打开版本历史去还原
12

只读三重守卫

应用守卫是硬约束；文件属性只是顺手挡一下
层挡什么失效时
① 应用守卫（硬约束）任何写入 resources/ 的 API 调用：直接拒绝，文案指向「先取回」不失效——这是模块硬约束
② 编辑器只读打开本体在编辑器里没有光标（只读档）用户仍可「另存为」到别处（期望行为）
③ 文件系统只读属性（辅助）顺手挡一下外部工具Windows / 网络盘上不可靠——只警告，不影响归档成立
指纹是最后一道：即便有人绕过前面三层改了本体，下一次刷新的索引扫描会发现「内容已变」，并在界面上摆出来。
13

架构 · 依赖只向下

模块不认识草稿箱，也不碰工作区文件——一律走端口注入
rds-app
窗口 · 主题 · 键位注册（Ctrl+F / Esc / Delete / Ctrl+A）
rds-workbench
宿主：把端口接到真实世界—— panels/resources（面板装配 · 轮询回填）· services/resource_jobs（单工作线程 + 结果槽）· components/resource_host（22 个端口的实现）
rds-analytics-resource
模型与纯函数 + 视图（视图随 crate）
纯逻辑：filter（筛选 / 五键排序 / 折叠分区）· present（快照合成）
服务：service（编排 + 事件）· payload（本体层）· store（登记 / 版本 / 标签 / 分组）· indexer（修复）
视图：resource_view · detail_view · dialogs/（八个对话框）
rds-engine
持久化（项目库 · DuckDB 连接）· 项目级回收站 ProjectTrash（与草稿箱共用）
gpui-kit · shared · shell
视图唯一依赖 · 错误类型 · 壳层尺寸常量（模块内不出现裸 px() 与裸色值）
依赖方向：app → workbench → analytics_resource → engine → shared。 M6 不依赖 M5（归档入参只有「路径 + 元数据」）；上游 scratchpad → M6 单向。
端口组（Rc<dyn ResourcesHost> 共 22 个方法）回答什么
归档（request_archive_from_drafts / _from_file）从哪来 · 目标被占怎么改
打开与路径（request_open / _reveal / _copy_path / _open_payload_dir）只读打开本体 · 在系统中显示 · 复制路径
取回与版本（request_checkout / _version_history / _undo_archive）工作副本落哪 · 版本历史 · 撤销归档
组织（request_edit_tags / _remove_tag / _move_to_group / _create_group / _rename_group / _delete_group）标签与分组的全部动作
删除与回收站（request_delete / _open_trash）移入回收站（批量）· 打开回收站对话框
健康（request_index_repair / _refresh）重建索引 · 重新取数
记忆（remember_sort / remember_collapsed）把用户的排序 / 折叠选择写回设置

纪律一 · 渲染零 I/O

面板只读自己持有的快照；取数、扫描（逐个本体算 sha256）、搬文件全在单工作线程上，结果经结果槽回填。

纪律二 · 纯函数优先

筛选 / 排序 / 折叠分区、尾巴字段、相对时间、版本行与修复行的合成全是纯函数，逐条断言；尺寸进 ui.rs、颜色走主题 token，契约测试守着。

边界 · 这些事它不做

不做的（逐条有理由）

多级文件夹树 / 面包屑 / 手动排序号 · 页码分页（10/20/50/100）· 归档本体的原地编辑 · 自动索引修复 · 版本行级 diff · config JSON 手工编辑 · 拖拽到 SQL 编辑器 · v1 设计文档里从未实现的 17 条命令。

还没做的（都记在册）

口径：没实现就不宣传——能力清单里它们单独成列。
